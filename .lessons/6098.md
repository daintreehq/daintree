## Context

`refreshPath()` resolves the user's real interactive PATH because an Electron app launched from Dock/Finder inherits a minimal launchd/login PATH (see #4248, #4700). PR #6098 replaced the `shell-env` parser with a markered `$SHELL -i -l -c` probe (`runShellProbe()` / `parseMarkeredPath()` / `resolvePathViaShellProbe()`), gated behind `DAINTREE_SHELL_PROBE=1` for one release of dogfooding before becoming default. The probe spawns a full interactive login shell so lazy-loaded version managers (mise/asdf shims, `eval "$(pyenv init)"`, fnm, pnpm) — invisible to a static `.bashrc` parse — show up.

## Problem

A naive "spawn login shell, capture stdout, JSON.parse it" implementation hangs forever on a meaningful fraction of real machines, and parses garbage on the rest. An interactive shell prints Powerlevel10k instant-prompt frames, oh-my-zsh update banners, fortune/motd, and compliance-script output interleaved with whatever you asked for — raw stdout is not parseable JSON. And piping stderr to drain it (the obvious "be safe, capture everything" move) is exactly what deadlocks the child.

## Root cause

Two structurally independent traps, both must be handled:

1. **stderr pipe deadlock.** `spawn(shell, [...], { stdio: ["ignore", "pipe", "ignore"] })` — stderr is `"ignore"`, NOT `"pipe"`. A noisy `.zshrc` can write tens of KB to stderr (banners, compliance scripts). A piped-but-undrained stderr blocks the child once the OS pipe buffer fills (~64KB), so the probe never reaches its closing `printf` marker — guaranteeing the 10s timeout on precisely the slow-init machines the probe exists to serve. Mirrors VS Code's `getUnixShellEnvironment`.

2. **Prompt-tool noise.** The probe brackets the env dump in a 16-byte random-hex marker: `printf '%s' "$marker"; <dump>; printf '%s' "$marker"`. `parseMarkeredPath()` extracts only the bytes between the first balanced marker pair (non-greedy `marker([\s\S]+?)marker`) and JSON-parses that — everything Powerlevel10k/oh-my-zsh/motd emitted outside the markers is discarded.

The env dump itself runs as `"${process.execPath}" -e 'process.stdout.write(JSON.stringify(process.env))'` with `ELECTRON_RUN_AS_NODE: "1"` in the child env — the Electron binary acts as plain Node, so the probe doesn't depend on `node` being on the user's (not-yet-resolved) PATH. Note this is the _deliberate inverse_ of #4232: scripts that spawn Electron-as-GUI must strip `ELECTRON_RUN_AS_NODE`; this probe sets it on purpose to get a Node env dump.

Supporting non-obvious choices, all load-bearing:

- **Non-zero exit is accepted** — `child.on("close")` settles on `parseMarkeredPath(stdout)` regardless of exit code, because interactive login shells routinely exit non-zero; valid markers + JSON is the only success signal.
- **Late-write guard** — `runRefreshPath()` checks a `timedOut` flag before writing `process.env.PATH`, so a shell that closes during the SIGTERM→SIGKILL grace window can't clobber the fallback-augmented PATH the post-race block already set.
- **Two singletons, cleared on null** — `shellProbePromise` (inner) and `pathRefreshPromise` (outer) dedup concurrent callers, but both clear on a null/failed result so a transient failure isn't cached for the whole session.
- **`DAINTREE_RESOLVING_ENVIRONMENT=1`** is set in the child env so users with slow init sections can guard them.

## Lesson

When spawning a login shell to read the user's environment:

- Set stderr to `"ignore"`, never `"pipe"` unless you actively drain it on `data` — an undrained pipe deadlocks the child the moment a chatty `.zshrc` fills the OS buffer, and the failure mode is a guaranteed timeout on exactly the machines that needed the probe.
- Bracket the payload in a random per-invocation marker and parse only between markers — interactive-shell stdout is contaminated by prompt frameworks, update banners, and motd; you cannot JSON.parse raw stdout.
- Dump env via the Electron binary with `ELECTRON_RUN_AS_NODE=1`, not `node` — `node` may not be on the PATH you're trying to discover.
- Treat valid markers+JSON as success even on non-zero exit; interactive login shells exit non-zero normally.
- Guard the post-timeout PATH write against a late `close` from a slow-dying child, and clear any in-flight singleton on failure so a transient hang doesn't poison the session.

## Applies when

- Touching `runShellProbe`/`parseMarkeredPath`/`resolvePathViaShellProbe` in `electron/setup/environment.ts`, or flipping the `DAINTREE_SHELL_PROBE` default on.
- Writing any new code that spawns `$SHELL -i -l -c` (or `--login`) to read PATH/env on macOS/Linux.
- Debugging a 10s PATH-resolution timeout that only reproduces on machines with heavy zsh frameworks (Powerlevel10k, oh-my-zsh) or corporate `.zshrc` compliance scripts.
- Seeing PATH resolve to garbage / fail to JSON.parse because prompt-tool output leaked into the captured stream.
