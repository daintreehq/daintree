## Context

`panelStore.addPanel` decides whether a newly-spawned panel claims keyboard focus. Panels carry a `spawnedBy: TerminalSpawnSource` ("quickrun" | "recipe" | "agent" | "palette" | "mcp") provenance tag. MCP-initiated spawns must not steal focus from a user typing in another pane (the #6959 assistant-focus-theft fix), so focus-suppression originally piggybacked on `spawnedBy === "mcp"`.

## Problem

Two orthogonal axes — provenance (who launched this panel) and focus policy (should focus move to it) — were collapsed into one field. The only way for a non-MCP background caller (recipes, watchdog auto-spawns, agent auto-relaunch) to opt out of focus capture was to lie about its origin. `useAgentLauncher.ts` did exactly that: `spawnedBy = launchOptions?.spawnedBy ?? (isMcpSpawnFocusSuppressed() ? "mcp" : undefined)` — silently re-tagging non-MCP spawns as MCP-originated purely to inherit a focus default, corrupting provenance for any consumer that reads `spawnedBy`.

## Root cause

A discriminator field was overloaded to also encode a behavioral policy. Once `spawnedBy: "mcp"` means "suppress focus," every code path that wanted focus suppression had to claim MCP origin, and conversely any future caller that legitimately had MCP provenance inherited the focus side effect whether it wanted it or not. The same `spawnedBy === "mcp"` check was duplicated across five gates: `panelStore.ts` focus advance, `panelRegistry/addPanel.ts` dock-popover suppression (two sites), and the `DockedTabGroup`/`DockedTerminalItem` Radix `onOpenAutoFocus` guards. Provenance and policy drifting through the same field meant a change to one silently changed the other.

## Lesson

- When a field is a provenance/origin discriminator, do NOT let it also gate behavior. Add an explicit policy field stating intent directly. PR #9035 added `AddPanelFocusPolicy = "auto" | "preserve" | "take"` (`shared/types/panel.ts`); the MCP bridge (`useMcpBridge.ts` `tagMcpSpawnSource`) now stamps BOTH `spawnedBy: "mcp"` (provenance) AND `focusPolicy: "preserve"` (policy) as two independent assertions.
- Resolve the policy to a concrete value at the SINGLE layer that owns the contextual default, synchronously before the async registry call. `panelStore.addPanel` computes `resolvedFocusPolicy = options.focusPolicy ?? (isMcpSpawnFocusSuppressed() || !kindPolicy.defaultFocusOnCreate ? "preserve" : "auto")`, folding three independent suppression signals (explicit caller policy, active MCP-suppression scope, the kind's `defaultFocusOnCreate: false` opt-out) into one value the five downstream gates read.
- Do NOT default the policy to `"preserve"` at intermediate pass-through layers. `recipeStore.runRecipe` passes `focusPolicy` through as-is (possibly `undefined`) with an explicit comment: defaulting to `"preserve"` there would strip focus from user-initiated recipe runs (dock menu, NewWorktreeDialog, WorktreeCard), while MCP-initiated runs already get `"preserve"` via `panelStore`'s `isMcpSpawnFocusSuppressed()` check. The layer that knows the MCP-dispatch context is the only one allowed to default.
- The pre-existing #6959 synchronous capture-before-await ordering and the #6590 atomic dock-activation fold are load-bearing; new policy fields slot BETWEEN those gates, not around them (regression tests: `panelStore.assistantFocusGuard.test.ts`, `dockActivateOnCreate.test.ts`).

## Applies when

- Adding any new option to `AddPanelOptions` / `addPanel` that controls focus, dock-popover activation, or panel visibility on create.
- Tempted to reuse `spawnedBy` (or any `*Source`/`origin`/`provenance` discriminator) to gate a behavior because "MCP/recipe/agent spawns should also do X."
- Touching focus-suppression gates in `panelStore.ts`, `panelRegistry/addPanel.ts`, `DockedTabGroup.tsx`, or `DockedTerminalItem.tsx` (`onOpenAutoFocus`), or the MCP stamper in `useMcpBridge.ts`.
- Adding a background/automated panel spawner (watchdog auto-spawn, agent auto-relaunch, batch recipe run) that must not steal keyboard focus — set `focusPolicy: "preserve"`, do not tag it `spawnedBy: "mcp"`.
- Designing any API where an origin/source enum is being asked to carry behavioral policy — split policy into its own explicit field and default it at the single layer that holds the contextual signal.
