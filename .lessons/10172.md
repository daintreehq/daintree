## Context

Terminal output reaches the renderer on two transports with two independent flow-control ledgers. The IPC path: the pty-host charges `ipcQueueManager.addBytes(id, Buffer.byteLength(dataString, "utf8"))` before each send (`electron/pty-host.ts`, charge near L1160/L1209) and pauses the PTY at the 67% high watermark of the 3MB per-terminal queue (`IPC_HIGH_WATERMARK_PERCENT` / `IPC_MAX_QUEUE_BYTES` in `electron/services/pty/types.ts`); the renderer's `TerminalWriteController.write` acks after xterm consumes the chunk, drained in `electron/pty-host/handlers/backpressure.ts`. The MessagePort path has its own queue, and the renderer additionally runs a third, renderer-local ingest ledger (`TerminalOutputIngestService.inFlightBytes`).

## Problem

Heavy non-ASCII output — box-drawing TUIs (i.e. every AI-agent CLI), CJK, emoji — tripped `paused-backpressure` on terminals that were keeping up fine. Each episode self-healed via the 10s safety timeout (`IPC_MAX_PAUSE_MS`), so the symptom was intermittent 10s output stalls rather than a permanent wedge, which masked that the underlying accounting error was deterministic and monotonic. Issue #9893 carries the full diagnosis.

## Root cause

The renderer acked with `typeof data === "string" ? data.length : data.byteLength` — JS `.length` is UTF-16 code units, but the host had charged UTF-8 bytes. UTF-8 byte count >= UTF-16 unit count for every character: a box-drawing char (U+2502) charges 3 and acks 1, an emoji charges 4 and acks 2. Every non-ASCII chunk therefore leaves a positive residue in the host's `queuedBytes`, which never drains and ratchets toward the high watermark. The wire field was named `charCount`, actively inviting the `.length` ack — the misnomer was part of how the bug arose. Tellingly, the port path had already hit and solved this exact mismatch: `src/clients/terminalClient.ts` queues the host's original byte count in the `pendingPortAckBytes` FIFO ("to avoid UTF-16 vs UTF-8 length mismatches") instead of re-measuring — the IPC path just never got the same treatment.

Articulating the two-ledger model exposed two adjacent bugs in the same code. (1) Double-drain: `acknowledgeData` fired for every chunk including port-delivered `Uint8Array`s, so mixed-path delivery spuriously drained the host's IPC ledger. (2) Hibernated leak: the hibernated early-return dropped data (never replayed) without acking the IPC ledger at all — a permanent per-terminal leak with no self-heal. The fix (#10172) kept each ledger internally consistent rather than "unifying" units: the IPC ack converts via `utf8ByteLength()` (module-level `TextEncoder`) to match the host's charge, while `acknowledgePortData`/`notifyWriteComplete` deliberately stay in UTF-16 because `inFlightBytes` is incremented via the same `.length` — routing UTF-8 there would unbalance the renderer ledger instead. The deferred-restore path is intentionally left un-acked: deferred chunks replay through the normal write path where the ack fires, so acking at defer time would double-drain (this invariant survives today with a deepened comment — the replay double-debit also corrupts the port-ack FIFO).

## Lesson

- **An ack against a remote ledger must be denominated in the unit the ledger was charged in — the safest pattern is to carry the producer's original charge with the data and echo it back**, like `pendingPortAckBytes` does, rather than re-measuring at the consumer where the unit choice can silently diverge. If you must re-measure, convert explicitly (`utf8ByteLength` in `TerminalWriteController.ts`).
- **`string.length` is not a byte count.** The idiom `typeof data === "string" ? data.length : data.byteLength` yields two different units depending on branch — fine for a renderer-local ledger charged the same way (`inFlightBytes`), wrong as an ack against a byte-charged remote ledger. Grep for this pattern whenever a byte-denominated protocol crosses a JS string boundary.
- **Multiple ledgers each want their own unit — don't unify, balance.** The host IPC ledger is UTF-8; the renderer ingest ledger is UTF-16; each is correct because its charge and drain match. The fix's `renderedBytes` vs `ackBytes` split in `TerminalWriteController.write` exists precisely to feed each ledger its own unit.
- **Every path that consumes, drops, or defers charged data must settle the ledger exactly once.** Drop paths must ack (the hibernated fix — since removed with hibernation itself in #10811); defer paths must NOT ack (deferred-restore replays through the normal path); and acks must be guarded by transport (`typeof data === "string"`) so a chunk never drains the other transport's ledger.
- **A safety-timeout self-heal converts a deterministic accounting bug into an intermittent symptom.** The 10s `IPC_MAX_PAUSE_MS` force-resume bounded each episode, so the drift looked like sporadic load stalls, not a monotonic leak. When backpressure pauses recur under a workload the pipeline demonstrably handles, audit the ledger arithmetic before the throughput.
- **Name wire fields by their unit.** `charCount` → `byteCount` was part of the fix; an ambiguous unit name on a protocol field is a standing invitation for the next caller to pick the wrong measurement.

## Applies when

- Touching `TerminalWriteController.write`, `acknowledgeData`/`acknowledgePortData`, `electron/pty-host/handlers/backpressure.ts`, `ipcQueue.ts`/`portQueue.ts`, or the `pendingPortAckBytes` FIFO in `terminalClient.ts`.
- Diagnosing spurious `paused-backpressure` / recurring ~10s output stalls that correlate with box-drawing TUIs, CJK, or emoji-heavy agent output rather than raw throughput.
- Adding any new credit/debit ledger that crosses a process or transport boundary (IPC vs MessagePort, main vs pty-host) — decide the unit once, name the wire field after it, and prefer echoing the producer's charge over re-measuring.
- Reviewing code that acks or measures chunk sizes with `.length` on a `string | Uint8Array` union, or that adds a new early-return (drop, defer, hibernate-like park) between charge and ack.
- Assuming an intermittent, self-recovering stall can't be a bookkeeping bug because "it clears itself" — the safety timeout is what makes ledger drift look nondeterministic.
