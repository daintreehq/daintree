## Context

Three independent issues were bundled here: dnd-kit bounding box staleness during drags, macOS back-navigation gesture triggering on dock scroll, and xterm terminals restoring from an offscreen/background tier with stale dimensions.

Note: per-terminal hibernation itself was later torn out entirely (PR #10811, `experiment/remove-terminal-hibernation` merged to develop) — a background-tier pane now stays fully live (host streams, renderer parses live) instead of being suspended. The stale-dimensions problem below didn't go away with it: it now shows up on the surviving reveal/reactivation path (foreground tier transitions and view-reveal after occlusion), which is what the "Lesson" section is framed against.

## Problem

### 1. Stale DnD measurements

`DndContext` uses dnd-kit's default measurement strategy, which caches droppable bounding boxes. The grid applies a 200ms CSS transition on `grid-template-columns`. During a window resize mid-drag, column layout changes but cached boxes are stale — panels drop into wrong slots.

### 2. macOS navigation gesture

The dock scroll container uses `overflow-x: auto` but lacks `overscroll-behavior-x: none`. On macOS, horizontal trackpad scrolling past the scroll boundary triggers Electron's back/forward navigation gesture.

### 3. Post-wake stale dimensions

`handlePostWake` used `latestCols`/`latestRows` — values cached before the terminal went to the background tier. After reactivation, if the window was resized while backgrounded, terminals would have incorrect dimensions until the next resize event. The post-wake path also only triggered for alt-screen terminals, not all terminals.

## Root cause

dnd-kit defaults to measuring only when dragging starts. The `TerminalRendererPolicy` alt-buffer gate on `onPostWake` was overly narrow.

## Lesson

- Configure `MeasuringStrategy.Always` with `frequency: 150` in dnd-kit's `DndContext` whenever any animated layout change (CSS transitions on grid, panel resize) can occur during a drag.
- Always set `overscroll-behavior-x: none` on any horizontally scrollable container in an Electron app on macOS.
- On reactivation from a background/offscreen tier, re-measure and call `fit()` before falling back to cached `latestCols`/`latestRows` — a container can resize while a pane is backgrounded and the cached grid goes stale. Skip `fit()` only for settled-strategy agents (Codex, Gemini, Cursor, Copilot, …) that need atomic xterm+PTY resize, and for alt-screen panes, which stay current from the live PTY stream and would only get re-wrapped mid-paint.
- The post-wake callback should fire for all terminals, not just alt-screen ones — this is what `handlePostWake` (`src/services/terminal/TerminalInstanceService.ts:1896`) does today, called from the tier-transition path in `TerminalRendererPolicy.ts` and from `TerminalRevealController.ts`'s reveal/reactivation flow; each callee then applies its own narrower internal skip (alt-buffer, in-flight stream) rather than the whole callback being gated.

## Applies when

- Adding new drag-and-drop droppable regions in animated layouts
- Adding horizontal scroll containers in Electron on macOS
- Implementing terminal reveal/reactivation logic after any off-screen or background-tier period (there is no more per-terminal hibernation to wake from, but the same stale-geometry trap applies to tier transitions and view-reveal after occlusion)
