## Context

`useAgentLauncher.ts` composes a panel's initial title at launch time (`title`, then a preset-aware `presetTitle`), and separately stamps `titleMode: "custom"` on `AddPanelOptions` when that title must survive later rewrites — otherwise a panel is implicitly `titleMode: "default"`. Two independent consumers of that flag then run whenever agent detection fires: the main-process `TerminalAgentDetection.ts` (via `computeDefaultTitle` in `electron/services/pty/terminalTitle.ts`) and the renderer's `src/store/listeners/panel/identityReducer.ts` (`reduceAgentDetected`, via `getDefaultTitle`). Both only touch the title when `(terminal.titleMode ?? "default") === "default"` — by design, so a plain terminal's tab picks up "Claude" the instant the CLI is detected inside it.

## Problem

Launching an agent through a preset (`agentPresetId`/`agentPresetColor` on the panel) composed a correct title at launch — `Claude (Z.ai)` in the older parens format, later just `Z.ai` after `b9b168973` dropped the agent-name half — but within moments of the terminal spawning, the panel title flattened to the bare agent name (`Claude`), discarding the preset entirely. The misleading part: the preset's icon color (`agentPresetColor`) stayed correct throughout, so the bug read as "title breaks, color doesn't" and pointed investigation at title-specific formatting/serialization code rather than at the shared detection-sync path that both features run through.

## Root cause

`presetTitle` in `useAgentLauncher.ts` was computed correctly at launch, but the `titleMode: "custom"` pin was wired only to `trimmedName` (the assistant/caller-supplied name path added in #10449) — `const customTitle = trimmedName ? { titleMode: "custom" } : {}` never considered whether a preset title was in effect. So every preset-launched panel started life as `titleMode: "default"` even though its title was not the default. The instant agent detection fired (which for a freshly-spawned agent CLI is near-immediate), `computeDefaultTitle` recomputed the title from `terminal.detectedAgentId`/`launchAgentId` alone — with no notion of "preset" — and both the pty-host and the renderer wrote that bare name back over the composed one because `titleMode` said it was safe to. `agentPresetColor` has no equivalent sync path, which is exactly why it never got clobbered and became a false lead. Fixed by computing `hasPresetTitle` alongside `presetTitle` and folding it into the same pin check: `trimmedName || hasPresetTitle ? { titleMode: "custom" } : {}`.

## Lesson

- **Any code that composes a non-default panel title at launch must pin `titleMode: "custom"` in the same branch that computes it** — a title and its pin are one atomic decision, not two independently-maintained fields; `useAgentLauncher.ts` had already made this mistake once (caller-name path was pinned, preset path wasn't) in the same function.
- **`titleMode: "default"` is watched by two independent consumers that must be kept in lockstep** — `computeDefaultTitle` in `electron/services/pty/terminalTitle.ts` (main process) and `getDefaultTitle` via `identityReducer.ts` (renderer); the file's own doc comment says as much ("Kept in lockstep with... If you change the rule here, update those files too"). A fix that only patches one side leaves the other still clobbering.
- **"One field survived, a related one didn't" is the fingerprint of a partial-clobber bug, not two separate bugs** — here, preset color survived because no sync path touches it while title reverted because `computeDefaultTitle` does; when a launch-time value degrades to its default asymmetrically with a sibling value, look for a detection/sync path that recomputes one field but not the other, not a formatting or persistence bug in the field that broke.
- **Detection fires fast enough that "it worked when I glanced at the panel right after launch" is not a valid manual test** — the composed title can be visually correct for a frame before the sync path overwrites it; verify post-detection state (wait for `agent:detected`), not launch-time state, exactly as the added `preset-panel-behavior.spec.ts` test 111 does via the dock chip.
- **This was a long-standing latent gap, not a clean single-commit regression** — the titleMode-gated overwrite predates the pinning concept itself (added for caller names in #10449/`b850eaf73`); presets were arguably always exposed, and `b9b168973` (April 2026) only made the symptom more visible by dropping the agent name from the composed title. Don't assume a single "blame" commit exists for every stale-state bug — some are gaps never closed, not regressions introduced.

## Applies when

- Adding or changing any launch-time title/label composition on a panel (presets, caller/assistant-supplied names, future per-launch metadata) in `useAgentLauncher.ts` — check whether `titleMode` needs to cover the new case too.
- Diagnosing "a value I set at launch reverted a moment later" on a `PtyPanelData` panel — check `terminal.titleMode` and search both `computeDefaultTitle` call sites (`TerminalAgentDetection.ts`, `TerminalExitHandler.ts`) and `identityReducer.ts`.
- Seeing one launch-time field survive (e.g. `agentPresetColor`) while a sibling field reverts (e.g. title) — treat it as one sync path touching one field, not two independent bugs.
- Touching `electron/services/pty/terminalTitle.ts`'s `computeDefaultTitle` or `src/store/listeners/panel/identityReducer.ts`'s `getDefaultTitle` — remember the doc-comment lockstep requirement between the two files.
- Writing an E2E assertion about a panel title right after `agent.launch` — assert post-detection state, not the launch-time value, or the test will pass on the very bug it should catch.
