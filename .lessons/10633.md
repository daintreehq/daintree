## Context

`ProcessTreeKiller` (`electron/services/pty/ProcessTreeKiller.ts`) tears down an agent's whole process tree on kill. It forks at `process.platform === "win32"`: Windows runs `spawnSync("taskkill", ["/T", "/F", "/PID", String(shellPid)], …)` then `ptyProcess.kill()`; Unix runs the SIGTERM→SIGCONT→SIGKILL bottom-up cascade. `terminalShell.ts` `findWindowsShell()` similarly branches (`pwsh.exe → powershell.exe → COMSPEC → cmd.exe`). #10633 was tests-only: it closed coverage gaps in these Windows node-pty paths — no production change.

## Problem

`ProcessTreeKiller.test.ts` looked well-covered, but every test opened with `if (process.platform === "win32") { return; }`. On Windows the whole suite passed **vacuously** — each test early-returned before its first `expect`, so the Windows kill path (`taskkill /T /F`, the load-bearing teardown for the entire agent tree) was asserted by _nothing_, anywhere, on any platform. Worse, Daintree runs unit tests on **Ubuntu only** for push/PR (`.github/workflows/ci.yml`; Windows is manual-dispatch `-f os=windows`), so those Unix-branch assertions ran, went green, and the `taskkill` branch stayed permanently untested while the suite reported full coverage.

## Root cause

Two failure modes hide behind the same `if (platform) return` idiom, and Ubuntu-only CI makes both invisible.

First, **an early-return is not a skip**. A test that returns before any assertion is reported as PASS, not SKIPPED — vitest counts it toward green, and the test summary gives no signal that its body was inert. So a POSIX-only suite guarded per-test with `if (win32) return` looks like a passing Windows suite to anyone reading Windows CI output.

Second, and Daintree-specific: because push/PR unit CI is **Ubuntu-only**, a _Windows_ code path can never be exercised by a real-platform test in CI — the `win32` branch is unreachable on the runner. Prior to #10633 the `taskkill` branch had zero coverage precisely for this reason. Guarding a Windows test with `if (posix) return` would make it green-with-zero-assertions on every CI run forever. The only way to actually assert a cross-platform branch in Ubuntu-only CI is to **mock `process.platform`** and mock the platform's syscall boundary (`spawnSync`/`execFileSync`), so the branch runs regardless of the runner's OS. #10633 does both: it wraps the POSIX cascade in `describe.skipIf(process.platform === "win32")(…)` (line 56) so it reports SKIPPED on Windows, AND adds a `"ProcessTreeKiller — Windows taskkill"` suite (line 266) that flips platform via a `setPlatform("win32")` helper (`Object.defineProperty(process, "platform", { value, configurable: true })`, restored in `afterEach`) over a mocked `spawnSync`, asserting exact args/options, taskkill-before-`pty.kill()` ordering, no POSIX signals, error swallowing, and the `shellPid <= 0` short-circuit. The anti-pattern still lives elsewhere (`electron/services/__tests__/McpPaneConfigService.test.ts` lines 58/66) — this is not a one-off.

## Lesson

- **Never gate a test with a bare `if (process.platform === X) return`** — an early return before any `expect` is reported as a PASS, so the platform you meant to exclude records a vacuous green with zero assertions. Use `describe.skipIf(cond)` / `it.skipIf(cond)` (or `const posixIt = win32 ? it.skip : it`) so the excluded platform reports **SKIPPED** — a visible, countable signal in the summary. The repo already uses this idiom in ~40 places; match it.
- **Daintree push/PR unit CI is Ubuntu-only** (`.github/workflows/ci.yml`; Windows only via `gh workflow run CI -f os=windows`). A Windows-branch test guarded to only run on Windows is therefore **dead in CI forever**. To cover a `win32`/`darwin` branch, MOCK `process.platform` via `Object.defineProperty(process, "platform", { value, configurable: true })` (save/restore the original descriptor in `afterEach`) and mock that branch's syscall boundary (`vi.mock("child_process", …)` for `spawnSync`/`execFileSync`) — then the branch is asserted on the Ubuntu runner. `skipIf` alone fixes visibility but leaves the other platform uncovered; you usually need both.
- **Prove the assertion is load-bearing with an anti-vacuous mutation.** #10633's own verification: dropping `/T` from the expected `taskkill` args must make the test fail. If deleting the behavior under test doesn't turn the test red, the test asserts nothing. This is the positive companion to CLAUDE.md's "no tautological assertions" rule.
- **When you touch a cross-platform-branching source file, audit its test for the guard direction.** A suite full of `describe`/`it` that all early-return on one platform is a coverage hole wearing a green badge — count the assertions that actually execute on each platform, not the tests that "pass".

## Applies when

- Writing or reviewing any test for code that branches on `process.platform` (`ProcessTreeKiller`, `terminalShell` `findWindowsShell`/`getDefaultShell`, `TerminalProcess.kill`, worktree/git/fs-permission paths) — check whether the non-CI platform's branch is actually asserted or just early-returned.
- You see `if (process.platform === "win32") return;` (or `=== "darwin"`) inside a test body — replace with `describe.skipIf`/`it.skipIf` for visibility, and add a mocked-`process.platform` suite if the branch needs real coverage (live example still present in `McpPaneConfigService.test.ts`).
- Asserting a Windows (or macOS) code path in a repo whose push/PR unit CI runs on Ubuntu only — real-platform guards give zero CI coverage; mock the platform and its syscall boundary instead.
- A suite reports all-green but you suspect it never runs its assertions on the target platform — mutate the behavior under test (drop a flag, change an arg) and confirm a test goes red; if none do, the coverage is vacuous.
- Adding tests to the pty-host / node-pty Windows surface (`taskkill /T /F`, `where pwsh.exe`, COMSPEC fallback) that CI's Ubuntu runners can never reach natively.
