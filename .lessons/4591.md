## Context

The project switcher palette was redesigned to show modifier key hints in a footer bar: `↵ Switch`, `⌘↵ New window`, `⌥↵ Background`. The hints update live as the user holds modifier keys, driven by a new `useModifierKeys` hook (`src/hooks/useModifierKeys.ts`) that tracks `meta`/`alt` state via `keydown`/`keyup` listeners on `window`.

## Problem

Modifier keys can get "stuck" if the user switches windows (Cmd+Tab, for example) while holding a modifier key. The `keyup` event never fires for the modifier because focus was transferred away, so the hint UI shows a modifier as permanently held after the user Cmd+Tabs away and back.

## Root cause

`keydown` sets `meta: true` or `alt: true`, but `keyup` is only delivered to the document that has focus. If the user presses `Cmd+Tab` while the palette is open, the window loses focus mid-modifier and the `keyup` for `Meta` never arrives in the renderer — leaving `meta: true` stuck in state. The same hole exists when the whole tab/view is hidden rather than just blurred.

## Lesson

Any hook that tracks modifier key state must reset on focus loss, not just on `keyup`. `useModifierKeys` covers both escape paths:

- `window` `blur` listener calls `reset()` to zero all modifier flags when focus leaves the renderer.
- `document` `visibilitychange` listener calls `reset()` when `document.hidden` becomes true, covering tab/view hide where `blur` may not fire reliably.

Implementation detail: the hook treats `Meta` and `Control` as the same `meta` flag (so the same hint logic works cross-platform), and uses functional `setState` updates that no-op when the flag is unchanged to avoid redundant renders.

Test the reset paths: `window.dispatchEvent(new Event('blur'))` should zero all modifier flags; likewise a `visibilitychange` with `document.hidden === true`.

This applies to any UI showing modifier-dependent hints (modifier-key shortcuts, contextual tooltips, drag-and-drop operations).

## Applies when

- Building keyboard shortcut hint UIs (tooltips, footer bars, overlays)
- Drag-and-drop with modifier-key modes
- Any React hook that tracks `keydown`/`keyup` for modifier keys
