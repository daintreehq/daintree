## Context

`terminalFont.ts` gates terminal startup on JetBrains Mono: `ensureTerminalFontLoaded()` races `document.fonts.load()` (regular + bold weights) against a 3s timeout, and `XtermAdapter` originally suspended on `use(terminalFontReady)` so `terminal.open()` measured cell metrics against the real font. xterm (pinned 6.1 beta) measures cell width/height once in `CharSizeService` at open and caches it; every grid dimension (`cols`/`rows`, fit, cursor placement) derives from that measurement.

## Problem

When JetBrains Mono lost the 3s race (cold cache, slow disk), the terminal opened measured against the fallback monospace stack and the grid stayed mis-sized for the entire session — the font eventually arrived and painted, but cell metrics never updated, so text/cursor/fit were all subtly wrong (#9776). Two things pointed diagnosis the wrong way: a stale comment in `XtermAdapter` claimed "xterm does not re-measure after open" (false for the pinned 6.1 beta — it re-measures on a genuine `fontFamily`/`fontSize` change), and the race swallowed its own outcome, so nothing downstream even knew the open had been mis-measured.

## Root cause

Two mechanisms compound. First, the race discarded its outcome in both branches — `Promise.race([load, timeout]).then(() => undefined, () => undefined)` — while the losing `document.fonts.load()` was never cancelled and kept running to completion. The recovery signal (the real load settling late) existed but no code held a reference to it. Second, even if you knew the font arrived, a plain `fit()` cannot repair the grid: `fit()` reuses `CharSizeService`'s cached metrics, and re-assigning the same `fontFamily` string is a silent no-op because xterm's `OptionsService` dedupes same-value sets before firing change events. The only way to invalidate the cell-metric cache without tearing the terminal down is to set `fontFamily` to a _distinct but CSS-identical_ string — a trailing space parses the same (no visible flicker) but defeats the dedupe, firing `onMultipleOptionChange` → `CharSizeService.measure()` — then restore the original. `repairFontGrid()` in `TerminalInstanceService` does exactly this per instance, then resets `managed.lastWidth`/`lastHeight` to 0 (the ResizeObserver-driven resize path dedupes by pixel size, so without the reset the next observation is suppressed) and refits.

The fix held the real load as `Promise.allSettled` (not `all` — a failed bold weight must not mask the regular weight arriving and changing metrics), chained late-arrival detection off it (keyed to JBM specifically, not a `document.fonts` `loadingdone` listener that any unrelated font would trip), and exposed a one-shot `onTerminalFontArrivedLate(cb)` that `TerminalInstanceService` wires in its constructor. Follow-up #9844 then removed the `use(terminalFontReady)` Suspense gate entirely — `use()` on an unannotated native promise suspends at least one render cycle even when the font is already cached, blanking the pane via `TerminalPane`'s `<Suspense fallback={null}>` on every cold open — and that exposed a latent condition bug: the repair trigger was `timedOut && anyLoaded`, which encoded the gate's existence. With the gate gone, terminals open immediately, so a cache-miss font landing _within_ the 3s window (the common case) also arrives after terminals measured against the fallback — #9844 dropped the `timedOut` half so the repair fires on any JBM load completion, and flipped the test that had asserted the old gated behaviour.

## Lesson

- **Setting an xterm option to its current value is a silent no-op** — `OptionsService` dedupes same-value sets, so "re-assign `fontFamily` to force a refresh" does nothing. To invalidate `CharSizeService`'s cell-metric cache without teardown, poke to a CSS-identical distinct string (trailing space) and restore; `repairFontGrid()` (`src/services/terminal/TerminalInstanceService.ts`) is the canonical pattern, now also proxied per-plane through `PaintFabricCompositor.repairFontGrid()`.
- **Never discard the outcome of a promise-vs-timeout race when the loser keeps running.** `document.fonts.load()` is not cancelled by losing `Promise.race`; hold the real promise and chain recovery off it. `.then(() => undefined, () => undefined)` on the race result destroyed the only signal that the open was mis-measured.
- **When you remove a gate, re-derive every downstream condition that assumed it.** `timedOut && anyLoaded` was correct only while the Suspense gate held terminals until timeout; after #9844 removed the gate the guard silently excluded the common repair case. A recovery trigger phrased as "after the timeout" often really means "after consumers proceeded without the resource" — encode that directly.
- **React 19 `use()` on a native promise suspends at least one render cycle even when already resolved** — with a `null` Suspense fallback that is a guaranteed blank frame per cold open. Prefer proceeding immediately plus out-of-band repair when a correct-after-the-fact fix exists.
- **A metric repair is incomplete without clearing downstream dedupe caches**: `fit()` alone reuses stale metrics, and the resize path dedupes by pixel size — reset `lastWidth`/`lastHeight` before refitting. Use `allSettled` per font weight so one weight failing doesn't mask the other arriving.
- **Verify library-behaviour comments against the pinned version before designing around them.** The stale "xterm does not re-measure after open" comment had locked in permanent mis-sizing as unavoidable; 6.1 beta re-measures on genuine option change through the public API.

## Applies when

- Touching `src/config/terminalFont.ts`, `repairFontGrid`, `onTerminalFontArrivedLate`, or adding runtime font-family/size changes (user font settings, per-terminal fonts, zoom/DPI handling).
- Diagnosing a terminal grid that is subtly mis-sized (wrong cols/rows, cursor drift, clipped last row) for a whole session, especially on cold start / first run / slow disk.
- Setting any `terminal.options.*` value expecting a side effect (re-measure, refresh, re-render) — same-value assignments are deduped and fire nothing.
- Writing any `Promise.race`-with-timeout fallback where the losing operation continues in the background — plan for late arrival, don't swallow the outcome.
- Removing a Suspense/loading gate (or any startup ordering guarantee) — audit conditions downstream that were only correct because the gate serialized events (#9844's `timedOut &&` guard).
