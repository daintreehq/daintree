## Context

#10437 added the global "Skip permission prompts for agents" toggle (Settings → CLI agents; #10432), with a first-run onboarding step in #10453. Effective bypass resolves as `(per-agent/preset dangerousEnabled) || (globalSkipPermissions && supports.permissionBypass)` — the global is OR-ed in only for agents declaring bypass support (`claude`, `codex`; `gemini`'s `--yolo` stays per-agent-only). At spawn, `buildAgentLaunchFlags`/`generateAgentFlags` bake the agent's canonical bypass token (`DEFAULT_DANGEROUS_ARGS[agentId]`, e.g. claude's `--dangerously-skip-permissions`) into the session's persisted `agentLaunchFlags` array.

## Problem

Turning the global toggle OFF did not turn it off for sessions that already existed. Any session whose `agentLaunchFlags` snapshot was captured while the global was ON kept replaying the baked-in bypass token on every future restart, project-state restore, and palette resume — silently launching agents in bypass mode long after the user disabled the switch. A security-relevant setting that looked disabled in the UI but wasn't, only for the exact sessions a user is most likely to keep resuming.

## Root cause

Persisted launch args are a **time capsule**: `agentLaunchFlags` records the flags as resolved at capture time, and every restore/resume path deliberately replays that saved array _verbatim_ rather than re-deriving from current settings — resume commands must never be rebuilt from live settings because session resume is directory/CLI-scoped and re-derivation corrupts it (#5343). So the effective-bypass computation at spawn never got a chance to veto a token already frozen into a snapshot. The global's semantics compound this: it's a _live override, not a default_ (OR-ed into `resolveEffectiveBypass`, never mutating per-agent `dangerousMode`), which is right for fresh spawns but means disabling it only takes effect if something actively re-examines persisted flags. The fix is `reconcileBypassFlags(flags, agentId, effectiveBypass, dangerousArgs)` in `shared/types/agentSettings.ts`: strip every whole-token occurrence of the canonical bypass token (matched against `dangerousArgs` AND the `DEFAULT_DANGEROUS_ARGS` fallback, so a snapshot captured under a different `dangerousArgs` still cleans), then re-append it only when `resolveEffectiveBypass` currently returns true. It's idempotent, order-preserving, non-mutating, and wired into _every_ relaunch chokepoint: `restart.ts`, `statePatcher.ts` (restore), and palette resume (`src/services/agentResume.ts` `reconcileResumeLaunchFlags`). Miss one chokepoint and the stale flag leaks through it.

## Lesson

- **Any global setting that injects a CLI flag at agent launch MUST own a reconciliation pass over persisted/resumed launch args, or disabling the setting doesn't disable it.** The injected token lives in each session's `agentLaunchFlags` snapshot; restore/resume replay it verbatim. Without a strip-and-reconcile step the toggle only governs brand-new spawns, never existing sessions.
- **Reconcile, don't rebuild.** Do not re-derive the launch command from current settings on resume (breaks directory-scoped resume, #5343). Instead strip the one injected token and re-add it only if the live decision resolves true — a whole-token filter (never substrings, so flag _values_ are never collaterally stripped), not a regeneration.
- **Route the decision through one resolver and reconcile at every chokepoint.** `resolveEffectiveBypass` is the single source of truth for the on/off/inherit intent; `reconcileBypassFlags` runs from restart, restore, and palette resume. A relaunch path that replays `agentLaunchFlags` but skips reconciliation reintroduces the trap.
- **This is a reusable idiom, not a one-off.** The identical pattern was cloned for the alt-screen global (`reconcileInlineModeFlag` for `globalUseAltScreen`, #10876); `reconcileResumeLaunchFlags` chains both. When you add the next "global default that bakes a flag," clone the strip-and-reconcile shape rather than inventing a new one.
- **Keep the override live — never let reconciliation mutate persisted per-agent state.** `reconcileBypassFlags` rewrites only the transient `agentLaunchFlags`, never `dangerousMode`, so flipping the global is instantly authoritative on the next spawn without rewriting the user's per-agent choices. (Since #10437 the per-agent field became tri-state `dangerousMode` `"on"/"off"/"inherit"` via `resolveDangerousMode`, and the reconciler's old `isAgentBypassSupported` guard was removed — `effectiveBypass` now carries the full decision.)

## Applies when

- Adding any global "default" toggle that injects a CLI flag into agent spawns (permission bypass, alt-screen, sandbox) — you owe it a reconciliation pass over `agentLaunchFlags` on restart/restore/resume, not just correct fresh-spawn generation.
- Touching `reconcileBypassFlags`, `reconcileInlineModeFlag`, `resolveEffectiveBypass`, or `resolveDangerousMode` in `shared/types/agentSettings.ts`, or the resume/restore wiring in `restart.ts`, `statePatcher.ts`, `agentResume.ts`.
- Adding a new code path that relaunches an agent by replaying a persisted `agentLaunchFlags` snapshot — confirm it runs the reconcile chokepoint, or a stale flag leaks through it.
- Auditing whether disabling a security-relevant agent setting actually takes effect on _existing_ sessions, not just new ones — persisted launch args are a time capsule of the flag state at capture time.
