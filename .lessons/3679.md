## Context

xterm.js terminals had two URL-detection paths: the frontend `@xterm/addon-web-links` (regex on every visible line during render) and the backend `UrlStyler` in the PTY host, which wrapped URLs with OSC 8 hyperlink sequences once on raw output. This PR deleted the frontend addon as "redundant," betting the backend OSC 8 path was strictly superior and removing per-line renderer regex.

## Problem

The bet was wrong and the change was fully reverted across three follow-up commits. OSC 8 only hyperlinks URLs that the backend actually wrapped, and it can't cover everything the frontend addon did. Pasted URLs never pass through the PTY-host output styler, so they stopped being clickable. Agent terminals emit ANSI-colored output, and `UrlStyler` skipped any text containing escape sequences (to avoid corrupting colors), so URLs in agent output also went unlinked. The "rare in practice" caveat in the original lesson was the dominant case for this app.

## Root cause

Two URL detectors are not equivalent restatements of the same work — they cover different input populations. Frontend WebLinksAddon detects URLs in the rendered buffer regardless of origin (typed, pasted, program output, ANSI-styled). Backend OSC 8 only annotates URLs in the raw output stream it inspects, and deliberately bails on ANSI-styled text. Treating one as a drop-in replacement for the other conflated "both make links clickable on plain output" with "both cover all link sources."

## Lesson

Restored WebLinksAddon (`4ef9d3778`), then deleted `UrlStyler` entirely (`7373a281a`) because keeping the backend styler alongside the addon caused double-wrapping and broke pasted-URL highlighting. The frontend addon is now the sole URL detector, in `setupTerminalAddons` / `createWebLinksAddon` (`src/services/terminal/TerminalAddonManager.ts`), routed through `TerminalLinkHandler.openLink`. The original CPU concern was instead addressed by a tier-based lifecycle: the addon is disposed on BACKGROUND tier and recreated when the terminal becomes active (`TerminalInstanceService` tier transitions), so idle background panes pay no per-line regex cost without losing link coverage. Before removing a "redundant" detector, enumerate the actual input sources each one covers (pasted text, ANSI-colored output, program output) rather than assuming functional equivalence from a happy-path test.

## Applies when

Auditing or removing one of two overlapping detectors/processors (URL detection, link providers, syntax highlighters) that appear redundant; deciding between PTY-host backend processing and renderer-side xterm addons; any "remove the frontend X, the backend already does it" refactor on terminal output.
