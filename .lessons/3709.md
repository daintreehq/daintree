## Context

`ActionPaletteItem` and `QuickSwitcherItem` render lists of rows during palette typing and keyboard navigation, so every keystroke re-renders all visible rows. PR #3709 wrapped both in `React.memo` and stabilized the parent's `onSelect` callback to cut that re-render cost.

## Problem

That manual memoization is now dead weight. The renderer build runs `babel-plugin-react-compiler` v1.0 in `compilationMode: "infer"` (`vite.config.ts:551-563`, `reactCompilerPreset`), which auto-memoizes every component and hook output. A hand-rolled `React.memo` wrapper on top of compiled output is redundant — it adds an import, an extra wrapper component, and a maintenance trap where reviewers assume the wrapper is load-bearing when it isn't.

## Root cause

The 2026 codebase adopted the React Compiler. Commit `b52c05459` ("retire React.memo wrappers superseded by React Compiler") removed `React.memo` from 36 components including both palette items, on the grounds that infer-mode handles their memoization automatically. The compiler succeeds on both files with zero bailouts (`compiler-bailout-baseline.json` entries for both show `success: 1`, empty `errorBailouts`/`skipReasons`). Note this is automatic inference, not an opt-in `"use memo"` directive — Daintree runs `infer`, not annotation mode. `QuickSwitcherItem` is now a plain exported function. `ActionPaletteItem` still carries `export const ActionPaletteItem = memo(ActionPaletteItemInner)` (`ActionPaletteItem.tsx:259`), but with no custom comparator it is a vestigial wrapper, not a deliberate optimization — the compiler already memoizes the inner component.

## Lesson

Under the React Compiler in `infer` mode, do NOT hand-add `React.memo` for routine "stop list rows re-rendering" cases — the compiler already does it, and the wrapper is noise. `memo` is only justified now when you supply a custom comparator (e.g. `GridPanel`, `GridTabGroup`, `SortableWorktreeCard` keep `memo(fn, areEqual)`) or the file bails out of the compiler (`WslGitBanner`, `DiagnosticsDock`). For those, the wrapper is deliberate; everywhere else it is leftover. Before reaching for memoization, confirm the file's entry in `compiler-bailout-baseline.json`: if it shows `success: 1` with no bailouts, the compiler is already memoizing it and a manual `memo` adds nothing. A bare `memo(InnerComponent)` with no comparator (like the surviving `ActionPaletteItem` wrapper) is a smell — it signals pre-compiler code that hasn't been cleaned up, not a real perf decision.

## Applies when

Reviewing or adding `React.memo` / `useMemo` / `useCallback` to renderer components or palette/list rows; seeing a `memo()` wrapper with no custom comparator; deciding whether a component needs manual memoization — check `compiler-bailout-baseline.json` and the `reactCompilerPreset({ compilationMode: "infer" })` config in `vite.config.ts` first.
