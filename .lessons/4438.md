## Context

The worktree sidebar renders a card row per open worktree, and rows are reorderable via dnd-kit (`useSortable` in `SortableWorktreeCard`). PR #4438 tried to cut layout/paint cost for offscreen rows by setting `content-visibility: auto` + `contain-intrinsic-size: auto 180px` on the card wrappers, gating it off during an active drag (`contentVisibility: isDragging ? 'visible' : 'auto'`).

## Problem

The drag gate was not enough. `content-visibility: auto` interferes with the CSS `transform`/`transition` that dnd-kit writes onto sortable elements — sibling rows that displace during a reorder, not just the dragged row, jitter or fail to translate. The original "disable only on the dragged row" fix masked the most obvious case but left reorder displacement of neighbouring rows broken.

## Root cause

`content-visibility: auto` implies layout/paint containment and lets Chromium skip rendering for offscreen subtrees. dnd-kit drives reorder animation by mutating inline `transform` on rows during the drag; those transforms compose unreliably against the containment/visibility skipping, so displaced rows don't move smoothly. The attribute and programmatically-applied transforms are fundamentally at odds on the same element.

## Lesson

Don't put `content-visibility: auto` on any element dnd-kit transforms. The render-skipping win is better bought with real windowing: commit `206878ad4` replaced the unbounded row render with react-virtuoso (flat list, 600px overscan) and dropped `content-visibility` from `SortableWorktreeCard` entirely. Virtuoso unmounts offscreen rows, which eliminates their layout cost outright and never touches the transform of a mounted, draggable row. `src/components/DragDrop/__tests__/SortableWorktreeCard.test.tsx` now asserts `wrapper.style.contentVisibility === ""` as a regression guard. `content-visibility: auto` is still fine on _non-draggable_ wrappers — `SidebarContent.tsx` keeps it on pinned/integration card wrappers and `WorktreeOverviewModal.tsx` keeps `auto 240px` on modal cards, because nothing applies dnd-kit transforms there.

## Applies when

Reaching for `content-visibility: auto` (or `contain: layout paint`) on a list whose rows are draggable/sortable via dnd-kit or any library that animates reorder through inline CSS transforms. Prefer Virtuoso/virtualization for the offscreen savings on those rows; reserve `content-visibility: auto` for static, non-transformed card wrappers.
