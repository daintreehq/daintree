## Context

The bottom dock shows a floating preview of a terminal (`DockedPanel.tsx` / `DockedTerminalItem.tsx`) that can be collapsed without touching the underlying PTY via `closeDockTerminal()` (`src/store/slices/terminalFocusSlice.ts`) — a pure state setter that only clears `activeDockTerminalId` and reconciles focus, no backend call. `usePanelHandlers.ts` is the shared close-button handler used by both the grid surface and the dock surface, and before #11189 its `surface === "dock"` branch called `trashPanelGroup()` instead.

## Problem

Clicking the X on a docked preview looked identical to Escape, click-outside, or re-toggling the chip — the pane collapsed the same way. But a `docker restart`, dev server, or long build running in that terminal died a few seconds later with no further user action (issue #11186). The X was the only dock dismiss gesture that destroyed the process; every other gesture already called `closeDockTerminal()`.

## Root cause

`trashPanelGroup()` calls the backend `terminal.trash`, which puts the terminal in `TerminalRegistry`'s trash map with a TTL (`TRASH_TTL_MS = 20_000` in `shared/config/trash.ts`) and a real `setTimeout` that logs `"Auto-killing trashed terminal after TTL"` and calls `onExpire(id)` when it fires. Trashing is instant and silent at the call site — no dialog, no countdown, nothing in the dock UI reads as "this will be destroyed" — so the 20-second fuse was invisible to both the user and, originally, the developer wiring the handler. `docs/architecture/destructive-action-safeguards.md` classifies `terminal.trash` as D0 "safe... reversible (restore from trash before next gc)", true in the abstract, but 20 seconds isn't a meaningfully reversible window for a gesture experienced as "just tucking the preview away," with zero signal a clock started. The bug was a **surface mismatch**: `usePanelHandlers` is shared by grid (X legitimately means close-and-trash — the grid is the terminal's real home) and dock (X is a preview-visibility toggle, not a lifecycle action); the dock branch borrowed the grid's destructive verb instead of calling the non-destructive setter every sibling gesture already used.

The fix routes `surface === "dock" && !force` straight to `closeDockTerminal(terminalId)`, returning before the `trashedRef` double-fire latch. That ordering is deliberate: the `DockedPanel` hook instance survives collapse/reopen (it isn't unmounted when the preview closes), so a dismiss branch placed after the latch would fire once per mount then silently stop responding on every later open. `closeDockTerminal` needs no such guard — it's an idempotent pure setter, not a side-effecting action to deduplicate. `Alt+Click` (force) still falls through to `removePanel()` on both surfaces; `PanelHeader.tsx` copy/`aria-keyshortcuts` were updated so the dock X reads "Dismiss preview" (no `Meta+W` advertised, since that chord still trashes) while grid keeps "Close session."

## Lesson

- **Before wiring any "close" button on a preview/overlay surface to an existing action, check what that action's backend actually schedules.** `trashPanelGroup` sounds like a UI-only hide; it is a soft-park with a real timed kill (`TerminalRegistry.trash`, `TRASH_TTL_MS`). Grep the store action for a following IPC/backend call, not just its name.
- **A delayed destructive consequence is a trap precisely because it's invisible at the call site.** No stack trace, no immediate symptom, and the user has moved on by the time the TTL fires — this is why the bug shipped and stayed unnoticed until someone lost a long-running process. When reviewing anything that "soft-deletes with a timer" (trash, park, archive-then-reap), ask what UI signal exists between the click and the timer firing; here there was none.
- **A shared handler branching on a `surface` prop is a smell when the surfaces have different destructive semantics** — the grid's X and the dock's X look like the same button but mean different things (close-the-terminal vs. hide-the-preview); route each surface to its own verb rather than reusing one action across both and hoping the shared code stays correct for both meanings.
- **When adding an early-return branch ahead of a de-dupe guard (`trashedRef`-style ref latch), check whether the component instance the guard protects actually remounts between invocations.** `DockedPanel` survives collapse/reopen, so a guard placed after the branch would have silently broken repeat-dismiss; the fix deliberately returns before the latch and relies on the target setter being idempotent instead.
- **Don't trust `docs/architecture/destructive-action-safeguards.md`'s D0/"safe" label as license to skip auditing where an action is reused.** `terminal.trash` is correctly D0 for the grid's close-means-trash affordance; the same action call site on a different surface (a preview toggle) inherited a destructive tier its own UI never disclosed.

## Applies when

- Adding or reviewing a close/dismiss button on any preview, popover, or overlay surface (dock, floating panel, modal) that shares a handler with a "real" close elsewhere in the app.
- Touching `usePanelHandlers.ts`, `PanelHeader.tsx`, or any `surface`-branched handler that decides between a destructive (`trashPanelGroup`, `removePanel`) and non-destructive (`closeDockTerminal`) path.
- Wiring a UI action to any store/service call whose name doesn't obviously say "starts a TTL" — `trash`, `park`, `archive`, `soft-delete` methods are candidates to check for a following auto-reap timer.
- Diagnosing "a process I thought I just hid/minimized died a few seconds later" — check for a trash/park TTL (`TerminalRegistry`'s `trashTimeouts`, `TRASH_TTL_MS`) between the dismiss gesture and the kill.
- Placing a new branch relative to a `useRef`-based double-fire latch — confirm whether the owning component instance remounts on the relevant lifecycle transition before deciding which side of the latch the branch belongs on.
