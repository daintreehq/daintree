## Context

Daintree (Finder/dock-launched on macOS) inherits a minimal PATH, so version-manager shims (mise/asdf/Volta), `~/.local/bin`, and CLI tools (`git`, `gh`, agent binaries) are missing unless PATH is rehydrated from the user's login shell. PR #4700 used the `fix-path` package (a synchronous `spawnSync` login-shell probe) at module load in `electron/setup/environment.ts`, plus a lazy `refreshPath()` before the first `CliAvailabilityService.checkAvailability()`.

## Problem

PR #4700's fix — `if (app.isPackaged) fixPath()` at the top of `environment.ts` — was the wrong shape and got fully removed in #8625. `fix-path` calls `spawnSync` to launch the user's login shell, blocking the main thread 100ms–2s+ (worse with heavy `.zshrc`) _before_ `app.whenReady()` even fires. The `app.isPackaged` guard only skipped this in dev; in packaged builds it sat directly on the cold-start critical path. The lazy-before-first-check half of #4700 survived in spirit but is no longer the only refresh trigger.

## Root cause

A login-shell PATH probe is inherently slow and must never be synchronous on the startup path, and it must never run pre-`whenReady` — spawning a child process before the app is ready leaks zombie processes on macOS Finder-launched packaged builds. The `app.isPackaged` guard treated a perf/lifecycle problem as a dev/prod toggle. The real fix is concurrency + dedup, not a conditional skip.

## Lesson

There is no `fixPath()` and no `app.isPackaged` guard anymore — `fix-path` was dropped from `package.json` and `shell-env` promoted to a direct dependency. PATH is now resolved by `refreshPath()` in `electron/setup/environment.ts`: async, awaits a `shell-env` (or `$SHELL -i -l -c` probe under `DAINTREE_SHELL_PROBE=1`, #6063) call raced against a timeout, then augments with Unix fallback shim dirs on macOS/Linux. It is kicked off via `kickOffEarlyPathRefresh()` as the first async work _inside_ `app.whenReady()` in `electron/main.ts` (NOT at module load, NOT pre-ready), so the shell probe overlaps the rest of startup. The PTY host fork is deferred (`PtyClient({ deferStart: true })` in `perWindowInit.ts`) and gated on the early refresh in `windowServices.ts`, preserving the invariant: PATH refresh → PTY fork, so node-pty inherits the full PATH (#8625, #8827). Two singletons enforce single-flight: `pathRefreshPromise` (cleared on settle, so retries are possible) dedups concurrent `refreshPath()` callers (early kick-off, `CliAvailabilityService`, `SystemHealthCheck`); `earlyPathRefreshPromise` (stays set after settle) ensures a second window never re-probes the shell.

## Applies when

- Adding any login-shell or environment probe at Electron startup — make it async, kick it off inside `whenReady()`, never `spawnSync` at module load, never pre-ready (macOS zombie leak).
- Touching `refreshPath()`, `kickOffEarlyPathRefresh()`, or the PtyClient `deferStart` gate in `electron/window/perWindowInit.ts` / `windowServices.ts`.
- Tempted to gate a slow startup operation behind `app.isPackaged` — ask whether the real fix is making it concurrent + deduped instead.
- Any code expecting `fixPath()` or a `fix-path` dependency — both are gone; use `refreshPath()` and `shell-env`.
