## Context

`ErrorService` (in `electron/ipc/errorHandlers.ts`) buffers errors in a `pendingQueue` (max `MAX_PENDING_ERRORS = 50`, defined in `electron/ipc/pendingErrorsStore.ts`; drops oldest on overflow) when `canSendToRenderer()` returns false — i.e., when the window is destroyed, webContents is unavailable, or the window is still initializing. On renderer ready, `flushPendingErrors()` drains the queue. This buffering protects against startup-phase errors being silently lost.

## Problem

The buffering/flush path had no E2E coverage. If the flush broke, users would miss errors that occurred during initialization — with no indication that errors were dropped.

## Timing challenge

To test buffering, an error must be injected _before_ the renderer is ready but _after_ the Electron app starts. On fast machines, the window may become ready before an `electronApp.evaluate()` call completes, making naive injection unreliable.

## Solution

Expose the `ErrorService` instance as a `__daintreeErrorService` global on `globalThis` in `errorHandlers.ts`, gated by `FAULT_MODE_ENABLED` (from `electron/ipc/faultRegistry.ts`, the fault-injection flag) so it only exists in test/fault mode. The E2E spec then calls `electronApp.evaluate()` to push directly into `svc.pendingQueue` synchronously, bypassing the `canSendToRenderer()` check, then later calls `svc.flushPendingErrors()`. This ensures errors are in the queue before the renderer attaches its listeners regardless of machine speed.

```ts
// fault-mode-only, in errorHandlers.ts
const errorService = new ErrorService();
if (FAULT_MODE_ENABLED) {
  (globalThis as any).__daintreeErrorService = errorService;
}
// E2E (e2e/full/resilience/core-error-buffering.spec.ts):
//   const svc = (globalThis as any).__daintreeErrorService;
//   svc.pendingQueue.push(err);
```

## Lesson

When testing timing-sensitive IPC paths (errors that must arrive before the renderer is ready), naive `evaluate()` injection is unreliable because the window may already be ready. The pattern is: expose a fault-mode-only global (here, the `__daintreeErrorService` instance, gated by `FAULT_MODE_ENABLED`) that lets the test bypass normal routing and write directly into the internal buffer. This gives deterministic test control without restructuring production code.

The same pattern applies to any main-process queue/buffer that has a "not yet ready, buffer it" codepath — expose a fault-mode-only inject point rather than trying to race the initialization sequence.

## Applies when

- E2E testing of "buffer until ready" patterns in Electron main process
- Testing startup-phase error handling, queued events, deferred IPC sends
- Any situation where the testability requires injecting state before a window/renderer lifecycle event completes
