## Context

`ErrorService` (in `electron/ipc/errorHandlers.ts`) buffers errors in a `pendingQueue` (max `MAX_PENDING_ERRORS = 50`, defined in `electron/ipc/pendingErrorsStore.ts`; drops oldest on overflow) when `canSendToRenderer()` returns false — i.e., when the window is destroyed, webContents is unavailable, or the window is still initializing. On renderer ready, `flushPendingErrors()` drains the queue. This buffering protects against startup-phase errors being silently lost.

## Problem

The buffering/flush path had no E2E coverage. If the flush broke, users would miss errors that occurred during initialization — with no indication that errors were dropped. Testing it is timing-sensitive: to exercise buffering, an error must be injected _before_ the renderer is ready but _after_ the Electron app starts.

## Root cause

On fast machines the window becomes ready before an `electronApp.evaluate()` call completes, so naive injection races the initialization sequence — the error reaches a renderer that already has its listeners attached and never lands in `pendingQueue`. There is no production-only hook that lets a test write into the internal buffer deterministically, because `report()` always routes through the `canSendToRenderer()` check (`errorHandlers.ts:247`).

## Lesson

Expose the `ErrorService` instance as a `__daintreeErrorService` global on `globalThis` in `errorHandlers.ts:504-506`, gated by `FAULT_MODE_ENABLED` (from `electron/ipc/faultRegistry.ts` — `process.env.DAINTREE_E2E_FAULT_MODE === "1"`) so it only exists in test/fault mode. The E2E spec (`e2e/full/resilience/core-error-buffering.spec.ts`) then calls `electronApp.evaluate()` to push directly into `svc.pendingQueue` synchronously, bypassing the `canSendToRenderer()` check, then later calls `svc.flushPendingErrors()`. This guarantees errors are in the queue before the renderer attaches its listeners regardless of machine speed, giving deterministic test control without restructuring production code.

```ts
// fault-mode-only, in errorHandlers.ts
const errorService = new ErrorService();
if (FAULT_MODE_ENABLED) {
  (globalThis as any).__daintreeErrorService = errorService;
}
// E2E (e2e/full/resilience/core-error-buffering.spec.ts):
//   const svc = (globalThis as any).__daintreeErrorService;
//   svc.pendingQueue.push(err);
```

The same pattern applies to any main-process queue/buffer that has a "not yet ready, buffer it" codepath — expose a fault-mode-only inject point rather than trying to race the initialization sequence.

## Applies when

- E2E testing of "buffer until ready" patterns in Electron main process
- Testing startup-phase error handling, queued events, deferred IPC sends
- Any situation where the testability requires injecting state before a window/renderer lifecycle event completes
