## Context

Terminals demoted to the `BACKGROUND` refresh tier pause xterm paint and defer buffer reflow until wake. `TerminalResizeController.resize()` services `ResizeObserver` events; `TerminalRendererPolicy.applyRendererPolicyImmediate()` runs the wake path (wake/restore then `terminal.refresh()`); `latestCols`/`latestRows` carry the intended geometry and `lastWidth`/`lastHeight` are a pixel-level dedup cache to skip redundant resizes.

## Problem

Restoring a backgrounded terminal under multi-worktree load produced garbled output — stale glyphs painted into the wrong grid. Any one of the three contributing bugs was individually survivable, so the failure looked intermittent until enough load made it near-certain.

## Root cause

Three independent geometry-corruption bugs that compounded across a single background→foreground transition:

1. **Early-return background guard dropped dims before capture.** `resize()` returned `null` for `BACKGROUND && !isFocused` _before_ computing cols/rows, so a `ResizeObserver` firing while hidden (window/split resized in a hidden tab) was silently discarded instead of captured into `latestCols`/`latestRows` for replay on wake. fitAddon can't help here — the host is inside a `content-visibility:hidden` container and reads 0x0, so cols/rows must be computed from cached cell metrics (`getXtermCellDimensions`).
2. **`refresh()` painted into pre-background geometry.** The wake path called `terminal.refresh()` before any deferred resize, so it repainted using xterm's old `cols`/`rows` while the PTY (and in-flight output) had already advanced to the new size.
3. **Stale dedup cache suppressed the corrective resize.** `lastWidth`/`lastHeight` were not reset on `BACKGROUND` entry, so the first foreground `ResizeObserver` event after restore could match the pre-background pixel values and be deduped — but the cached value was now _stale, not redundant_. A normally-correct optimization became a correctness hazard precisely because a visibility transition invalidated its premise.

A fourth issue surfaced in review: the wake resync must be **atomic and bypass the 500ms settled-strategy debounce** (`applyDeferredResize` calls `clearSettledTimer` then resizes xterm and PTY together). The debounce exists to coalesce drag-resize bursts; wake is a single one-shot correction, and splitting it across 500ms leaves xterm sized for the new container while the PTY still wraps at the old geometry.

## Lesson

- **A per-frame/per-event dedup cache becomes a correctness hazard across a state transition that invalidates its baseline.** When entering `BACKGROUND` (or any tier where geometry can change unobserved), reset `lastWidth`/`lastHeight` to 0 so the first post-transition observation is never suppressed against a now-stale value. "Redundant" and "stale" are different — only the former is safe to dedup.
- **Capture before you guard.** An early-return guard for a paused/hidden state must still capture and defer the input it's skipping work for. Drop the _work_ (xterm reflow), not the _data_ (target cols/rows). Compute geometry from cached cell metrics when the DOM reads 0x0.
- **Ordering invariant: reconcile geometry before repaint.** On every wake branch — sync, async-success, and async-failure-recovery — call `applyDeferredResize(id)` _before_ `terminal.refresh(...)`. Refreshing into an unreconciled grid paints stale glyphs for at least one frame.
- **Wake resync is one-shot and atomic; do not route it through the steady-state debounce.** Clear the settled timer and resize xterm + PTY together so they never diverge across the settled window.

## Applies when

- Editing `TerminalResizeController.resize()` / `applyDeferredResize()`, the `BACKGROUND`-entry block in `TerminalInstanceService`, or the refresh calls in `TerminalRendererPolicy`.
- Adding a new refresh tier or visibility state that pauses paint/reflow, or any path that defers xterm geometry work while hidden.
- Introducing or modifying a dedup/coalescing cache (`lastWidth`/`lastHeight`, debounce baselines) that spans a lifecycle transition — verify the cached baseline is reset when the transition can change the underlying value unobserved.
- Investigating garbled/stale terminal output that appears only on tab-switch or panel-restore under load.
