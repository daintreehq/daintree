## Context

Agent terminals (Claude, Codex, Gemini) emit high-rate output that the renderer cannot always consume in real time. The original design assumed a SharedArrayBuffer visual stream carried its own producer/consumer backpressure and that only the IPC fallback path lacked flow control. That IPC path had no flow control, so a chatty agent could queue unbounded data and OOM the app. (Since then the SAB transport has been disabled entirely — SharedArrayBuffer is not supported in Electron's UtilityProcess — so the MessagePort/IPC queue is now the _sole_ PTY output transport, which makes its flow control mandatory rather than a backstop.)

## Problem

The SAB ring buffer was assumed to carry backpressure via producer/consumer pointers. Output routed to the IPC/port path had no equivalent, and nothing replaced it. The host heap grew until crash.

## Root cause

There are two transports for terminal output (SAB and IPC) and only one had flow control. Anything routed to IPC — not just agents but also suspended/backgrounded terminals, or terminals before the renderer attaches — inherits this problem.

## Lesson

Every PTY output transport must have bounded queuing with PTY pause/resume. node-pty supports `pause()`/`resume()`, so use them: pause at a high-watermark fraction of a per-terminal byte cap (currently `IPC_HIGH_WATERMARK_PERCENT` = 67% of `IPC_MAX_QUEUE_BYTES` = 3MB), resume at a low watermark (`IPC_LOW_WATERMARK_PERCENT` = 33%), drop with a telemetry event if the hard cap is exceeded, and always force-resume after a safety timeout (`IPC_MAX_PAUSE_MS` = 10s) so a stuck consumer cannot permanently freeze the PTY. Track exact byte counts — approximations drift and defeat the cap. Clean up all per-terminal backpressure state on exit or the maps leak across reused terminal IDs.

## Applies when

Adding any new PTY output transport, any direct `terminal:data` IPC path, or any consumer that might stall (backgrounded tiers, detached renderers, SAB suspension). If you find yourself calling `event.sender.send` with PTY data, you need flow control.
