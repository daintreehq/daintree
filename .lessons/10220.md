## Context

`PullRequestService` (main) detects a PR per worktree and emits `sys:pr:detected`; `WorkspaceService` / `WorktreeMonitor` project that into the canonical `linked` snapshot (source of truth since #8452) consumed by renderer and plugin SDK. `NormalizedPRState` (`shared/types/forge.ts`) is the provider-agnostic union `open | merged | closed | declined`; `declined` is the Bitbucket-style terminal state. GitHub never emits it, so it is inert at runtime today — but the abstraction (`docs/architecture/forge-provider-abstraction.md`) exists so a future provider needs zero reshape.

## Problem

`linked.pr.state` could never carry `declined` even though the entire renderer (~15 sites: `PRBadge`, `WorktreeHeader`, `worktreeFilters`, `useWorktreeStatus`, …) and the plugin SDK's `PluginWorktreeLinkedPR.state` were typed to handle it — a plugin reading a declined PR would see `closed`. No user-visible bug today (GitHub-only), but a future Bitbucket provider would silently misreport. Review surfaced a second, unrelated defect: an in-flight CI enrichment could revert freshly re-detected PR state.

## Root cause

Two independent mechanisms.

1. The `declined → closed` collapse ran at the DATA layer (the producer), not the legacy-compat boundary. `InternalLinkedPR.state` was typed `"open" | "closed" | "merged"`, and both the detection and revalidation paths did `pr.state === "declined" ? "closed" : pr.state` before assembling `linked`. Introduced by #8350 (`09ef71cfa`) as a display-parity goal implemented one layer too deep. Because the narrowing was baked into the internal TYPE, every downstream consumer got a lossy projection — and the RIGHT boundary's own `declined→closed` compat collapse became dead code, its declined branch reachable only via a direct `setLinked` test seed.

2. The phase-2 CI-enrichment re-emit (fire-and-forget, after phase-1 detection) read `prState` from the captured `pr` closure variable rather than `this.detectedPRs.get(worktreeId)`. A re-detection that replaced the map entry while the enrichment was in flight got reverted when the stale capture re-emitted the old state.

Fix: widen the internal types to `NormalizedPRState` end-to-end (`InternalLinkedPR.state`, `PRDetectionResult.prState`, the `sys:pr:detected` payload, `PRIntegrationCallbacks.onPRDetected`, `composeLinked`'s `pr.state` param), delete the two producer-side ternaries, and keep the `declined→closed` collapse ONLY where legacy flat fields are written/derived: `WorkspaceService.sendEvent` and both snapshot paths (now in `SnapshotBuilder.ts` after `getSnapshot` was later extracted into `snapshotBuilder.build()`). The re-emit now reads `detected.state` from the live map.

## Lesson

- **Collapse an enum to a narrower legacy-compat set at the OUTPUT boundary, never in the producer.** The `declined→closed` collapse inside `PullRequestService` made the canonical `linked.pr.state` projection permanently lossy for every consumer. The canonical projection must carry the widest type (`NormalizedPRState`); the narrowing belongs only where a legacy flat field (typed without `declined`) is emitted — `WorkspaceService.sendEvent` and `SnapshotBuilder`.
- **A collapse baked into an internal TYPE silently kills the downstream compat boundary.** `SnapshotBuilder` already did the correct `declined→closed` collapse, but its declined branch was unreachable because the upstream type was pre-narrowed. Reachable-only-via-test-seed is the tell: if a defensive branch can only fire when you seed state directly (`setLinked`), the producer already destroyed the case upstream — the branch is dead, not defensive.
- **When you widen a type, grep every consumer to confirm it already handles the wide case before assuming the narrowing was load-bearing.** The renderer and plugin SDK branched on `declined` everywhere; the producer was the only lossy link — the narrowing protected no one and defeated a capability the rest of the stack had already paid for.
- **A fire-and-forget / `await`-deferred re-emit must re-read shared state from the live source at emit time, never from a value captured at scheduling time.** The CI enrichment captured `pr` and re-emitted `pr.state`; a concurrent re-detection mutating `detectedPRs` reverted it. Read `detectedPRs.get(worktreeId).state` in the deferred callback — any `detectedPRs`-derived field re-emitted after an `await` has this hazard.
- **`declined` is inert on GitHub today — the value is a provider-abstraction contract, not a live feature.** Don't equate "no runtime impact" with "no bug": `NormalizedPRState` exists so a Bitbucket/GitLab provider needs zero reshape; a chokepoint dropping it guarantees a future reshape or silent misreport.

## Applies when

- Adding or collapsing a value in `NormalizedPRState` (or any provider-agnostic enum) flowing `PullRequestService` → `linked` → renderer/plugin SDK — collapse at `WorkspaceService.sendEvent` / `SnapshotBuilder`, never the producer.
- Touching `InternalLinkedPR`, `PRDetectionResult.prState`, the `sys:pr:detected` payload, `PRIntegrationCallbacks.onPRDetected`, or `composeLinked` — these must carry the full `NormalizedPRState`.
- Reviewing any fire-and-forget re-emit or `await`-deferred callback that reports state from a captured object (`pr`, snapshot, closure var) rather than re-reading the live map/store entry.
- Finding a defensive branch (`x === "declined" ? …`) that only fires from a direct test seed, never the real pipeline — suspect the producer narrowed the type upstream and the branch is dead.
