## Context

Panels serialize to disk via `panelToSnapshot(t)` (`src/store/persistence/panelPersistence.ts`), which writes a fixed `base` (id/kind/title/worktreeId/location/extensionState/pluginId/…) then merges a kind-specific `fragment` from the kind's registered serializer (`getPanelKindConfig(kind).serialize(t)`). Panel kinds are an open, plugin-extensible set: an extension registers its serializer at runtime. Saves run on a debounce and also during project switch.

## Problem

When a kind's serializer is NOT registered at save time, the old code did `config?.serialize?.(t) ?? {}` — an empty fragment. Any kind-specific fields the extension had previously written (browserUrl, notePath, custom config, disabled-extension state) were silently overwritten with base-only on the next save cycle. This is a write-path data-loss footgun, distinct from read-path schema rejection (#1581): the data survives hydration but is erased on the first save afterward.

## Root cause

A serializer can be absent at save time for mundane lifecycle reasons even though the panel and its persisted state are perfectly valid: extension disabled mid-session, plugin not yet (re-)registered after launch, or kind renamed in code. The save path treated "no serializer right now" as "this kind has no fields," conflating a transient registration gap with authoritative emptiness. The first save after launch is the worst case — there is no in-memory "previous" to fall back to because nothing has saved yet this session.

## Lesson

When serializing an extensible/plugin discriminated union, a missing serializer means "I can't re-derive these fields," NOT "these fields are empty." Carry forward the last-known persisted fragment instead of clobbering it: thread an optional `previousSnapshot` into the serializer and, when no serializer is registered, copy every non-base key from the previous snapshot. Three guards make this safe: (1) double-match `previousSnapshot.id === t.id && previousSnapshot.kind === t.kind` so a kind change for the same id does NOT leak the old kind's fragment; (2) spread order `{ ...preserved, ...base }` so live base fields always win over stale preserved values; (3) `BASE_PANEL_FIELDS` is the single source of truth for what counts as base, ratcheted with `as const satisfies readonly (keyof PanelSnapshot)[]` so dropping a key is a compile error (adding a new base field still needs manual listing or it leaks as a stale "preserved" value). Cover every write entry point, not just the debounced one: `PanelPersistence.primeProject(projectId, snapshots)` seeds the cache from hydration (`src/utils/stateHydration/index.ts`) so the very first save preserves fields, and `getPreviousSnapshotMap(projectId)` (queued-state-preferred over persisted) exposes the cache to the synchronous project-switch capture in `buildOutgoingState` (`src/store/projectStore.ts`) — the main process pre-applies that payload, so a switch would otherwise overwrite on-disk fields with base-only. Preservation is gated on the default transform (`this.options.transform === panelToSnapshot`); custom transforms own their output entirely.

## Applies when

Editing `panelToSnapshot` or adding a base field to `PanelSnapshot`; adding any new persisted write/capture path for panels (must thread `getPreviousSnapshotMap`); building any serializer for a plugin-extensible discriminated union where the serializer can be unregistered while the data is still valid. Red flag: any `serializer?.(x) ?? {}` (or equivalent empty default) on a save path for an extensible kind set.
