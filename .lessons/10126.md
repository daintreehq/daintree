## Context

Session restore (`hydrateAppState`, `src/utils/stateHydration/index.ts`) batch-restores panels and deliberately skips the per-`addPanel` focus side effect, so `focusedId` is null when hydration completes. A fallback in `useAppHydration` then picks which panel gets initial focus. Three persisted/quasi-persisted recency signals hang off focus: per-panel `lastActiveAt` (stamped by `stampLastActive` inside `setFocused`, persisted via `saveNormalized`, and read by `panelRestorePhase.ts`'s `maxLastActiveAtByWorktree` map to promote each worktree's most-recent panel to the priority restore tier), the MRU list (`recordMru` via the orchestrator's `focusedId` subscription, debounced persist), and the runtime-only `lastFocusedTerminalByWorktree` (via `trackTerminalFocus`).

## Problem

Issue #9933: after every restart, focus landed on whichever grid panel happened to sort first in saved order — not the panel the user was working in. Worse than the wrong pick: that arbitrary panel then got stamped as the most-recently-used one, so the corruption was persisted and became the input to the next boot. The recency signals degraded a little more on every restart — a self-compounding loop, not a one-off glitch. Misleading part: hydration DOES have an MRU suppression window (`suppressMruRecording(true)` at `index.ts:178`), so the code looked protected.

## Root cause

Two independent defects combined. (1) The fallback ran in `useAppHydration` AFTER `hydrateAppState`'s `finally` had already lifted `suppressMruRecording` (`index.ts:689`), and it called `setFocused` — the full user-focus path. So `stampLastActive` wrote `lastActiveAt = Date.now()` on the arbitrary panel and persisted it (overwriting the real signal that drives next boot's restore prioritization), and the orchestrator's subscription pushed the panel to the MRU head. A suppression flag scoped to the hydration call cannot protect synthetic work that runs post-hydration in a different effect. (2) The picker couldn't have picked correctly anyway: saved `lastActiveAt` was never propagated to live panels at creation — every restored panel started at `0` — so a recency-keyed pick had no data and the code just took first-in-`panelIds`-order.

The fix has three legs, and all three were required: `pickBootFocusPanelId` (exported from `useAppHydration.ts`) selects the active worktree's grid panel with the highest valid saved `lastActiveAt` (`Number.isFinite && > 0`, deliberately mirroring `panelRestorePhase`'s validity check; first-in-order fallback for legacy snapshots); a new `setBootFocus` action on `terminalFocusSlice` commits `focusedId` bare — no `stampLastActive`, no `terminalInstanceService.wake` (the restore pipeline already woke the panel), no `pingTerminal`, `previousFocusedId` moved only on real change — with the caller wrapping it in its own `suppressMruRecording(true)/finally(false)` window to gate the orchestrator's MRU subscription (`isMruRecordingSuppressed()` bail at `rendererStoreOrchestrator.ts:158`); and saved `lastActiveAt` threaded to live panels via `AddPanelOptionsBase.lastActiveAt` (`shared/types/addPanelOptions.ts`) → `statePatcher.ts`'s `sanitizeLastActiveAt` in all four `buildArgsFor*` → conditional spread in `addPanel.ts`.

## Lesson

- **Machine-initiated state changes must never route through user-intent recording paths.** Any automatic focus/selection (boot restore, crash recovery, eviction return) that calls `setFocused` will stamp `lastActiveAt`, persist it, and rewrite the MRU — masquerading as the user. Give synthetic actors a dedicated non-recording action (`setBootFocus` is the template) instead of trying to undo the side effects afterward.
- **A suppression flag lifted in a `finally` does not cover follow-up work in a later effect.** `suppressMruRecording` protected `hydrateAppState`'s own writes but the focus fallback ran after the window closed. Anything synthetic that runs post-hydration must open its OWN `suppressMruRecording(true)/finally(false)` window — check window timing, not just window existence.
- **Suppress selectively — runtime-only state with no other writer still needs the synthetic write.** `setBootFocus` deliberately lets the orchestrator's `trackTerminalFocus` and `selectWorktree({ source: "focus" })` subscriptions fire: `lastFocusedTerminalByWorktree` is never persisted and has no other seeder, so blanket suppression would break worktree switch-back last-focus (#9512). The rule is "no writes to persisted user-intent signals", not "no side effects".
- **Corruption of a persisted signal that feeds its own next read compounds — grade severity accordingly.** Each boot consumed the previous boot's corrupted output as input. A once-per-boot wrong write to a persisted recency store is worse than a per-session bug because it ratchets.
- **A ranker with no data silently degrades to arbitrary order.** The recency pick was impossible until saved `lastActiveAt` actually reached live panels (previously always `0`). When keying a picker off a persisted field, verify the field is propagated to the read site — and mirror the existing validity semantics (`Number.isFinite && > 0`, matching `panelRestorePhase`) rather than inventing new ones.

## Applies when

- Adding any automatic/synthetic focus, selection, or navigation that writes `focusedId` or calls `setFocused` — boot restore, crash recovery, view-eviction return, MCP/agent-driven focus — decide explicitly which recording paths it may touch.
- Touching the post-hydration block of `src/hooks/app/useAppHydration.ts`, `terminalFocusSlice` (`setFocused`/`setBootFocus`/`stampLastActive`), or the `focusedId` subscriptions in `rendererStoreOrchestrator.ts`.
- Diagnosing "wrong panel focused after restart" or an MRU/recency order that doesn't match actual use — check for a synthetic writer stamping itself as the user.
- Relying on `suppressMruRecording` (or any suppression flag lifted in a `finally`) to protect work that runs in a later effect or callback.
- Adding a new persisted per-panel field consumed at hydration time — confirm it round-trips through `statePatcher.ts` `buildArgsFor*`, `AddPanelOptionsBase`, and `addPanel.ts` to the live panel, or readers will see the default forever.
