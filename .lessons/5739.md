## Context

`ThemeBrowser` is a full-screen overlay mounted by `AppLayout`. Overlays register themselves in a LIFO `overlayStack` (`useUIStore`) via `useOverlayClaim(id, active)` (`src/hooks/useOverlayState.ts`) so the rest of the app can apply `inert`/scrim treatment to whatever is behind the topmost claim. The claim is consumed elsewhere through `useOverlayOpen("theme-browser")`.

## Problem

After #5721 added the overlay-claim system, the theme browser stopped opening entirely. The open action dispatched, but `<ThemeBrowser />` never appeared.

## Root cause

#5721 used the overlay claim itself as the mount gate: `{useOverlayOpen("theme-browser") && <ThemeBrowser/>}`. But the claim is registered by `useOverlayClaim("theme-browser", true)` (`src/components/ThemeBrowser/ThemeBrowser.tsx:123`), which runs in a `useEffect` _inside_ `ThemeBrowser` — so it only fires after the component mounts. The gate can never become true because the only thing that sets it true is the component that the gate is supposed to mount. A self-referential deadlock: mount→effect→claim, but gate reads claim→decides to mount.

## Lesson

A mount gate must read a signal that exists _before and independently of_ the component it gates. #5739 split the two roles cleanly: the store flag `useThemeBrowserStore((s) => s.isOpen)` (set synchronously by the open action before any render) is the mount gate; the effect-registered `overlayStack` claim drives inert/scrim _for siblings_, which is correct because that treatment intentionally lags one render behind the mount. Any presence/derived signal produced by a child's own `useEffect` (overlay claims, ref registries, portal-target registration, ResizeObserver-reported size) cannot gate that child's existence — only state owned by an ancestor or an external store can. Also added `onError={() => useThemeBrowserStore.getState().close()}` to the wrapping `ErrorBoundary` so a render crash clears `isOpen` and unblocks the app rather than leaving a permanently-armed inert layer.

## Applies when

Conditionally mounting a component based on a value, and that value is set by a `useEffect`/registration hook (`useOverlayClaim`, portal/ref registration, observer callbacks) that lives inside the very component being gated; or when reusing one "is-open" signal for both mount control and post-mount sibling effects (inert, scrim, focus-trap) without checking whether each consumer needs the pre-mount or post-mount edge.
