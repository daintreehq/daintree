## Context

Same-day motion-polish arc as `11180.md` (#11173, #11175, #11177, #11180, #11181, resolving sibling issues #11165-#11171). This lesson covers the reduced-motion/merge-correctness traps from #11177 (`ForgeStatPill`), #11173 (`AppDialog`/`AppPaletteDialog`), and #11181 (`SegmentedToggle`/`FleetPickerPalette`), independent of the keyframe-authoring trap in `11180.md`.

## Problem

Three different-looking symptoms shared one class of root cause — a className or the app's global reduced-motion policy was wired with the wrong scope. `ForgeStatPill`'s hover tint snapped instead of easing and its press gave no scale feedback, despite `Button`'s cva already defining both. `AppDialog` had zero visual feedback under reduced motion — no fade, nothing — even though only the spatial rise/zoom was meant to be removed. `SegmentedToggle`'s new sliding thumb (#11181) needed its own reduced-motion detection because neither "obvious" API (framer's `MotionConfig`, `useReducedMotion()`) saw Daintree's own settings.

## Root cause

**1. tailwind-merge conflict-group clobbering.** `ForgeStatPill`'s className passed a bare `transition-opacity` into `cn()` alongside the base `Button` cva's `transition` (`button.tsx:9`, a multi-property declaration). tailwind-merge treats both as the same "transition" conflict group, and the consumer class merges last, so `transition-opacity` didn't narrow the cva's set — it fully replaced it. The effective `transition-property` became `opacity` only, silently deleting `background-color` (the hover tint) and `scale` (what the cva's `active:scale-[0.98] active:duration-[1ms]` press snap needs to interpolate). Fix: spell out the full property list the consumer needs, `transition-[opacity,background-color,scale]`, instead of a shorthand that collides with the base class's conflict group.

**2. `motion-reduce:transition-none` is scope-blind.** `AppDialog` used `motion-reduce:transition-none motion-reduce:duration-0` to strip its rise-and-zoom entrance under reduced motion. `transition-none` rewrites `transition-property` to `none`, which also kills the opacity fade riding the same shorthand — but WCAG 2.3.3 targets vestibular-trigger _movement_ (translate/scale), not opacity, so the fade should have survived. Fix: narrow the kill to `motion-reduce:transition-opacity`, keeping the existing `motion-reduce:translate-none motion-reduce:scale-none` neutralizers — same resting position, only the spatial motion is removed. (`motion-reduce:duration-0` in the same className was already fully inert: both dialogs set `transitionDuration` as an inline style, which outranks a non-`!important` utility — a second silent no-op stacked on the first.)

**3. Radix `data-state` escapes the app's own global reset, and no single API sees every reduced-motion signal.** The global button reset in `index.css` (`button:not([data-state="open"]):not([data-state="closed"])...`) deliberately excludes elements carrying `data-state="open"`/`"closed"`, since Radix overlays need their own enter/exit transform handling. But any plain Radix trigger (`Tooltip.Trigger`, a context-menu trigger) _always_ carries `data-state` — `"closed"` at rest — so it always falls outside that exclusion and needs its own reduced-motion rule (`.toolbar-stat-pill` in `toolbar.css`; `.launcher-press` in `index.css` for the same reason on recipe cards). Separately, #11181's `useShouldSkipMotion` hook exists because there are three independent "don't animate" signals — OS `prefers-reduced-motion` (framer's `useReducedMotion()` reads this, `MotionConfig` does not), the in-app "Reduce animations" toggle (`document.body.dataset.reduceAnimations`), and performance mode (`dataset.performanceMode`) — and nothing reads all three, so each must be checked explicitly and OR'd.

## Lesson

- **Never pass a narrower `transition-<property>` className alongside a base component's own multi-property `transition` class.** tailwind-merge treats them as one conflict group and the consumer wins, deleting every property the base class listed but the consumer didn't. Spell out the _full_ property list needed (`transition-[opacity,background-color,scale]`) — tailwind-merge never unions two transition declarations.
- **`motion-reduce:transition-none` removes ALL transitioned properties, including opacity.** WCAG 2.3.3 only requires removing spatial motion (translate/scale/rotate), not fades. Scope the kill to `motion-reduce:transition-<property>` so reduced-motion users keep _some_ feedback instead of an instant, unindicated pop.
- **Any bare Radix trigger (`Tooltip.Trigger`, `ContextMenu.Trigger`) always carries `data-state`, so it escapes** the global `button:not([data-state="open"]):not([data-state="closed"])` reduced-motion reset in `index.css` — give it its own rule (`.toolbar-stat-pill`, `.launcher-press` pattern).
- **No single API sees all three of Daintree's reduced-motion signals.** OS preference, the in-app toggle, and performance mode are independent and must be OR'd explicitly (`useShouldSkipMotion`) — framer's `MotionConfig` sees none of them, `useReducedMotion()` sees only the OS one.
- **An inline style always wins over a utility class for the same CSS property, absent `!important`.** An inert `motion-reduce:duration-0` sitting next to `style={{ transitionDuration }}` is a real, previously-shipped bug here, not a hypothetical — check for this before trusting a utility class is doing anything.

## Applies when

- Adding a `className` to a `cva`-based component (`Button`, etc.) that already declares its own `transition`/`animate-*` classes — check the conflict group before assuming tailwind-merge unions properties.
- Writing or reviewing a `motion-reduce:`/`@variant reduce-motion` rule — confirm it targets only spatial properties, not a blanket `transition-none`/`animation: none` that also kills opacity feedback.
- Adding reduced-motion handling to a Radix trigger component (tooltip, context menu, dropdown, select) — it always carries `data-state`, so the generic button reset does not cover it.
- Adding a new animated component and needing to respect Daintree's motion prefs — use `useShouldSkipMotion`/`useUiMotionTransition` rather than `useReducedMotion()` or `MotionConfig` alone.
- Diagnosing "hover/press feedback stopped working" or "transition snaps instead of easing" on a component whose className merges with a shared base component's transition classes.
