## Context

#10971 added `AssistantContentMirror.syncAssistantContent`, which copies user-authored commands/skills from `~/.daintree/assistant/` and `<project>/.daintree/assistant/` into the per-project help-session directory at every assistant provision, so Claude Code / Codex / Copilot discover them natively via cwd (`electron/services/HelpSessionService.ts`). The session dir also holds Daintree-managed secrets (`.mcp.json` bearer token, sandbox `settings.json`), and the CLIs spawned into it (Codex, Copilot) are not write-sandboxed, so the mirror's own delete/copy logic runs inside a directory the thing it just launched can write back into.

## Problem

Nothing broke in production — this is a preventive-design PR, not a bug fix. The risk being defended: a manifest-driven cleanup step that deletes "no-longer-desired" files by relpath, or a copy step that writes to a computed destination path, can be walked outside its intended root by either (a) a crafted relpath string in the manifest, or (b) a symlink planted at any directory level by the very CLI session running inside that directory.

## Root cause

Two distinct traps had to be closed, and one architectural fact makes both non-obvious.

1. **Windows `path.resolve` treats backslash as a second path separator.** `isUnderMirrorRoot` splits candidate relpaths on `/` and rejects any segment that is `""`, `"."`, `".."`, or contains `\` or `:`. The backslash check matters because a validator that only rejects a literal `/`-delimited `".."` segment is safe on POSIX but not Windows: `".claude/commands/x\\..\\..\\.mcp.json"` has no `/`-delimited `".."` segment, so a POSIX-only check waves it through — but Windows' native `path.resolve` also treats `\` as a separator, so it silently pops two directories and escapes the mirror root at resolve time. The colon check guards the same class (`c:evil.md` as a drive-letter smuggle). Both are exercised in `AssistantContentMirror.test.ts` ("rejects manifest entries that smuggle traversal through backslash segments").
2. **A directory component can turn into a symlink between syncs, planted by the session's own spawned CLI.** `verifyRealDirChain` `lstat`s every _existing_ directory component of a computed dest/stale path (not just the leaf) before any delete or copy, failing closed if any component is a symlink or unprovable. The corresponding test plants `.claude/skills → <outside dir>` and asserts zero files are copied or deleted through it, and the outside target stays untouched.

The non-obvious part: realpath+relative containment was already an established idiom in Daintree before this PR, with three prior call sites, not one — `electron/ipc/handlers/files.ts` (PR #6263) established the pattern, `electron/ipc/handlers/pathGuard.ts` (`resolveContainedPath`, 2026-05-27) explicitly cites and reuses it, and `electron/services/plugin/pluginFsContainment.ts` (`resolveContainedPath`, 2026-06-15, for the plugin `host.fs`/`host.git` surface, closing a CVE-2025-53109/-54794-class gap) reuses it again via `realpath()` on the candidate and allowed roots plus `path.relative` containment. #10971 did not reuse or reference any of them, and independently invented per-segment `lstat` walking with its own memoization cache instead. The two shapes are each defensible for their own problem (one arbitrary absolute path vs. many relpaths mkdir'd into fixed roots), but the repo now carries two structurally different security-critical containment techniques — the realpath+relative family (three call sites) and this PR's per-segment lstat walk — with no shared test surface or shared bug-fix path.

## Lesson

- **Any relpath validator meant to block traversal must reject embedded `\` and `:`, not just `/`-delimited `..` segments** — Windows' `path.resolve` treats backslash as a separator regardless of what separator the string "looks like" it uses. A check written and tested only on macOS/Linux will pass CI and still be exploitable on Windows. See `isUnderMirrorRoot` in `AssistantContentMirror.ts` for the pattern.
- **When any spawned/sandboxed process can write into a directory your code later deletes-from or copies-into, `lstat` every existing directory component of the computed path immediately before the operation, not just the manifest/relpath string** — a symlink planted after the manifest was trusted but before the delete/copy executes is a real race, not a hypothetical; `verifyRealDirChain` closes it and is memoized per-sync (`chainCache`) so the cost is one `lstat` per unique directory, not per file.
- **Before writing new path-containment/symlink-defense code, grep for `resolveContainedPath` first** — it already has three call sites (`electron/ipc/handlers/files.ts` from PR #6263, `electron/ipc/handlers/pathGuard.ts`, `electron/services/plugin/pluginFsContainment.ts`), all realpath+`path.relative` containment, versus `AssistantContentMirror.ts`'s per-segment `lstat` walk. Confirm which shape fits (single arbitrary path with existing allowed-roots vs. batch of relpaths under fixed mkdir'd roots) rather than reinventing a fourth variant.
- **Layer resolved-path prefix checks on top of string checks, not instead of them** — the mirror does both: `isUnderMirrorRoot` on the raw relpath AND `destAbs.startsWith(sessionBase + path.sep)` after `path.resolve`. String checks alone miss OS-specific separator semantics; resolved-path checks alone don't stop a symlink swapped in mid-chain.
- **Never write through an existing symlink at a copy destination** — `copyFile` follows symlinks, so landing bytes there requires `lstat`-checking for a symlink and `rm`-ing it first, or the write lands wherever the symlink points.

## Applies when

- Writing any feature that mirrors, syncs, or copies content into a directory that a spawned subprocess (agent CLI, plugin worker, dev-preview process) can also write into.
- Implementing manifest-driven or ownership-tracked cleanup (delete files by relpath from a stored list) anywhere in Main — the relpath validator needs the backslash/colon check, not just a `..`-segment check.
- Touching `electron/services/AssistantContentMirror.ts` or `electron/services/plugin/pluginFsContainment.ts` — check whether an existing `resolveContainedPath` call site already covers the new case before adding a fourth implementation.
- Reviewing any PR that adds path-traversal or symlink defenses and tests only on the reviewer's own OS (usually macOS/Linux) — ask whether the check was verified against Windows `path.resolve` separator semantics specifically.
- Adding a new mirror/sync destination root to `AssistantContentMirror.ts` (`MIRROR_DEST_ROOTS`) — deletion is scoped to exactly that list, so a new root must be added there or its files become permanently unmanaged.
