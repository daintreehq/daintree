## Context

Browser and dev-preview panels create their `<webview>` element immediately on mount, regardless of whether the panel is visible. Docked panels and panels in the background grid spawn full Chromium renderer processes even if the user never opens them.

## Problem

Each `<webview>` spawns a separate Chromium renderer process. Background or docked panels that the user has never visited would consume memory and CPU for page loading that is completely unnecessary.

## Root cause / Design decision

Solved with a `useHasBeenVisible(panelId, location)` hook backed by panel-store state. For grid panels it returns `true` immediately; for dock panels it latches to `true` the first time the panel becomes the active dock panel (`usePanelStore.activeDockTerminalId === panelId`) and never reverts. The webview element is only rendered once `hasBeenVisible` flips true. After first render, the webview is never re-hidden — the "lazy" gate is one-way: open once, stay open.

This does not interfere with the existing webview eviction system (`useWebviewEviction`) — lazy-load controls initial creation, eviction controls teardown under memory pressure.

## Lesson

Use a `hasBeenVisible` boolean gate (not a reactive visibility toggle) to defer webview creation to first use. The gate must be one-way (once true, stays true) to avoid recreating the webview when a dock panel is switched away from and back. Drive the latch off the panel store's active-dock state rather than re-deriving visibility each render. This pattern is composable with separate eviction hooks — lazy creation and pressure-based destruction are orthogonal concerns.

The hook initializes its `useState` lazily from `usePanelStore.getState()` so a panel that is already the active dock target on mount renders its webview synchronously without a flicker frame, then subscribes via the store selector to latch on the first activation.

## Applies when

- Adding new panel types that embed a webview
- Implementing lazy initialization for any expensive resource tied to panel visibility
- Combining with `useWebviewEviction` for full webview lifecycle management
- Debugging unnecessary Chromium process spawning for background dock panels
