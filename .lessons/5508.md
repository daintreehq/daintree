## Context

Main-process startup cost is dominated by how much code runs eagerly before `app.whenReady()`. PR #5508 added a budget script (`scripts/build-import-budget.mjs` + `check-import-budget.mjs` + `import-budget-lib.mjs`, baseline `scripts/baselines/eager-import-baseline.json`) that ratchets that footprint, mirroring the compiler-bailout budget (`check-compiler-budget.mjs`, #5225). It has since grown a renderer counterpart (`check-renderer-import-budget.mjs`). Like the other perf/size budgets, it is intentionally NOT wired into `ci.yml` pre-1.0 (see the header comment in `check-import-budget.mjs`) — it runs locally on demand via its npm script and only fails when someone runs it.

## Problem

"How much loads at startup" is invisible to normal review — a single new top-level `import` in a deep module silently drags its whole transitive closure (and any sync FS / `store.get` / `new Database()` call on that path) into boot, with no failing test. Counting needs a precise, stable definition of "eager," and the measuring build must match the shipping build or the count is wrong in ways nobody notices.

## Root cause

The eager subgraph is BFS from `electron/main.ts` over the esbuild metafile's `inputs[file].imports[]`, following ONLY `import-statement` / `require-call` edges, stopping at `dynamic-import` boundaries (deferred work), and skipping `external` modules (native `.node`, Node built-ins) — `walkEagerGraph` in `import-budget-lib.mjs:93`. Three non-obvious design constraints make it correct and stable:

- The budget build (`build-import-budget.mjs`) must replicate `build-main.mjs`'s `external` list, `define` block, and `target` verbatim; drift silently changes coverage (a missed native module turns a `.node` loader edge into graph noise). It uses `write: false` so it never clobbers the real `dist-electron` artifacts.
- The gate is the file-path **allowlist**, not the `syncViolations` list. `syncViolations` is a checked-in informational snapshot only; gating on call sites would churn the baseline on every line-number refactor (`compareToBaseline`, `import-budget-lib.mjs:182`). Allowlist hygiene is enforced as hard errors: an unused allowlist entry fails (you must drop the entry in the same PR that removes the sync call), and a still-used entry whose file lacks a `// eager-import-allow: <reason>` header marker fails.
- The renderer counterpart walks Vite's `manifest.json` by **chunk key** (`imports[]`, skipping `dynamicImports[]`), not source module, because Rolldown code-splitting groups (vendor-react, vendor-xterm) would otherwise double-count shared chunks — the chunk graph is what actually loads.

## Lesson

To ratchet "startup cost," count the statically-reachable closure from the entry, define "static" as the bundler's non-dynamic edge kinds, and STOP at dynamic-import boundaries — that boundary is the whole point of lazy-loading work. Measure on a metafile/manifest produced with the SAME externals/define/target as the real build, or the graph diverges silently. Ratchet by a coarse, refactor-stable key (file path / chunk key) and keep the fine-grained snapshot informational; make allowlist entries self-justifying (header marker) and self-expiring (unused = error) so the ratchet can only tighten.

## Applies when

Adding or modifying any startup/eager-import budget gate; touching `scripts/*import-budget*.mjs` or the baselines under `scripts/baselines/` (`eager-import-baseline.json`, `renderer-import-baseline.json`); adding a top-level `import` to a module on the `electron/main.ts` eager path (it may bust the count); adding a sync FS / `store.get` / `new Database()` call to a main-process module (needs an allowlist entry + `// eager-import-allow:` marker, or move it behind `app.whenReady()` / a dynamic import); editing `build-main.mjs`'s `external`/`define`/`target` (mirror it in `build-import-budget.mjs`); or designing a similar code-size/bailout ratchet for another entry point.
