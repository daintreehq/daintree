## Context

Each supported CLI ships a `detection` block in `shared/config/agents/<id>.ts`: `primaryPatterns`/`fallbackPatterns` (working-state regexes), `bootCompletePatterns`, and per-tier confidences. Kimi's config (`kimi.ts`) had been authored against a look-alike agent rather than kimi-cli's actual output: no `bootCompletePatterns` at all, and the braille spinner as `primaryPatterns` at 0.95. #10269 (issue #9876) corrected both against upstream kimi-cli source.

## Problem

Every Kimi terminal recorded a ~15s boot in `[AgentStartup]` telemetry regardless of actual readiness, and the configured working spinner never matched during the model-latency stretch it was meant to cover. Neither failure surfaced an error — the terminal just sat in boot state for the full timeout, reading as "kimi is slow to start" rather than a config bug.

## Root cause

Two independent traps in the same config, both silent.

Boot: `bootCompletePatterns` was absent. `buildBootCompletePatterns` (`terminalActivityPatterns.ts`) returns `undefined` when the array is missing OR empty, and `BootDetector`'s constructor then substitutes the module-level `BOOT_COMPLETE_PATTERNS` — hardcoded Claude/Codex/Gemini banner regexes that never match kimi-cli output. So the only remaining boot exit is the `timeSinceBoot >= POLLING_MAX_BOOT_MS` fallback in `ActivityMonitor` (`?? 15000`). Boot detection runs live in the simple-output polling path (#7616), so the 15s wait happens on every launch. The fix: `bootCompletePatterns: ["Welcome to Kimi Code CLI!"]` — a literal substring kimi-cli's `_print_welcome_info` prints in a Rich Panel before the first spinner frame.

Working glyphs: kimi-cli's live view renders Rich's _moon_ spinner (`🌑🌒🌓🌔🌕🌖🌗🌘`, empty text) during model latency — the dominant working indicator before any tool/content block — while the braille _dots_ appear later with text ("Compacting...", "Connecting to MCP servers..."). The original config had braille at `primaryPatterns` (0.95), which missed the real primary signal AND repeated the #3941 footgun: that braille class is identical Unicode to cliclack's and is shared today by goose, crush, kiro, mistral, qwen, and kimi — not disjoint. #3941 was the same bug the other direction: OpenCode had been given _Gemini's_ braille instead of its Bubble Tea set (`⣾⣽⣻⢿⡿⣟⣯⣷`). The fix promotes the disjoint moon set to primary (with an end-of-line alternative `(?:\s|$)` for renderers that drop the trailing space) and demotes braille to `fallbackPatterns` (0.75). At runtime these patterns are scoped to an _already-identified_ agent (identity comes from `ProcessDetector`, not output regex), so a shared glyph doesn't literally cross-classify identity — the discipline guards against wrong-Unicode copy-paste and against a generic spinner earning a false 0.95 "working" verdict.

## Lesson

- **Always give a new agent config an explicit `bootCompletePatterns`, or the terminal eats the full 15s `POLLING_MAX_BOOT_MS` on every launch — silently.** Missing/empty makes `buildBootCompletePatterns` return `undefined`, and `BootDetector` falls back to `BOOT_COMPLETE_PATTERNS` (Claude/Codex/Gemini banners) that never match a different CLI. No error, no log — just a phantom ~15s boot and wrong `[AgentStartup]` telemetry. If you actually want the hardcoded banners, opt in with `bootCompletePatterns: []` and a comment (see `antigravity.ts`); don't leave the field off by accident.
- **Pick a boot pattern the CLI prints BEFORE its first spinner frame, as a literal substring resilient to Rich Panel box-drawing** — kimi's `"Welcome to Kimi Code CLI!"` still matches inside `╭─ Welcome to Kimi Code CLI! ─╮`. Verify the exact string from upstream source, not from memory.
- **A spinner glyph earns `primaryPatterns` (0.95) only if disjoint from every other agent's set; a shared/generic class stays `fallbackPatterns` (0.75).** The braille dots `[⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏]` are shared by goose/crush/kiro/mistral/qwen/kimi — never primary-grade. Kimi's moon set is disjoint, so it earns primary.
- **Never copy a glyph set between agent configs — that is literally #3941 (OpenCode was given Gemini's braille instead of its Bubble Tea set `⣾⣽⣻⢿⡿⣟⣯⣷`).** Different spinner libraries render different Unicode (Rich "dots"/"moon", cliclack braille, Bubble Tea, Ink) — read the CLI's source (`_live_view.py`, `_blocks.py`) and confirm the actual frames.
- **Test detection patterns against realistic rendered strings, not by mirroring the regex.** #10269 asserts all 8 moon frames (trailing-space AND bare), the banner inside Panel box-drawing, and a guard that braille must NOT match primary. `primaryPatterns`/`fallbackPatterns` are working-STATE signals for an already-identified agent — identity is process-tree based (`ProcessDetector`), not regex.

## Applies when

- Authoring or fixing a `shared/config/agents/<id>.ts` `detection` block — spinner glyphs, boot banners, or confidence tiers.
- A specific agent's terminals feel slow to become ready, or `[AgentStartup]`/`bootCompleteAt` telemetry shows a uniform ~15s boot — check for missing `bootCompletePatterns` first.
- Deciding whether a working glyph belongs at `primaryPatterns` (0.95) vs `fallbackPatterns` (0.75) — grep the braille class `⠋⠙⠹` across `shared/config/agents/` to check disjointness.
- Tempted to copy a spinner regex from a similar agent — the #3941 wrong-Unicode trap; verify frames from the CLI's source instead.
