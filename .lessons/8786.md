## Context

Help-session PTY trees (Claude Code, Gemini, etc. spawned for in-app help) must be reaped even if the main Electron process dies hard — crash, OOM, SIGKILL — when cooperative teardown (`taskkill /T`, `displacePriorSessions`, renderer teardown) never gets to run. `HelpSessionJobService` (`electron/services/HelpSessionJobService.ts`) owns this "last cleanup tier." On Windows it holds a single `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` Job Object via `win-job-object` (#7526): when the kernel closes the job HANDLE on main's death, the OS reaps every assigned process and its descendants for free.

## Problem

The feature was framed as a shipped crash-safety guarantee, but macOS and Linux were a **silent no-op for the entire life of the feature**. The original `binding.gyp` emitted zero targets on non-Windows, the wrapper returned `false`, and nothing reaped orphaned PTYs after a hard crash. A senior engineer would reasonably assume "crash-safe reaping shipped" meant cross-platform parity — it did not.

## Root cause

Windows' kill-on-close Job Object has **no POSIX kernel analog.** `PR_SET_PDEATHSIG` only signals direct children (agent CLIs call `setsid()`/`setpgid()` to escape the PTY shell's group, so they're no longer in the tree the signal reaches), and `kqueue EVFILT_PROC` requires a live watcher process anyway. The only portable mechanism that survives a hard crash is an **external supervisor process watching a pipe for EOF**:

- Main spawns the compiled `daintree_pty_supervisor` C binary `detached` + `unref()`'d, holding the **write end of the supervisor's stdin** for the app's lifetime (the "death pipe").
- The supervisor reads a tiny line protocol: `ADD <pid>` registers a PTY root, `DISARM` marks a clean quit.
- On clean quit, `dispose()` writes `DISARM` then closes the pipe → supervisor stands down. On a crash, the kernel closes every fd main held with no DISARM → supervisor sees EOF and `reap_all()`.

Several non-obvious constraints make this correct:

- **CLOEXEC on the death pipe is load-bearing.** libuv sets CLOEXEC on the parent's pipe end, so node-pty PTY children never inherit it. If they did, a PTY child would hold the pipe open and EOF would never fire on main's death.
- **DISARM must be sent _last_, after PTY teardown** (`electron/lifecycle/shutdown.ts`). Disarming before the graceful kill completes opens a window where a crash leaves PTYs orphaned but the supervisor disarmed.
- **`kill(-pgid)` is insufficient** — agents `setsid()` out of the group. The supervisor walks the live process table by PPID ancestry (`/proc/<pid>/stat` on Linux, `KERN_PROC_ALL` sysctl on macOS) and kills the subtree **leaves-first**, so killing a parent can't reparent a not-yet-killed child onto init and let it escape.
- **PID-reuse safety via start-time anchoring.** The supervisor captures each root's start time at `ADD` (Linux `/proc/<pid>/stat` field 22; macOS `kp_proc.p_starttime`) and refuses to SIGKILL a tree whose start time no longer matches — a recycled PID must not trigger reaping of an unrelated process.

## Lesson

"Crash-safe" is a per-platform claim, not a feature flag — verify each OS independently before asserting parity, because the Windows Job Object pattern has **no drop-in POSIX equivalent**. To reap a child process tree after a hard parent crash on macOS/Linux:

- Spawn a **detached, unref'd supervisor sidecar** that holds the **read end of a pipe whose write end the parent owns**. Pipe EOF (kernel closes the parent's fds on death) is the only crash-surviving death signal. Add an explicit DISARM line-protocol message for clean shutdown, and send DISARM **after** cooperative teardown, never before.
- Rely on libuv's CLOEXEC on the parent pipe end so spawned PTY children can't hold the death pipe open; never pass that pipe fd into a child's `stdio` inheritance.
- Reap by walking PPID ancestry and killing **leaves-first**, not `kill(-pgid)` — agent CLIs `setsid()` out of their group.
- Anchor every registered PID to its start time at registration and re-check before killing, to defend against PID reuse (mirrors the command-name check in #3762).
- Swallow `EPIPE`/stream errors on the supervisor's stdin — Electron 41 makes unhandled stream errors fatal, so a dying supervisor must never crash main.
- The native target ships **source-only** and is compiled by `electron-rebuild` during `postinstall` (binding.gyp emits an `executable` on non-Windows, `type: none` on Windows); the `.node`/binary must be added to `electron-builder.config.cjs` `extraResources`, `x64ArchFiles`, and the macOS `binaries` notarize list.

## Applies when

- Adding or auditing crash-safe cleanup for any spawned process tree (PTYs, dev servers, agent CLIs) and claiming cross-platform parity.
- Porting a Windows-Job-Object-based mechanism to macOS/Linux — there is no kernel analog; reach for a pipe-EOF supervisor sidecar.
- Reasoning about why `PR_SET_PDEATHSIG` or `kill(-pgid)` fail to reap agent processes (they `setsid()` away).
- Reviewing shutdown ordering where a "disarm/cancel" signal interacts with cooperative teardown — disarm last.
- Shipping a native executable (not just a `.node` addon) through electron-builder packaging and notarization.
