## Context

`index.html` carried a single `<meta http-equiv="Content-Security-Policy">` tag that had to allow `localhost:5173` and `ws://localhost:5173` so Vite HMR could connect in dev. That same permissive CSP shipped into production builds, silently weakening the runtime security posture of the packaged app.

## Problem

A dev-friendly CSP that references localhost or `ws://` bypasses one of Electron's main defenses against remote-content attacks. But editing `index.html` between runs, or maintaining two copies, is fragile — developers forget, and CI happily ships the dev version.

## Root cause

Static CSP in `index.html` has no concept of build mode. Vite does, via the `transformIndexHtml` hook on plugins: `ctx.server` is present in dev and absent in production, so a plugin can swap the CSP meta tag's `content` attribute at build time.

## Lesson

The CSP bodies are the single source of truth in `shared/config/csp.ts` — `getDaintreeAppDevCSP()` and `getDaintreeAppProdCSP(options?)` (where `options.scriptSrcHashes` carries `'sha256-...'` hashes for inline scripts like the host import map) — NOT hardcoded in `vite.config.ts`. The reason for the shared module: the same CSP must be applied at two layers — the build-time `<meta>` tag injected here, and the `Content-Security-Policy` HTTP response header set by the main process via `webRequest.onHeadersReceived` on the `persist:daintree` session. The browser intersects header + meta, so any divergence silently tightens the effective policy and breaks the app (documented at `vite.config.ts:17-20`); keeping both layers reading the same function bodies prevents that drift. `vite.config.ts` imports both functions and registers `cspTransformPlugin` (plugin `name: "csp-transform"`) whose `transformIndexHtml` picks `DEV_CSP` (= `getDaintreeAppDevCSP()`) when `ctx.server` is truthy, else `getDaintreeAppProdCSP(...)`. It matches the meta tag with a case-insensitive regex (`/<meta\s+[^>]*http-equiv=["']Content-Security-Policy["'][^>]*>/i`) and rewrites `content`. Crucially, the plugin **throws to fail the build** if the meta tag is missing — a silent failure here would ship an empty CSP, which is worse than the dev version. Allow both single and double quotes in the attribute regex since formatters can rewrite them.

## Applies when

Any time you need environment-specific CSP, HTML meta tags, or inline script nonces/hashes in a Vite-based Electron renderer. The same pattern handles dev-only hot-reload hooks, production-only CSP hashes, and localhost allow-lists that must never reach production — and any case where a build-time meta tag must stay byte-aligned with a runtime HTTP header.
