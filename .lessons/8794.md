## Context

`ProcessDetector` (`electron/services/ProcessDetector/ProcessDetector.ts`) identifies which agent CLI is running in a terminal by walking the PTY process tree (via `ProcessTreeCache`) and matching each child's `comm`/argv against `AGENT_CLI_NAMES`/`PROCESS_ICON_MAP`. #8794 adds `ImagePathProbe` (`electron/services/pty/ImagePathProbe.ts`) as a third identity signal that resolves a PID's on-disk executable basename: `readlink /proc/<pid>/exe` (Linux), `lsof -a -d txt -p <pid> -Fn` (macOS), `Get-CimInstance Win32_Process … ExecutablePath` (Windows). One probe instance is shared across all terminals from `pty-host.ts`.

## Problem

Agent CLIs (`claude`, `gemini`, `codex`) rewrite their own process title via `process.title`/`setproctitle` to a marketing name like "Claude Code", and node-hosted agents report `comm="node"` with blanked argv. Both `comm` and argv — the columns `ps` and the kernel expose — are clobbered, so the detector fell through to the grandchild heuristic or settled on a generic icon, mis-identifying the agent.

## Root cause

`comm`/argv are process-controlled and therefore unreliable as identity. The kernel's on-disk image path is NOT process-controlled — a CLI that renames itself to "Claude Code" still has `/opt/homebrew/bin/claude` as its mapped executable. That is the stable signal. Two non-obvious traps come with caching it per-PID inside a shared, long-lived probe:

- **PID reuse.** The probe keeps entries for up to a 30s eviction TTL (`IMAGE_PATH_EVICTION_TTL_MS`) and a 5s hard-max staleness window. A child exits, the OS recycles its PID into a different terminal's tree, and a stale cached basename mis-identifies the new process. `ProcessDetector` defends against this by diffing the set of probed PIDs between passes (`previouslyProbedPids` vs `currentProbedPids` in `evictDisappearedImagePathPids`) and calling `imagePathProbe.evict(pid)` for any PID that vanished — plus evicting all last-known children on `stop()`. The shared probe cannot self-evict on PID disappearance because it has no tree view; the per-terminal detector must drive eviction.
- **macOS `lsof -d txt` lists every mapped text segment**, not just the binary — dylibs, frameworks, system libs share the `txt` fd class. `parseLsofOutput` must skip `/System/Library/`, `/usr/lib/`, `/Library/Apple/` prefixes and `.dylib`/`.framework`/`.bundle` paths to land on the real executable (note: `/System/Library/` not bare `/System/`, so `/System/Applications/*.app` binaries still resolve).
- **Staleness window must be 3-4× the poll interval.** `IMAGE_PATH_MAX_AGE_MS` (5000ms) vs the 1500ms `ProcessTreeCache` poll: anything close to the poll interval lets setTimeout jitter push every poll past max-age, blanking the basename and defeating detection hysteresis.

## Lesson

- When a process can rewrite its own `comm`/argv (`setproctitle`/`process.title`), resolve the kernel executable image path as a higher-trust identity signal: `/proc/<pid>/exe` (Linux), `lsof -d txt` filtered (macOS), `Win32_Process.ExecutablePath` (Windows). Strip `(deleted)` suffixes from procfs readlinks (upgrade-in-place) and `.exe/.cmd/.bat` extensions so the basename lines up with the lowercase registry keys.
- Feed image-path as an ADDITIONAL candidate through the existing `selectPreferredCandidate` priority logic — do NOT make it a strict override of argv. Both signals run, the agent-priority promotion picks the agent over a generic icon when both fire, and a null probe result (unsupported platform / not yet resolved) degrades cleanly to the comm/argv path.
- Any shared, TTL-cached, per-PID native probe MUST have an explicit eviction path driven by whoever owns the tree view, or OS PID reuse will surface a prior process's cached value. Diff probed-PID sets between passes and evict on stop. Persist `null` with a fresh timestamp on probe failure to avoid tight-retry; reuse the monotonic-checkId stale-write guard (see #1377) but make the counter PROBE-WIDE, not per-entry, so an in-flight refresh can't clobber a recreated entry after evict.

## Applies when

- Adding or changing agent/process identification in `ProcessDetector`, `ImagePathProbe`, `ProcessTreeCache`, or anything reading `comm`/argv to name a process.
- A node-hosted or self-renaming CLI shows up as `node`, a generic icon, or "unknown" despite being a known agent; or detection works on one platform but not another.
- Writing any service that caches per-PID data (foreground process group, image path, CPU/memory by PID) with a TTL longer than a single poll — audit for PID-reuse staleness and add a tree-driven eviction path.
- Parsing `lsof` output on macOS and getting a system dylib/framework instead of the real binary.
- Choosing a staleness/max-age window for a stale-while-revalidate cache that is polled on a fixed interval — keep max-age a multiple of the poll period.
