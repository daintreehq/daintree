## Context

The automatic terminal grid (`useContentGridContext.tsx`, `ContentGridDefault.tsx`, `src/lib/terminalLayout.ts`) picks column count and a scroll-vs-fit layout from the measured size of `#panel-grid` via a `ResizeObserver`. Column count already had thrash protection: `applyHysteresis()` is a Schmitt trigger with an 80px dead band (`GRID_HYSTERESIS_BUFFER_PX`), so crossing a column breakpoint while dragging doesn't flip back and forth. Scroll mode (`isScrollMode`, from `gridRowsOverflow()`) was a bare boolean threshold with no such guard.

## Problem

Issue #10871: the grid rapidly oscillated between two layouts — panels shifting position and resizing many times a second — when dragging a window through macOS Mission Control split-screen, and briefly when adding a 7th terminal to a 6-terminal grid. It settled only once the window stopped changing size, which read like a resize-storm rather than a state-derivation bug; the column logic looked like the obvious suspect since it also depends on width, but its 80px buffer was far larger than anything actually moving.

## Root cause

Three things combined. First, the asymmetry: `isScrollMode` had zero hysteresis while column count had 80px, so the row-overflow boundary chattered on every height sample while crossing it. Second, a self-referential feedback edge: `#panel-grid` is the exact element the `ResizeObserver` measures, and `isScrollMode` also toggled that element's `paddingRight` (22px gutter), `gridAutoRows`, and `overflowY` — the layout decision changed its own measured input (`isScrollMode → paddingRight → measured width → cols/rows → isScrollMode`). Third, a box-model mismatch made the edge worse on some paths: the `ResizeObserver` callback read `entry.contentRect` (content-box, excludes padding) while the initial-mount and post-unlock paths read `clientWidth`/`clientHeight` (includes padding), so the same resize was measured under different semantics depending which path fired. #10872 fixed all three: added `gridRowsOverflowWithHysteresis` + `gridRowOverflowHysteresisBuffer` (a Schmitt trigger mirroring `applyHysteresis`), unified every measurement path onto `clientWidth`/`clientHeight`, and — as an initially-unconditional third belt-and-suspenders layer — reserved the 22px gutter at all times instead of toggling it with `isScrollMode`. The issue write-up ranked two more contributors deliberately left unfixed: framer-motion's FLIP re-animation re-arming because `gridWidth` sits in `layoutDependency`, and `GridNotificationBar`'s animated height sweeping the row-overflow boundary near the threshold — amplifiers, not the oscillator; fixing causes 1+2 made the flicker disappear without touching either. One day later #10898 proved the unconditional gutter was redundant now that measurement is unified on `clientWidth` and the native scrollbar is CSS-hidden — toggling `paddingRight` just reallocates space inside a box whose measured size never moves — so it made the gutter conditional again after a second-opinion review confirmed no remaining feedback edge. A residual issue surfaced from that: the gutter can still shift usable terminal width by ~1 column, and #10912 found this could make a pane's `fitAddon.proposeDimensions()` never converge with its actual `cols`/`rows`, so `TerminalReconciliationWatchdog`'s per-cycle repair (a full scrollback re-wrap) ran forever on that pane; it added a per-terminal circuit breaker (`WATCHDOG_MAX_GEOMETRY_REPAIR_ATTEMPTS = 3`) that gives up after 3 non-converging repairs and re-arms only on genuine convergence or a fresh `attachGeneration`.

## Lesson

- **A layout flicker near a size threshold means: find the boolean without hysteresis.** One size-derived decision (columns) had a Schmitt trigger, a sibling decision from the same `ResizeObserver` (scroll mode) didn't — audit every boolean/threshold derived from a measurement, not just the one with the bigger buffer.
- **Never toggle CSS on the exact element a `ResizeObserver` measures without checking which box model it reads.** `entry.contentRect` is content-box (excludes padding); `clientWidth`/`clientHeight` include it. Mixed box models across measurement paths (initial mount, RO callback, post-unlock) let a self-toggled property feed back into its own input asymmetrically.
- **A defensive triple-fix is fine as a first landing, but each layer needs independent justification before it's kept permanently.** #10872 shipped hysteresis + box-model unification + an unconditional gutter together; #10898 proved (with a second-opinion review) the box-model fix alone made the gutter toggle safe, then removed the always-on 22px dead strip.
- **A repair loop that retries toward a target on a timer needs a give-up path for target-never-converges.** #10912's `geometryRepairAttempts`/`WATCHDOG_MAX_GEOMETRY_REPAIR_ATTEMPTS` (mirroring the one-way trip in `TerminalWebGLManager`) stops a pane whose dimensions never settle from paying a full scrollback re-wrap every watchdog cycle forever.
- **Not every plausible amplifier needs a fix.** The ranked list included framer FLIP re-animation and `GridNotificationBar`'s animated height as contributors; fixing only causes 1+2 closed the bug, so the rest were correctly left alone.

## Applies when

- Diagnosing a UI element flickering between two layouts near a size threshold — check for a missing Schmitt trigger on the specific boolean flipping, not just the resize path in general.
- Touching `src/lib/terminalLayout.ts`, `useContentGridContext.tsx`, or `ContentGridDefault.tsx`, or adding any new size-driven layout decision.
- Writing or reviewing a `ResizeObserver` callback — verify `contentRect` vs `clientWidth`/`clientHeight` matches every other measurement path for the same element.
- Reviewing a reconciliation loop comparing a measured value to a target on a timer (`fitAddon.proposeDimensions()` vs `cols`/`rows`) — confirm a circuit breaker exists for permanent non-convergence.
- Relaxing a belt-and-suspenders fix to fewer layers — verify the remaining layer covers the case end to end before removing one, the way #10898 did.
