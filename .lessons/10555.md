## Context

Daintree's plugin trust model is TOFU (trust-on-first-use): the user consents once and the grant is persisted keyed by a stable identity — MCP tool pins by `(pluginId, serverId, toolName)` in `PluginMcpConsentStore`, JIT host-capability grants by `(pluginId, capability)` in `PluginCapabilityConsentService`. This arc (#10535 MCP fingerprint + audit gaps, #10551 JIT capability consent, #10555 install/update/CLI-socket hardening) audited every place a consent/validation decision is made once and then the thing it authorized changes underneath it.

## Problem

Five gaps, one shape. A pinned MCP tool could be flipped benign→destructive by the server (a "rug pull") and the pin auto-approved it, because the fingerprint covered only description + input schema, not the danger tier. A plugin _upgrade_ under the same id inherited the prior version's MCP pins and capability grants — new, possibly-compromised code ran with old code's approvals. A deliberately-invalid `spawn("")` could bank a silent `shell:exec` grant that real commands then rode unprompted. The download SSRF guard checked the literal redirect host but not the _resolved_ IP, so a public name answering `127.0.0.1` / `169.254.169.254` (cloud metadata) at connect time slipped through. And the CLI control socket accepted commands with no authentication at all.

## Root cause

The consent/validation decision was **keyed to too little, or made too early, relative to what could change afterward** — a TOCTOU family. `fingerprintTool(descriptionRaw, inputSchema, annotations)` originally hashed `rawHash`/`displayHash`/`schemaHash`; #10535 added `annotationHash` = `sha256Hex` over exactly the three tier-influencing `ToolAnnotations` hints (`destructiveHint`/`openWorldHint`/`readOnlyHint`, null-normalized in fixed key order via `hashAnnotations`). `PluginMcpConsentStore.lookup` compares it and returns a distinct `annotation-changed` reason; legacy pins predating the field carry a `""` sentinel from `normalizeRecord` that never equals a 64-char digest, so they re-consent once. Scope is deliberate — hashing the _whole_ annotations object would re-prompt when the SDK adds a benign field like `title`.

For upgrades, `PluginInstaller._purgeConsentPins(pluginId, "upgrade")` revokes BOTH stores (`revokeAllForPlugin` on the MCP consent and capability-consent services) unconditionally on the swap path (`if (existing)`), after the new code lands and before it loads. For JIT consent (#10551), `ensureCapabilityConsent` — now in `electron/services/plugin/PluginHostFactory.ts`, extracted from `PluginService.ts` — fires LAST in each gated host closure, after the static capability check, input validation, and containment, so a call that throws anyway can't bank a grant. For downloads, `fetchWithPrivateHostGuard` in `pluginDownloadPolicy.ts` DNS-resolves each redirect hop (`dns.lookup(hostname, { all: true })` via `resolvesToPrivateAddress`) and rejects a private resolved IP (`private-host`) or `https→http` downgrade (`insecure-protocol`). For the CLI socket, `PluginCliServer` mints a per-launch 256-bit `authToken`, advertises it in an owner-only control file, and checks it with `crypto.timingSafeEqual` before any dispatch.

## Lesson

- **A TOFU pin/grant keyed by a stable identity MUST be invalidated whenever the artifact behind that identity mutates** — otherwise new content inherits old consent. Any field that raises the danger tier belongs in the fingerprint (`annotationHash`), and any code change (archive-hash diff on upgrade) must revoke ALL grants via `PluginInstaller._purgeConsentPins`. Same-id reinstall/rebuild/upgrade is a trust reset, not a continuation.
- **Fingerprint the decision inputs, and ONLY the decision inputs.** `hashAnnotations` hashes exactly three tier hints in fixed key order so a rug-pull re-prompts but the SDK adding a cosmetic `title` does not. Too-narrow silently inherits; too-broad trains users to click through spurious prompts. When you widen a fingerprint, migrate old pins with a sentinel that can never match a real value (`annotationHash: ""`), never a backfilled guess — a plausible backfill silently keeps an approval that never covered the new dimension.
- **Consent must be the LAST gate, fired after validation and path containment, never before.** `ensureCapabilityConsent` runs after input checks and `resolveContainedPath`, so `spawn("")` throws without ever prompting — a doomed call can't harvest a silent grant that real calls then ride. Fail-closed: order side-effect authorization after every check that could reject the call.
- **Re-validate the RESOLVED IP per redirect hop, not the literal host — but know the residual.** `resolvesToPrivateAddress` uses `all: true` so a split-horizon answer can't hide a private address behind a public one. The code is honest that a sub-ms TOCTOU remains because `net.fetch` re-resolves DNS independently and Electron exposes no pinned resolver — do NOT read the PR summary's "pinned for the lifetime of the request" as literal; the check shrinks the window, it doesn't close it.
- **A same-user local socket still needs authentication.** The 0700 dir doesn't stop a same-user process (the real threat); `PluginCliServer` gates every frame on a per-launch token via `timingSafeEqual`, setting `conn.terminated` synchronously so an unauthenticated peer can't probe frame-by-frame.

## Applies when

- Adding a field to `fingerprintTool` / `PluginMcpConsentStore`, or any TOFU/consent fingerprint — decide whether it changes the authorization decision, and add a sentinel migration for pins that predate it.
- Touching the plugin upgrade/uninstall path in `PluginInstaller.ts` — any code-replacing operation under a stable id must call `_purgeConsentPins` (both MCP pins AND capability grants), or new code inherits old approvals.
- Wiring a new JIT-gated host capability in `electron/services/plugin/PluginHostFactory.ts` — put `ensureCapabilityConsent` LAST, after validation and containment, and re-check plugin liveness after the await.
- Reviewing any decision "check once, then the thing changes underneath" — MCP tool danger tier, downloaded IP (`fetchWithPrivateHostGuard`), socket peer identity, plugin code hash — re-key or re-check at use time, or invalidate on mutation.
