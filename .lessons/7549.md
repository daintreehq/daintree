## Context

`HelpSessionService.provisionSession` (`electron/services/HelpSessionService.ts`) provisions a per-project Daintree Assistant session dir on every launch. It first copies the bundled `help/` template into the session dir with `fs.cp(helpFolder, sessionPath, { recursive: true })`, then writes per-session secrets (`.mcp.json` bearer, `.claude/settings.json`, `meta.json`) via `resilientAtomicWriteFile`. The bundled `help/` template only changes between app versions.

## Problem

The recursive `fs.cp` ran unconditionally on every launch. `fs.cp` is non-atomic and has no atomic equivalent (you can't temp-write-then-rename a whole directory tree the way `resilientAtomicWriteFile` does for one file). A crash mid-copy left a torn session dir — a mix of old and new template files — and the next launch reused whatever partial state was on disk. A `claude` process started in that cwd could read torn files. The every-launch copy was also pure waste, since the template is identical between version bumps.

## Root cause

There's no atomic primitive for a recursive directory copy, so the only robust mitigation is to _not run the copy_ when it isn't needed. The fix gates `fs.cp` behind a SHA-256 content stamp:

- `computeTemplateHash(helpFolder)` walks the tree (`fs.readdir({ recursive: true, withFileTypes: true })`), filters `isFile()`, sorts by **full relative path** (not basename — identical basenames in different subdirs would otherwise hash non-deterministically), normalizes separators to `/`, and feeds `<rel>\0<contents>` into one running hash. The `\0` separator stops `"a"+"bc"` colliding with `"ab"+"c"` across the path/content boundary. Uses `Dirent.parentPath` (the deprecated `.path` is removed in Node 24).
- The stamp (`.template-hash`) is written **only after** `fs.cp` resolves, via `resilientAtomicWriteFile`. A failed copy never marks itself valid, so the next launch sees the mismatch and re-copies.
- Gating on the **content hash**, not the app version, is the robust choice: it re-copies on any template change (dev edits, partial-install drift) without depending on a version string being bumped.

The non-obvious regression this introduced: once the copy is skipped, every side effect the copy _used to perform as a byproduct_ must be reproduced explicitly. The Codex/Gemini branches don't call `writeMcpConfig`; previously `fs.cp` restored the bundled `.mcp.json` and thereby wiped a stale `daintree` bearer left by a prior Claude provision. With the copy skipped, that dead bearer survives in cwd — so the branch now calls `stripStaleDaintreeMcpEntry(sessionPath)` to preserve the hygiene the copy used to provide for free.

## Lesson

- A recursive directory copy (`fs.cp`) cannot be made atomic. Don't try to wrap it like a single-file write — instead gate it so it runs only when the source actually changed, shrinking the torn-write window to genuine update events.
- Use a **content hash** of the source as the gate, not an app version or mtime. Write the stamp **after** the copy succeeds and via an atomic write, so a crashed/failed copy is never recorded as complete.
- When hashing a directory for a skip gate: sort by full relative path (not basename), normalize path separators, and use a separator byte between path and contents to avoid concatenation collisions. Use `Dirent.parentPath`, not the removed-in-Node-24 `.path`.
- Treat the stamp as an optimization, not a security gate: non-ENOENT read failures should warn-and-treat-as-missing (re-copy) rather than abort provisioning.
- **Whenever you add a skip gate around a copy/overwrite, audit every byproduct that copy silently performed.** Overwrites that "happened to" reset other files (clearing stale secrets, removing torn entries) no longer fire on the skip path — reproduce those effects explicitly in the skip branch, and keep per-session secret writes (rotated bearers, current settings) unconditional and outside the gate.

## Applies when

- Touching `HelpSessionService.provisionSession`, the Daintree Assistant session-dir provisioning, `.template-hash`, `computeTemplateHash`, or `stripStaleDaintreeMcpEntry`.
- Adding or modifying any recursive `fs.cp` / directory-copy that runs on launch or per-provision, especially where a crash could leave a torn directory read by a spawned agent.
- Introducing a hash/version/mtime "skip the copy" optimization and needing it to be crash-safe and deterministic.
- Investigating stale bearer tokens, leftover `.mcp.json` entries, or other state that "used to get wiped" but now persists after a copy-skip change.
- Writing a content hash over a directory tree and worrying about determinism (basename collisions, path-separator differences, path/content concatenation ambiguity, Node 24 `Dirent.path` removal).
- Contrasting against single-file atomic writes (`resilientAtomicWriteFile`, lesson #4292): this is the directory-tree case where atomicity is impossible and skip-gating is the answer.
