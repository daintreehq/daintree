## Context

Every git invocation routes through the hardened SimpleGit factories in `electron/utils/hardenedGit.ts`, which pass a fixed `SAFE_GIT_CONFIG` array as `-c` flags so behavior is deterministic regardless of the user's `.git/config` or global git defaults. Git status/porcelain output feeds path strings to many consumers: React list keys, `WorktreeMonitor.previousStateHash` (`electron/workspace-host/WorktreeMonitor.ts:121`) change detection, and any code keying a `Map`/`Set` by file path.

## Problem

On macOS (HFS+/APFS) git emits filenames in NFD (decomposed) Unicode unless `core.precomposeunicode=true`. A path like `café.txt` arrives from `git status` as `cafe` + combining-acute (NFD), while the same name from any other source — a literal, a filesystem read normalized elsewhere, an IPC payload — is NFC. JavaScript `===` is a bitwise comparison, so the two strings compare unequal. This silently breaks React reconciliation (duplicate/remounting rows), defeats `previousStateHash` equality (spurious "changed" or missed updates), and corrupts path-as-key lookups. It reproduces only on some macOS machines, because modern git installs default `core.precomposeunicode` to `true` — so it depends entirely on the user's local default.

## Root cause

`SAFE_GIT_CONFIG` already pinned `core.quotepath=false` (so non-ASCII bytes survive IPC unquoted) but left `core.precomposeunicode` unset, inheriting the user's system git default. Pinning only `quotepath` makes the _encoding_ deterministic but not the _normalization form_: an NFD path is still emitted as raw UTF-8 NFD bytes, just unquoted. The fix adds `"core.precomposeunicode=true"` to `SAFE_GIT_CONFIG`, forcing git to report working-tree paths as NFC on every invocation. It is a no-op on Linux/Windows, and pre-existing NFD index entries in legacy repos are unaffected (it governs how the working tree is reported, not how the index is rewritten).

## Lesson

- Pin Unicode-affecting git config explicitly in `SAFE_GIT_CONFIG`; never rely on the user's local default for anything that crosses into path-equality logic. The hardened factories exist precisely to remove "depends on the user's machine" variance.
- Treat git-derived paths as potentially un-normalized. When comparing a git path against a path from another source, normalize both with `.normalize("NFC")` (the codebase already does this defensively in `electron/services/ProjectStore.ts:283,474` and `electron/services/FileSearchService.ts:161`). `core.precomposeunicode=true` is the upstream fix; per-site NFC normalization is the belt-and-braces.
- macOS-only, default-dependent bugs are invisible on CI and on most dev machines. If a symptom is "works for me / breaks for one user with accented filenames," suspect NFD/NFC mismatch before suspecting logic.

## Applies when

- Adding or auditing config flags in `SAFE_GIT_CONFIG` / `HARDENED_GIT_CONFIG` / `AUTHENTICATED_GIT_CONFIG` in `electron/utils/hardenedGit.ts`.
- Comparing, hashing, or de-duplicating file paths that originate from `git status`/porcelain output — `WorktreeMonitor.previousStateHash`, conflict detection, `FileChangeList`, React keys built from changed-file paths.
- Investigating a bug that only reproduces on macOS, or only for some users, involving accented/non-ASCII filenames (`café.txt`, emoji, combining marks).
- Using a git-derived path as a `Map`/`Set` key against a path obtained from a literal, IPC payload, or `fs` read.
- Symptoms: list rows that duplicate or remount, change-detection that fires spuriously or misses updates, lookups that miss for accented filenames.
