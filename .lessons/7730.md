## Context

Per-agent toolbar buttons (Claude/Gemini/Codex etc.) appear or disappear based on whether each agent's CLI binary is installed, unless the user has explicitly pinned/unpinned them. The pin state lives in `AgentSettingsEntry.pinned` in the persisted `agentSettingsStore`, and CLI install/uninstall is observed live via `cliAvailabilityStore`. Multiple surfaces render this state: the toolbar, the toolbar settings tab, the agent tray, the welcome screen, the menu order.

## Problem

After first launch, toolbar buttons stopped reacting to CLI install/uninstall events entirely. Installing a new agent's CLI did nothing; uninstalling left a dead button. Toolbar visibility was frozen to whatever availability snapshot happened to exist at startup, with no way to recover short of editing the store by hand.

## Root cause

`normalizeAgentSelection` was eagerly materializing `pinned: true/false` for every registered agent from a single CLI-availability snapshot taken at hydration. Once `pinned` held a concrete boolean, every later availability refresh hit the early-exit guard (`entry.pinned !== undefined`) and bailed without recomputing. The bug is the collapse of three distinct states into two: "user explicitly wants it" (true), "user explicitly doesn't" (false), and "no opinion — follow live availability" had all been forced into a concrete boolean at first observation, destroying the third state permanently. A boolean field literally cannot represent "follow live" once written.

## Lesson

- When a field encodes user override of a live-computed default, it must be **tri-state**: `true`/`false` are explicit user intent; **`undefined` must be preserved as a first-class "no intent — follow the live source" state**. Never seed a concrete boolean from a one-time snapshot to "initialize" it — that erases the follow-live state forever and any later refresh early-exits on the now-present value.
- Resolve visibility at **read time** through one shared selector, not by writing derived booleans back into the store. `isAgentToolbarVisible(entry, availability)` in `shared/utils/agentPinned.ts` is the single source of truth — `true`→show, `false`→hide, `undefined`→`isAgentInstalled(availability)`. Every surface (`Toolbar.tsx`, `ToolbarSettingsTab.tsx`, `AgentSettings.tsx`, `toolbarButtonMetadata.ts`, `agentMenuOrder.ts`, `toolbarVisibilityDispatch.ts`) calls it so they cannot disagree. Keep `isAgentPinned` (strict `=== true`) reserved for routing paths that need actual user intent, not visibility.
- Legacy stores already poisoned with eager booleans need a **one-shot migration that clears the concrete values back to undefined**, gated by a `settingsVersion`. `migrateAgentSettings` strips `pinned` from every entry, then `scheduleMigrationWriteBacks` fire-and-forgets the per-agent clears and only stamps `settingsVersion` via a dedicated IPC channel (`agent-settings:stamp-version`) **after every clear succeeds** (`Promise.allSettled` + all-fulfilled check). A partial clear leaves the version unstamped so the next cold start re-runs the (now-idempotent) migration — never stamp-then-clear.
- To actually delete a key via the settings IPC, write `{ pinned: undefined }`: object spread keeps the key in-memory, but electron-store serializes through `JSON.stringify`, which drops `undefined`, removing the field from disk. This is the deliberate delete mechanism the migration depends on (documented inline in `electron/ipc/handlers/ai.ts`).

## Applies when

- Adding or changing any per-agent toolbar/tray visibility, pinning, or `AgentSettingsEntry.pinned` logic, or touching `isAgentToolbarVisible` / `isAgentPinned` / `normalizeAgentSelection` / `migrateAgentSettings`.
- Designing a persisted setting that overrides a live-computed default (availability, capability detection, feature flag) — deciding whether the field should be boolean or tri-state.
- A symptom where UI stops reacting to live state changes after first launch / first hydration, especially with an early-exit guard like `if (x !== undefined) return`.
- Writing migrations against a versioned persisted store (`settingsVersion`) where you must clear eagerly-seeded values and need partial-failure safety before stamping the version.
- Deleting a field from electron-store via the agent-settings IPC and relying on `JSON.stringify` dropping `undefined`.
- Adding a new surface that renders agent toolbar buttons — it must consume the shared selector, not recompute visibility independently.
