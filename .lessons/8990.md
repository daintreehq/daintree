## Context

Several Daintree surfaces announce transient state to screen readers via `aria-live` regions: `ShortcutHint` (shortcut-tip tooltip), `VoiceRecordingAnnouncer` (`role="status"` recording state), and dnd-kit's built-in announcer plus the sidebar's own assertive live region for worktree-sort drags. All three were written with textbook-correct ARIA markup yet announced nothing in Chromium 146 (Electron 41). Fixed in #8990 (resolves #8942).

## Problem

Screen-reader announcements were silently dropped. The markup looked correct, jsdom-style assertions on attributes passed, but VoiceOver/NVDA spoke nothing — or, for drag cancels, spoke the same thing twice. Failures are invisible without a real screen reader because they live entirely in Chromium's accessibility-tree commit model, not in the DOM.

## Root cause

Three distinct failure modes, all Chromium accessibility-tree timing, not ARIA-correctness:

1. **Live region inside an unmounting portal (`ShortcutHint`).** The `aria-live` attributes were on the visual tooltip, which lived in a `createPortal` that fully unmounts when no hint is active. Chromium treats text _present at the moment a live region mounts_ as pre-existing static content and never announces it. Re-creating the live node on each activation means its text is always "already there" → never spoken.

2. **`setTimeout(0)` clear-then-set coalesced into one frame (`VoiceRecordingAnnouncer`).** The pattern `el.textContent = ""; setTimeout(() => el.textContent = newText, 0)` relies on the empty state committing to the a11y tree as its own observable change before the new text. A `setTimeout(0)` callback fires in a fresh task that Chromium 146 can fold into the same frame as the clear, so the accessibility tree only ever sees the final text and detects no _change_ — nothing is announced.

3. **Two announcers double-speaking (dnd-kit + sidebar).** Worktree-sort drag cancels were announced by both dnd-kit's built-in announcer (`onDragCancel`) and the sidebar's own assertive live region (`useDndMonitor.onDragCancel`), so Escape spoke the cancellation twice. Note: the naive "fix" of `accessibility={{ announcements: {} }}` on `DndProvider` throws in `@dnd-kit/core` 6.3.1 (callbacks invoked unguarded) and detaches dnd-kit's `HiddenText` node, breaking `aria-describedby` pickup instructions for every draggable app-wide.

## Lesson

- **Keep the live region permanently mounted**, decoupled from any portal/conditional UI; swap only its `textContent`/children. In `ShortcutHint` the `sr-only` `role="status"` node renders unconditionally (returned even on the early-bail path) and the visual tooltip is `aria-hidden="true"` to avoid double-announcing.
- **For clear-then-set re-announcement, use `requestAnimationFrame`, not `setTimeout(0)`.** A rAF callback runs at a pre-paint boundary that guarantees the cleared frame commits to the a11y tree before the new text. Always pair with `cancelAnimationFrame` cleanup on unmount and capture the text value into a local before scheduling (avoid reading stale store state inside the frame).
- **When two independent live regions cover the same event, suppress one narrowly** — return `undefined` from the redundant dnd-kit `onDragCancel` only for the specific drag type the sidebar already announces (`isWorktreeSortDragData`), leaving all other announcements intact. `undefined` is a safe no-op (`useAnnouncement` ignores nullish). Never blanket-disable dnd-kit announcements via `announcements: {}`.
- **Unit tests assert behavior, not markup:** node _identity_ persists across activate/deactivate (same DOM node), region is empty pre-frame then populated post-frame, stale frames cancelled, no mutation after unmount. Attribute-presence checks would have passed against all three bugs.

## Applies when

- Adding or debugging any `aria-live` / `role="status"` / `role="alert"` region in the renderer, especially one whose markup is correct but a screen reader announces nothing.
- A live region lives inside a `createPortal`, a conditionally-rendered component, an animated-presence wrapper, or anything that unmounts/remounts between announcements.
- Using a clear-then-set or "toggle text to force re-announce" pattern with `setTimeout(0)` / microtask / immediate scheduling — switch to `requestAnimationFrame`.
- Working in `ShortcutHint.tsx`, `VoiceRecordingAnnouncer.tsx`, dnd-kit announcers (`DndProvider.tsx`, `dndAnnouncements`), or any surface where two live regions might cover the same user action and double-speak.
- Touching `@dnd-kit/core` accessibility config — do not pass `announcements: {}` (throws in 6.3.1, breaks `aria-describedby` pickup instructions).
- Writing a11y unit tests in jsdom — assert node identity, text-over-time, and cleanup, not just static attribute presence.
