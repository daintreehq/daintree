## Context

When `ProjectViewManager` deactivates a project view (switching to another project), the view is detached from the window but kept alive in an LRU cache. React unmounts components, but V8's lazy GC doesn't immediately reclaim the freed memory from orphaned closures, detached DOM refs, and stale Zustand subscriptions.

## Problem

10-30MB of memory per deactivated view stayed on the heap indefinitely because V8's incremental GC deferred collection of the now-unreachable objects from the unmounted React tree.

## Solution

After detaching the view, schedule a `window.gc()` call inside a `requestIdleCallback` via `webContents.executeJavaScript("requestIdleCallback(() => { if (window.gc) window.gc(); }, { timeout: 1000 })")`. The idle callback defers the GC until the renderer is otherwise quiet, making any GC pause imperceptible to the user; the 1s `timeout` guarantees it still runs even under background CPU throttling. (The original PR used a 500ms `setTimeout` defer; the current implementation in `ProjectViewManager.deactivateEntry` uses `requestIdleCallback`.) Schedule the GC BEFORE freezing the renderer via `Page.setWebLifecycleState` — freezing suspends the event loop, so the idle callback would never fire if you froze first.

## Lesson

V8's lazy GC is not designed for tight memory budgets. After a predictable "large deallocation event" — React tree unmount, route change, tab switch — you can trigger a GC cycle explicitly via `window.gc()` (requires `--expose-gc`, set in Daintree via the `js-flags` switch in `electron/main.ts`: `--max-old-space-size=768 --max-semi-space-size=64 --expose-gc`).

Guard the call: re-fetch the live entry and check that the view still exists in the cache, is still in the `cached` state, and its webContents are alive and not destroyed. Use `webContents.executeJavaScript()` — not `webContents.send()` — because `gc()` is a synchronous V8 call that doesn't require a renderer IPC handler.

Scheduling via `requestIdleCallback` (with a `timeout` fallback) is the right tradeoff: it lets the GC run when the renderer is idle and off-screen, short enough to reclaim memory before the user switches back, and it must run before any `Page.setWebLifecycleState("frozen")` freeze that would suspend the event loop.

## Applies when

- `WebContentsView` LRU caches in Electron
- Tab-switching architectures where large React trees unmount
- Any scenario where predictable large allocations are freed at a known point
