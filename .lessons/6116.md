## Context

IPC handlers throw `AppError` (`electron/utils/errorTypes.ts`) carrying a discriminated `code` (`AppErrorCode` in `shared/types/appError.ts` — `BINARY_FILE`, `RATE_LIMITED`, `VALIDATION`, etc.) so renderer callers can `if (e.code === "BINARY_FILE")` instead of substring-matching `e.message`. PR #6116 migrated 11 handlers off ad-hoc `{ ok: false }` / `{ success: false }` shapes onto throw-`AppError`, and ~50 renderer/test files onto `try/catch` with `isClientAppError`.

## Problem

The error crosses TWO boundaries, not one. Lesson #3769 documented the first hop (main→preload structured-clone strip) and the `IpcEnvelope` fix: `serializeError`/`deserializeError` in `shared/utils/ipcErrorSerialization.ts` re-attach `code` as a property on a fresh `Error`. That looks complete — but the deserialized `Error` then crosses the preload→renderer **contextBridge realm boundary**, which strips custom Error properties AGAIN, including the own `name`. So `code` re-attached in `deserializeError` never reaches the renderer; `e.code` is `undefined` and `e.name === "Error"`, breaking every `e.code === "..."` consumer — and only in packaged/contextIsolated builds, so it passes in naive same-realm tests.

## Root cause

Electron's `contextBridge` deep-clones Error instances that cross the preload→renderer realm and preserves only `message` and `stack` — it discards every own property including `name`. `instanceof` is also unreliable across the realm. The IPC envelope's `deserializeError` setting `error.code`/`error.name` is therefore irrelevant for renderer consumers; those props are set "for callers in the same realm" only. The discriminant must ride on a surviving field. The fix encodes it INTO `message`: `_reconstructAppError` in `electron/preload.cts` rewrites the message to `[AppError|<code>|<urlencoded userMessage>] <original message>`, and the renderer-side `isClientAppError` guard (`src/utils/clientAppError.ts`) decodes it with the regex `/^\[AppError\|([A-Z_]+)(?:\|([^\]]*))?\] (.*)$/s`, re-attaches `name`/`code`/`userMessage`, and strips the prefix back off `e.message`. `GitOperationError` uses the identical trick (`_reconstructGitError`, `[GitError|<reason>|<leaseSha>|<branchName>] msg`, fixed three-slot positional layout). `_unwrappingInvoke` selects the reconstructor by sniffing `serialized.name === "AppError"` (then `"GitOperationError"`, else generic `deserializeError`) on the still-intact preload-side envelope.

## Lesson

- A typed error must survive TWO strips to reach renderer code: structured-clone (main→preload) AND contextBridge realm clone (preload→renderer). The IPC envelope only fixes the first. Re-attaching a property in `deserializeError` is invisible to renderer callers.
- Carry any discriminant the renderer must branch on (error code, git reason, lease sha) inside the `message` string as a parseable prefix, set in the preload reconstructor, decoded by a same-name renderer guard. Do NOT rely on custom Error properties or `instanceof`/`name` across the bridge.
- Detect the error type in the preload by sniffing the envelope `serialized.name`/`serialized.code` BEFORE the contextBridge crossing, and choose the reconstructor there — that's the last point those fields exist.
- `serializeError` (`ipcErrorSerialization.ts`) only forwards a fixed `KNOWN_ERROR_KEYS` allowlist plus string-typed `code`; a new discriminant field that is non-string or not on the allowlist silently vanishes at hop one before it can even be re-encoded. Add the key explicitly.
- Multi-message validation payloads (settings import: `appTheme.ts`, `terminalConfig.ts`, `keybinding.ts`) deliberately stayed on discriminated-union return shapes — they don't map to a single `code`, so don't force them onto throw-`AppError`.

## Applies when

- Adding a new `AppErrorCode` or a new IPC handler whose renderer caller must `switch`/branch on the error type rather than show a raw message.
- A renderer `catch` reads `e.code` (or `e.name`/`instanceof`) and it works in unit tests but is `undefined`/`"Error"` in the packaged app or E2E — classic second-strip symptom.
- Touching `electron/preload.cts` `_reconstructAppError`/`_reconstructGitError`/`_unwrappingInvoke`, `src/utils/clientAppError.ts` / `clientGitError.ts`, or `shared/utils/ipcErrorSerialization.ts` (`serializeError`/`KNOWN_ERROR_KEYS`).
- Propagating any new structured field (lease sha, branch name, recovery hint) from a main-process error to renderer UI.
- Reviewing a change that re-attaches custom props in `deserializeError` and assumes the renderer can read them.
