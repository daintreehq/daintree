## Context

The command palette (`ActionPalette`) renders its empty-query rail as a `role="listbox"` with `Favorites` and `Recently used` section headers interleaved among `role="option"` rows. WAI-ARIA's listbox pattern recommends grouping options under `role="group"` with a labelled header. The palette is built on the generic `SearchablePalette` (`src/components/ui/SearchablePalette.tsx`), whose primary screen-reader target is Chromium 146 (Electron 41) + macOS VoiceOver.

## Problem

With the headers as `role="presentation"` siblings, VoiceOver never announced the section structure — users heard a flat list of options with no "Favorites"/"Recently used" context. The obvious spec-conformant fix (wrap each section in `role="group"` with `aria-label`) was worse: under Chromium 146 + VoiceOver the group's accessible name was dropped and VoiceOver announced "empty group" for the visually non-empty section.

## Root cause

The Chromium 146 accessibility tree + VoiceOver bridge mishandles `role="group"` nested directly inside `role="listbox"`: the group label is not surfaced and the group is reported as empty even when it contains option children. Following the ARIA spec recommendation literally actively degrades the experience on the real target platform. The working pattern is a flat listbox where the header itself is `role="option" aria-disabled="true" aria-selected="false"` carrying an `aria-label` — AT announces the section name as a (non-interactive) row, and arrow-key navigation skips it because the header is NOT part of the `results` array that drives `selectedIndex` (the listbox children stay structurally interleaved but the keyboard model only walks real results).

## Lesson

- For section headers inside a `role="listbox"` targeting Chromium + VoiceOver, do NOT use `role="group"`. Render the header as a disabled option: `role="option" aria-disabled="true" aria-selected="false" aria-label="<section>"`. See `SECTION_HEADER_CLASS` usage in `ActionPalette.tsx`.
- Keep the keyboard navigation model decoupled from DOM order: the separator options must NOT be in the `results` array that drives `selectedIndex`/active-descendant, or arrow keys will land on a non-interactive row.
- Treat WAI-ARIA / WAI-APG recommendations as a starting hypothesis, not ground truth — verify against the actual Chromium 146 + VoiceOver target, because the spec-conformant markup can be the broken one. Leave an inline comment naming the platform and the symptom so the next engineer doesn't "fix" it back to `role="group"`.
- Secondary pattern from this PR: to announce per-row affordances, point every option's `aria-describedby` at a single stable footer-hint node id (`useId()` wrapper around the rendered footer), appending the row's danger-rationale id only while selected. Mirrors `QuickSwitcherItem`.
- Live-region result counts: announce on the `isFiltering` true→false trailing edge, debounced by `UI_DOHERTY_THRESHOLD` (400ms), skipping empty-query passes — so fast typists don't chatter the polite region.

## Applies when

- Adding or auditing screen-reader support for any `role="listbox"`/combobox/palette surface: `ActionPalette`, `SearchablePalette`, `QuickSwitcher`, `AppPaletteDialog`, or any new command-palette-style dropdown.
- Sectioning options under headers inside a listbox and reaching for `role="group"` or `role="presentation"`.
- VoiceOver reports "empty group", drops a group/section label, or fails to announce section structure under Electron/Chromium.
- Deciding between WAI-ARIA spec markup and what actually works on the Chromium + macOS VoiceOver target.
- Wiring `aria-describedby`, polite live-region announcements, or Home/End keyboard navigation into a palette/combobox.
