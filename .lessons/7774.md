## Context

`eslint.config.js` uses ESLint flat config (`tseslint.config(...)`). A global block (`files: ["**/*.{ts,tsx}"]`) sets `no-restricted-syntax` at `"error"` with four codebase-wide selectors: the `instanceof Error ? .message` ternary, `void window.electron.*` fire-and-forget IPC, raw `error.message` piped into `notify()`/`addNotification()`, and bare `dangerouslySetInnerHTML.__html`. Multiple narrower blocks (`shared/**`+`electron/**`, `src/**` renderer hygiene, `electron/ipc/handlers/**`) add their own selectors at `warn` level.

## Problem

PR #7774 added a new `no-restricted-syntax` warn-level block scoped to `shared/**`+`electron/**` to ban literal panel-kind compares (`kind === "browser"`). Adding only the new panel-kind selector would have silently disabled all four global error-level selectors for every file under `shared/` and `electron/` — the IPC/notify/CSP/error-message guards would stop firing there with no warning, no error, and no test failure.

## Root cause

ESLint flat config does NOT merge the configuration value for a given rule across overlapping blocks. For rules whose value is an array (like `no-restricted-syntax`), the LAST matching block wins entirely — its array fully replaces, never appends to, earlier blocks' arrays. So once a later block (matching the same files) re-declares `no-restricted-syntax`, the global block's selector array is gone for those files. There is no "extends/concat" semantics for the selector list; the only way to keep prior coverage is to physically replicate every prior selector into the new block (and pick the effective severity, since severity is also part of the last-write-wins value).

## Lesson

- Before adding any `no-restricted-syntax` (or any array-valued rule) block in `eslint.config.js`, find every earlier block whose `files` glob overlaps yours. The new block must re-list ALL of those blocks' selectors plus your new ones — you cannot append.
- Choose the effective severity deliberately: the new block's severity (`"warn"` vs `"error"`) applies to ALL replicated selectors for the overlapping files, not just your additions. PR #8577 intentionally promoted the replicated globals to `"error"` for `electron/ipc/handlers/**`; the renderer block keeps them at `"warn"` to match the lint ratchet.
- This trap has recurred across #7672, #6050/#6392 (globals), #8097/#8249/#9007/#8322 (renderer), #9123 (autoUpdater.channel), and #8577 (handlers). Treat the replication comment as mandatory: each block in `eslint.config.js` carries an inline note naming which selectors it mirrors and from where.
- Per-file overrides that need to allow a banned pattern must disable the whole rule for that file (or use `// eslint-disable-next-line no-restricted-syntax -- <reason>` at the call site, as the three sanctioned type guards in `shared/types/panel.ts` do) — there is no flat-config way to remove a single selector while keeping the rest.

## Applies when

- Editing `eslint.config.js` to add, scope, or change any `no-restricted-syntax` selector, or any other array-valued rule (e.g. `no-restricted-imports`, `no-restricted-syntax`, `no-restricted-properties`).
- Adding a new `files`-scoped config block whose glob overlaps `**/*.{ts,tsx}`, `shared/**`, `electron/**`, `src/**`, or `electron/ipc/handlers/**`.
- A previously-enforced lint guard (IPC `void window.electron.*`, raw `error.message` in `notify`, `dangerouslySetInnerHTML` Trusted Types, panel-kind literal compares) appears to have stopped firing for a subset of files even though the global rule still exists.
- Migrating ESLint legacy `.eslintrc` (which deep-merges overrides) to flat config and expecting the same merge semantics — flat config does not merge rule values.
- Reviewing a PR that touches `eslint.config.js` and adds a selector without re-listing the existing ones for the overlapping glob.
