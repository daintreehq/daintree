## Context

Daintree's Ubuntu CI jobs (`ci.yml`, `e2e.yml`, `e2e-single.yml`, `stabilize.yml`, `nightly-publish.yml`) launch Electron under xvfb to run Playwright E2E and build steps. On first font render Chromium asks fontconfig to enumerate system fonts before Skia can paint glyphs; a fresh GitHub runner has no `~/.cache/fontconfig`, so it pays a 200–500ms scan and writes the cache from scratch under load.

## Problem

Two failure modes, one of them disguised: (1) the cold fontconfig scan added latency variance to the renderer-startup phase of every Ubuntu job; (2) far worse, a corrupt or partially-written fontconfig cache triggered intermittent **SIGILL / SIGTRAP crashes inside Skia** in recent Electron/Chromium builds. The crash surfaces as a flaky E2E failure with no useful JS stack — it looks like a GPU or Electron renderer bug, so the natural (wrong) instinct is to chase Chromium GPU flags, swrast, or disable-gpu workarounds.

## Root cause

The Skia crash is a _fonts_ problem, not a GPU problem. Skia memory-maps the fontconfig cache; a truncated or version-mismatched cache file (e.g. half-written when a previous run was killed, or restored from a stale `actions/cache` blob that no longer matches the runner's installed font set) yields garbage that Skia executes/dereferences, producing SIGILL/SIGTRAP. Because the cache is regenerated nondeterministically on fresh runners, the crash is intermittent and uncorrelated with any code change — the classic profile of a "flaky test" that is actually environmental.

## Lesson

For Ubuntu Electron/Playwright CI, persist _and validate_ the fontconfig cache — don't treat it as a pure speed tweak:

- Restore `~/.cache/fontconfig` via `actions/cache` (now `@v5`), keyed compositely on `runner.os`, `runner.arch`, the Ubuntu release (`/etc/os-release` ID/VERSION_ID/CODENAME), the `fc-cache --version`, and a `sha256` of the installed `fonts-*`/`fontconfig` dpkg package set. The font-package hash is the load-bearing part: it rotates the key whenever the runner image or font set changes, so you never mmap a cache built against a different font inventory.
- Run `fc-cache -fv` **unconditionally after the cache restore** ("Warm fontconfig cache" step). This both warms a cold cache and _repairs_ a restored-but-corrupt one — it is the validation gate, not an optimization. Skipping it on a cache hit reintroduces the SIGILL risk.
- Gate every step on Linux (`if: runner.os == 'Linux'` or `matrix.os == 'ubuntu-22.04'`); macOS/Windows have their own font stacks and don't use fontconfig.
- When an Electron E2E job crashes with SIGILL/SIGTRAP and no JS stack on Linux runners, suspect the fontconfig cache before reaching for `--disable-gpu`.

## Applies when

- Adding or editing any Ubuntu GitHub Actions job that launches Electron or runs Playwright/xvfb (`ci.yml`, `e2e.yml`, `e2e-single.yml`, `stabilize.yml`, `nightly-publish.yml`, release-linux).
- Investigating intermittent CI crashes that present as SIGILL / SIGTRAP / "renderer process crashed" with no useful stack trace, only on Linux runners.
- Triaging a "flaky E2E" that shows no correlation with code changes and clears on re-run — consider environmental font-cache corruption, not test logic.
- Setting up `actions/cache` keys for any system-level cache (fonts, build caches) where a stale/partial restore can be silently mmapped — key on the underlying package/version inventory, and run a validate/repair step after restore.
- Debugging Linux Electron font/glyph rendering or Skia paint failures in headless environments.
