## Context

`PanelLocation` (`shared/types/panel.ts`) is the string union that ~20 consumers use to decide grid membership: fleet building (`buildFleetPanels`), fleet/error-cluster eligibility (`fleetEligibility.ts`), the central visibility gate (`isTerminalVisible`), refresh tiers and focus fallback (`panelStore.ts`), badges (`AgentButton`, `AgentTrayButton`, `useOverflowBadgeSeverity`), tab groups, backgrounding, and worktree-scoped bulk ops. The Daintree Assistant terminal had long carried a fictional `location: "dock"` — it never renders in the dock, joins no tab group, and never moves through `moveTerminalToDock` (#9640). #9668 gave it an honest value by adding `"overlay"` to the union and flipping the four spawn sites in `HelpSessionController` and `helpActions.ts`.

## Problem

Type into the Assistant, launch another agent: two panels appear in the grid, and one is the Assistant — the same PTY in both places, so closing the grid copy kills the session and the sidebar Assistant restarts itself (#9699). It also counted in badges, waiting lists, switchers, and worktree bulk ops. The misleading part: issue #9640 explicitly said "audit the existing consumers that check `location === \"dock\"`" — and #9668 did that audit. The positive `=== "dock"` checks were all fine. The leak came from a shape of consumer the instruction never named.

## Root cause

Nearly every location filter in the codebase gated by exclusion (`location !== "trash" && location !== "background"`) or by binary coercion (`location === "dock" ? "dock" : "grid"`, e.g. `getPanelTabGroupLocation` in `tabGroups.ts` and five sites in `useAgentLauncher.ts`). A widened union member matches no exclusion and no positive arm, so it falls into the default bucket of every single one — for this union, the default bucket is "grid". `"overlay"` therefore became a grid member everywhere at once, with zero type errors, the moment #9668 merged. The exclusion style wasn't sloppiness: `undefined` must mean grid (legacy panels persisted before the `location` field existed), so positive `=== "grid"` checks were never an option, and exclusion lists were the natural idiom.

#9700 centralized the predicate: `GRID_MEMBER_BY_LOCATION = { grid: true, dock: false, overlay: false, trash: false, background: false } satisfies Record<PanelLocation, boolean>` behind `isGridPanelLocation(location | undefined)` (undefined → true). The `satisfies` annotation makes any future widening a compile error at the map — forcing an explicit placement decision instead of a silent default. Proven since: PR #11247 widened the union again with `"dialog"` and the map forced `dialog: false` plus a consumer re-sweep (`tabGroups.ts` now excludes dialog alongside overlay).

## Lesson

- **When widening a shared string union, grep for the union's other members, not the new one.** The dangerous consumers never mention the value you're adding — they're exclusion lists (`!== "trash" && !== "background"`) and binary coercions (`=== "dock" ? X : Y`) whose fallback arm silently admits it. Auditing consumers of the value you're replacing (what #9640 asked for, what #9668 did) misses this class entirely.
- **Centralize union-membership predicates behind a `satisfies Record<Union, boolean>` map.** `GRID_MEMBER_BY_LOCATION` in `shared/types/panel.ts` is the template: the next widening fails to compile at the map, turning a silent behavioral leak into a forced decision. It worked in practice — #11247's `"dialog"` had to be classified before anything built.
- **The helper only covers true grid-membership sites; the compile error is your tripwire to re-sweep the rest.** ~20 raw `"overlay"` exclusions remain by design (worktree bulk ops in `terminalBulkActionsSlice.ts` / `worktreeSessionActions.ts` span dock+grid, so `isGridPanelLocation` is the wrong predicate there). When the map errors on a new member, grep `location !== "overlay"` / `location === "overlay"` and decide each site for the new value too.
- **`useAgentLauncher.ts` still has five `=== "dock" ? "dock" : "grid"` coercions** — any non-dock location (including overlay) reports its launch back as `"grid"`. They survive because launch results genuinely are binary today, but they are the exact pattern that caused #9699; check them on every widening.
- **Overlay panels self-manage; membership exclusion alone is not enough.** `moveTerminalToDock/Grid` early-return on overlay (`panelRegistry/core.ts`), backgrounding skips it before the `originalLocation` collapse records a bogus restore target (`background.ts`), `toggleDockAll`'s `allDocked` would be permanently false if the overlay were counted (`terminalLayoutActions.ts`), and layout undo must preserve rather than orphan it (`layoutUndoStore`). But exclusion cuts both ways: nothing else wakes the Assistant on view reactivation, so `wakeActiveWorktreeTerminals.ts` special-cases it. Global kill-all/restart-all still includes it intentionally — nuke-everything semantics, real PTY.
- **`isGridPanelLocation(undefined) === true` is deliberate** — legacy panels persisted before the field existed are grid members. Don't "harden" it to false; that orphans restored sessions.

## Applies when

- Adding a member to `PanelLocation` or any widely-consumed shared string union (`ActionSource`, agent-state values, panel kinds) — the compile error at `GRID_MEMBER_BY_LOCATION` is the start of the audit, not the whole audit.
- Diagnosing the Daintree Assistant (or any overlay panel) appearing in the grid, badge counts, waiting lists, send-to-agent palette, or worktree bulk-op previews.
- Writing or reviewing any filter over `panelsById` that branches on `location` — exclusion lists and `? "dock" : "grid"` coercions are silent admission points for future members.
- Touching `useAgentLauncher.ts` launch-location reporting or `getPanelTabGroupLocation` in `tabGroups.ts`.
- Tempted to treat "give this entity an honest enum value" (#9668-style refactor) as rename-safe — the consumers of the value you remove are the safe ones; the consumers that never named any value are the ones that break.
