## Context

Daintree renders agent terminals (Claude, Codex, Gemini) via `@xterm/xterm` in the renderer, and runs a parallel headless `@xterm/headless` terminal per PTY inside `TerminalProcess` (`electron/services/pty/TerminalProcess.ts`). The headless buffer feeds `SynchronizedFrameAnalyzer` (`electron/services/pty/SynchronizedFrameAnalyzer.ts`), which reads `cell.width` per column to track spinner rotation and agent state.

## Problem

Modern emoji used in agent spinner/status output (✨ ⏳ ✅ ❌) and many CJK glyphs rendered as a single cell instead of two, breaking TUI alignment in the visible terminal. Less visibly, the headless analyzer saw the same wrong widths, so its per-cell column tracking drifted — silently corrupting agent-state detection rather than just producing a cosmetic glitch.

## Root cause

`@xterm/xterm` 6.0 (and `@xterm/headless`) ship the **Unicode 6** width table by default. Unicode 6 predates the modern emoji/East-Asian-width assignments, so a code point like ✨ is measured as width 1. The fix is the separate `@xterm/addon-unicode11` package, and activation is two ordered steps: `terminal.loadAddon(new Unicode11Addon())` registers the version, then `terminal.unicode.activeVersion = "11"` actually switches the active table. Setting `activeVersion` before/without loading the addon is a no-op. The terminal must also be constructed with `allowProposedApi: true` (the `unicode` API is proposed). The non-obvious part is that this is needed in **two independent terminal instances**: the renderer xterm (visual correctness) and the headless terminal (so `SynchronizedFrameAnalyzer.cell.width` reads, which skip width-0 continuation cells, align with what the user actually sees). Fixing only the renderer leaves agent detection reading a different geometry.

## Lesson

- Any new xterm or `@xterm/headless` instance that handles agent output must activate Unicode 11: `loadAddon(new Unicode11Addon())` then set `terminal.unicode.activeVersion = "11"`, in that order, before writing data. Construct with `allowProposedApi: true`.
- Treat the renderer terminal and the headless analyzer terminal as a matched pair. Whenever you change cell-width-sensitive behavior on one (Unicode version, wrap mode, cols), mirror it on the other — otherwise agent-state detection silently diverges from the visible buffer with no error.
- xterm version defaults are not a safe assumption: the canonical wiring for the renderer lives in `setupTerminalAddons()` (`TerminalAddonManager.ts`), which lazy-loads `Unicode11Addon` via `loadUnicode11Addon()` before setting `terminal.unicode.activeVersion = "11"` (`TerminalAddonManager.ts:107`) — a load failure degrades to Unicode 6 widths rather than failing terminal creation; the headless side wires the same activation in the `HeadlessTerminal` constructor inside `setupInThreadAnalysis()` in `TerminalProcess.ts`. New terminal-spawning paths should route through these, not hand-roll a bare `new Terminal()`.

## Applies when

- Adding or refactoring any `@xterm/xterm` or `@xterm/headless` instance, or touching `TerminalAddonManager.setupTerminalAddons()` / the `HeadlessTerminal` constructor in `TerminalProcess.ts`.
- Symptoms: emoji or CJK glyphs render at half width / break TUI box alignment; spinner frames look squashed; agent-state detection misfires only when agent output contains emoji or wide characters.
- Working on `SynchronizedFrameAnalyzer` or any logic that reads `IBufferCell.getWidth()` / `cell.width` for column tracking.
- Upgrading the `@xterm/*` packages (verify the default Unicode version and the `addon-unicode11` API haven't shifted).
- Any cell-geometry-sensitive feature (scrollback trim, serialize, wrap) where the headless and renderer terminals must agree.
