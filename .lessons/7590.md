## Context

When SharedArrayBuffer output stalls, the pty-host falls back to an IPC queue (`IpcQueueManager`) with a per-terminal byte cap. At capacity the host drops the chunk to avoid OOMing the host process (the bound itself is lesson #1510). The terminal's `flowStatus` field on `PtyPanelData` is both a live runtime signal AND persisted panel state, with `TerminalRuntimeStatus` derived from it.

## Problem

On a drop the host returned early after emitting only a reliability metric — no user-visible signal. Agent transcripts silently lost bytes, corrupting output with zero indication anything happened. The naive fix (add a `"data-loss"` status and route it like any other flow status) introduces two fresh traps: (1) writing `data-loss` into the persisted `flowStatus` freezes `runtimeStatus` on `data-loss` forever, since the drop is instantaneous and nothing ever clears it; (2) `BackpressureManager.emitTerminalStatus()` dedups consecutive identical statuses, so back-to-back drops on the same terminal collapse to a single event and under-report the corruption.

## Root cause

`data-loss` is a _pulse_ (an instantaneous discontinuity), but it was added to the same `TerminalFlowStatus` union that backs durable persisted state. A status union that serves both "momentary event" and "current state" roles will leak momentary values into persisted state unless the type system forbids it. The dedup gate is correct for steady-state transitions (`running` → `paused-backpressure`) but wrong for pulses, where each occurrence is independently meaningful.

## Lesson

- When one status union serves both transient pulses and durable persisted state, carve out a persistable subset at the type level: `PersistableFlowStatus = Exclude<TerminalFlowStatus, "data-loss">` (`shared/types/panel.ts:96`). Type the persisted field (`PtyPanelData.flowStatus`), the store mutator (`updateFlowStatus`), `deriveRuntimeStatus`, and the component props as `PersistableFlowStatus` — so `data-loss` is a _compile error_ if anyone tries to persist it. `TerminalRuntimeStatus` is derived from the subset, guaranteeing the pulse never appears in runtime state.
- The renderer listener must intercept the pulse and `return` before `updateFlowStatus` (`src/store/listeners/panel/lifecycle.ts:356`) — it renders a one-shot discontinuity marker instead of mutating state.
- Emit pulses by calling `sendEvent` directly, NOT through `BackpressureManager.emitTerminalStatus()` — its dedup guard is for state transitions and will swallow repeated identical pulses (`electron/pty-host.ts`, near the `isAtCapacity` drop site).
- Report `droppedBytes` as UTF-8 byte count via `Buffer.byteLength(str, "utf8")`, never JS `string.length` — multi-byte output (CJK, emoji, accented chars) would otherwise mis-report the drop size.

## Applies when

- Adding a new value to `TerminalFlowStatus`, `TerminalRuntimeStatus`, or any status enum that is simultaneously emitted as an event and stored as persisted panel/terminal state.
- Working in the pty-host IPC fallback / `IpcQueueManager` capacity path (`electron/pty-host.ts`), or anywhere the host drops PTY output and you need a user-visible signal.
- Touching `BackpressureManager.emitTerminalStatus` and deciding whether a status should be deduped — pulses must bypass it, steady-state transitions must use it.
- Routing a new field through the PTY status pipeline (`PtyEventRouter` → `PtyEventsBridge` → `DaintreeEventMap["terminal:status"]` → `TerminalStatusPayload` → renderer listener) — every layer must forward it or it's silently dropped before reaching the renderer.
- Computing byte counts of terminal/PTY string data for telemetry or limits — use UTF-8 byte length, not string length.
