## Context

Two long-standing "heal a frozen/garbled pane" mechanisms were each considered safe. The wake-on-focus safety net (commit `51ba86d8d`, Dec 2025) calls `wake()` -> `wakeAndRestore` -> `restoreFromSerialized` (`terminal.reset()` plus a serialized-scrollback replay) whenever focus genuinely moves onto a pane, from three call sites in `src/store/slices/terminalFocusSlice.ts` (`setFocused`, `activateTerminal`, `openDockTerminal`). Separately, the #10632 tracking-issue arc added `TerminalResizeController.reconcileGeometryFresh` (#10488, extended to a periodic watchdog sweep by #10637) — a lock-exempt fresh re-fit that corrects stale column-wrap after a project switch-back. Both predate widespread use of agents that don't block the alt screen (OpenCode, any `blockAltScreen:false` config), so neither had been exercised against a genuinely live, absolutely-positioned full-screen frame.

## Problem

Clicking a settled OpenCode pane (or any alt-screen TUI) garbled it — duplicated prompt/status, a collapsed splash, or a diagonal column-shift cascade — cured only by a manual resize or adding another terminal to force a reflow. An earlier, plausible fix gated `wake()` behind `focusActuallyChanged` (skip re-focusing the _already_-focused terminal, #10800), on the theory that a redundant wake was clobbering an unchanged buffer. It did not fix it: the corruption also happened on a genuine focus _move_, and via the periodic reveal/watchdog reconcile, which has nothing to do with focus at all. `git bisect` against `v0.19.0` (before the #10632 arc) is what located the second trigger.

## Root cause

Two unrelated call paths shared no common "is this safe here" gate, and each guarded the wrong axis. (1) `wake()`'s reset+replay ran on every genuine focus move because the "host unchanged, skip it" logic can't help — an alt-screen TUI redraws continuously so it never looks unchanged, and `focusActuallyChanged` (did focus move?) is orthogonal to the real hazard (is this pane a live alt-screen frame?). (2) `reconcileGeometryFresh`, reachable for alt-buffer panes via the watchdog loop from #10637, was only protected by `inSynchronizedBlock` — whether a DEC 2026 block is _instantaneously open_. That's false almost all the time between paints, so it barely stopped an out-of-band `resize()`+reflow from mangling an absolutely-positioned frame; it only guards against tearing mid-paint, not the destructive act of resizing a full-screen app's grid at all.

Both needed the same predicate: `managed.isAltBuffer`, the persistent flag xterm's buffer-mode listener sets (`TerminalListenerInstaller.ts`, tracking `buffer.active === buffer.alternate`) — "does this pane currently show the alternate buffer," not "did a transient timing condition just occur." Bisect isolated `reconcileGeometryFresh` (added by commit `1310f7d6d` / #10488) as first-bad-commit for the reflow half; the fix makes it return `true` immediately on `managed.isAltBuffer` (skip resize, still report success so callers don't retry-spin — live in `TerminalResizeController.ts`). The reset+replay half needed an unrelated second fix: `wakeForFocus(id)` (now on `TerminalRevealController`, delegated via `TerminalInstanceService.wakeForFocus`) checks `isHibernated` / `needsWake` / `location === "background"` first — genuinely stale panes still get a real `wake()` — and otherwise no-ops for a live foreground alt-screen pane. All three focus call sites in `terminalFocusSlice.ts` moved from raw `wake(id)` to `wakeForFocus(id)`, except a dock pane's _first_ reveal from parked/offscreen, which still needs the real restore.

## Lesson

- **Gate a repair primitive on the persistent condition it's actually unsafe for (`isAltBuffer`), never a transient flag that merely correlates with when the bug was noticed.** `inSynchronizedBlock` answers "is a frame mid-paint right now" — nearly always false — not "does this pane own its own full-screen frame." Conflating the two left the reflow live between every paint.
- **A shared repair op with multiple call sites needs every call site audited, not just the one that reproduced.** `wake()` fired from `setFocused`, `activateTerminal`, and `openDockTerminal`; the first attempted fix (`focusActuallyChanged` re-focus gating, #10800) touched none of the actual hazard and still shipped as "the fix" until bisect proved otherwise.
- **Before reusing a "resync from snapshot" primitive, ask whether the target is genuinely stale or already correct.** `wakeForFocus` checks stale-ness (`isHibernated`/`needsWake`/backgrounded) first; a live foreground alt-screen pane is fed directly by the PTY stream, so the right action is _do nothing_, not re-derive state from a replay that duplicates what's already painted.
- **In a zustand action, snapshot `get()` BEFORE a `set()` in the same handler changes the flag you're branching on.** `terminalFocusSlice.ts:252` captures `wasActiveDockTerminal = get().activeDockTerminalId === id` before `set({ activeDockTerminalId: id })`; reading it after would always report the just-clicked pane as "already active," collapsing the first-reveal-vs-already-open distinction the fix depends on.
- **When a corruption bug survives a plausible, narrow fix, bisect the whole range instead of reasoning forward from the newest suspect.** `git bisect` against `v0.19.0` (pre-#10632) is what isolated `reconcileGeometryFresh`; reasoning about "which recent focus change is guilty" had already shipped one wrong answer (`focusActuallyChanged`).

## Applies when

- Any agent config with `blockAltScreen: false` (OpenCode, or a future agent) garbles, duplicates, or collapses its frame on click, focus change, or a project-switch reveal.
- Adding or reviewing a repair/recovery/reflow primitive reachable from a click, focus, reveal, or watchdog path — check it against `managed.isAltBuffer`, not just whether a sync block happens to be open right now.
- Touching `TerminalRevealController.wakeForFocus`, `TerminalResizeController.reconcileGeometryFresh`, or the `setFocused`/`activateTerminal`/`openDockTerminal` handlers in `terminalFocusSlice.ts`.
- A targeted fix for a "click/focus corrupts the terminal" bug doesn't fully resolve it — check for a second, structurally unrelated trigger.
- Reviewing zustand code that calls `get()` after a `set()` inside the same action — confirm the read isn't checking a flag `set()` just overwrote.
