## Context

Each project gets its own `WebContentsView` (per-project V8 context). On cold-start project switch, `ProjectViewManager` paints a first-paint skeleton (`injectSkeletonCss` / `injectSkeletonProjectIdentity`) into the renderer before React mounts, and the renderer must know which project it is loading. Views are created with `v8CacheOptions: "code"` (#3621) to reuse compiled bytecode.

## Problem

Two latent traps in the cold-start path: (1) the skeleton CSS injection was running before `loadURL`, so the skeleton never appeared — a silent no-op. (2) The destination project id was passed as a `?projectId=<id>` query string on the loaded URL, which prevented the V8 bytecode cache from being reused across project switches (every project minted a fresh cache entry for identical renderer code).

## Root cause

- `insertCSS` / `executeJavaScript` are scoped to the **live document**. Calling them before `wc.loadURL(...)` targets the prior `about:blank` context, which the pending navigation discards. The injection silently vanishes. `createWindow.ts` already wired this correctly on `dom-ready`; `ProjectViewManager` had drifted out of sync.
- The V8 code cache key (`v8CacheOptions: "code"`) includes the **full document URL**. `app://daintree/index.html?projectId=A` and `?projectId=B` are different cache keys even though the JS bundle is byte-identical, so the cache fragmented one entry per project — defeating the caching enabled in #3621 and the shared-session cache in #4686.

## Lesson

- Inject first-paint CSS/JS into a `WebContentsView` **after** the document exists — wire it on `wc.once("dom-ready", ...)` (or `.on` if the view can re-navigate), never before `loadURL`. Mirror the existing `createWindow.ts` dom-ready wiring. Guard with `wc.isDestroyed()` and re-read store state inside the handler (don't close over a value captured at create time) so the freshest data paints.
- Keep the document URL **static** across views that share a renderer bundle. Pass per-view scope (project id, theme, etc.) through `webPreferences.additionalArguments` (e.g. `--daintree-initial-project-id=<id>`), read it in `preload.cts` from `process.argv`, and expose it on `window` (`window.__DAINTREE_INITIAL_PROJECT__`). A `?query=` string on `loadURL` is the easy default but it busts the V8 bytecode cache because the cache key is the whole URL.
- Renderer stores should read the seeded global first, with the URL query string as a fallback (the initial-window load via `createWindow.ts` still passes `?projectId=`).
- When building DOM-mutating injection scripts for `executeJavaScript`, JSON-encode interpolated values (`JSON.stringify(label)`) — this escapes quotes/backslashes **and** U+2028/U+2029 line separators that would otherwise break a naive string-spliced script literal.

## Applies when

- Adding or modifying first-paint / skeleton / pre-React painting in a `WebContentsView` or `BrowserWindow` (calling `insertCSS` or `executeJavaScript` around `loadURL`).
- Threading any per-view bootstrap value (project id, theme, session scope) into an Electron renderer that uses `v8CacheOptions: "code"` — reach for `additionalArguments` + preload, not a URL query string.
- Touching `electron/window/ProjectViewManager.ts` createView/load path, `skeletonCss.ts`, or `preload.cts` argv parsing.
- Debugging why injected skeleton/styles never appear, or why startup bytecode-cache hit rate is low despite caching being enabled (#3621, #4686).
- Generating `executeJavaScript` strings that splice in user-controlled text (project names, labels).
