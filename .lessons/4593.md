## Context

Daintree recipes can contain per-terminal `env` entries — potentially sensitive environment variables like API keys. PR 4593 added the ability to mirror recipes to `.daintree/recipes/{name}.json` in the project repo so they can be committed to version control and shared with the team.

## Problem

If recipes were written to disk verbatim, any per-terminal `env` values would end up in committed files. Developers who share their repo would inadvertently leak API keys and tokens to collaborators or public repositories.

## Root cause

The in-repo persistence path needed a sanitization step that the clipboard export path did not. The key insight is that `.daintree/recipes/*.json` files are tracked in git, so the standard for what is "safe to write" is stricter than for a local-only clipboard export.

## Lesson

- Build the on-disk payload through a dedicated redaction step before writing to any tracked file path. Today `buildInRepoRecipePayloadString()` (in `electron/services/ProjectIdentityFiles.ts`) redacts every per-terminal `env` value (blanks each to `""`) and drops machine-local fields (`projectId`, `worktreeId`); `sanitizeRecipeTerminals()` (`shared/utils/recipeSanitizer.ts`) validates/strips control chars. The in-memory store retains the full recipe; only the disk representation is sanitized.
- On import from file, merge sanitized file data with existing env values from the store if a recipe with the same ID already exists — this handles the "team member imports a shared recipe and supplies their own keys" workflow.
- Recipe file names must be safe for all filesystems. Use the `safeRecipeFilename()` utility (`shared/utils/recipeFilename.ts`, re-exported from `electron/utils/recipeFilename.ts`) that normalizes diacritics, strips OS-forbidden chars, replaces spaces with hyphens, lowercases, and caps length (currently 200 chars).
- Document this security property in the `.daintree/recipes/` directory so developers understand the invariant.

## Applies when

- Any feature that writes user-configured data (settings, recipes, templates) to tracked git paths
- Designing import/export flows for data that may contain credentials
- Building "sync to repo" features for team-shared configuration
