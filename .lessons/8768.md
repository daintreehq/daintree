## Context

Worktree deletes run as fire-and-forget MessagePort requests from the renderer (`worktreeClient.deleteWorktree`) to the `workspace-host` utility process; the delete dialog dismisses immediately and success is reported asynchronously via the `worktree-removed` event, not the request's promise. The host runs `git worktree remove` and tracks live worktrees in `monitors`. The host is a per-project utility process that can crash and respawn under a new epoch.

## Problem

If the host crashed mid-delete (or the port dropped), the in-flight mutation was silently lost — the user's delete request just evaporated, and the only state was in the now-dead host. A naive replay made it worse: re-firing a delete the host had actually completed pre-crash hit `git worktree remove` on an already-gone monitor and threw `Worktree not found`, surfacing a spurious permanent error for a delete that had in fact succeeded.

## Root cause

Fire-and-forget IPC over a MessagePort has no at-least-once delivery and no client-side record of intent. There are three distinct loss windows that a single retry cannot disambiguate: (1) the request never reached the host, (2) the host completed and emitted `worktree-removed` but crashed before the result ack reached the renderer (success-but-ack-lost), (3) the host crashed mid-`git worktree remove`. Window (2) is the trap — the target is already absent from the post-crash snapshot, so a blind replay looks like a delete of a non-existent worktree.

## Lesson

For any fire-and-forget mutation to a crashable utility-process host that must survive the crash, build a renderer-side **mutation outbox** plus a host-side **ack map**, both keyed by a stable `mutationId` minted once per user intent:

- Mint `mutationId` per intent and **reuse it on replay** (`retryOutboxEntry` resets the retry budget but keeps the id) so the host can dedupe. A new intent for the same worktree only mints a fresh id if no live outbox entry exists.
- The host keeps an **epoch-scoped** `Set<mutationId>` of successful acks and echoes it as `lastAcknowledgedMutationIds` in _every_ `get-all-states` snapshot. The renderer prunes acked entries on each snapshot — no guessing from worktree presence. The set is cleared implicitly on respawn (new epoch = empty set = renderer's outbox replay takes over).
- Host `deleteWorktree` **short-circuits to a success ack** if `mutationId` is already in the ack set, instead of re-running `git worktree remove`. This is what makes replay idempotent.
- On reconnect, run **two passes** (`replayOutboxAfterReconnect`): first reconcile entries whose target is already absent from the fresh snapshot (success-but-ack-lost → prune, do NOT replay), then replay only survivors whose target still exists. Skipping reconcile is the bug that produces spurious "Worktree not found".
- **Classify errors, don't blindly retry.** Connectivity errors (`HOST_EXITED`, `port not ready`, `port disconnected`, `port replaced`, `APP_SHUTDOWN` — see `isConnectivityError`) leave the entry `pending` and do NOT increment the retry count — they're handled by the reconnect replay, so burning the cap on them would exhaust retries before the host is even back. Permanent errors (uncommitted changes) flip to `failed` immediately; generic errors retry up to `OUTBOX_RETRY_CAP` (3).
- Preserve the outbox across `setFatalError` (the host-crash path) — it has no server-side fallback to re-hydrate from; clearing it silently drops the user's request.
- Guard against double-replay: flip entries to `in-flight` during the replay pass and skip `in-flight`/`failed`, so two rapid `onReady` events don't double-fire.
- The port dispatcher must pass `throwOnError: true` so semantic failures reject the request and the outbox can classify them; the legacy IPC path keeps the resolve-and-emit-event contract.

## Applies when

- Adding any renderer→workspace-host (or renderer→pty-host) mutation that must not be lost when the utility process crashes/respawns, or that has user-visible optimistic state (deletes, attach/detach — the same outbox was extended to issue attach/detach in #9163).
- Touching `src/store/createWorktreeStore.ts` (`mutationOutbox`, `replayOutboxAfterReconnect`, `pruneAcknowledgedMutations`, `runDeleteAsync`, `retryOutboxEntry`, `dismissOutboxEntry`) or `electron/workspace-host/WorkspaceService.ts` (`acknowledgedMutations`, `getAcknowledgedMutationIds`, `deleteWorktree` short-circuit).
- Debugging "Worktree not found" / spurious permanent-error banners after a host crash or project switch, or deletes that vanish on reconnect.
- Wiring epoch/seq snapshot plumbing (`GetAllStatesResponse`, `WorkspaceHostState`) — anything carrying per-snapshot reconciliation state across the MessagePort.
- Designing crash-survivable IPC where you must distinguish "never delivered" from "completed but ack lost" — a single retry counter cannot; you need an idempotency key plus a snapshot-echoed ack set.
