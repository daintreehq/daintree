## Context

Canopy uses a WebGL context pool (`TerminalWebGLManager`) for xterm.js terminal rendering, with a global `webgl`/`dom` mode switch and threshold-based eviction to avoid exceeding the browser's WebGL context limit. Standard terminals and agent terminals share the pool.

## Problem

Standard terminals would occasionally show blank content. The blank content was caused by the WebGL context release/reacquire cycle leaving the terminal with no active renderer for a window. Additionally, a race condition could fire a context-loss handler after the terminal was disposed, triggering a reattach on a dead instance.

## Root cause

Standard terminals were competing for WebGL leases that they don't actually need for their use case. The release/reacquire cycle (needed for agent terminals to reclaim contexts) would transiently leave standard terminals with no active renderer, causing blank frames. The disposed-terminal check in `onContextLoss` happened after the reattach attempt rather than before.

## Lesson

Reserve WebGL exclusively for agent terminals; standard terminals should use DOM rendering unconditionally. Mixing terminal kinds in the WebGL pool creates a class of transient blank-renderer bugs that are difficult to reproduce. Implement the exclusion by gating the context allocation (`webGLManager.ensureContext(id, managed)`) on `managed.runtimeAgentId` being set before attempting allocation.

Also: always guard against a disposed/replaced instance at the top of async renderer callbacks (context loss, context restore) before taking any action — callbacks can fire after the terminal is torn down or its addon replaced. The context-loss handlers in `TerminalWebGLManager` guard with `this.pool.get(id)?.addon === ownAddon` (the pool entry still owns this addon) and deliberately drop the pool entry without auto-requeueing, to avoid an eviction loop.

## Applies when

- Adding new panel kinds that use xterm.js
- Modifying `src/services/terminal/TerminalInstanceService.ts` or `src/services/terminal/TerminalWebGLManager.ts` WebGL allocation logic
- Any `onContextLoss` / `onContextRestore` / `webglcontextlost` handler
- Changing the WebGL context pool tier logic (`TerminalRefreshTier`: BURST/FOCUSED/VISIBLE/BACKGROUND in `shared/types/panel.ts`)
