## Context

The pty-host emits `terminal-status` events (`paused-backpressure`, `paused-resource-governor`, `running`) only on pause/resume _transitions_ — there is no periodic level re-emit. The renderer batches them through `panelStatusBuffer.ts` (RAF-coalesced patch maps flushed by `flushPanelStatusBuffer`) into per-panel `flowStatus` / `flowStatusTimestamp` / `heldDurationMs` fields on `usePanelStore`. The header pill in `TerminalHeaderContent.tsx` renders directly off `flowStatus`, and `deriveRuntimeStatus` (`src/store/slices/panelRegistry/helpers.ts`) folds any non-`running` flow status into `runtimeStatus`, which dock pills and tab labels read.

## Problem

A terminal paused for backpressure, then killed, restarted, or caught in a pty-host crash showed "Paused" forever while streaming output fine (#9899). The trigger is self-selecting: the output flood that causes the pause is exactly the load that makes users kill the process or OOMs the host. The symptom misleads — it reads as a flow-control bug ("why isn't it resuming?") when actually the pause died with the process and no resume event can ever arrive.

## Root cause

`flowStatus` is level state (a persistent store field) written exclusively by an edge-triggered event stream. Three lifecycle points destroyed the emitter's pause state without clearing the renderer's copy: `onExit` in `lifecycle.ts` wrote `runtimeStatus: "exited"` but left `flowStatus`; `restartTerminal` in `restart.ts` cleared four error fields but no flow fields; `onBackendReady` in `backendHealth.ts` reset xterm instances and backend status but no per-panel flow state. The non-obvious half is why the system can't self-heal: a freshly respawned pty-host starts with an **empty status map** and only emits on transitions, so a terminal that was paused at crash time never receives a corrective `running` event unless it coincidentally hits backpressure again. The staleness is not eventually-consistent — it is permanent.

The fix (#10100) also had to defeat two secondary mechanisms. First, the resurrection race: a flow patch enqueued into the RAF buffer _before_ exit survives a store-level clear, and the flush's monotonicity guard (`patch.timestamp < prevTs`) passes vacuously because the clear set `flowStatusTimestamp` to `undefined` — a staleness comparator cannot protect a field whose clear resets the comparand. So every clear site evicts the per-terminal buffer first (`cancelTerminalFlowState(id)`; host recovery uses the global `cancelPanelStatusBuffer()`). Second, the derived-state leak: clearing raw `flowStatus` alone leaves the stale value already folded into `runtimeStatus`, so each reset site re-derives via `deriveRuntimeStatus(isVisible, undefined, prev)`. A sink-side guard in `flushPanelStatusBuffer` (skip flow patches when `runtimeStatus === "exited"`, `panelStatusBuffer.ts:166`) catches late events from the dead PTY that arrive after all clears ran. All symbols verified present on current develop.

## Lesson

- **Edge-triggered event streams cannot self-correct level state across a process boundary.** Any store field written only on transitions needs an explicit reset at every lifecycle event that destroys the emitter's state — exit, user restart, and host crash/respawn are three _separate_ code paths (`lifecycle.ts` onExit, `restart.ts` restartTerminal, `backendHealth.ts` onBackendReady) and each one must clear independently; fixing one leaves the other two stale.
- **Clearing store state is not enough when writes are RAF-buffered — evict the pending buffer atomically with the clear.** A patch enqueued in the same frame survives the clear and the flush writes it back. `cancelTerminalFlowState` exists precisely for this; it evicts flow/held-duration patches for one terminal without touching other terminals' patches or activity patches.
- **A timestamp/monotonicity guard dies when the clear path resets the timestamp.** `< prevTs` is vacuously false against `undefined`, so "the fold will reject stale patches" is wrong for any just-cleared field. Don't lean on staleness comparators for lifecycle resets; evict at the source and guard at the sink.
- **Clear derived state alongside raw state.** `deriveRuntimeStatus` folds `flowStatus` into `runtimeStatus` on visibility/location changes, so a raw-field clear without re-derivation leaves the stale value baked into dock pills and tab labels — every surface that reads `runtimeStatus`, not just the header pill.
- **Belt-and-suspenders at the sink is warranted for dead-emitter events:** the `runtimeStatus === "exited"` skip in `flushPanelStatusBuffer` catches a late event from a dead PTY arriving after all lifecycle clears — source eviction alone can't cover events still in transit.
- **Importing `panelStatusBuffer` statically from a panelRegistry slice trips the cold-graph init gate** (`worktreeStore.circularInit.test.ts` — slice → panelStatusBuffer → panelStore cycle); `restart.ts` uses a dynamic `await import()` placed _after_ the synchronous `markTerminalRestarting` so the exit-race guard is unaffected. Copy that ordering if you add buffer eviction to another slice.

## Applies when

- Adding any renderer status surface fed by pty-host or subprocess transition events (flow pills, backpressure indicators, agent-state chrome) — enumerate the exit/restart/host-recovery reset story before shipping, or the field goes permanently stale on the first crash.
- Diagnosing a pill/badge/banner stuck after the underlying condition ended, especially post-restart or post-pty-host-crash — check whether the field is only ever written by the event path and whether a respawned emitter would ever re-emit.
- Touching `flushPanelStatusBuffer` fold logic, adding new patch types to `panelStatusBuffer.ts`, or adding a new lifecycle clear — pair every store-level clear with buffer eviction.
- Reviewing crash-recovery in `backendHealth.ts` `onBackendReady` — every per-panel field written by host events needs an explicit recovery reset; the recovered host will not restate levels.
- Assuming a timestamp guard protects a field against out-of-order writes when some path clears that field's timestamp to `undefined`.
