## Context

Daintree's IPC type layer has two channel maps: the hand-maintained `IpcInvokeMap` in `shared/types/ipc/maps.ts` and the codegen-emitted `GeneratedIpcInvokeMap` in `shared/types/ipc/generated.ts` (produced from `defineIpcNamespace`/`op()` blocks by `scripts/codegen/ipc-map.mjs`). `IpcInvokeMap extends GeneratedIpcInvokeMap`. The migration path is: move a channel into a `defineIpcNamespace` block, then DELETE its hand-written entry from maps.ts and lower the count in `scripts/baselines/ipc-handwritten-baseline.json` (the ratchet). Three separate guards are supposed to keep the two maps honest.

## Problem

`project:clone-repo` and `project:clone-cancel` were migrated into a `defineIpcNamespace` block (`electron/ipc/handlers/projectCrud/gitClone.ts`), so codegen emitted them into `GeneratedIpcInvokeMap` — but the hand-written entries in maps.ts were never removed. Both interfaces declared the same two channels. There was no compile error, no failing ratchet, no failing drift test, no codegen-check failure. Dead duplicate entries accumulated in a 2000+-line file and the hand-written baseline read two higher than the true count, with zero signal anywhere (#9886).

## Root cause

TypeScript permits a child interface to redeclare a structurally-compatible property already declared on the interface it `extends` — so `IpcInvokeMap` silently redeclaring `GeneratedIpcInvokeMap`'s `project:clone-repo` is not an error. The compiler is not the overlap guard here. Each of the three safety nets had a blind spot covering this exact case: (1) `scripts/ipc-handwritten-ratchet.mjs` only fails when the hand-written count EXCEEDS the baseline — a duplicate keeps the count flat, so it passed; it counts entries, never their identity, so a migration that should have dropped the count and a net-zero migrate-out/add-in swap both sail through. (2) `channelDrift.test.ts` built its key set with `extractInvokeMapKeys`, which takes the UNION of the two maps' keys — a union collapses duplicates, so an overlap can never be reported. (3) `scripts/codegen/ipc-map.mjs --check` only diffs `generated.ts` against handler sources; it never inspects the hand-written half. Three guards, three orthogonal blind spots, all covering the same failure. The fix deleted the stale entries, lowered the baseline (268→266; since drifted to 237 as more channels migrated), and added an overlap guard in `channelDrift.test.ts` that intersects the two key sets built by two INDEPENDENT `extractKeysFromBlock` calls (not the unioning helper), plus a synthetic negative-control test that re-introduces a removed entry inline and asserts the guard fires.

## Lesson

- **When one interface `extends` another, TypeScript silently allows the child to redeclare a structurally-compatible parent property** — so a half-finished codegen migration that leaves a channel in both `IpcInvokeMap` and `GeneratedIpcInvokeMap` compiles clean. Do not rely on the compiler to catch overlap between a hand-written map and the generated map it extends; it is structurally invisible.
- **Count-based ratchets are blind to swaps and duplicates.** `ipc-handwritten-ratchet.mjs` fails only when the count grows, so a duplicate (count stays flat) and a net-zero migrate-one-out/add-one-in both pass. If a guard exists to catch identity drift, key it on the SET of channel names, not a bare integer — a count can only catch net growth.
- **A drift test that UNIONS two key sets can never report their overlap** — the union collapses the very duplicate you want to find. To detect "appears in both maps," intersect two sets built by two independent extractions (`extractKeysFromBlock` per interface), never the shared unioning helper (`extractInvokeMapKeys`). Union answers "what channels exist"; intersection answers "what's duplicated."
- **A codegen `--check` that validates only the generated half is blind to stale entries on the hand-written half.** `ipc-map.mjs --check` diffs `generated.ts` against handler sources and never looks at maps.ts. Overlap between the two halves is nobody's job unless a dedicated guard owns it — don't assume the codegen check covers the map it feeds.
- **Regression-test the guard itself with a negative control when its green state is indistinguishable from "guard broken."** The overlap test's live-files pass looks identical whether the intersection logic works or is silently no-op'd; the added negative-control test re-introduces a removed entry inline and asserts the guard fires, so a future refactor that reverts to the unioning helper is caught even while the real files are clean.

## Applies when

- Migrating any IPC channel from `IpcInvokeMap` (maps.ts) into a `defineIpcNamespace`/`op()` block — you MUST delete the hand-written entry AND lower `scripts/baselines/ipc-handwritten-baseline.json`; nothing else will tell you the duplicate exists.
- Designing or reviewing any CI guard (ratchet, drift test, codegen check) — ask what identity it keys on: count-based guards are blind to swaps, union-based guards are blind to overlaps, one-sided checks are blind to the other side.
- Touching `electron/ipc/__tests__/channelDrift.test.ts`, `scripts/ipc-handwritten-ratchet.mjs`, or `scripts/codegen/ipc-map.mjs` — three independent nets with three different blind spots; changing one does not cover the others.
- Two TypeScript interfaces where one `extends` the other and both may declare the same key — structurally-compatible redeclaration is silent; you need a source-text guard, not a type check.
- Writing any guard whose passing state looks the same whether it's working or neutered — add a synthetic negative control that forces it to fire.
