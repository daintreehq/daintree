## Context

The Fleet arming ribbon (`src/components/Fleet/`) shows per-pane health and worktree scope by reading title + `agentState` for each armed pane out of `usePanelStore`. The natural selector shape is one `useShallow` selector that walks `armOrder` and returns `Record<paneId, { title, agentState }>`.

## Problem

That single selector triggered a "Maximum update depth exceeded" infinite re-render loop on every store tick — even though it was already wrapped in `useShallow`, the fix prescribed by lesson #3683. Adding `useShallow` (the standard remedy) did not stop the loop, which makes the bug look like correctly-applied memoization that mysteriously fails.

## Root cause

`useShallow` from `zustand/react/shallow` only does a **one-level** shallow equality check. For a selector returning `Record<string, { title, agentState }>`, `useShallow` compares the top-level Record's keys and their _values by reference_. Each call constructs fresh inner `{ title, agentState }` objects, so every value fails `===` even when title and agentState are unchanged. The Record is therefore "different" on every store notification, React re-renders, the store re-notifies, and the loop never settles. `useShallow` defeats reference-equality only at depth 1; nesting objects one level deeper silently reintroduces the exact problem `useShallow` was added to solve.

## Lesson

- A `useShallow` selector is only loop-safe when its returned container is **one level deep** — a flat array/object/Record whose values are _primitives_. The instant a value is itself a freshly-constructed object or array, `useShallow` can't help and you're back to an infinite loop.
- Fix by splitting into multiple primitive-valued selectors: instead of one `Record<id, {title, agentState}>` selector, use `Record<id, string>` for titles and `Record<id, AgentState>` for states, each wrapped in its own `useShallow`. See `FleetCountChip.tsx` (`titlesByPane` + `agentStatesByPane`) and `useFleetWorktreeScope.ts` (`worktreeIdsByPane` + `agentStatesByPane`).
- Never aggregate multiple per-item fields into a nested-object selector for convenience; flatten by field. Combine the parallel maps afterward in render or in a `useMemo`.
- This is the trap one level past lesson #3683: it says "wrap object/array selectors in `useShallow` (and accumulate in one loop)." This says "`useShallow` is not transitive — it does not rescue a Record/object whose values are objects."

## Applies when

- Writing or reviewing any `usePanelStore(useShallow(...))` / Zustand selector that builds a `Record`, `Map`-like object, or array by iterating ids and packing multiple fields per entry (`{ title, agentState }`, `{ x, y }`, `{ color, count }`).
- A component still throws "Maximum update depth exceeded" / infinite re-renders _despite already being wrapped in `useShallow`_.
- Fleet (`src/components/Fleet/`), or any per-pane / per-worktree rollup that reads several `panelsById[id]` fields at once.
- Code review heuristic: a `useShallow` selector whose return type has an object or array as the _value type_ of its container — flag it and split per field.
