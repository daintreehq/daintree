## Context

Codex and Gemini use Ratatui (Rust TUI library) to render their prompt UI. When Daintree switches projects or worktrees it reattaches terminals, triggering a post-wake resize and a pre-warm resize path for offscreen agents. (Agents that need careful resize handling are now flagged via `resizeStrategy: "settled"` in their `agentRegistry.ts` capabilities rather than detected as Ratatui at runtime; `TerminalResizeController.getResizeStrategy()` reads that capability.)

## Problem

Switching projects/worktrees left Codex terminals visually corrupted — overlapping text, mis-positioned cursor, ghost lines.

## Root cause

Ratatui redraws on every `SIGWINCH`. When PTY resize and xterm.js resize happen on different frames, Ratatui sees two dimension changes back-to-back and the second redraw writes into an already-repainted buffer. Additionally, forcing an extra resize to provoke a fresh paint (a resize-then-resize-back "bounce") is actively harmful to Ratatui which treats every resize as authoritative. Stale `settled` timers from a previous project could also fire a resize after detach. And injecting clear-screen via PTY stdin (rather than through xterm.js) was racing with Ratatui's own output stream.

## Lesson

For settled agents (those with `resizeStrategy: "settled"` in `agentRegistry.ts` — Codex, Gemini, anything Ratatui-based): (1) never force an extra resize bounce to provoke a repaint — it corrupts Ratatui state; instead make the wake-time resize atomic (`f6ec11e1c`); (2) defer the xterm.js resize so it fires atomically with the PTY resize in the same frame (the settled-timer callback in `TerminalResizeController` does this); (3) clear the screen via xterm.js (`terminal.reset()`), not by writing `\x1b[2J` to PTY stdin, because the TUI owns the PTY output stream and will overwrite you; (4) clear the settled timer on project-switch detach via `clearSettledTimer(id)` — called directly from `TerminalInstanceService.ts`'s `detachForProjectSwitch()` and `destroy()` (per-terminal hibernation itself was fully removed in PR #10811; the timer-clearing survives independent of it) — so no stale resize fires after the terminal is gone; (5) skip the duplicate prewarm resize for offscreen agents — `FitAddon.fit()` already handles initial sizing; (6) route all prewarm resizes through the settled-aware `sendPtyResize()` so they respect the Ratatui guards.

## Applies when

Touching resize paths in `TerminalResizeController`, `TerminalInstanceService`, `TerminalRegistryController`, or anywhere that sends a resize to an agent terminal running Codex, Gemini, or any Ratatui/ncurses full-screen TUI.
