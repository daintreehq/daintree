## Context

The worktree diff viewer caches fetched `git diff` content per file so stepping back and forth through a change set doesn't re-pay a git spawn + IPC round trip for files already viewed. At the time of #11035 the cache lived in `FileDiffModal.tsx` / `FileViewerModal.tsx`; a later panel-migration refactor (`1a63964db`, 2026-07-19, #11247-adjacent, "retire the modals") moved the same logic verbatim into `src/panels/diff/diffContentCache.ts` (cache + freshness key), `useDiffContent.ts` (fetch orchestration), and `DiffPane.tsx` (the banner UI) — the mechanism this lesson describes is unchanged, only relocated.

## Problem

The dialog showed a `git diff` for a file and never updated while the dialog stayed open, even though the sidebar's live-watcher-backed changed-files list kept updating in the background. The common Daintree case is a user reviewing a file an AI agent is still actively editing in another terminal, so the diff going stale is not an edge case, it's close to the default reviewing experience (issue #11032). It didn't look like a cache bug at first glance because the cache key already included the file's git `status` — the instinct is "the key changes when the file changes," but `status` only changes on a category transition (untracked→added, etc.), not on repeated edits that keep the file "modified."

## Root cause

`diffCacheKey` was `worktreePath + filePath + status + ignoreWhitespace`. For the dominant case — a file edited repeatedly while remaining classified `modified` — every field is constant, so the key never invalidates, no matter how many times the agent rewrites the file. The fix leaves the cache key untouched and adds an orthogonal _freshness key_ read live from the worktree store: `selectDiffFreshnessKey` builds `${status}:${mtimeMs}:${insertions}:${deletions}` for the one file from `WorktreeSnapshot.worktreeChanges.changes`, via `useSyncExternalStore` on `WorktreeStoreContext`. A baseline is captured at fetch initiation and diffed against the live key on every store update; divergence flips a `stale` boolean, it never auto-refetches. Two traps made this non-trivial. First, `worktree.worktreeChanges.changes` is rebuilt wholesale every poll tick, so returning the matched entry object would defeat `useSyncExternalStore`'s `Object.is` bail-out (new array + object every tick regardless of real change) — returning a primitive string collapses re-renders to actual per-file changes (same class as #8635). Second, the store keys `worktreeChanges` entries by **absolute path** (`electron/utils/git.ts` builds its change map off `resolve(gitRoot, rel)`) while every UI caller passes a **worktree-relative** path, so naive string equality against `change.path` silently never matches — both sides go through `comparablePath()` (`isAbsolute(path) ? normalize(path) : join(worktreePath, path)`) first. A file leaving the change list entirely (staged/reverted/committed) must also read as changed, so `FRESHNESS_MISSING` is a distinct sentinel from "no signal at all" (`undefined`: no store context, untracked worktree, or not yet hydrated) — only `undefined` is treated as fresh.

## Lesson

- **A cache/staleness key built from an enum-like classification (git status, review state, connection state) will miss any change that doesn't cross a category boundary.** If the dominant real-world case is "the same category, edited repeatedly" (an agent rewriting a file that stays `modified`), the enum is the wrong invalidation signal — pair it with a continuously-varying scalar (mtime, insertion/deletion counts, a revision counter) sourced from the live store, not the props the component was opened with.
- **Keep the freshness signal separate from the cache key.** #11035 didn't touch `diffCacheKey` at all — it added a parallel baseline-vs-live comparison that only flips a `stale` boolean. This means changing the invalidation logic later can't accidentally invalidate the LRU/generation eviction logic (explicitly called out as unchanged in the PR body); the two concerns don't need to move together.
- **When deriving a `useSyncExternalStore` selector from a store field that's rebuilt wholesale every poll tick, return a primitive, not the matched object/array** — returning the live object defeats the `Object.is` bail-out and re-renders on every tick regardless of real change (see `selectDiffFreshnessKey`'s comment and the reference to #8635; this is a recurring Daintree footgun with poll-refreshed worktree state).
- **Before comparing a caller-supplied path against a worktree store's change list, normalize both to the same path space.** `electron/utils/git.ts` keys `worktreeChanges` by absolute path; UI callers pass worktree-relative paths. A silent mismatch here doesn't error, it just never matches — the bug is invisible unless you specifically test relative-path callers (#11035 added a dedicated test case for exactly this).
- **When a background signal invalidates something a user is actively reading (a diff, a document, a list), default to an explicit refresh affordance over silent auto-refresh**, unless you've confirmed the reader has no in-progress state to protect (scroll position, comment draft, selection). The PR's design survey found three real precedents — VS Code/GitHub Desktop/JetBrains silently auto-refresh (fine, they protect against unsaved local edits only), GitLab shows a banner with an explicit action (protects reviewer scroll/comment state), Cursor just goes frozen with no affordance at all (a known pain point, not a deliberate choice) — and picked the GitLab pattern deliberately for review UI.

## Applies when

- Adding or debugging a fetch cache in front of any git-derived or agent-editable content (diffs, file previews, status summaries) where the natural cache key is a status/category field.
- Diagnosing "this panel/dialog shows stale content while open" for anything backed by a worktree, file watcher, or other continuously-updating background signal.
- Writing a `useSyncExternalStore` selector over `WorktreeSnapshot`/`worktreeChanges` or any other poll-rebuilt store slice — check whether the selector returns a primitive or a fresh reference.
- Comparing a path from UI/caller code against a worktree store's change entries — check whether the store's paths are absolute (they are, per `electron/utils/git.ts`) before assuming string equality works.
- Deciding between silent auto-refresh and an explicit-refresh banner for content a user is actively reading — use the VS Code/GitLab/Cursor precedent split from this PR as the reasoning template.
