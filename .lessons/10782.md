## Context

`electron/ipc/handlers/logs.ts` manages the app's log-level override system: a `logLevelOverrides` map (per-module levels plus a `"*"` wildcard) persisted in electron-store and re-hydrated on every boot by `electron/main.ts` (`setLogLevelOverrides(store.get("logLevelOverrides") ?? {})`). The Settings > Troubleshooting "Verbose logging" toggle (`TroubleshootingTab.tsx`, subtitle "Resets on app restart.") is meant to be an ephemeral session flag, implemented by writing `"*": "debug"` into that same map. A separate UI, `LogLevelPalette`, lets users set persistent per-module overrides through `LOGS_GET_LEVEL_OVERRIDES` / `LOGS_SET_LEVEL_OVERRIDES`.

## Problem

Issue #10774: flipping Verbose for a quick debug session silently kept the whole app at debug level across every subsequent restart, contradicting its own subtitle. The first fix commit (`eacd2928c`) made `handleLogsSetVerbose` source its working copy from the in-memory `getLogLevelOverrides()` instead of `store.get("logLevelOverrides")` and stopped calling `store.set` there. That looked complete and matched the issue's repro. It wasn't — ten minutes later a second commit (`4b2c6fad8`, same PR #10782) had to plug a leak the first commit reopened through a different handler entirely.

## Root cause

`logLevelOverrides` is one mutable map shared by three IPC handlers, and only one of them was taught about the session-only wildcard. After the first commit, `handleLogsSetVerbose` correctly stopped persisting `"*":"debug"` itself — but `handleGetLevelOverrides` still returned the raw in-memory map unchanged, including that wildcard, to any caller. `LogLevelPalette` is exactly such a caller: it fetches current overrides via `LOGS_GET_LEVEL_OVERRIDES` to display them, and its save path, `handleSetLevelOverrides`, persists whatever set it's handed verbatim via `store.set("logLevelOverrides", clean)`. So toggle-verbose-on, open the palette (now shows `"*":"debug"` as if it were a real override), save any per-module change or just re-save, and `store.set` writes `"*":"debug"` to disk — reproducing the original bug through a door the first commit never touched. The fix wasn't "stop the reported call site from persisting", it was "make every consumer of the shared map agree the wildcard is provisional." The second commit added a `verboseSessionActive` module flag used in two more places: `handleGetLevelOverrides` now hides the wildcard from readers (showing the user's real underlying wildcard via `savedWildcardBeforeVerbose`, or nothing), and `handleSetLevelOverrides` strips a `"*":"debug"` entry before its `store.set` call, then re-applies the overlay in memory afterward so verbose keeps working. `handleClearLevelOverrides` needed the same treatment so clearing per-module overrides doesn't silently kill verbose. Separately, the PR made a deliberate no-migration call: users who already have `"*":"debug"` persisted from before this fix see verbose re-enabled on their first post-update boot, because provenance (deliberate setting vs. this bug) can't be distinguished — no destructive boot migration was written to guess it.

## Lesson

- **A "session-only" flag implemented by writing into an existing persisted map is not fixed by making the ONE call site that flips it stop persisting.** Every handler that reads that map to show "current state" (`handleGetLevelOverrides` -> `LogLevelPalette`) or writes it back verbatim (`handleSetLevelOverrides`) is a second leak path — audit all readers and writers of the shared map, not just the one named in the bug report.
- **Overloading an already-persisted keyspace (the `"*"` wildcard) to also carry an ephemeral signal is what forces two-tier bookkeeping** (`verboseSessionActive` + `savedWildcardBeforeVerbose`) just to tell "user's real wildcard" apart from "verbose's provisional one." Prefer a key space no persisted feature ever touches for new session-only state — it needs none of this machinery.
- **Hide the overlay at the read boundary, not just the write boundary.** `handleGetLevelOverrides` must never expose the session value to a persistence-capable UI; stripping only at `store.set` time is one guard short whenever another path can round-trip what it just read.
- **A same-day second commit for "the same fix" usually documents the first attempt's blind spot better than either commit message alone** — `git log -- electron/ipc/handlers/logs.ts` shows `eacd2928c` then `4b2c6fad8` ten minutes apart, both squashed into PR #10782; diff them against each other to find the actual mechanism.
- **A field with unclear provenance (deliberate vs. bug-induced persisted state) should not get a destructive migration guess.** The PR declined to auto-clear pre-existing persisted `"*":"debug"` on upgrade rather than risk clobbering a real deliberate setting — when you can't tell the two apart, don't guess.

## Applies when

- Adding any "resets on restart" / "this session only" toggle that is implemented by writing into a config object or map that already gets persisted and re-hydrated on boot (electron-store keys, Zustand `persist` slices, any `main.ts` boot re-hydration path).
- Touching `electron/ipc/handlers/logs.ts`, `logLevelOverrides`, `verboseSessionActive`, or `LogLevelPalette` — the wildcard/session-overlay logic spans `handleLogsSetVerbose`, `handleGetLevelOverrides`, `handleSetLevelOverrides`, and `handleClearLevelOverrides` together; changing one without the others reopens this exact class of bug.
- Reviewing a persistence-toggle fix that only patches the handler named in the bug report — check every other handler that reads or writes the same underlying map before approving.
- Diagnosing "a UI copy/subtitle claims ephemeral behavior but state survives restart" — grep for where that toggle's value is sourced (a persisted store key vs. a true in-memory-only variable) and check every consumer of that source, not just the toggle handler.
- Deciding how to migrate a persisted value whose provenance (deliberate user config vs. a fixed bug's side effect) can't be determined — default to no destructive migration and document the tradeoff, per this PR's precedent.
