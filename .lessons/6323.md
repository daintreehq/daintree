## Context

The Actions system (`ActionService`, ~308 `BuiltInActionId`s across 28 definition files in `src/services/actions/definitions/`) has invariants every action must satisfy: an `isEnabled` callback needs a paired `disabledReason` (so the palette can explain why a command is grayed out), every runtime registry key must appear in the public `BuiltInActionId` union and vice versa, every `BuiltInKeyAction` in `KEY_ACTION_VALUES` (`shared/types/keymap.ts`) must resolve to a registered action, query actions need a `resultSchema`, etc. Before #6323 the only enforcement was a `console.warn` inside `ActionService` gated on `import.meta.env.DEV`.

## Problem

The dev-mode warning was effectively never read in aggregate — it scrolled past in a noisy console and no run failed because of it. By the time the invariants were promoted to hard CI assertions, 13 actions had accumulated `isEnabled`-without-`disabledReason` violations (commands disabled in the palette with no explanation) across `terminalLayoutActions`, `terminalLifecycleActions`, and `worktreeActions`, plus `terminal.background` was missing from the `KEY_ACTION_VALUES` runtime set — drift no one noticed.

## Root cause

A validator that only emits warnings has no enforcement teeth: drift between the runtime registry and the public type/keybinding surfaces accumulates monotonically because nothing ever fails. The fix has three structural moves worth reusing:

- **Extract the validator as a pure function.** `validateDefinitionInvariants(def): string[]` (returns violation messages, no side effects) is called from three places: dev-mode `console.warn`, `ActionService.register()`, and the vitest CI gate. One source of truth for the rule.
- **Audit the registry by injecting a shim Map.** `createActionDefinitions(callbacks, actions?)` gained an optional registry param so the test passes a `Map` whose `.set()` is wrapped to record duplicate registrations (last-write-wins overwrites that would otherwise silently mask different definitions).
- **Check drift in both directions.** registry→`BUILT_IN_ACTION_IDS` (orphan runtime IDs) AND `BUILT_IN_ACTION_IDS`→registry (declared-but-unregistered, modulo a `KEY_ONLY_ACTIONS` allowlist for pure keybinding/nav targets that bypass `ActionService`). One direction alone misses half the drift.

## Lesson

- If an invariant is worth a dev-mode `console.warn`, it is worth a CI assert. A warn-only check is enforcement theater — promote it to a hard `expect([]).toEqual([])` gate. The canonical home is `actionDefinitions.quality.test.ts`.
- For invariants with too much accumulated drift to fix in one pass, land the check **warn-only with a `TODO(#issue): Promote to hard assert`** comment (see the `dangerRationale`, ≥80-char description, and examples gates) — this flags _new_ violations at PR time without blocking on a backlog cleanup. Promote to hard assert once the backlog is drained.
- When you add a new `BuiltInActionId`, register it in `BUILT_IN_ACTION_IDS` (`shared/config/actionIds.ts`) AND wire a registry definition, or add it to `KEY_ONLY_ACTIONS` if it is a pure keybinding/navigation target. The bidirectional drift test will fail otherwise.
- When you add `isEnabled` to an action definition, you MUST add a paired `disabledReason` callback returning a string when disabled and `undefined` when enabled. This is now CI-enforced.
- New keybinding-only actions go in `KEY_ACTION_VALUES` and `DEFAULT_KEYBINDINGS`; both have coverage gates against the registry.

## Applies when

- Adding, renaming, or removing any action ID (`BuiltInActionId`, `BUILT_IN_ACTION_IDS`, `shared/config/actionIds.ts`, `src/services/actions/definitions/*.ts`).
- Adding `isEnabled`, `disabledReason`, `resultSchema`, `dangerRationale`, or `danger:"confirm"` metadata to an action definition.
- Adding or editing keybindings (`KEY_ACTION_VALUES` in `shared/types/keymap.ts`, `DEFAULT_KEYBINDINGS`) and a CI test fails on unregistered action IDs.
- A CI failure in `actionDefinitions.quality.test.ts` (drift, missing registry entry, isEnabled-without-disabledReason, duplicate registration, missing resultSchema).
- Designing any registry/manifest with a public type union or keybinding map that must stay in sync — reach for a bidirectional drift CI gate plus a pure extractable validator, not a dev-mode warning.
- Deciding whether to land a new lint/quality invariant as warn-only vs hard-fail when existing code already violates it.
