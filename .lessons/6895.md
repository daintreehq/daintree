## Context

The PTY host runs as an Electron `utilityProcess` (`electron/pty-host.ts`). When it panics, the parent (`PtyClient` in the main process) is supposed to notice via `app.on("child-process-gone")` / the child's `"exit"` event and restart it. As a backstop for _hangs_ (where the process is alive but unresponsive), `PtyHealthWatchdog` (`electron/services/pty/PtyHealthWatchdog.ts`) pings on a heartbeat interval and SIGKILLs after `MAX_MISSED_HEARTBEATS` (3) consecutive missed pongs.

## Problem

On a fatal `uncaughtException` / `unhandledRejection` inside the host, the process did not die. Its top-level handlers logged and tried to send an error event, but never exited — so the parent's `child-process-gone` supervision path never fired. The host sat in an undefined state (broken but alive), and recovery only happened ~90s later when the heartbeat watchdog finally hit its missed-pong threshold. Users stared at a frozen terminal long enough to assume the whole app had hung.

## Root cause

Two compounding facts:

- **Electron 37+ no longer crashes a utility process on an unhandled rejection** — it _warns_ (in v36 and earlier it crashed). So the long-standing assumption that "a fatal error kills the host" is false on the current runtime; the host survives in a broken state. (Note: two earlier lessons #4156/#4372 state the opposite — that Electron 37+ _crashes_ utility processes on unhandled rejection. The authoritative behavior per CLAUDE.md and this fix is _warn, not crash_; treat those older lessons' crash-claim as superseded for the exit-behavior question, though their "always attach `.catch()`" advice still stands.)
- The host's error handlers never called `process.exit()`, so nothing converted the broken state into a clean death the parent could supervise.

The fix wires `setImmediate(() => process.exit(1))` into all four fatal paths (`uncaughtException`, `unhandledRejection`, the `initialize()` inner catch, and the `initialize().catch()`), placed _outside_ the surrounding try/catch so it always fires. `setImmediate` (not a bare synchronous `process.exit`) is required so Mojo IPC gets one event-loop tick to flush the system error event to the parent before the process dies — otherwise the parent may never receive `child-process-gone` and the host disappears silently. Separately, `healthCheckIntervalMs` was dropped 30000→5000 in `PtyClient.DEFAULT_CONFIG` and `perWindowInit.ts`, collapsing the _hang_ detection window from ~90s to ~20s (watchdog increments missed count before checking, so SIGKILL fires on the tick after 3 missed pongs at 5s each).

## Lesson

- A long-running utility-process host (pty-host, workspace-host) must **explicitly `process.exit(1)` on every fatal path** (`uncaughtException`, `unhandledRejection`, init failure). Do NOT rely on the runtime to crash it — Electron 37+ only warns on unhandled rejection, leaving the host alive but broken.
- Put the exit **outside** any try/catch in the handler so it fires unconditionally, and use **`setImmediate(() => process.exit(1))`**, not a synchronous `process.exit`, so Mojo IPC can flush the outgoing system/error event so the parent's `child-process-gone` / `"exit"` supervision actually fires.
- The heartbeat watchdog is a backstop for _hangs_ (alive-but-unresponsive), not a substitute for fast crash detection. With explicit exit, panics surface in <1s; the watchdog only covers the case where the process can't run code at all. Don't let the watchdog interval be the only thing standing between a broken host and recovery.

## Applies when

- Adding or editing top-level error handlers (`process.on("uncaughtException"|"unhandledRejection")`) in any utility-process entry point: `electron/pty-host.ts`, `electron/workspace-host.ts`, or new host entries.
- Reasoning about "why didn't the PTY/workspace host restart after it errored" or "terminal frozen, recovered ~90s/~20s later" symptoms.
- Touching `PtyClient` watchdog config (`healthCheckIntervalMs`, `MAX_MISSED_HEARTBEATS`) or `PtyHealthWatchdog` — understand it gates _hang_ detection, while explicit `process.exit` gates _crash_ detection.
- Any code assuming "an unhandled rejection will crash the utility process" — that assumption is false on Electron 37+ (it warns); the host must self-terminate.
- Wiring host-side fatal exits that must reach the parent via Mojo IPC — defer the exit one tick so the error event flushes first.
