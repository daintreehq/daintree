## Context

Per-terminal hibernation was added by #4213 (superseding that lesson, now deleted): background terminals were suspended (`TerminalWakeManager`, `TerminalHibernationManager`, host background coalescing, renderer ingest hold/evict) and resynced from a serialized snapshot on wake, on the theory that not parsing/streaming a backgrounded pane's output saved memory. #10811 removed all of it — background terminals now stay fully live end to end, and revealing a pane is just a repaint plus reacquiring its WebGL context.

## Problem

Full-screen TUIs (OpenCode, and to a lesser extent Codex/Gemini/Claude) corrupted on wake: zebra striping, double-spacing, dropped messages, blank-then-recover. #10800 tried gating the wake behind `focusActuallyChanged` and #10805 (this arc's other PR, `.lessons/10805.md`) found a second, structurally unrelated corruption trigger (`reconcileGeometryFresh` reflowing the alt buffer) — two separate fixes chased two separate symptoms of the same underlying design, and each shipped as "the fix" before the next artifact surfaced.

## Root cause

Full-screen TUIs are absolutely-positioned and stateful — they own their own frame and expect a continuous PTY stream, not a periodic checkpoint. Suspending one and reconstructing it later from a serialized buffer snapshot is inherently lossy: there is no snapshot format that captures "what the alt-screen app would have drawn had it kept receiving SIGWINCH and its own redraw ticks." Every attempt to patch the resync (skip-if-unchanged heuristics, focus-change gating, geometry reconciliation) just moved the corruption to a different trigger, because the hazard was the resync primitive itself, not any one call site into it.

The economic case against keeping it was just as direct. #10796 measured hibernation freeing roughly 1MB out of 1939MB total with 2 cached projects open — the terminal-level suspend bought almost nothing. The actual lever is the per-project `WebContentsView` renderer: `ProjectViewManager.destroyView()` on a hibernated, off-screen project freed ~493MB in the same repro. Chromium already throttles hidden renderers for free, and a backgrounded agent pane's output is a token trickle — so keeping the terminal live costs little, while hibernating it bought a rounding error against a memory hierarchy where the renderer, not the terminal buffer, is the 100-500MB-per-project line item.

#10811 kept the parts that were actually paying for themselves: the WebGL context swap (hidden terminals release their GPU context, reacquire on foreground, staying under Chromium's ~16-context cap), cold serialized restore for app restart/host-reconnect/LRU-rehydrate (a one-time load, not a live-pane resync), project-level hibernation, and IPC backpressure. Only the per-terminal suspend-then-resync loop was removed (-9445/+804 lines: `TerminalWakeManager`, `TerminalHibernationManager`, the wake/resync IPC, host background coalescing, renderer ingest hold/evict, the host cold-wake executor).

Project-level hibernation carried its own sub-regression while this was being sorted out. #10832: the `EXPERIMENT_HIBERNATION_DISABLED` guard in `HibernationService.hibernateProject` ran unconditionally across every reason (`scheduled`, `memory-pressure`, `user-initiated`), so the user-facing "Close Them" idle-terminal action skipped `gracefulKillByProject` entirely — `terminalsKilled=0`, every terminal left resident — while still evicting the renderer cache (#10796's fix). Fixed by scoping the guard to background-only paths and letting `user-initiated` bypass straight to `gracefulKillByProject({ preserveSession: true })`.

## Lesson

- **A suspend-then-resync pattern is fundamentally unsafe for absolutely-positioned, continuously-redrawing state** (full-screen alt-screen TUIs). If the "fix" for a resync corruption bug is another heuristic layered on the resync (skip-if-unchanged, focus-gating, geometry reconciliation), that signals the primitive itself is wrong, not that it needs one more guard — exactly the pattern #10800 and #10805 went through before #10811 removed the primitive outright.
- **Measure the actual memory hierarchy before optimizing a leaf.** #10796's numbers (~1MB from hibernation vs ~493MB from renderer eviction, out of 1939MB total) turned "hibernation is a nice-to-have" into "hibernation is net-negative" — the terminal-buffer lever was two orders of magnitude smaller than the `WebContentsView` lever beside it. Before defending a memory optimization, check what fraction of the actual budget it touches.
- **Trust the platform's existing throttling before building your own.** Chromium already deprioritizes hidden renderers, and agent output is a low-volume token trickle — keeping background terminals fully live turned out to be cheap. Don't assume "background = must be suspended to be cheap" without measuring.
- **An experiment kill-switch guarded across ALL reasons/paths silently breaks the one path meant to bypass it.** #10832's `EXPERIMENT_HIBERNATION_DISABLED` check needed to live inside the background-only branch, not wrap the whole `hibernateProject` function — the `user-initiated` path needs different behavior than the disabled-by-default `scheduled`/`memory-pressure` paths, and an unconditional flag can't express that.
- **When multiple targeted fixes for the same symptom keep surfacing new triggers, escalate to reconsidering the design rather than patching each one.** #10800 (focus-gate) and #10805 (alt-buffer reflow gate) were both correct, narrow fixes for real bugs — but #10811's full removal is what actually ended the corruption class, because the shared root cause was the suspend/resync model, not either call site.

## Applies when

- Touching `HibernationService.ts`, `ProjectViewManager.destroyView()` / `getOutgoingBridgeProjectId()`, or the project-level hibernation/eviction path — this is the ONLY hibernation layer left; there is no per-terminal suspend anymore.
- Seeing references to `TerminalWakeManager`, `TerminalHibernationManager`, or per-terminal wake/resync IPC in old docs, issues, or `.lessons/4213.md`-style history — that subsystem was deleted whole by #10811, not refactored; do not resurrect the pattern.
- Diagnosing TUI corruption (garbled/duplicated/collapsed frames) in a full-screen agent pane and finding the trigger is a background-to-foreground transition — check whether it's a cold-restore path (still legitimate, still resyncs) vs. something reintroducing a live per-terminal suspend/resync loop (regression of this PR's intent).
- Adding a new "reason" branch to a service like `hibernateProject` that has an experiment/feature flag guarding some but not all reasons — verify the flag's scope matches the reasons list, or a legitimate bypass path silently no-ops (#10832's exact bug).
- Proposing a memory optimization scoped to per-terminal or per-pane buffers — first measure it against per-project `WebContentsView` renderer cost (100-500MB/project) before assuming the terminal-level lever is worth the complexity.
