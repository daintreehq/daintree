## Context

PR #4224 tried to stop compiling node-pty from source. The Windows source build needs the MSVC "Spectre-mitigated libraries" component (`MSB8040`), absent from the default VS 2022 C++ workload, so dev onboarding and packaging both broke. The fix swapped `electron-rebuild -f` for prebuild-aware `@electron/rebuild`, stopped excluding `node_modules/node-pty/prebuilds` from the package, and added a `scripts/beforeBuild.cjs` electron-builder hook to copy prebuilts into `build/Release/`.

## Problem

The prebuild approach was fully reverted within a day. Two failures surfaced in packaging that source compilation never had: the `beforeBuild.cjs` hook silently broke asar unpacking, and shipping the `prebuilds/` tree broke the macOS universal build.

## Root cause

electron-builder treats the mere presence of a `beforeBuild` hook as "the caller owns native-module preparation" and skips its own module-prep step — so node-pty was never placed into `app.asar.unpacked` and the packaged app couldn't load it (`baef35850`). Separately, keeping `node_modules/node-pty/prebuilds` in `build.files` made the macOS universal merge hit an `x64ArchFiles` conflict (`16657f3a0` re-added the `!node_modules/node-pty/prebuilds` exclusion). Both regressions only appear at package time, not during `npm install`, so the PR's unit tests passed while the real builds broke.

## Lesson

Native modules are now FORCE-rebuilt from source on every platform — the opposite of PR #4224's goal. `scripts/postinstall.cjs` rebuilds `node-pty` (and `win-job-object`, `posix-pty-reaper`) via `@electron/rebuild` with `force: true`; `better-sqlite3` is the only module left on prebuilds (gated by an ABI probe). `electron-builder.config.cjs` excludes `!node_modules/node-pty/prebuilds` and `scripts/afterPack.cjs` verifies the source-compiled `build/Release/conpty*.node` with a `third_party/conpty` fallback copy. Do NOT re-introduce a `beforeBuild` hook to prep native modules — it disables electron-builder's own asar-unpack step. Do NOT ship node-pty's `prebuilds/` dir — it breaks the macOS universal merge. The Windows Spectre-libs requirement is paid for by building on a Windows runner with the right VS component, not by shipping prebuilds.

## Applies when

- Editing `scripts/postinstall.cjs`, `scripts/afterPack.cjs`, or native-module entries in `electron-builder.config.cjs`
- Tempted to add an electron-builder `beforeBuild` hook (it suppresses default module prep + asar unpacking)
- Tempted to include `node-pty/prebuilds` in `build.files` (breaks macOS universal build)
- Debugging "node-pty not found in app.asar.unpacked" or macOS universal `x64ArchFiles` conflicts
- Adding a new native dependency, or bumping node-pty / better-sqlite3 / Electron
