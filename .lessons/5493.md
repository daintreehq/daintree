## Context

Daintree's main/workspace-host processes drive git through `createHardenedGit` / `createAuthenticatedGit` (`electron/utils/hardenedGit.ts`) and `withNonInteractiveEnv` (`electron/ipc/handlers/git-write.ts`). These run headless — no controlling TTY — and several call sites regex-classify git's stderr (error-message matching for `WorktreeRemovedError`, "already exists", continue-operation failures, etc.).

## Problem

Two independent silent failures on non-default machines: (1) on a non-English system locale, git emits localised stderr (`fatal: Verzeichnis ... existiert bereits`), so every stderr-regex classifier silently misfires (see #5369). (2) An agent-driven clone/fetch to an SSH remote whose host key isn't yet cached hangs forever — ssh wants to prompt `Are you sure you want to continue connecting?` but there's no TTY to answer.

## Root cause

Two prompt surfaces and a locale surface, all distinct: `GIT_TERMINAL_PROMPT=0` only suppresses git's _credential_ prompt (#4949), NOT ssh's _host-key_ prompt — that prompt lives in ssh itself and needs `StrictHostKeyChecking=accept-new` + `BatchMode=yes` (+ `ConnectTimeout` so a dead host fails fast) injected via `GIT_SSH_COMMAND`. Separately, English stderr requires `LC_MESSAGES=C`, but POSIX gives `LC_ALL` priority over every `LC_*`, so `LC_MESSAGES=C` is inert unless inherited `LC_ALL` is also cleared (`LC_ALL: ""`). `LC_MESSAGES` (language) is deliberately split from `LC_CTYPE`/`getGitLocaleEnv` (encoding) — pin language to C for English text while keeping UTF-8 encoding for non-ASCII paths; don't collapse them into `LC_ALL`.

## Lesson

Headless git in Electron must defeat THREE surfaces, not one: git credential TTY (`GIT_TERMINAL_PROMPT=0` / `GIT_ASKPASS`), ssh host-key TTY (`GIT_SSH_COMMAND="ssh -o StrictHostKeyChecking=accept-new -o BatchMode=yes -o ConnectTimeout=15"` on the authenticated factory only), and stderr language (`LC_MESSAGES=C` + `LC_ALL=""` to defeat LC_ALL precedence). If any code path classifies git errors by matching stderr strings, the language pin is load-bearing, not cosmetic — without it the classifier passes on the maintainer's English box and fails in the field. Keep language (`LC_MESSAGES`) and encoding (`LC_CTYPE`) as separate vars; `LC_ALL` is a footgun that overrides both (cross-ref #4194).

## Applies when

- Adding a new git invocation that runs in main/workspace-host (always go through `hardenedGit.ts` factories — the locale + prompt env is baked in there).
- Writing or relying on any regex/string match against git stderr (error classification, conflict detection, "already exists" handling) — assume non-English unless `LC_MESSAGES=C` is in force.
- Any agent-automated clone/fetch/push to an SSH remote — the first-connect host-key prompt is a separate hang from credential prompts.
