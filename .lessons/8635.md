## Context

`useContentGridContext` (`src/components/Terminal/useContentGridContext.tsx`) is the "use memo" hook that derives the entire terminal grid: grid terminals, tab groups, fleet panels, focus targets. It read `state.panelsById` (`Record<string, PanelInstance>`) inside a `useShallow` selector to materialize panel objects. The panel map is mutated by `updateAgentState`/`updateActivity` in `src/store/slices/panelRegistry/core.ts`, which return `{ panelsById: { ...state.panelsById, [id]: {...terminal, agentState, ...} } }` on every state-changing agent tick.

## Problem

With multiple active agents, the whole grid hook re-ran on every agent state/activity tick even when grid structure (membership, order, location) was unchanged. Each tick rebuilt grid terminals, tab groups, and fleet panels and re-rendered the grid subtree — pure churn proportional to agent activity, not to anything the user could see change.

## Root cause

`useShallow` does NOT save you here. Two distinct facts compound:

- Every agent tick produces a **new `panelsById` reference** AND a **new value at the changed `id` key** (the panel object is spread). A `useShallow` selector returning the whole map shallow-compares element references and correctly sees one changed entry — so it invalidates. `useShallow` only absorbs churn when contents are reference-identical; here they aren't.
- This is a sharper case than the `useShallow + .filter()` → `createSelector` fix (lesson #3683). `createSelector` memoizing off `panelsById` would still invalidate, because the input reference genuinely changes every tick and the changed element is real. You cannot memoize your way out of a map whose element references legitimately churn.

The only escape is to **decouple membership from materialization**: subscribe reactively to a derived list that is stable across ticks, and read the churning map non-reactively. Agent ticks mutate `panelsById[id]` but do not change `id`, `location`, or `panelIdsByWorktreeId` — so a filtered list of IDs has stable membership and order across ticks, and `useShallow`'s element-wise compare returns the previous array reference.

## Lesson

For a Zustand map whose element references churn faster than its membership (the classic shape: per-row state ticks on an entity map), never subscribe to the map to materialize objects in a hot hook. Instead:

- Subscribe with `useShallow` to a **narrow derived ID list** filtered from a stable index (here `gridPanelIds` from `state.panelIdsByWorktreeId[worktreeId]` filtered by `location`; `fleetPanelIds` projected from `buildFleetPanels(...).map(p => p.id)`). The selector body re-runs every tick, but `useShallow` returns the prior reference when IDs + order are unchanged, so downstream memos don't fire.
- **Materialize objects non-reactively**: inside a memo keyed ONLY on the ID list, read `panelStoreApi.getState().panelsById` and index by id. Reading via `getState()` does not create a subscription, so the memo only re-runs when membership changes — not on every tick.
- Return a **stable module-level empty array** (`EMPTY_PANEL_IDS`, `EMPTY_TERMINALS`) when filtered results are empty, so the empty case doesn't emit a fresh `[]` each call and re-invalidate `useShallow`.
- Keep secondary structural deps explicit when membership alone is insufficient — `tabGroups` here voids `gridPanelIds` + `storeTabGroups` + `trashedTerminals` because tab-group mutations and restore-from-trash don't always shift the grid ID list.

## Applies when

- Building or auditing any selector/hook over `panelsById`, `panelIdsByWorktreeId`, or any Zustand entity map that `updateAgentState`/`updateActivity`/per-row tick actions mutate by spreading.
- A "use memo" / hot React hook re-renders on agent state/activity ticks even though grid/list structure is unchanged; profiling shows re-renders proportional to agent count × tick rate.
- You reached for `useShallow` or `createSelector` on a map selector and it didn't stop the re-renders — the element references are genuinely changing every tick.
- Deriving grid terminals, fleet panels, tab groups, or any list-of-entities from a frequently-mutated store map in `useContentGridContext.tsx` or similar list-rendering hooks.
- Reviewing a new memo that closes over a whole store map; check whether it should instead gate on a derived ID list and read the map via `getState()`.
