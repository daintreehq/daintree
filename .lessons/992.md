## Context

Daintree had a legacy per-terminal flow-control path that paused the PTY when a single terminal's unacknowledged bytes crossed a watermark. The acknowledgments came from the renderer after xterm.js consumed output. That worked for visible terminals but broke for any terminal that never had an attached, mounted renderer.

## Problem

Background terminals (minimized, in another workspace, in trash, on a tab never mounted) had no xterm instance to emit per-terminal acks. Their unacked byte count rose to the watermark, that one PTY paused, and since no ack would ever arrive it never resumed. Agents in those terminals silently froze.

## Root cause

The legacy per-terminal ACK gate conflated "data delivered to the host→renderer transport" with "data rendered by an attached xterm." Only the second requires a renderer, yet the pause decision was tied to it. A terminal that may never mount xterm could therefore deadlock on a condition only a mounted renderer could clear.

## Lesson

Flow control must never gate on UI-attach state for a terminal that might never mount xterm. The fix was to remove the legacy per-terminal renderer-ACK PAUSE entirely — `TerminalProcess.acknowledgeData(_charCount)` (`electron/services/pty/TerminalProcess.ts:710`) is now a deliberate no-op. The comment there mentioning "SAB-based backpressure" is stale: the SharedArrayBuffer transport never shipped and is unreachable in production (`FUTURE_SAB_*` caps in `electron/pty-host/backpressure.ts:21-22`, the `init-buffers` handler and SAB branch in `electron/pty-host/handlers/connection.ts:137` and `electron/pty-host.ts:404` are reachable only from adversarial tests because `SharedArrayBuffer` is unsupported in Electron UtilityProcess; `isSabMode()` is `false` in prod). Do NOT frame SAB ring-buffer backpressure as "the sole throttle" — that mechanism does not exist at runtime.

The live backpressure is the MessagePort/IPC ACK + high/low-watermark system on the host→renderer queues (`portQueueManager.applyBackpressure` / `electron/pty-host/ipcQueue.ts`, renderer-side ACK timing per lesson #4862, string-based acks per #4639). That queue-level scheme is the correct place to throttle: it pauses on the _transport queue_ filling, which drains as the renderer (or the bounded IPC queue) consumes, rather than on whether any single terminal has rendered. Bounded IPC fallback queueing (lesson #1510) is part of this too — and it likewise must not depend on a terminal ever mounting a renderer.

## Applies when

Designing or touching PTY flow control, adding a new terminal transport, debugging "terminal froze in background", or changing when a PTY is paused/resumed. Especially when adding any feature that keeps terminals alive without mounted xterm instances (detached panels, headless agents, pooled terminals): the pause/resume condition must be one the host can clear on its own, never one that requires a renderer to attach.
