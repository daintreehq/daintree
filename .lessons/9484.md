## Context

The Portal is a right-anchored resizable dock. Its width is persisted via zustand's `persist` middleware (`src/store/portalStore.ts`) and restored on launch. On a narrower display than the one the width was saved on, an over-wide persisted width can crowd the editor canvas to nothing, so the restore needs a viewport-relative clamp (`vw - PORTAL_MIN_EDITOR_WIDTH`).

## Problem

The natural place to clamp a persisted value against the viewport is the persist `merge` callback — it already reshapes the hydrated state. But a clamp written there computes against `window.innerWidth === 0`, so `safeMax` collapses to `PORTAL_MIN_WIDTH` and _every_ restore snaps to the floor regardless of the real screen size.

## Root cause

The main window is created with `show: false` (`electron/window/createWindow.ts:182`) and only shown after the renderer signals ready. Zustand's `persist` `merge` callback runs _synchronously during store creation_, which happens while the window is still hidden — at that point Chromium reports `window.innerWidth === 0` because the BrowserWindow/WebContentsView has no laid-out viewport yet. Any viewport-relative math in `merge` (or any other synchronous-hydration path) silently divides against zero. Layout dimensions are only meaningful _after_ first paint, i.e. inside a mount effect.

## Lesson

- Never read `window.innerWidth`/`innerHeight` (or any laid-out layout metric) inside a zustand `merge`/`migrate`/`partialize` callback or any other synchronous-hydration code path. Under Electron's `show: false` startup the viewport is `0`. Defer viewport-relative clamps to a `useEffect` that runs after first paint.
- Make the one-shot guard _retry-safe_: gate the "already ran" ref **after** the `vw <= 0` bail (`if (vw <= 0) return;` _before_ `didClampRestoredWidthRef.current = true;`), so an early mount that races first paint doesn't permanently consume the single clamp opportunity — a later mount (e.g. after the window is shown, or a remount) can still apply it. Tripping the ref unconditionally would mean a clamp that ran too early never runs at all.
- For click-vs-double-click disambiguation on the same element, guard the drag start with `e.detail > 1` (skip the second `mousedown` the browser fires before `dblclick`), not `setTimeout` arbitration — the timer fires too late, after the drag has already started. This is the carry-forward from #4997.
- Document `mousemove`/`mouseup` drag listeners attached in a `mousedown` handler outlive the component unless the unmount effect can tear them down — store the cleanup in a ref (`dragCleanupRef`) and invoke it from the unmount effect, or the closure keeps writing through the surviving store.

## Applies when

- Restoring a persisted layout dimension (width, height, split ratio) that must be clamped against the current viewport on launch.
- Writing zustand `persist` `merge`/`migrate` logic that is tempted to read DOM/layout state.
- Implementing one-shot mount effects that depend on post-layout values during Electron's hidden-window startup — guard the "ran once" flag so a too-early run can retry.
- Adding double-click reset alongside a drag handler on the same resize separator or splitter.
