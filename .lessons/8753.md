## Context

`ActivityMonitor` (`electron/services/ActivityMonitor.ts`) drives the agent idle/working/waiting state machine. Its `simpleOutputState` path detects "working" by diffing successive snapshots of the last N _visible_ terminal lines, obtained via `getVisibleLines(n)` (`createVisibleContentSnapshot`, used around `ActivityMonitor.ts:464,558,713`). If the snapshot changes between polls, the agent is treated as active.

## Problem

Agents that were actively working showed as idle (#8701). The trigger was geometry, not time: in a **small grid tile** the viewport exposes only a couple of lines, so the visible-line snapshot stops changing even while the agent streams output below the fold. The change-driven detector is starved, `lastActivityTimestamp` ages out, and the 8s `IDLE_DEBOUNCE_MS` gate fires a false idle. (Scrolling up produces the same starvation, but the dominant case is a small tile, not user scroll — the triage framing of "scrolled up" was narrower than the real cause.)

## Root cause

The activity signal was bound to the _rendered viewport_ (N visible xterm lines) rather than the underlying byte stream. Viewport height / scroll position have no bearing on whether the agent is working, so any detector keyed off the visible buffer is inherently geometry-dependent. The fix taps a signal that the agent emits regardless of what's on screen: OSC `9;4` taskbar-progress sequences (ConEmu spec, adopted by Claude Code v2.0.56 — state 1/3 = working, 0 = idle). `Osc94Parser` (`electron/services/pty/Osc94Parser.ts`) streams the raw PTY chunks in `TerminalProcess.handlePtyData` (`TerminalProcess.ts:1585`) upstream of everything, and routes `onWorking`/`onIdle` into `ActivityMonitor.onOscProgressWorking/onOscProgressIdle`, which refresh `lastActivityTimestamp`/`lastDataTimestamp` as a heartbeat.

Two non-obvious sub-traps the implementation had to solve:

- **The tap must be read-only, but the sequence must still be stripped downstream.** The parser does NOT consume bytes from the renderer- or byte-volume-bound paths; `IdleSequenceFilter.stripIdleTerminalSequences` (`OSC_NOISE` regex) still removes OSC 9;4 downstream so other detectors stay clean and xterm still renders the progress bar. This is the same strip-on-success invariant `OscResponder` uses for OSC 10/11.
- **OSC 9;4 state=0 is NOT a completion signal.** Claude emits state=0 between _every_ tool call. So `onOscProgressIdle` must NOT force idle — it only arms a 200ms `OSC_IDLE_DEBOUNCE_MS` timer that a subsequent state=1/3 cancels. Real idle is left to natural decay of `lastActivityTimestamp` through the existing 8s gate, and `onOscProgressWorking` refreshes `lastDataTimestamp` so the `MAX_WORKING_SILENCE_MS` safety net still fires when OSC stops (guarding the #4974 stuck-working regression).

## Lesson

- Any agent-activity detector keyed off the **rendered/visible buffer** (`getVisibleLines`, scrollback snapshot, cursor-line text) is implicitly a function of viewport height and scroll position. When a small grid tile or scroll-up can hide the output, the detector silently mis-fires. Supplement it with an out-of-band signal parsed from the **raw PTY byte stream** in the host, where geometry has no effect.
- When tapping a control sequence as a side-channel signal, keep the tap **read-only and parallel** to the existing strip path — don't consume the bytes from the renderer/volume paths. Reuse the existing strip-on-success invariant rather than rerouting the stream.
- Don't equate a "progress removed / hide" marker with "task complete." Agents emit hide between sub-steps; treat it as a debounced advisory that cancels on the next working marker, and let an independent decay/timeout own the real idle transition. Always refresh the silence-timeout timestamps from the new signal so a hung agent still recovers (#4974).
- A streaming OSC parser must be stateful across chunk boundaries (node-pty reads at OS boundaries): carry partial fragments, handle ESC / `ESC]` split introducers, BEL vs ST terminators, foreign-OSC swallow with nested-introducer reseed, and cap the carry buffer against an unterminated malformed/hostile peer.

## Applies when

- Touching `ActivityMonitor`, `AgentStateMachine`, or the agent idle/working/waiting/completed transitions.
- A bug report says an agent shows idle/done while still working, or behaves differently in small vs large grid tiles, when maximized vs tiled, or after scrolling up in the terminal.
- Adding or changing any detector that reads `getVisibleLines`, `createVisibleContentSnapshot`, cursor-line text, or otherwise diffs the visible xterm buffer.
- Parsing or stripping OSC sequences (OSC 9;4 progress, OSC 9 notification, OSC 10/11, OSC 52) in `electron/services/pty/` — especially `Osc94Parser`, `OscResponder`, `IdleSequenceFilter`.
- Wiring a new raw-PTY-stream tap in `TerminalProcess.handlePtyData`, or any signal that must coexist with `stripIdleTerminalSequences` without double-consuming bytes.
- Interpreting a "remove/hide/reset progress" marker as task completion, or adding any signal that could leave the agent stuck working without refreshing `MAX_WORKING_SILENCE_MS` timestamps.
