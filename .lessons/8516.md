## Context

`WorkspaceService` (workspace-host utility process) keeps the worktree sidebar in sync via a `@parcel/watcher` (FSEvents on macOS) "topology watcher" subscribed to `.git/worktrees/`. Create/delete of a `.git/worktrees/<name>` subdir fires a watcher event that drives `scheduleTopologyReconcile()`. A slow background poll (`DEFAULT_BACKGROUND_WORKTREE_INTERVAL_MS`, plus the adaptive backoff up to ~300s) is the only other refresh driver.

## Problem

Removing the last worktree externally (`git worktree remove`, `rm -rf`) left a phantom row in the sidebar — sometimes for minutes. The topology watcher emitted nothing: no error callback, no event. The row only cleared whenever the slow background poll happened to reach the deep `fs.access` check inside `getWorktreeChangesWithStats`.

## Root cause

Two structural blind spots that are NOT errors to be caught:

1. A watcher subscribed to a directory cannot report the deletion of that directory itself. When `.git/worktrees/` is removed (last worktree gone), FSEvents goes permanently silent on the now-vanished root — no error, no final event.
2. `TopologyWatcher.startWatcher()` (`electron/workspace-host/TopologyWatcher.ts:172` — the watcher cluster was later extracted out of `WorkspaceService.ts` into its own module; the method was renamed from `startTopologyWatcher()`) early-returns when the metadata dir is absent (`if (!existsSync(metadataDir))`). The exact "all worktrees removed" state is the state in which the real watcher refuses to (re)start. So even on a restart path there is nothing watching.

Because both failure modes produce silence rather than an error, any recovery gated on watcher liveness inherits the same blind spot.

## Lesson

When a file watcher's coverage gap is "the watched root itself disappeared," a safety net that depends on that watcher is no safety net. Two complementary defenses:

- **Watcher-independent periodic reconcile.** Run an idempotent `setInterval` (`TOPOLOGY_SAFETY_INTERVAL_MS = 90_000`, `unref()`'d — now defined in `electron/workspace-host/TopologyWatcher.ts`) that calls `scheduleReconcile()` regardless of watcher state; `WorkspaceService.scheduleTopologyReconcile()` (`WorkspaceService.ts:1913`) remains the thin public delegate onto it. Start it (`TopologyWatcher.startSafetyTimer()`) directly in `loadProject` and on `setPollingEnabled(true)` resume — NOT inside `startWatcher()` (renamed from `startTopologyWatcher()`), which no-ops in exactly the case the net exists to cover. Clear it in `TopologyWatcher.stop()` (renamed from `stopTopologyWatcher()`, invoked from `setPollingEnabled(false)`) so dispose/pause tears it down symmetrically; the start method is a no-op when already live so both call sites can invoke unconditionally.
- **Per-refresh existence preflight.** At the very top of `WorktreeMonitor.refresh()`, `await access(this.path)`; on `ENOENT` call `stop()` + `onRemoved()` and return, so every refresh path (reconcile-triggered or poll) self-detects removal at the cheapest possible point instead of waiting for the deep git-status `fs.access`. Crucially, fall through to a normal refresh on non-ENOENT codes (EACCES/EPERM/transient) — do not misclassify a permission blip as a removal. Guard the method with an early `if (!this._isRunning) return` so a concurrent refresh (background poll racing the reconcile) after the first `stop()` cannot emit a duplicate `worktree-removed`.

This is distinct from #3332 (circuit-breaker masking the existence check) and #3033 (enumerating git error strings for removal): here the signal is _absence of any signal_ from the watcher, not a misclassified error.

## Applies when

- A phantom/stale worktree row persists in the sidebar after external removal, especially when removing the _last_ worktree of a project.
- Touching topology watching in `electron/workspace-host/TopologyWatcher.ts` (`startWatcher`/`stop`/`scheduleReconcile`), its `WorkspaceService.scheduleTopologyReconcile()` delegate, or `WorktreeMonitor.refresh`.
- Adding or relying on any `@parcel/watcher`/FSEvents subscription where the watched directory could itself be deleted (the root-deletion blind spot generalizes beyond `.git/worktrees/`).
- Designing a "safety-net" reconcile and tempted to start/stop it inside the watcher setup — verify the net survives the case the watcher cannot observe.
- Adding a removal-detection short-circuit to a polled monitor: ensure idempotency under concurrent refreshes (running guard + stop-before-emit) and ENOENT-only classification.
