## Context

On Linux desktop (AppImage/Wayland), the app is launched by a `.desktop` file with no controlling terminal, so the main process's stdout/stderr (fd 1/2) point at an orphaned pty slave (or nothing). `WorkspaceHostProcess` forks the workspace-host via `utilityProcess.fork(hostPath, [], { stdio: "inherit", ... })` (`electron/services/WorkspaceHostProcess.ts:509`). The process-level stdio error guards in `electron/setup/environment.ts`, `electron/pty-host.ts`, and `electron/workspace-host.ts` originally only swallowed `EPIPE`.

## Problem

The forked host inherited the main process's broken fd 2. Any `console.error`/`logger` write inside the host (or the main process) threw an uncaught errno error that crashed the process. The crash was invisible in dev (terminal-attached fd 2 is fine) and only reproduced from a packaged GUI launch — the hardest environment to debug.

## Root cause

Two compounding traps. (1) `stdio: "inherit"` means the child writes directly to the parent's fd 2; when that fd is dead the child crashes on its first log line, and the parent's own error guard never sees it because the throw happens in the child. (2) The errno on a dead GUI fd is `EIO` (disconnected/orphaned pty slave), not `EPIPE`. `EPIPE` only occurs when a live reader closes a pipe (e.g. quitting Terminal.app mid-run); a fd pointing at a vanished tty returns `EIO`, and a closed fd returns `EBADF`. The single-errno guard let the dominant GUI-launch errno straight through.

## Lesson

Fork utility processes with `stdio: "pipe"` and forward their output through the parent's logger (`installHostLogForwarding`/`forwardHostOutput` line-buffer stdout→`logger.info`, stderr→`logger.warn`), exactly as `PtyClient` already does — never `"inherit"`, which couples the child's survival to the parent's possibly-dead fds. On the piped streams, attach a no-op `"error"` listener (an unhandled Readable `error` becomes an uncaughtException) and flush partial line buffers on `"close"` (the tail of a crash stack trace arrives after `exit`). For the process-level stdio guard, swallow the whole dead-fd errno family `STDIO_DEAD_CODES = {EPIPE, EIO, EBADF, ECONNRESET}`, but keep rethrowing real conditions like `ENOSPC`.

## Applies when

Forking any `utilityProcess` or child (pty-host, workspace-host, future hosts), wiring its stdio, or writing a `process.stdout/stderr` `"error"` guard. Reach for this whenever a bug reproduces only from a packaged Linux/AppImage GUI launch and not from `npm run dev`.
