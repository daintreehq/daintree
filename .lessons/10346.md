## Context

#10346 was a large cold-start branch (main-process eager modules 1318→994, renderer eager JS 850→699KB gzip) restructuring the boot critical path: window reveal, Vite/rolldown chunk grouping, tree-shaking of a boot module, V8 compile hints, and the synchronous bootstrap read of `config.json`. Each trap below is a silent platform seam — no build error, no crash.

## Problem

Slow time-to-interactive, a blank-window flash, and — most misleadingly — boot cost that grew silently with usage (MCP audit volume). None of it threw or failed a test; the tree-shake bug that dropped the boot-IPC module surfaced only on second-pass review, not in CI.

## Root cause

Four independent, non-obvious platform behaviors.

1. **Electron `dom-ready` on a `<script type="module">` entry fires only after the ENTIRE deferred module graph evaluates**, so gating `win.show()` on it serialized the OS window-map behind all renderer JS eval. Fix: a _classic_ (non-module) `public/skeleton-ready.js` calls `window.electron.app.skeletonParsed()` → `CHANNELS.APP_SKELETON_PARSED` the instant the skeleton markup is in the DOM; `dom-ready` + a 5s fallback stay as backstops. This early signal is now load-bearing across the project-view switch reveal gate (`ProjectViewSwitchController`, `ProjectViewPaintGateController`, ~150ms).

2. **rolldown/Vite `advancedChunks` groups capture each matched module's full DEPENDENCY CLOSURE unless a higher-priority group claims those deps first.** `vendor-react` sat at priority 15; `vendor-editor` (priority 60) matched CodeMirror, and because CodeMirror depends on React it swept `react/index.js` + `react/jsx-runtime.js` into `vendor-editor` — pinning ~451KB of CodeMirror into the entry's eager static closure on every boot. Fix: raise `vendor-react` to priority 80, above every React-dependent group. Sub-trap: `@lezer/lr` in the eager `vendor` group re-dragged CodeMirror back in (via `@lezer/common` → vendor-editor), so it had to be excluded from the `vendor` regex.

3. **A side-effect-only import is tree-shaken out of the PRODUCTION bundle unless the file is in package.json `sideEffects`.** `src/lib/bootIpcEager.ts` exists only to fire `app:boot` early (`import "./lib/bootIpcEager"` in `main.tsx`, body `void getSafeBootPromise()`, no exports consumed). Prod dropped it silently; dev kept it. Fix: add it to `sideEffects`.

4. **`electron/bootstrap.ts` reads and `.bak`-copies `config.json` SYNCHRONOUSLY before `main.js` loads, so boot cost scales with `config.json` size.** The MCP audit + turn-outcome rings lived inside it and grew to multiple MB. Fix: migration v22 (`022-audit-logs-store.ts`) moves the rings to a lazily-constructed `auditLogsStore` (a Proxy that builds the `Store` only on first real read, never at bootstrap). It bails when the store fell back to in-memory (`auditLogsStore.path === ""`) rather than stripping the keys and losing the rings.

Related plumbing gotcha: V8 compile hints (`//# allFunctionsCalledOnLoad`) are honored only on physical line 1, so prepend them in `generateBundle` with `order: "post"` — after minify and after `vite:build-import-analysis`; `renderChunk`/`banner` get stripped or bumped to line 2 where V8 ignores them.

## Lesson

- **Never gate an Electron window/view reveal on `dom-ready` for a module-type entry** — it waits for the whole module graph to evaluate. Signal HTML-skeleton parse from a tiny classic (non-module) script over IPC and reveal on that, with `dom-ready` + a timeout as backstops; `ready-to-show` doesn't cover `WebContentsView` paint.
- **In `codeSplitting.groups`, a group captures its matched modules' entire dependency closure; priority decides who claims a shared dep first.** Any vendor package that transitively depends on React must sit at LOWER priority than `vendor-react` (pinned at 80); never add a React-matching group above 80, and check what a new group's `test` transitively pulls in.
- **A module imported purely for its side effect (no consumed exports) is dead code to the prod tree-shaker unless it's in `sideEffects`** — and it fails ONLY in the packaged build, silently. Treat "works in dev, missing behavior when packaged" as a tree-shake suspect.
- **Nothing that grows with usage may live in a file the bootstrap reads synchronously before `main.js`.** `config.json` is read + `.bak`-copied pre-main; move unbounded rings/logs to a lazily-built separate store via a versioned migration.
- **Boot regressions pass CI green** — the tree-shake, mis-grouping, and config bloat all cleared typecheck + the unit suite. Guard the path with the import/bundle baselines (`eager-import-baseline.json`, `renderer-import-baseline.json`, `first-render-chunk-baseline.json`) and a packaged `perf:cold-start` run.

## Applies when

- Touching `vite.config.ts` `codeSplitting`/`advancedChunks` groups or a plugin mutating emitted chunk text, or seeing React/CodeMirror land in the eager entry closure or wrong vendor chunk.
- Gating any window or `WebContentsView` reveal on `dom-ready`/`ready-to-show` in `electron/window/createWindow.ts`, or debugging a blank-window flash at launch.
- Adding an `import "./x"` for its side effect only and finding the behavior missing when packaged but present in dev.
- Putting log/ring/audit/cache data into `config.json` or anything `electron/bootstrap.ts` reads synchronously, or diagnosing boot time that grows with usage.
