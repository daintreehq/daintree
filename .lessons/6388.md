## Context

`ActivityMonitor.onData` (`electron/services/ActivityMonitor.ts`) watches PTY output bytes to drive the agent working/idle (busy/waiting) state machine. PR #3200 added cosmetic-redraw classification (`isStatusLineRewrite`) so that spinner/status-line repaints would not spuriously escalate an _idle_ monitor to _busy_. It did this with an early `if (isCosmeticRedraw) return;` placed **before** the debounce-reset path.

## Problem

Long-running agents (Claude/Gemini "thinking" for tens of seconds) flipped to `waiting` mid-thought (#6365). During extended model thinking the only PTY output is spinner ticks (`\r⠙ Working…`, Ink cursor-up + erase-line frames). Those are cosmetic redraws, so the early return fired and the idle debounce counted down uninterrupted while the spinner was visibly still ticking — the agent looked alive on screen but the state machine declared it idle.

## Root cause

#3200 conflated "cosmetic redraw" with "no activity." The two are not the same: the same spinner byte stream means _don't escalate idle→busy_ (it's not new work) **and** _do stay busy_ (the agent is demonstrably alive). #3200's single early return collapsed both into "ignore entirely," so the busy-keepalive path never ran. The signal is asymmetric — its meaning depends on the current state, not just the bytes.

A second, subtler trap: once you want to count _real_ post-spinner output at a low byte threshold, raw `Buffer.byteLength(data)` over-counts. Agents emit per-frame protocol noise every redraw (DECSET toggles `\x1b[?25h/l`, OSC 0–9/133/633/1337 metadata, CPR `\x1b[r;cR`, DSR `\x1b[6n`, bracketed-paste markers). With a low `minBytes`, that noise alone would re-escalate idle→busy forever.

## Lesson

- Treat a cosmetic redraw as a **state-dependent** signal, not a no-op. When `state === "busy"`, reset the debounce timer for `isCosmeticRedraw || filteredLength > 0` (spinner ticks keep a busy agent alive); only _after_ that reset short-circuit on `isCosmeticRedraw` so it still can't escalate an _idle_ monitor. See the ordering at `ActivityMonitor.ts:553-557` — the busy-keepalive reset MUST precede the cosmetic early-return.
- To count "real" bytes at a low threshold, **strip known protocol noise first, then count the remainder** (`filteredLength`), and route that filtered count to every volume detector — never skip counting entirely. `filteredLength === 0` is the new "pure noise" early-return; pure protocol noise must NOT reset a busy debounce or it would pin the monitor busy until `MAX_WORKING_SILENCE_MS`.
- The stripper (`stripIdleTerminalSequences`, `electron/services/pty/IdleSequenceFilter.ts`) is stateless and **ReDoS-safe by construction**: every quantifier is bounded and the OSC terminator scan uses a negated class `[^\x07\x1b]{0,512}` instead of `.{0,N}` — a malicious PTY peer could otherwise force catastrophic backtracking. Spinner frames are deliberately NOT stripped here (cosmetic-redraw classification owns those, and they must stay valid liveness evidence).
- Alternation order matters in the OSC pattern: `1337` precedes `133` because JS regex picks the leftmost branch, not the longest — reordering would leave a stray `7`. Combined private modes (`\x1b[?25;2026h`) are stripped only when _every_ code is allowlisted, so unknown TUI modes stay observable.
- DEC mode `2026` (Synchronized Output) is intentionally in the noise list for the byte-volume path, but `TerminalProcess` passes raw PTY data to the headless terminal so `SynchronizedFrameDetector` still sees frame-close events (#6668) — don't remove 2026 assuming it's dead.

## Applies when

- Editing `ActivityMonitor.onData` or any of the busy/idle transition guards, debounce reset, or volume/high-output detectors in `electron/services/ActivityMonitor.ts`.
- Touching `stripIdleTerminalSequences` / `IdleSequenceFilter.ts` — adding a new "idle-noise" escape class, changing OSC/DECSET allowlists, or adjusting the bounded quantifiers (keep ReDoS bounds; never use `.*`).
- Agents report flipping to `waiting`/idle mid-thought while a spinner is still visibly ticking, or the inverse: a monitor pinned busy forever after the agent finished (pure prompt-redisplay protocol noise resetting the debounce).
- Lowering any byte threshold (`minBytes`, activation threshold) in `OutputVolumeDetector`/`HighOutputDetector` — verify protocol noise is filtered before the count so the lower threshold doesn't make idle-noise escalate state.
- Writing or interpreting any heuristic that uses raw PTY byte volume as a proxy for "work happening" — the strip-then-count rule and the cosmetic-redraw-is-liveness asymmetry generalize to notification triggers and other output-driven state machines.
