## Context

A "camera zoom" effect was needed in the main renderer. The natural Electron primitive is `webFrame.setZoomFactor`, and the obvious implementation animates it per-frame in a rAF loop to get a smooth zoom of the whole viewport. This PR removed that live-renderer zoom primitive entirely after it destroyed the xterm panes; the in-codebase example of the correct approach now lives in `DemoCursor.tsx`, which animates with CSS `transform: scale()` via the Web Animations API (`src/components/Demo/DemoCursor.tsx` — see the `scale(1)`/`scale(0.85)` keyframes).

## Problem

While the zoom animated, the terminal grid blanked, snapped resolution, and showed sub-pixel wobble. The effect looked fine on static DOM but destroyed the xterm panes specifically.

## Root cause

`webFrame.setZoomFactor` is Blink _page-level layout zoom_, not a compositor transform. Every value change forces a full style recalc + layout + paint, and — critically — it changes the renderer's effective device pixel ratio. xterm 6.0 renders through `@xterm/addon-webgl` (`src/services/terminal/TerminalWebGLManager.ts`), whose glyph TextureAtlas is keyed to DPR; a DPR change tears down and rebuilds the atlas. Animating zoom per-frame meant a full atlas rebuild _every frame_, hence the blanking and snap. This is distinct from `webview.setZoomFactor` (BrowserPane/DevPreviewPane), which zooms a separate guest WebContents and never touches the host renderer's xterm canvases. The fix removed the live-renderer zoom primitive entirely; a viewport zoom belongs in a CSS `transform: scale()` (compositor-only, never repaints content or perturbs DPR) or in post-production.

## Lesson

Never animate `webFrame.setZoomFactor` per-frame in a renderer that hosts xterm (or any WebGL/canvas content keyed to DPR). It is layout zoom: it relayouts the whole page and rebuilds the WebGL TextureAtlas on each step. For a smooth visual zoom of the _entire_ viewport, use a CSS `transform: scale()` (compositor-only, no relayout, no DPR change) or do it in post-production — `DemoCursor.tsx` is the live example of the correct CSS-transform approach. Reserve `setZoomFactor` for discrete, settled zoom-level changes, and keep it mentally separate from `webview.setZoomFactor`, which targets guest content and is safe to use for browser/dev-preview panes.

## Applies when

Adding any animated/transitioning zoom, focus-follow, presentation-mode, or accessibility-magnification feature to the main renderer; reaching for `webFrame.setZoomFactor` in a rAF loop; or debugging xterm grid blanking / resolution snap / glyph corruption that correlates with a zoom or DPR change.
