## Context

The perf harness (`scripts/perf/run.ts`, dispatched via the `REGISTRY` in `scripts/perf/index.ts` — `npm run perf ci|nightly`) gates each scenario against `scripts/perf/config/budgets.json`: absolute `p95Ms` budgets, `maxMetricValues` ceilings, `maxRegressionPct` against committed baseline files, a `criticalScenarios` list (PERF-001/011/020), and a `--compare` A/B arm against the merge-base. The suite is intentionally dormant in routine CI pre-1.0 (dormancy note in `ci.yml`), so nothing exercised the gate's failure paths day-to-day.

## Problem

Issue #10005: `perf:ci` and `perf:nightly` could exit 0 ("PASS") while enforcing nothing on exactly the scenarios the gate existed to protect. The misleading part was that the gate _looked_ alive — it printed warnings and reason strings, and the absolute `p95Ms` budgets technically applied — but those budgets were orders of magnitude looser than the baselines (PERF-020: budget 2500ms vs baseline 0.149ms), so a real regression in a critical startup/idle path would sail through green.

## Root cause

Six independent fail-open mechanisms, each individually reasonable-looking:

1. **The noise-floor exemption swallowed the entire protected set.** `MIN_REGRESSION_BASELINE_MS = 5` gated the percentage check on `baselineP95 >= 5` — legitimate intent, since percentage math on sub-millisecond timings is scheduler noise. But nobody checked the exemption against real data: all three `criticalScenarios` sit below 5ms (3.885 / 0.552 / 0.149ms), and 18 of 24 nightly scenarios did too. The filter meant to remove noise removed the whole signal. Fix: below the floor, critical scenarios fall back to an absolute-delta gate (`ABSOLUTE_REGRESSION_MS_FLOOR = 1`ms) instead of skipping.
2. **Undefined data skipped silently.** `baseline?.p95ByScenario?.[scenarioId] === undefined` bypassed the whole regression check — scenarios added after baselines were generated (PERF-033) were never gated. The one branch that noticed a missing baseline _file_ pushed a reason string but never set `failedBudget`, so the report showed the reason next to PASS. Failure state lived in two parallel channels (`reasons[]` + `failedBudget`) that desynced.
3. **`--compare` structurally could not fail.** `runBaselineArm` is an unimplemented stub returning empty aggregates (it still is today — the fix made this fail closed, not implemented the arm), so `computeComparisons` produced nothing and the run warned-and-passed. Separately, an unresolvable merge-base (shallow clone) also warned-and-continued. Now both fail closed whenever any scenario in the run carries a `comparison` budget.
4. **A/B regressions mutated a detached copy.** The regression path set `failedBudget = true` on `comp.head` — an object `computeComparisons` builds fresh, not the aggregate serialized into the summary/report. Exit code failed correctly, but every report showed `failedBudget: false`. The fix looks up the report-owned aggregate by id and mutates that.

Two numeric traps rode along: `NaN > maxValue` is always false in JS, so a non-finite p95 or metric passed every threshold (now `Number.isFinite` fails closed); and the old inline averaging divided each metric sum by the _total_ sample count, so a metric reported in 1 of 4 samples was diluted 4× toward zero and slipped under its ceiling (`averageMetrics` in `scripts/perf/lib/stats.ts` now divides by per-metric occurrence count). The structural fix enabling all of this: `evaluateScenarioBudget()` was extracted as a pure function into `scripts/perf/lib/gate.ts`, which is what made the 21 tests in `scripts/perf/__tests__/gate.test.ts` possible (the PR description claims 30; `npx vitest run scripts/perf/__tests__/gate.test.ts` currently reports 21).

## Lesson

- **When adding a threshold exemption to a gate, enumerate the real entries it exempts before shipping.** Here 100% of `criticalScenarios` fell under the 5ms noise floor, so the gate's core promise was void from day one. Prefer a fallback check (absolute delta) over a skip — an exemption should change _how_ you check, not _whether_ you check.
- **Every "can't check" branch must pick fail-open or fail-closed explicitly, keyed to criticality.** Missing baseline file, missing baseline entry, unresolvable merge-base, and empty comparison arm are four distinct branches; critical scenarios fail closed on each, non-critical warn. An implicit skip (optional chaining to `undefined`, early `continue`) is a decision nobody made.
- **Never carry pass/fail in two parallel channels.** A `reasons[]` push without setting `failedBudget` produced reports explaining a failure while claiming PASS. Compute both in one pure function and return them together — this is also the only shape you can unit-test by forcing a regression and asserting the gate trips.
- **Mutating a result object marks the report only if the report serializes _that object_.** `computeComparisons` returned detached copies; flags set on them were invisible in output while `failedScenarios` (exit code) diverged. When exit code and report disagree, look for a copy boundary between the live aggregate and what got mutated.
- **Numeric gates need `Number.isFinite` guards and occurrence-count averaging.** NaN silently passes every `>` comparison; sparse metrics divided by total sample count dilute toward zero under their ceilings.
- **A dormant gate rots open.** Nothing in routine CI runs this suite pre-1.0, so no failure path was ever exercised. If you touch the gate, run `npx vitest scripts/perf/__tests__/gate.test.ts` — and know that `--compare`'s baseline arm is still a stub that fails closed rather than a working A/B run.

## Applies when

- Touching `scripts/perf/run.ts`, `scripts/perf/lib/gate.ts`, `scripts/perf/lib/stats.ts`, or `budgets.json` — including adding a scenario (a critical scenario with no baseline entry now fails closed by design, not by accident).
- Writing or reviewing ANY verification gate script (size budgets, lint ratchet, `check:*` guards, CI shell steps) — audit every early-return, `undefined`-skip, and warn-and-continue branch for an implicit fail-open.
- Adding a noise floor, minimum-sample threshold, or "too small to measure" exemption to any check — first list which real entries it exempts.
- Diagnosing "the gate passed but the regression shipped", or a report/summary that disagrees with the process exit code.
- Implementing the real `runBaselineArm` (worktree-at-merge-base A/B arm) — the fail-closed guards in the `cli.compare` block of `run.ts` are what currently substitute for it.
