## Context

`panelStatusBuffer.ts` (added by an earlier commit, `6f2ba85a7`) coalesces high-frequency terminal activity/flow-status/held-duration writes into one `setState` per animation frame — a real win, since Zustand 5's notify loop fires synchronously per `setState`, collapsing N writes/frame into 1. But every flush still constructs a fresh `panelsById` object (new reference each frame while an agent streams). `SidebarContent`, `ContentDock`, and `DndProvider` are always mounted for the app's life and were each subscribed to `usePanelStore((state) => state.panelsById)` — the whole map, by reference.

## Problem

Issue #10908 diagnosed it directly: while any agent produces output, `panelsById`'s identity changes up to 60×/sec, and each of the three components re-ran its full derived-structure computation on every flush — `SidebarContent` looping every worktree to rebuild `panelStateByWorktree`, `ContentDock` recomputing `tabGroups`/`dockTerminals` over every panel id, `DndProvider` re-deriving its active-drag panel. A status change in ONE panel fanned out into O(worktrees)/O(panels) work app-wide, once per frame, for as long as any agent kept streaming — worktree/panel count is uncapped, so cost scales with session size, not with what actually changed.

## Root cause

A raw reference-identity subscription (`usePanelStore((state) => state.panelsById)`, no equality function) treats "the map object changed" as "something I care about changed." The buffer flush changes the map's identity every frame regardless of which fields moved, so any subscriber gating on that reference alone re-renders at the buffer's cadence, not at the cadence of the data it consumes. This is invisible in review because the subscription looks idiomatic Zustand — the bug is purely in the mismatch between what the buffer touches (`activity`/`flow`/`held`/`runtimeStatus` fields) and what the read side needs (agent state, visibility, dock membership, structural id sets), and nothing in the type system flags that mismatch.

The fix, per consumer, is the transferable part. `SidebarContent` extracted `sidebarPanelDerivation.ts`: flat-primitive `useShallow` selectors (`selectSidebarVisiblePanelIds`, `selectSidebarAgentStateByPanelId`, `selectSidebarFleetEligibleWorktreeById`) reading ONLY fields the buffer never writes, so `useShallow` bails on a pure-buffer flush — still iterating `panelsById` (not `panelIds`) to preserve counting a panel committed to the map before `panelIds` is revealed at spawn-batch flush (#9649). `ContentDock` replaced the whole-map read with a structural `${id}:${worktreeId}` signature list (`dockPanelSignature`) for the activity-agnostic `tabGroups`, plus a separate object-valued `dockTerminalsRaw` selector for the live chrome that needs current objects — both narrowed to `location === "dock"` so grid-agent churn never touches the dock. `DndProvider` dropped its subscription entirely, reading `usePanelStore.getState().panelsById` as a one-shot snapshot inside the `useMemo`, since drag start/end already re-key that memo via `activeId`/`activeData`.

## Lesson

- **For an always-mounted component reading a high-frequency Zustand store, never subscribe to the whole map by raw reference — use a narrow `useShallow` selector over only the fields you read**, and confirm those fields are ones the hot writer never touches by grepping its `set(...)` call for the field names.
- **A structural id-signature string (`${id}:${scopeId}`) makes a derivation re-run on membership/scope change but not on unrelated field churn**, when the derivation itself doesn't need live objects — used for the dock's `tabGroups`.
- **When a derivation genuinely needs live objects, keep the selector object-valued but scope its `useShallow` to the exact subset that matters** (`dockTerminalsRaw` narrows to dock-location PTY panels only) — conflating this with the id-signature case either under- or over-reacts.
- **Every `useShallow` selector that can return an empty collection needs a module-level stable empty constant** (`EMPTY_DOCK_SIGNATURE`, `EMPTY_ELIGIBLE_IDS`), not an inline `[]`/`{}` — otherwise "nothing matched" itself produces a fresh reference and `useShallow` never bails on the empty case.
- **A one-shot read inside a handler or a `useMemo` already gated by other deps doesn't need a live subscription — use `store.getState()`** (`DndProvider`'s drag-active-panel lookup) instead of subscribing and fighting the resulting churn.
- **Narrowing a selector can silently break an invariant the old whole-map read accidentally preserved** — the sidebar rollups deliberately kept iterating `panelsById` instead of `panelIds` to not regress the #9649 spawn-batch counting fix; check for load-bearing side effects before changing a selector's iteration source.

## Applies when

- Adding or reviewing a `usePanelStore((state) => state.panelsById)` (or any whole-map/whole-array) subscription in a component mounted for the app's lifetime (sidebar, dock, drag-drop provider, toolbar, global banners).
- Touching `panelStatusBuffer.ts` or any other rAF/batched-write buffer folding high-frequency events into one `setState` — check who subscribes to the object it replaces, not just who writes to it.
- Diagnosing renderer CPU/recompute churn that scales with "an agent is streaming output" or with worktree/panel count, especially when profiling shows cost concentrated in components not doing anything agent-specific.
- Writing a new derived-state selector against `usePanelStore` for a component that must stay reactive to structural changes but not per-frame activity/status noise.
- Reviewing any `useShallow` selector whose empty branch returns a literal `[]`/`{}` instead of a shared constant.
