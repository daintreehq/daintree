## Context

`gracefulShutdown` (`electron/services/pty/TerminalGracefulShutdown.ts`) sends a `/quit` slash command to an agent's TUI before killing the PTY, then watches the echoed output for the session-ID line (e.g. `claude --resume abc-123`) so the session can be resumed later. How the quit body and the trailing Enter (`\r`) are written to the PTY is governed per-agent.

## Problem

A prior fix (commit `acc38bd36`, "split quit command from Enter") changed the submit path to write the body, sleep `submitEnterDelayMs` (~200ms), then write `\r` separately — to stop Codex conflating the combined bytes as a paste. That async gap silently broke Claude: its Ink TUI never submitted `/quit`, the session-ID line was never echoed, and graceful shutdown resolved `null`, so Claude sessions could no longer be resumed. No shared test caught it because the fix was validated only against Codex's parser.

## Root cause

The two agent CLIs have **directly opposite** PTY-input requirements for the same body+Enter delivery:

- **Ink-based TUIs (Claude Code):** the slash-command parser only fires if the body and `\r` arrive in the same event-loop tick / same PTY write. Any non-zero gap is interpreted as deliberate slow typing, so the command never submits.
- **Ratatui-based TUIs (Codex):** read the PTY buffer atomically and conflate a single combined `body+\r` write as a _paste_, so they require the body and Enter as **separate** writes with a delay between them.

There is no single keystroke-delivery mechanism that is correct for both. A fix tuned to one agent's input parser is a latent regression for the other.

## Lesson

Treat PTY command-submission write-atomicity as a **per-agent capability**, not a global constant. The fix added `quitSubmitMode: "single-write" | "split-write"` to the agent capability schema (`shared/config/agentRegistry.ts`), defaulting to `"split-write"` (safe for Codex / readline CLIs); Claude is set to `"single-write"` (`shared/config/agents/claude.ts`). The shutdown path branches on it: `single-write` does `write(quitCommand + "\r")` and skips the inter-write liveness guard (there is no async gap to guard against); `split-write` keeps the body → delay → `\r` sequence plus the mid-flight `isAgentLive` re-check that aborts the trailing Enter if the agent demoted into a plain shell during the gap.

- When adding a new agent, classify its TUI framework (Ink vs Ratatui vs readline) and set `quitSubmitMode` deliberately — do not inherit the default blindly.
- Any change to how body+Enter are delivered to one agent's PTY must be re-validated against every other agent, because the correct mechanism inverts by framework.
- The `isAgentLive` liveness re-check only exists to cover the `split-write` async gap; it is unreachable for `single-write`, so don't assume that guard protects the single-write path.

## Applies when

- Adding or onboarding a new agent CLI (especially Ink/React-based or Ratatui/Bubble Tea-based TUIs) and wiring its graceful-shutdown / session-resume capture.
- Touching `TerminalGracefulShutdown.ts`, `submitEnterDelayMs`, `quitSubmitMode`, or any code that writes a slash command + Enter to an agent PTY.
- Debugging "session ID not captured" / "graceful shutdown resolves null" / "Claude session can't be resumed" / "`/quit` never submits" for one agent while another works.
- Fixing a paste-vs-Enter conflation bug for one agent — check whether the fix regresses agents with the opposite write-atomicity requirement.
