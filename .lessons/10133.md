## Context

The recovery banner system arbitrates ONE top-of-app global banner via `useGlobalBannerPriority()` (`GlobalBannerCoordinator` — the CLAUDE.md single-slot rule), and `useShouldSuppressLocalError(category)` demotes pane-local `backend-dependent` error banners (spawn/reconnect/restart failures in `TerminalPane`) while a global cause holds the slot — the rationale being "the user can't act on the pane error until the global cause clears." When the suppression hook was built (#9372), the priority hook was `useRecoveryPriority` with four recovery-only slots (`host-crash`, `watchdog-disabled`, `safe-mode`, `restore-confirmation`), so suppression was recovery-scoped by construction.

## Problem

After #9332 (issue #9182) consolidated ALL top-of-app banners into one priority slot, the union gained two advisory members — `github-token` (expired token, now `forge-token`) and `cloud-sync` (project in a Dropbox/iCloud folder). Both are reachable only while `backendStatus === "connected"`, yet either one now suppressed the pane-local spawn/reconnect/restart banners that carry the only recovery actions. `cloud-sync` persists until the user clicks "Don't warn for this project," so a terminal that failed to spawn could show nothing in the pane indefinitely while an unrelated folder warning held the slot. The misleading part: every piece looked individually correct — the hook's doc comment still asserted the (now false) recovery-only justification, and the test suite passed because it never imported the advisory stores.

## Root cause

`isSuppressedByGlobalCause` answered `case "backend-dependent": return true` for ANY non-null cause. That blanket `true` was a correct compression while the union held only recovery slots — but a boolean predicate over a union member produces no compile error when the union widens, unlike an exhaustive `switch` with a `never` check. #9332 widened `GlobalBannerSlot` from 4 recovery slots to 6 mixed slots; the suppression hook got re-pointed at the widened union in `baed9a185` (inside #9372), a mechanical post-rebase "update all references" commit that swapped the import from `useRecoveryPriority` to `useGlobalBannerPriority` without re-deriving what the predicate assumed about the union's semantics. The rename itself encoded the semantic shift — "recovery priority" became "global banner priority" — but nothing forced the consumer to notice.

A second, independent bug hid in the sticky-on/delayed-off machinery: suppression releases only after `LOCAL_ERROR_SETTLE_MS` (= `UI_DOHERTY_THRESHOLD`, 400ms) of sustained no-suppression, a tail that exists solely to absorb `backendStatus` flicker between `"recovering"` and `"connected"`. The tail was keyed on `rawSuppressed` going false, not on WHY — so when the backend recovered INTO an advisory-only cause (host-crash clears, `forge-token` takes the slot), the leftover timer kept the pane error hidden for another 400ms even though the fix already knew suppression shouldn't apply. #10133 scoped the tail to `cause === null` (`return rawSuppressed || (cause === null && held)`, plus an effect branch that drops `held` synchronously when `cause !== null`).

The structural fix is `SLOT_IS_RECOVERY: Record<Exclude<GlobalBannerSlot, null>, boolean>` — recovery slots suppress, advisory don't, and TS2741 makes an unclassified new slot a compile error. This has since proven itself twice in the current codebase: the `github-token` → `forge-token` rename (forge-provider abstraction) and the newly added `rosetta` advisory slot both flowed through the record and were forced to declare a classification.

## Lesson

- **Suppression of a local error is valid only when the global cause explains the local failure.** "Some global banner is active" is slot-occupancy, not causation — an advisory banner leaves the backend connected, so pane spawn/reconnect/restart errors remain independently actionable and must stay visible. Classify causes semantically (recovery vs advisory), never proxy on "slot non-null."
- **A boolean predicate keyed on a union silently keeps its old answer when the union widens.** `return true` for a whole category can't fail compile the way an exhaustive `switch` does. Encode per-member policy as `Record<Exclude<Union, null>, boolean>` so every future member is a forced decision — `SLOT_IS_RECOVERY` caught both the `forge-token` rename and the `rosetta` addition.
- **Mechanical post-rebase "update all references" commits are where semantic widening sneaks in.** `baed9a185` re-pointed the import across a rename that changed the type's meaning (recovery-only → mixed). After rebasing over a rename/consolidation, re-derive each consumer's assumption about the renamed symbol instead of just fixing imports.
- **Scope a sticky-off settle tail to the exact state it absorbs.** The 400ms tail exists for `recovering`↔`connected` flicker (true no-cause); a recovery→advisory transition is not flicker. A tail gated only on "suppression went false" over-holds across cause-type transitions — gate on `cause === null`.
- **Pin a suppression/demotion domain by enumerating every union member in tests.** The pre-#10133 suite covered recovery slots but never imported `forgeProviderHealthStore`/`cloudSyncBannerStore`, so the domain widened with zero red tests; #10133 added per-slot tests plus recovery→advisory and advisory→recovery transition tests as retrieval-proof pins.

## Applies when

- Adding a slot to `GlobalBannerSlot` or registering a banner in `GlobalBannerCoordinator` — you must classify it in `SLOT_IS_RECOVERY` (compile-forced) AND decide deliberately whether it should suppress pane-local errors.
- Writing or reviewing any predicate of the form "if some global condition is active, hide/demote a local signal" — notify routing, banner tier demotion, error dedup across surfaces.
- Rebasing a branch over a rename or consolidation of a shared type/hook and producing a mechanical "update references" commit.
- Diagnosing a pane-local error banner (spawn/reconnect/restart in `TerminalPane`) that never appears while any top-of-app banner is up, or reappears ~400ms late after recovery.
- Reviewing sticky-on/delayed-off timers built on `LOCAL_ERROR_SETTLE_MS`/`UI_DOHERTY_THRESHOLD` in multi-cause state machines — check what the tail is scoped to.
