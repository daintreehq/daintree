## Context

`KeybindingService` (`src/services/KeybindingService.ts`) is a plain non-React singleton holding the live keybinding map plus a listener set. Display hooks `useEffectiveCombo` / `useKeybindingDisplay` (`src/hooks/useKeybinding.ts`) surface the current combo for an action into React UI (shortcut labels, `aria-keyshortcuts`), re-rendering when the user rebinds.

## Problem

The hooks read the service via `useState(initial) + useEffect(() => subscribe(setX))`. That pattern was correct under React 18's fully-synchronous render but is unsafe under React 19 concurrent rendering: a render pass can be interrupted and resumed, and the `useEffect` subscription commits _after_ paint, so a mid-render mutation of the service can produce torn UI — one component painting the old combo while a sibling paints the new one during a rapid-rebind sequence.

## Root cause

React 19's concurrent renderer can interleave/restart renders, so any state derived from an external mutable source via `useState`+`useEffect` can read a value that's already stale by commit time. `useSyncExternalStore(subscribe, getSnapshot)` is the only API with a _tear-free snapshot contract_: React re-reads `getSnapshot` synchronously during commit and bails the render if it changed.

The non-obvious trap is in `getSnapshot`'s return identity. React compares consecutive snapshots with `Object.is`; if `getSnapshot` returns a **freshly-allocated object/array each call**, every check looks "changed" and you get an infinite render loop (`Maximum update depth exceeded`). Here it's safe for two specific reasons that must be preserved:

- `getDisplayCombo` / `getEffectiveCombo` return **primitive strings** — two equal strings are `Object.is`-equal regardless of when they're computed, so `formatComboForDisplay` recomputing the string on every call is fine. (The linked issue #7285 wrongly worried this needed a per-action string cache; primitives make caching unnecessary.)
- `getSnapshot` is `useCallback`-wrapped on `[actionId]` and `subscribe` is a **module-level constant** (`subscribeToKeybindings`), so neither identity churns across renders — a new `subscribe` identity each render would force `useSyncExternalStore` to resubscribe every render.

## Lesson

- When a hook **reads a value out of a non-React mutable source into render output**, use `useSyncExternalStore`, not `useState`+`useEffect`+`subscribe`. This is already the codebase default (~25 call sites).
- `getSnapshot` must return either a **primitive** or a **cached/reference-stable** value. Never return `{...}`, `[...]`, `.map(...)`, or `.filter(...)` computed inline — that is the infinite-loop footgun. If you must derive an object, memoize it in the store and invalidate on mutation, then return the cached reference.
- Keep `subscribe` reference-stable (module-level const or `useCallback`), and `useCallback`-wrap `getSnapshot` on its real deps; an unstable `subscribe` resubscribes every render.
- The boundary matters: `useEffect`+`subscribe` is still correct when the subscription **fires a side effect** (notifications, imperative listeners) rather than reading a value into render — see `useHibernationNotifications`, `useDiskSpaceWarnings`, etc. Don't blanket-migrate those.
- Independent of React: when a singleton notifies a fan-out listener set, snapshot with `Array.from(this.listeners)` before iterating and wrap each call in `try/catch` so one throwing/self-unsubscribing listener can't break propagation to the rest, and use a `Set` for O(1) add/delete.

## Applies when

- Adding or refactoring a React hook that reflects live state from a plain singleton/service (`KeybindingService`, an `ActionService`-style registry, a non-Zustand event emitter) into rendered UI.
- You see `useState(() => service.getX()) + useEffect(() => service.subscribe(setX))` in a hook — flag it as concurrent-unsafe under React 19.
- Debugging "Maximum update depth exceeded" or an infinite re-render right after introducing `useSyncExternalStore` — inspect whether `getSnapshot` returns a fresh object/array per call.
- Debugging torn or stale shortcut labels / `aria-keyshortcuts` that update inconsistently across components during rapid rebinding.
- Writing a fan-out listener/notify mechanism in a service and deciding the data structure and error isolation for the listener set.
