## Context

Terminal panes guard their xterm area with two layers of defensive event handling. `TerminalPane.handleXtermPointerDownCapture` suppresses stray pointerdowns on _unfocused_ grid panes (`shouldSuppressUnfocusedClick`) so a click that merely activates a pane doesn't poke at cursor positions or start a selection. `XtermAdapter`'s `attachCustomKeyEventHandler` intercepts certain keys before xterm forwards them to the PTY. Both layers were tuned for physical mouse/keyboard users.

## Problem

Two assistive-technology gaps. (1) When a VoiceOver/NVDA user routed the screen-reader cursor onto terminal output, the synthesized click was `stopPropagation`/`setPointerCapture`-swallowed by the unfocused-pane suppression, so cursor positioning silently failed for AT users. (2) PR #9004 then tried to fix keyboard trapping by intercepting Tab/Shift+Tab in the xterm key handler to escape the focus region — which broke shell and agent Tab-completion in _every_ terminal pane, and was reverted by #9082.

## Root cause

AT-synthesized pointer events are **indistinguishable from real clicks by their own properties** in Chromium 146: `isTrusted` is `true` and `pointerType` is `"mouse"`. The only behavioral tell is the _absence of a preceding `pointermove`_ — a physical pointer emits continuous moves immediately before a click; AT cursor routing fires a bare `pointerdown`. `isLikelyAtSynthesizedPointer(lastMoveAt, now, thresholdMs=100)` (`terminalFocus.ts`) infers this: it records the last `pointermove` `timeStamp` in `lastXtermPointerMoveAtRef` and treats a `pointerdown` with no recent move as AT-synthesized. When AT-synthesized, the handler activates the pane (`setFocused`) but must NOT `preventDefault`/`stopPropagation`/`setPointerCapture`, letting the event reach xterm for cursor positioning. Separately, Tab is not slack to repurpose in a terminal: it is core terminal input (HT / shell+agent autocomplete). The escape-region path already exists via F6/Shift+F6, so trapping Tab was redundant _and_ destroyed autocomplete — current live code in `XtermAdapter` deliberately `preventDefault()`s only the DOM/default focus-traversal path and returns `true` so xterm still emits HT for Tab and CSI Z for Shift+Tab, with `aria-keyshortcuts="F6 Shift+F6"`.

## Lesson

- Pointer-event suppression written for mouse users will silently break screen-reader cursor routing. AT clicks carry no distinguishing property; detect them by the missing-`pointermove` heuristic and let them through to xterm without `stopPropagation`/`preventDefault`/`setPointerCapture`.
- Do NOT repurpose Tab (or other core terminal keys) for app navigation inside a focused terminal — Tab is shell/agent autocomplete. Use F6/Shift+F6 for focus-region escape and leave Tab to emit HT to the PTY. When you must cancel a key's DOM/default side-effect (Tab focus traversal, bare F11 fullscreen accelerator), `preventDefault()`+`stopPropagation()` but `return true` so xterm still transmits the sequence — xterm v6 leaves handled keys uncanceled in screen-reader mode, so the DOM path otherwise leaks.
- Read xterm selection state (`terminal.hasSelection()`) synchronously _before_ any RAF-deferred focus handoff: xterm v6 clears selection on blur, and deferring the check let focus briefly land on the `ContentPanel` container, which screen readers announced instead of the target.

## Applies when

- Touching `src/components/Terminal/terminalFocus.ts`, `TerminalPane.tsx` pointer/click handlers, or `XtermAdapter.tsx`'s `attachCustomKeyEventHandler`.
- Adding any `stopPropagation`/`preventDefault`/`setPointerCapture` on terminal pane pointer events, or any new key intercept in the xterm custom key handler.
- Diagnosing reports that VoiceOver/NVDA can't position the cursor in a terminal, or that the screen reader announces a container instead of the focused element.
- Diagnosing broken shell or agent Tab-completion in terminals (regression smell: a key was repurposed for navigation/focus-region escape).
- Deciding focus-region escape keys for any xterm-hosting surface — prefer F6/Shift+F6 over keys with terminal meaning.
- Distinguishing AT-synthesized from physical pointer events anywhere in the renderer where `isTrusted`/`pointerType` look identical.
