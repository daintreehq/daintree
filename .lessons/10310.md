## Context

The pty-host `ResourceGovernor` reacts to V8 heap pressure with two blunt levers: `trimBuffers()` flattened EVERY terminal's headless scrollback to `SCROLLBACK_MIN` (100), and `engageThrottle` paused every terminal in one synchronous loop. Neither had per-terminal memory attribution — nothing knew which terminals actually held the memory. #10310 (resolves #9904) added that attribution and rebuilt the non-critical pre-pause reclaim around it.

## Problem

Under pressure the governor punished quiet terminals exactly as hard as chatty ones. A terminal holding 80 lines of scrollback got flattened to 100 alongside a 10 000-line agent — pure churn that destroyed history from terminals barely contributing to the pressure, while there was no signal (log, metric, or otherwise) identifying the real memory drivers. The docs even overstated the pause "runway" (idle-first / active-last ordering claims runway that doesn't exist — everything pauses in the same tick, microseconds apart).

## Root cause

This is a design lesson, and the enabling mechanism is a cheap closed-form estimate. An xterm headless buffer line is a `Uint32Array(3 × cols)` — 3 uint32s per cell (codepoint + fg attr + bg attr) — so `lines × cols × 12` bytes is each terminal's buffer footprint with NO serialization (`BYTES_PER_CELL = 12` in `ResourceGovernor.ts`; `getTerminalBufferSizes()` in `PtyManager.ts` reads `TerminalProcess.getCurrentScrollback()` and `cols || 80`). With that estimate the reclaim splits into two deliberately different shapes: the graduated warning/engage-band `performPrePauseTrim` ranks heaviest-first and trims only terminals strictly above `SCROLLBACK_MIN` down to the floor, leaving light terminals' history intact; the ≥95% critical path stays uniform-global (`trimBuffers()` flatten, no ranking, no estimator) because when the next allocation could OOM you can't afford selectivity. Uniform flatten is also the fallback when attribution isn't wired or the targeted call throws.

The subtle trap this PR's first cut left open: it ranked by the CONFIGURED scrollback CAP (`_scrollback`), not actual occupancy — a terminal capped at 10 000 but holding 40 lines estimates as huge and gets "trimmed" for nothing. A later PR (`a7ddd3027`, "restore memory governance across analysis worker isolation") fixed this by preferring ACTUAL `bufferLines` from fresh analysis-worker samples (`getActualBufferLines()`, `effectiveLines()`), falling back to the cap — so a mostly-empty high-cap terminal now contributes 0 and is excluded by the added `&& effectiveLines(s) > SCROLLBACK_MIN` guard. Cap is a ceiling, not a measurement.

## Lesson

- **Estimate xterm headless-buffer memory as `lines × cols × 12` — 3 uint32s per cell — never by serializing.** This is the canonical cheap attribution primitive in the pty-host (`BYTES_PER_CELL = 12`); reuse it for per-terminal ranking rather than serialized state, which only exists opportunistically at wake (`serializedStateBytes`) and is unavailable at pressure time.
- **Rank by ACTUAL occupancy (`bufferLines`), not the configured scrollback cap (`_scrollback` / `getCurrentScrollback()`).** The cap is a ceiling — a cap-10 000 terminal holding 40 lines has nothing to give, and ranking/trimming it is pure churn. The current code prefers fresh-worker `getActualBufferLines()` and only falls back to the cap; the strict `> SCROLLBACK_MIN` filter (not `>=`) excludes anything already at the floor.
- **Keep two reclaim shapes: attribution-based and selective for the graduated band; uniform-global for the ≥95% panic path.** Targeting belongs where there's time to be selective; at critical pressure ranking is overhead you can't pay and you want maximum reclaim now. Don't let a future "make it smarter" change drag attribution into the critical path.
- **The trim targets the headless analysis mirror, not the renderer's visible xterm scrollback** — flattening to 100 lines is invisible to the user and cheap; this is the same buffer #10948 later mis-protected. Know which buffer you're touching before deciding a trim is "destructive."
- **Keep the observability gauge pure and separate from reclaim.** `emitBufferMemoryGauge()` (`buffer-memory-gauge` metric) computes the same estimate but is warning-band- and metrics-gated and must NEVER mutate or trim; all reclaim lives in `performPrePauseTrim` behind the one-shot `trimAttemptedForCurrentPressure` flag.
- **This is the LIVE, surviving baseline — build on it, don't replace it.** #10948 layered tier-awareness on top (exempt `foreground` terminals) which inverted the intent into the self-defeating global-PTY-pause regression and was reverted WHOLE back to this design (`9adfb0b51`; see `10948.md`). Future work extends 10310's heaviest-first shape, it doesn't swap the filter predicate.

## Applies when

- Adding or changing per-terminal memory attribution / ranking in the pty-host — reach for `lines × cols × 12` and `getActualBufferLines()`, not serialization or the scrollback cap.
- Touching `performPrePauseTrim`, `emitBufferMemoryGauge`, `getTerminalBufferSizes`, `trimBuffersTargeted`, or `trimTerminalScrollback` in `ResourceGovernor.ts` / `PtyManager.ts`.
- Tempted to make the ≥95% critical reclaim "smarter" with ranking or estimation — that path is uniform-global on purpose.
- Estimating a terminal's memory from its scrollback cap — cap (ceiling) and actual occupancy (`bufferLines`) diverge wildly for high-cap idle terminals.
- Reviewing a change that exempts or reweights a terminal category in the trim path — cross-check `10948.md`; the last exemption (foreground) inverted the intent and shipped a regression.
