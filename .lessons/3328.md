## Context

The terminal wrapper div applies a CSS gutter (`pl-3 pt-3 pb-3 pr-3` in normal-buffer mode, stripped in alt-buffer for tight TUI fit) around the xterm canvas. When a user picked a custom terminal color scheme, the canvas background followed the scheme but the wrapper frame stayed on the app's static surface color (`bg-daintree-bg`), producing a visible rectangle of wrong-colored padding around the content.

## Problem

Any terminal color scheme whose background differed from the app surface color showed a mismatched frame around the terminal content. The instinctive fix — "just use xterm's built-in padding option so xterm paints the gutter with `ITheme.background`" — does not exist: xterm 6.0's `ITerminalOptions` has no `padding` field (verify: `node_modules/@xterm/xterm/typings/xterm.d.ts`). xterm only paints the cell grid; it has no concept of a gutter and cannot extend its theme background past the canvas.

## Root cause

CSS padding on the wrapper lives outside xterm's rendering surface entirely, so the wrapper's background must be kept in sync with the scheme manually. There is no native xterm hook to delegate this to — the gutter is ours to own. A static Tailwind background class can never track a runtime-selectable scheme.

## Lesson

Keep the gutter as CSS padding on the wrapper (xterm cannot render it), and drive the wrapper's `backgroundColor` from an inline style sourced from a store selector, never a static class. `XtermAdapter.tsx:637-644` reads `selectWrapperBackground` from `terminalColorSchemeStore` and applies `style={{ backgroundColor: wrapperBackground }}`. The selector (`terminalColorSchemeStore.ts:54`) resolves precedence — picker hover preview → app-theme preview → committed selection — and falls back to `var(--theme-surface-canvas)` for the default scheme or any missing background token. Padding stays gated on `!isAltBuffer` so TUI apps still fill the full space. Do not reach for an `ITerminalOptions.padding` option; it isn't there in 6.0.

## Applies when

Adding or restyling chrome around an xterm host (padding, rounded corners, gutter background), wiring a terminal color-scheme or theme picker, or reviewing any static `bg-*` / `padding-*` Tailwind class on the xterm wrapper that must track a runtime scheme. Also when someone proposes `ITerminalOptions.padding` to fill the gutter — it does not exist in xterm 6.0.
