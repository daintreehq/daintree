## Context

`WorktreeLifecycleService.substituteVariables()` (`electron/workspace-host/WorktreeLifecycleService.ts:1085`) expands `{{branch}}`, `{{endpoint}}`, `{{worktree_path}}` etc. into resource lifecycle command strings that are later run with `shell: true`.

## Problem

The substitution was raw string replacement: `return value != null ? value : match`. Configs are user-authored, so the trust boundary "feels" closed — but the _values_ are not all user-typed. Branch names, endpoints, and other interpolated fields carry collaborator-controlled data, so a branch named `feat/$(whoami)` or `main; rm -rf /` would execute as a subshell/chained command the moment the lifecycle command ran.

## Root cause

"The config is trusted" conflates the _template_ (user-authored) with the _substituted values_ (often collaborator-controlled, e.g. a branch name from a fetched remote). With `shell: true`, any unescaped metacharacter in a value is live shell syntax. Escaping is also not platform-uniform: `/bin/sh` is safe with single-quote wrapping (`'` → `'\''`), but `cmd.exe` _expands `%VAR%` even inside double quotes_, so Windows escaping must double every `%` to `%%` in addition to doubling `"`. A Unix-only escaper leaves a Windows env-var-expansion hole.

## Lesson

Shell-escape every substituted value at the interpolation site via `shellEscapeValue()` (`WorktreeLifecycleService.ts:1112`), branching on `process.platform`: Unix single-quote wrap, Windows double-quote wrap **plus `%` → `%%`**. The one deliberate exception is `{branch-slug}`, left unquoted only when it still matches its locked charset `/^[a-z0-9-]*$/`, with an escaping fallback if it somehow doesn't — never trust a "sanitized" field without re-asserting the invariant at use. Don't reason about injection at the trust boundary of the _config file_; reason about it at the boundary of each _value_, because the dangerous data rides in on individual fields.

## Applies when

Building command strings that run with `shell: true` (or any shell-interpreted spawn) by interpolating values — branch names, paths, endpoints, hostnames — into a template, especially in the workspace-host / lifecycle / recipe layer, on both `/bin/sh` and `cmd.exe`.
