## Context

#3243 replaced the single-lease `TerminalWebGLManager` (attach addon on focus, destroy on blur — which recompiled shaders on every focus switch) with a `Map<id, WebGLEntry>` LRU pool that kept a live context for every FOCUSED/BURST/VISIBLE terminal and evicted the least-recently-active when the pool hit Chromium's 16-context cap.

## Problem

The LRU pool was itself superseded by commit `7b0d1e312` ("replace LRU WebGL pool with hysteresis mode switch"). At 12-20 visible agent terminals the pool churned: contexts cycled out, fell back to DOM, got re-requested, and flashed — continuous visible jitter rather than a one-time cost.

## Root cause

Chromium hard-caps active WebGL contexts at 16 per renderer process and silently evicts the oldest on overflow (`webglcontextlost`, crbug 40939743). An in-renderer LRU pool was duplicating the exact eviction decision Chromium already makes one layer below — two evictors fighting over the same budget produces strobing reacquisition, not stability. Worse, a bulk Chromium eviction triggered BY over-subscription would re-request contexts immediately and re-trigger the same eviction, looping.

## Lesson

Don't run a per-context LRU evictor inside the renderer for a resource Chromium already caps and evicts. Make ONE coordinated decision for the whole fleet keyed on a count. Current `TerminalWebGLManager` runs in `"webgl"` or `"dom"` mode: when `wants.size` exceeds the upper threshold (`getWebglUpperThreshold()`, bootstrap default 18, resolved from a RAM-tiered ceiling and pushed by resource profile) it flips every terminal to DOM via a rAF-staggered release drain; when the count drops back to the lower threshold (bootstrap 15) it flips back, re-attaching every still-wanting terminal through the same one-per-frame drain. The hysteresis band (18/15 at bootstrap; ratio-derived per profile thereafter) stops a single panel opening/closing at the boundary from flapping the fleet. `attachWithLoadedAddon` has NO eviction branch — the mode switch guarantees the pool never exceeds the cap. Stagger both attach and release one-per-`requestAnimationFrame` so a burst never over-subscribes the context budget mid-flip (#7467). Chromium's default per-renderer cap is 16, but Daintree raises it (`max-active-webgl-contexts`, `electron/setup/environment.ts`) to a RAM-tiered ceiling of 24/28/32 via `getMaxWebGLContextCeiling` (`electron/utils/webglContextBudget.ts`), and the fleet-flip thresholds are resolved from that same ceiling (`resolveWebglThresholds`) so the raised cap and the guarding thresholds can't drift apart (#11192). On a real context loss, drop the pool entry but keep the `wants` membership and do NOT auto-requeue (auto-requeue re-triggers the eviction that caused the loss); let the next consumer event re-ensure. A circuit breaker (3 losses / 60s, burst-coalesced to one tick per frame so a single bulk GPU eviction isn't counted N times) disables WebGL for the session on persistent GPU faults.

## Applies when

Managing any browser-capped GPU resource (WebGL/WebGPU contexts) across many panes. If you're writing your own LRU eviction for something Chromium already silently evicts, you've built a second evictor that will fight the first — switch to a count-based mode flip with hysteresis instead, and pace allocation/release one-per-frame.
