## Context

Terminal panels are xterm.js instances that get reparented between DOM containers when focus changes (agent dock vs. grid layout). `TerminalInstanceService.attach()` appends the terminal's host element to a new container, then forces a repaint via `terminal.refresh()` and reveals once xterm signals it has rendered.

## Problem

Clicking an agent terminal to focus it caused a brief visual flash (~1 frame) in ~70-80% of cases. The terminal content momentarily went blank before rendering correctly.

## Root cause

The DOM element was made visible immediately on `appendChild`, but the xterm content was not refreshed until the next `requestAnimationFrame`. This created a one-frame window where the terminal container was visible but xterm had not yet repainted — producing a blank/white frame.

The issue was specific to the reparent path (agent dock ↔ grid transitions), not to terminals that stay in the same container.

## Lesson

**When reparenting a canvas-rendered element (xterm, WebGL), hide it until the renderer has repainted.** Set `opacity: "0"` immediately before `appendChild`, then clear it (`opacity: ""`) once xterm fires `terminal.onRender()` — a more reliable "has repainted" signal than a single `requestAnimationFrame`. Call `terminal.refresh()` after wiring the `onRender` disposable so the repaint is guaranteed to fire.

```ts
element.style.opacity = "0";
container.appendChild(element);
requestAnimationFrame(() => {
  const reveal = () => {
    element.style.opacity = "";
  };
  managed.attachRevealDisposable = terminal.onRender(reveal);
  managed.attachRevealTimer = setTimeout(reveal, 150);
  terminal.refresh(0, terminal.rows - 1);
});
```

**Use a safety timeout** (currently `setTimeout(reveal, 150)`) to restore visibility even if `onRender` never fires (e.g., if the tab is backgrounded or rAF is throttled). Without it, the terminal could remain permanently invisible.

**Reset opacity on early-return paths** (e.g., when the target element is null, or in `cancelAttachReveal`). Otherwise a prior `opacity: "0"` can persist if the attach is interrupted.

Using `visibility: hidden` instead of `opacity: 0` would also work but causes layout shifts; `opacity: 0` preserves layout.

## Applies when

- Reparenting xterm.js terminal elements between DOM containers
- Any canvas or WebGL element moved in the DOM that needs a repaint before display
- WebContentsView or offscreen rendering elements that need post-attach refresh
