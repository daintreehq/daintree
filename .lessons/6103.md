## Context

Every IPC handler return is auto-wrapped by `electron/setup/security.ts` (`wrapSuccess(result)` → `{ __daintreeIpcEnvelope: true, ok: true, data }`), and the preload's `_unwrappingInvoke` transparently unwraps it (the runtime envelope pattern from #3769). Handlers are registered through `typedHandle` / `typedHandleWithContext` in `electron/ipc/utils.ts` and `PlainHandler` / `ContextHandler` in `electron/ipc/define.ts`.

## Problem

A handler that signals failure by _returning_ a failure-shaped value (e.g. `{ ok: false, error }` or `{ success: false, error }`) gets nested inside the success envelope: the outer wrapper still reports `ok: true` with the failure object sitting in `data`. The renderer unwrapper sees `ok: true`, returns the inner object as success, and the failure is silently swallowed. The inner-envelope antipattern leaks discriminator shape into the transport layer and defeats the error channel entirely.

## Root cause

The fix is a pure type-level constraint, `ForbidIpcEnvelopeKeys<T>` (`shared/types/ipc/errors.ts`), wired into every typed-handler return position. It maps any return type containing an `ok` or `success` key to a branded `IpcHandlerEnvelopeViolation`, producing a tsc error at the registration site. Two non-obvious mechanics:

1. **The conditional must be written `T extends object ? ...` (distributive), not `[T] extends [object] ? ...` (non-distributive).** The tuple-wrapped form short-circuits the whole union when _any_ member is a non-object: `{ success: boolean } | null` (the real `webview:oauth-loopback` result) slipped through unbranded because `null` made the outer guard fail. The distributive form evaluates each union branch independently, so the brand attaches only to the offending object branch (`IpcHandlerEnvelopeViolation | null`). This was caught in Codex review before merge.

2. **The violation type carries its own remediation hint as a property name:** `interface IpcHandlerEnvelopeViolation { readonly "IPC handler must throw new AppError(...) instead of returning {ok|success: ...} — see #6020": never }`. Because the property is `never` and required, tsc emits `Property '"IPC handler must throw...see #6020"' is missing` — the fix instruction is the error message. A self-documenting compile error, no external lookup needed.

The 19 pre-existing violators are not migrated; each is parked with `// @ts-expect-error: ... See #6020.` so the backlog is grep-able. The contract: handlers signal failure by `throw new AppError(...)`, never by returning a failure-shaped value.

## Lesson

- IPC handlers must **throw** to signal failure, never return `{ ok: ... }` / `{ success: ... }`. The envelope is added by the transport, not the handler; returning a discriminator nests it and silences the error.
- When writing a type-level constraint that must reject a _property across all branches of a union_, use a **distributive** conditional (`T extends X ? ... : ...` with a bare type param). The tuple-wrapped `[T] extends [X]` form is non-distributive and will let `Violator | null | undefined` pass unchecked — the classic trap when results are nullable. Add a regression test for the `{ banned } | null` shape specifically (`shared/types/__tests__/ipcEnvelopeConstraint.test.ts`).
- For compile-time guardrails, encode the remediation as a required `never`-typed property whose **name is the human-readable fix instruction**. tsc surfaces the missing-property name verbatim, turning the type error into self-contained guidance.
- Land a sweeping type constraint behind `@ts-expect-error` markers tagged with the migration issue (`See #6020`) rather than blocking the PR on migrating every existing violator — keeps CI green and makes the backlog enumerable with one grep.

## Applies when

- Writing or reviewing a new IPC handler in `electron/ipc/handlers/*` — it must throw `AppError` on failure, not return `{ ok }` / `{ success }`.
- Touching `typedHandle`, `typedHandleWithContext`, `PlainHandler`, `ContextHandler`, or the `ForbidIpcEnvelopeKeys` / `IpcHandlerEnvelopeViolation` types in `shared/types/ipc/errors.ts`.
- Seeing a tsc error like `Property '"IPC handler must throw new AppError(...)..."' is missing` on a handler registration — the result type contains a banned envelope key; throw instead.
- Migrating any of the 19 `// @ts-expect-error ... See #6020` handler sites off the inner-envelope shape.
- Authoring any distributive vs non-distributive conditional type that must filter a key/property across a union, especially when members include `null` / `undefined` / `void`.
- Designing self-documenting compile-time guardrails (branded "violation" types) anywhere in the codebase.
