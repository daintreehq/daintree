## Context

Each terminal carries an activity tier (`"active" | "background"`) the renderer and pty-host must agree on. `TerminalRendererPolicy` computes it from focus/visibility and pushes it down via `terminalClient.setActivityTier(id, tier, pollingIntervalMs)`; the pty-host stores it in `TerminalProcess._activityTier` and can also rewrite it itself. This arc (#10266 this PR, #10284, #10285) fixed three tier-convergence bugs found together (#9911/#9906/#9894). Caveat: the tier then also gated a per-terminal suspend/wake/hibernation path (`TerminalWakeManager`, the stale-wake correction, the background hold-queue cap) torn out three weeks later by hibernation removal (#10811, `eb9cd64a7`). Today background terminals stream live and the tier only sets the headless **agent-state** poll cadence — but the explicit-value + broadcast-dedup convergence contract below is fully live.

## Problem

Visible-but-unfocused panes were stored as `"background"` on the host despite being on screen; the misclassification flowed through `terminalInfo` snapshots into hydration and (at the time) armed a spurious `needsWake=true`, firing needless `wakeAndRestore`/`reset()` on visible panes. Two companions were nastier: a rate-limited wake timer firing _after_ backgrounding left a hidden terminal streaming at full 50ms rate forever (#9906/#10284); a declined wake returned `true` and permanently cleared `needsWake`, killing all future resyncs (#9894/#10285).

## Root cause

All three violate one invariant three ways: **tier must be an explicit value that is broadcast and reconciled, never inferred from a co-transmitted parameter and never silently dropped.**

1. **Derived from a coincidental parameter (#10266, still live).** `setActivityMonitorTier(pollingIntervalMs)` computed `_activityTier = pollingIntervalMs <= 50 ? "active" : "background"`. Per the #8596 cadence contract a **visible-unfocused pane sends `("active", 200ms)`** (focused = 50ms, background = 500ms). Since `200 > 50`, every visible-unfocused pane was stored `"background"`. The fix threads tier as an explicit `"active" | "background"` argument through `TerminalProcess.setActivityMonitorTier(tier, pollingIntervalMs)`, `PtyManager.setActivityMonitorTier`, and both IPC handlers; the interval is now only a cadence hint.

2. **Same-tier host correction dropped by the renderer dedup (#10284's core, still live via #9778).** `TerminalRendererPolicy.setBackendTier` early-returns when neither tier nor polling changed — the renderer never re-sends a value it believes the host holds. So a _host_-side authoritative rewrite must broadcast `tier-changed` AND the renderer must re-seed `lastBackendTier` **without echoing back** (`ensureHostTierSubscription` → `initializeBackendTier` via `terminalClient.onTierChanged`), or the next genuine correction is dedup-dropped and the pane freezes. #10284 added this for the stale-wake case; that path is gone, but the identical trap recurred as **#9778/#8998** and the reconcile machinery survives.

3. **Fail-open decline (#10285, machinery deleted).** `wakeAndRestore` short-circuited alt-buffer panes with `return true`, permanently clearing `needsWake` — a decline reporting success suppresses all future retries. Fixed with a bounded retry loop; the code is gone, but the anti-pattern transfers.

## Lesson

- **Never derive a discrete state category from a coincidental numeric parameter that happens to correlate.** `_activityTier = interval <= 50ms` looked equivalent to the tier until #8596 added the 200ms visible-unfocused cadence and quietly inverted it. If two facts (tier and cadence) travel together, carry BOTH explicitly — one authoritative, one a hint; a `<=` threshold standing in for an enum is the smell.
- **A dedup baseline is a correctness hazard when a second writer changes the value out-of-band.** `setBackendTier`'s same-value early-return means the renderer won't re-send a tier it thinks the host holds — so any host-side rewrite MUST broadcast `tier-changed` and the renderer MUST reconcile `lastBackendTier` via `initializeBackendTier`/`onTierChanged` **without echoing back** (#9778, #8998, #10284), or you strand the pane.
- **A decline/skip on a resync path must never report success or clear the re-arm flag.** `return true` + `needsWake=false` on a declined wake (#10285) killed every future correction; declines return failure and leave the retry armed — only an applied snapshot clears the flag.
- **Verify blast radius against the CURRENT architecture, not the PR's.** This misclassification originally caused spurious wake/reset cycles — gone since #10811 removed the wake path. Today the same bug only slows the **headless agent-state poll** on visible panes (200ms → 500ms).

## Applies when

- Touching `setActivityMonitorTier`, `_activityTier`, the `set-activity-tier`/`wake-terminal` IPC handlers, or threading tier/cadence between `TerminalRendererPolicy`, `PtyManager`, `TerminalProcess`, and `pty-host/handlers/backpressure.ts`.
- Adding code where the pty-host rewrites a tier on its own (project switch, window connect/disconnect, recompute) — confirm it broadcasts `tier-changed` and the renderer reconciles `lastBackendTier` without echoing (#9778/#8998).
- Reviewing state inferred from a correlated numeric parameter (poll interval, timeout, debounce) standing in for an enum, or diagnosing a visible pane behaving as backgrounded (slow agent-state detection, wrong stream rate) or a same-value update that "does nothing" because a dedup/early-return swallowed it.
