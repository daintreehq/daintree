## Context

The content grid (`ContentGrid` / `ContentGridDefault` / `useContentGridContext`) lays panels out with CSS Grid and reflows them when the column count changes (panel added/removed, window resized, layout strategy switch). Each panel is a `SortableTerminal` — a dnd-kit `useSortable` item wrapping an xterm.js canvas/WebGL terminal. The goal was to make panels glide to their new cell instead of teleporting.

## Problem

Three independent traps stacked on the same elements:

1. A `transition: grid-template-columns ...ms` on the grid container animated the _track sizes_ but not the _items inside them_, so panels still snapped instantly to their new cell while the columns resized — a jarring teleport.
2. The naive fix — FLIP via framer-motion `layout="position"` — collided with dnd-kit, which also writes `style.transform` on the same node during drag, producing visible jitter as the two libraries fought over one transform.
3. Even with FLIP working, the xterm terminal canvas blurred mid-animation, and resize-sensitive CLIs (Codex) saw spurious SIGWINCH from fractional `getBoundingClientRect` reads during the slide.

## Root cause

- CSS grid transitions are scoped to grid properties; item position within the grid is not an animatable property, so track-size interpolation never moves the children. Position animation requires measuring old/new rects and interpolating a transform yourself — i.e. FLIP, which framer-motion's `layout`/`layout="position"` provides.
- dnd-kit and framer-motion both own `transform` on the sortable node. The split is: outer `m.div` owns the FLIP transform (`layout="position"` + `transformTemplate`), inner `div` holds the dnd-kit `setNodeRef` + drag `transform`. dnd-kit's own layout animation must be disabled via `animateLayoutChanges: () => false` (`SortableTerminal.tsx:69`) or it re-introduces the fight.
- Chromium (bug 40892376) blurs a canvas/WebGL subtree when an ancestor carries a _fractional_ CSS transform. framer-motion emits sub-pixel translations every frame, so a `transformTemplate` rounds x/y to integer device pixels: `translate3d(${Math.round(tx)}px, ${Math.round(ty)}px, 0)` (`pixelSnapTransform`, `SortableTerminal.tsx:13`). Separately, mid-flight rect reads produce fractional terminal dimensions and spurious SIGWINCH, so `suppressResizesDuringLayoutTransition` (`TerminalInstanceService.ts:721`) locks xterm resizes for the animation window and runs one corrective resize pass on unlock.

## Lesson

- To animate items reflowing within a CSS Grid, do NOT transition `grid-template-columns` — use FLIP (framer-motion `layout`/`layout="position"`). Grid transitions move tracks, not items.
- When framer-motion `layout` and dnd-kit `useSortable` apply to the same item, give each its own DOM node (outer motion wrapper, inner dnd-kit node) and disable dnd-kit's layout animation with `animateLayoutChanges: () => false`. Two libraries must never co-own one element's `transform`.
- Any FLIP/transform animation over an xterm canvas (or any WebGL/canvas subtree) must integer-snap the transform via `transformTemplate` to dodge Chromium fractional-pixel blur (bug 40892376).
- Lock terminal resizes for the FLIP window (`suppressResizesDuringLayoutTransition`) so mid-animation `getBoundingClientRect` doesn't fire spurious SIGWINCH at resize-sensitive CLIs; schedule a corrective resize pass on unlock since ResizeObserver won't retroactively fire. Guard the suppress call with `!isProjectSwitching && !isDragging` — the unconditional unlock would otherwise prematurely clear a drag-held lock if a drop crosses a column threshold.
- Keep CSS containment (`contain-layout contain-style`) on the inner div, NOT the motion wrapper — containment on the FLIP boundary scopes `getBoundingClientRect` and breaks layout measurement.

## Applies when

- Adding or changing motion on the panel grid: `ContentGrid`, `ContentGridDefault`, `ContentGridFleetScope`, `useContentGridContext`, `SortableTerminal`, `SortableDockItem`, `SortableWorktreeTerminal`, `DockedTabGroup`.
- Animating layout reflow with CSS Grid/Flex and finding items teleport instead of sliding.
- Combining framer-motion `layout`/`LayoutGroup`/`AnimatePresence` with dnd-kit on the same draggable element (jitter during drag, fighting transforms).
- An xterm/WebGL/canvas surface goes blurry during or after a CSS transform or animation — suspect fractional-pixel transforms (Chromium bug 40892376) and integer-snap with `transformTemplate`.
- Codex or other resize-sensitive PTY CLIs misbehave/redraw during a panel layout change — suspect spurious SIGWINCH from fractional rect reads; reach for `suppressResizesDuringLayoutTransition`.
- Touching `lockResize` / resize suppression timing around grid column-count changes, project switch, or drag drops (relates to #4170, #4467, #8597).
