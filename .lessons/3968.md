## Context

`ActivityMonitor` detects agent state via pattern matching (`PromptDetector`) and an idle timeout (`IDLE_DEBOUNCE_MS`, now 8s for simple-output agents / 4s otherwise). Pattern matching catches known prompt formats fast (500ms). Unknown formats fall through to the timeout, making agents appear stuck in "working" until it elapses.

## Problem

Pattern-based detection has an inherent blind spot: new agents, version updates, or natural-language clarifying questions (e.g., `"Which file should I modify?"`) never match configured patterns. The system had no catch-all mechanism — the only fallback was the idle timeout with low confidence.

## Root cause

The design correctly used pattern-first detection but had no intermediate heuristic layer. The idle timeout was conservative to avoid false positives, but this penalized all unrecognized prompts equally.

## Lesson

Implement a three-tier prompt detection hierarchy:

1. **Pattern match** — highest confidence, 500ms fast-path
2. **Stall + lexeme heuristic** — medium confidence (0.7) via `detectPromptLexeme()` in `electron/services/pty/PromptDetector.ts`, fires after `max(3000ms, IDLE_DEBOUNCE_MS)` of quiet if the last visible line matches a prompt lexeme (`?`, `:`, `y/n`, `[Y/n]`, etc.)
3. **Idle timeout fallback** — lowest confidence, `IDLE_DEBOUNCE_MS` (8s simple-output / 4s otherwise), all other cases

The lexeme heuristic is the pexpect/SWE-agent pattern: "output stall + incomplete line + prompt indicator." Key conditions to prevent false positives: it is gated behind `!effectiveWorkingPattern`, `!isSpinnerActive`, `!hasHighOutputActivity`, and `!hasRecentOutputActivity` so it never fires while output is still flowing or a working pattern is active. Always add the lexeme check AFTER existing pattern detection to avoid changing existing behavior.

## Applies when

Agents display novel prompt formats or clarifying questions that don't match configured patterns. Also relevant when tuning the balance between false-positive rate and detection latency.
