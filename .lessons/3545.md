## Context

When a user is typing a prompt in an agent terminal (directing state) and presses Enter, the state should immediately transition to working (prompt submitted). Previously it reverted to waiting first, causing a visible flicker.

## Problem

Pressing Enter in directing state reverted to waiting before transitioning to working, creating a brief wrong-state flash. The transition was not immediate.

## Root cause

The input path was not distinguishing Enter from regular keystrokes at the state controller level. The directing debounce would expire and emit waiting before the agent's response began triggering the working transition from the main process.

## Lesson

`Enter` in directing/waiting state is semantically different from all other keystrokes — it submits the prompt and should immediately emit `working` without waiting for the debounce. The detection lives in `TerminalListenerInstaller.ts` (the xterm `terminal.onKey` listener) and routes through `TerminalAgentStateController.onEnterPressed`, which clears the directing timer and emits `working` synchronously.

Two important distinctions for the Enter detection — both handled today via the DOM `KeyboardEvent` (`domEvent`) on `onKey`, rather than byte-level `onData` parsing:

1. **Plain Enter vs Shift+Enter**: Detect plain Enter as `domEvent.key === "Enter"` with no modifiers (`!domEvent.shiftKey && !domEvent.ctrlKey && !domEvent.altKey && !domEvent.metaKey`). Shift+Enter (a multi-line continuation) is excluded by the `!shiftKey` guard — at the byte level it surfaces as the Kitty Keyboard Protocol sequence `\x1b[13;2u`, but the `onKey` path keys off `domEvent.shiftKey` instead of parsing the escape sequence.

2. **IME composition guard**: CJK input methods may emit Enter to confirm a composition candidate, not to submit the whole prompt. The `!domEvent.isComposing` guard suppresses the transition while composition is active; the controller separately tracks `compositionCounts` per terminal.

The transition only applies to agent terminals (`managed.runtimeAgentId`) in the `waiting` canonical state — shell terminals are unaffected (see the early return in `onEnterPressed`).

## Applies when

Any agent terminal state controller that interprets user input. Whenever distinguishing Enter from other keys, account for modifier keys (Shift+Enter / Kitty Protocol modifier encoding) and IME composition state.
