## Context

Dock panels park offscreen and reveal inside a Radix popover on click (`DockedTerminalItem`, `DockedTabGroup`, hosted by `DockPanelOffscreenContainer`). The subtree is `ContentPanel` chrome + `TerminalPane` (own hook state) + `HybridInputBar`'s CodeMirror editor, plus an xterm canvas/WebGL context for terminals. The original design called `createPortal(content, portalContainer, key)` with `portalContainer` flipping between an offscreen slot and the popover's inner div, and a `MutationObserver` `migrated` signal to know when the host had landed before focusing.

## Problem

Every popover open/close (and every tab switch in an open dock tab group) fully unmounted and remounted the whole panel subtree — twice per cycle — despite code comments in both files claiming the portal existed "to prevent unmount/remount". `TerminalPane` lost local state (`isSearchOpen`, `dismissedRestartPrompt`) and CodeMirror was destroyed and rebuilt. The terminal only _appeared_ to survive because `terminalInstanceService` owns the xterm host and reattaches it imperatively — masking the remount while paying a double DOM hop, an opacity hide/reveal dance, and the MutationObserver focus-timing workaround.

## Root cause

React (react-dom 19.2, `updatePortal`) reuses a portal fiber only when `stateNode.containerInfo` is the _same element reference_. A stable `key` is NOT sufficient — when the container node changes, React deletes and recreates the portal fiber, remounting the whole subtree. Flipping `portalContainer` between offscreen slot and popover div therefore guaranteed a remount on every reveal/park, by construction.

The fix inverts the invariant: create **one permanent wrapper `<div>` per panel** (`wrappersRef`, made once in a layout effect) and make it the createPortal container _forever_ — `createPortal(content, wrapper, key)`. React never sees a container identity change, so the fiber (and all subtree state) is never torn down. To reveal/park, the wrapper **node itself** is relocated with `Node.moveBefore(wrapper, null)` — a Chromium 148 / Electron 42 API (stable since Cr133) that moves a connected node **atomically without resetting live browser state**: xterm canvas, WebGL context, focus, and iframe/media state all survive. A plain `appendChild`/`insertBefore` re-runs the browser's insertion steps and drops that state (fresh GL context, blanked canvas). The move being synchronous, the `migrated` MutationObserver collapses to a direct focus call; move and focus effects fire in declaration order, so the wrapper is in the popover before focus runs.

## Lesson

- **A stable portal `key` does NOT prevent remount — only a stable container node does.** React's `updatePortal` compares `containerInfo` by reference; swapping the `createPortal` second argument between two elements remounts the entire subtree (killing xterm/WebGL/CodeMirror/iframe state). For any park/reveal architecture, portal once into a permanent per-item wrapper and move that wrapper — never re-point the portal.
- **Relocate DOM subtrees with live browser state via `Node.moveBefore`, not `appendChild`.** `moveBefore` (Cr133+, in this Electron 42 / Chromium 148 build) is atomic and preserves WebGL contexts, canvas pixels, focus, playing media, and iframe state; the classic remove-and-insert path resets all of it. This is what lets a docked terminal survive reveal without a GL reinit.
- **Guard `moveBefore` and keep `appendChild` as the reconnecting fallback.** It throws `HierarchyRequestError` on disconnected/cross-document moves (e.g. while Radix tears down `PopoverContent`). The guard is `wrapper.isConnected && dest.isConnected && typeof dest.moveBefore === "function"` in try/catch, falling back to `dest.appendChild(wrapper)` — the `typeof` probe also covers `moveBefore` being absent from the TS DOM lib here.
- **`moveBefore` preserves focus; `appendChild` does not — and Cr148 can drop a focused field's selection on move.** Capture `hadFocus`/`active` before the move and restore focus on the fallback path.
- **Depend on the scalar `activePanelId`, never the `activePanel` object, in the move/focus effects.** Agent-state polling mints a fresh panel object every poll; using the object as a dep re-fires the move and yanks focus back into the terminal while the popover is open (`DockedTabGroup` switched to scalar deps for exactly this).
- **Parking a focused pane must `active.blur()` it (follow-on #11133).** The offscreen container is `aria-hidden` + `content-visibility: hidden`; a focused element left inside is invisible but still eats every keystroke ("typing into a pane that isn't there"). On park, blur and let the store reconcile `focusedId` onto a visible pane; on reveal, re-ask via `focusPanelInput(panelId)`.

## Applies when

- Building any panel park/reveal, dock, or offscreen-hosting flow on `createPortal` that needs the subtree (terminal, editor, iframe, media) to keep live state across the move.
- Diagnosing why a docked/popover terminal reinitializes WebGL, blanks its canvas, resets CodeMirror, or loses `TerminalPane` local state on open/close or tab switch — suspect a changing portal container before app-side pooling code.
- Touching `DockPanelOffscreenContainer.tsx` (`moveToDestination`, `wrappersRef`), the `DockedTabGroup`/`DockedTerminalItem` move/focus effects, or `dockPanelPortalContext.ts`; or reaching for `appendChild`/`insertBefore` to relocate a node owning GPU/canvas/focus state (prefer `Node.moveBefore` with the `isConnected` + try/catch fallback, Chromium-133+ only).
