## Context

#9564 added the `daintree://` URI scheme (`plugin/install?url=…`, `plugin/open?id=…`) deep-linking into the Plugin Manager. OS registration is `electron-builder.config.cjs` `protocols` (CFBundleURLTypes / NSIS HKCU / x-scheme-handler) plus `registerDeepLinkProtocolClient()` in `electron/setup/protocols.ts`. The hard part was not the parsing — it was delivering a one-shot OS event to a React subscriber deep inside a cold-launching Electron app without ever dropping it.

## Problem

A deep link arrives via three OS-specific paths with wildly different timing: macOS fires `app.on("open-url")` during early startup (before `app.whenReady()` resolves on cold launch); Windows/Linux put the URL in `process.argv` on cold launch and in the `second-instance` `commandLine` on warm launch (main.ts holds `requestSingleInstanceLock`). The naive design — register handlers in the ready chain, `webContents.send` after window creation — silently drops the intent at several distinct points, and each drop only reproduces on a slow cold launch, making it look flaky rather than structural.

## Root cause

Three independent gaps, each requiring its own buffer, because no single signal spans them.

Gap 1, OS→main: on macOS a listener added inside `whenReady` misses cold-launch `open-url`. `electron/setup/deepLinkUrlQueue.ts` registers the listener synchronously at module load (with `event.preventDefault()` — Chromium may otherwise navigate the focused window to the URI) and queues URLs until `activateDeepLinkHandler` installs the live consumer. It is a deliberately lightweight module (no `app.getPath` side effects) side-effect-imported by `environment.ts` — main.ts's first import — AND listed in `package.json` `sideEffects` so bundlers can't tree-shake the import away. `activateDeepLinkHandler` installs the consumer BEFORE draining the queue, so an event arriving mid-drain can't land in an already-snapshotted queue.

Gap 2, main→renderer: main holds `pendingIntent` until the primary view reports first paint (`CHANNELS.APP_VIEW_PAINTED` → `notifyAppViewPainted`). But the paint signal is sent from the Suspense parent, which renders BEFORE `AppInner` — the component owning the subscription — mounts past its `app:boot` gate. So even a paint-gated send can arrive with zero subscribers. The fix is the preload replay buffer in `electron/preload.cts` (`_eventBusReplayable` / `_eventBusBuffered`): an `events:push` envelope with no subscriber is buffered and replayed to the first subscriber of that name.

Gap 3, subscriber→hydration: `usePluginDeepLink(isStateLoaded)` subscribes unconditionally on mount (so the listener is live before paint) but buffers the intent in a ref until `isStateLoaded` — opening the Plugin Manager against unhydrated panel/plugin stores races (#8465 precedent).

Supporting invariants: painted-ness is revoked on `did-start-loading` and `destroyed` (reload or teardown means "painted" must be re-earned); `deliver()` clears `pendingIntent` only on confirmed send, so a teardown race re-queues instead of dropping; delivery targets the primary window only (lesson #9533) — a non-primary view painting first leaves the intent queued.

## Lesson

- **macOS `open-url`/`open-file` listeners must attach at module scope on the earliest import path, in a side-effect-safe module.** The pattern is `deepLinkUrlQueue.ts`: tiny module, synchronous `app.on` at load, queue-until-consumer, imported for side effect by `environment.ts` and declared in `package.json` `sideEffects`. A listener registered in the `whenReady` chain silently loses cold-launch URLs — and only on macOS, since Windows/Linux use argv/`second-instance` instead.
- **A "renderer has painted" signal does not mean "the subscriber is mounted".** Paint fires from the Suspense parent before `AppInner` passes its `app:boot` gate. Any main-originated one-shot event whose subscriber lives behind Suspense or a hydration gate needs the preload replay buffer: add the event name to `_eventBusReplayable` in `electron/preload.cts`. The buffer only works because `_ensureEventBusWired()` runs eagerly at preload module load — when it was lazy, catching a pre-subscriber event depended on some unrelated hook having subscribed first (fixed in #11280).
- **Choose replay semantics per event, explicitly.** Deep links are latest-wins at every stage (a newer user action supersedes an unconsumed older one); `.dntr` archive-install intents (#11280) are one-decision-per-file and use FIFO via `_eventBusFifoReplay`. Collapsing a FIFO-shaped event to latest-wins silently drops user actions; replaying a stale high-frequency state event is equally wrong — only single-shot, low-frequency signals belong in the replayable set (`window:disk-space-status` joined it in #9769).
- **Main-side "ready to receive" bookkeeping must be revocable and delivery must be confirmed.** Revoke painted-ness on `did-start-loading` (reload = listener gone), clear the pending intent only when `webContents.send` actually succeeded, and target the primary window exclusively. New OS-ingress queues should reuse this bookkeeping via `registerPaintedFlushListener` (how #11280's archive queue shares it without an import cycle) rather than duplicating paint tracking.
- **A deep link is fully attacker-controlled input — any web page can fire one.** `parseDaintreeUrl` fails closed on scheme, host (`plugin` only, so future hosts opt in explicitly), path, and payload: the nested install `url` must parse as `http(s)` (rejects `javascript:`/`file:`/nested `daintree:` pre-fill), plugin ids must match `SCOPED_PLUGIN_NAME_PATTERN` (now in `electron/schemas/pluginIdentifiers.ts`; it was `schemas/plugin.ts` at merge time). Installs still route through `handleInstallFromUrl`'s confirm + SSRF/size gates — a deep link may only pre-fill, never install. Log echoes truncate at 200 chars; `app.setAsDefaultProtocolClient` is gated on `app.isPackaged` so dev/E2E builds don't hijack the user's Launch Services / XDG handler database.

## Applies when

- Adding any new OS-ingress path — a new `daintree://` host, a file association, a protocol handler — that must reach the renderer: reuse the `deepLinkUrlQueue` early-listener pattern, `registerPaintedFlushListener`, and the preload replay buffer instead of a bare `webContents.send`.
- Adding a main→renderer one-shot event whose React subscriber mounts behind Suspense, `app:boot`, or an `isStateLoaded` gate — decide latest-wins vs FIFO and register it in `_eventBusReplayable` (+ `_eventBusFifoReplay` if FIFO).
- Diagnosing "works when the app is running but drops on cold launch" for deep links, file opens, or any startup-time push event — check which of the three gaps swallowed it before assuming flakiness.
- Registering `app.on("open-url")` or `open-file` anywhere, or touching `electron/setup/environment.ts` import order / `package.json` `sideEffects`.
- Touching the preload event bus (`_ensureEventBusWired`, `_eventBusOn`) — eager wiring and the no-subscriber buffering branch are load-bearing for every replayable event.
