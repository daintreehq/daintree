## Context

Production builds must not ship E2E backdoors: `scripts/build-main.mjs` uses esbuild `define` to replace `process.env.DAINTREE_E2E_*` reads with `""` so the minifier dead-code-eliminates the gated branches, and the hard CI gate `scripts/ci/check-preload-backdoors.mjs` (#9148, runs after `npm run build`) scans compiled output for forbidden strings. Issue #10026 found the gate structurally leaky; #10091 rebuilt it. Companion #10087 (issue #9915) fixed the renderer side, which the bundle scan never covers.

## Problem

The gate stayed green while backdoors shipped. It scanned only `dist-electron/electron/preload.cjs`, so main-process backdoors like `DAINTREE_E2E_SIDELOAD_PLUGIN_DIR` (read in `PluginService`, can silently redirect the user-plugin root in prod) were never verified, and three flags (`DISABLE_CACHED_VIEW_CPU_THROTTLE`, `CRASH_DUMPS_DIR`, `DEFER_RENDERER_LOAD`) were neither stripped nor checked. In the renderer, store-mutating globals in `App.tsx`, the `E2EFaultInjector` mount, and ~12 `TerminalInstanceService` globals — including `__daintreeReadTerminalBuffer`, which exposes full terminal scrollback (even WebGL-rendered text that never reaches the DOM) — attached unconditionally in every production session.

## Root cause

Three hand-maintained lists — the gate's `FORBIDDEN` strings, the `build-main.mjs` define keys, and the actual `process.env.DAINTREE_E2E_*` reads in source — mirrored each other with no cross-check, so every new E2E flag was a fresh chance to update one and not the others; three divergences had accumulated silently.

Two sharper mechanisms hid underneath. First, esbuild `define` rewrites only the literal member expression `process.env.NAME` — `shouldDeferRendererLoadForE2E(opts: { env })` reading `opts.env.DAINTREE_E2E_DEFER_RENDERER_LOAD` (an injected-env signature written for testability) evades the rewrite entirely, so the flag stays live in production even when its define key exists. #10091 rewrote it zero-arg reading `process.env` directly; tests use `vi.stubEnv` instead of injection. Second, the build uses `splitting: true`, so a stripped branch can be emitted into a shared `chunks/*.js` — scanning one file structurally misses hits.

The fix made drift fail CI rather than asking authors to remember: `STRIPPED_BY_BUILD` is exported and spread into `FORBIDDEN` (one source, not two), and a policy-sync test in `check-preload-backdoors.test.mjs` reads `build-main.mjs` source at runtime, regex-extracts its `process.env.DAINTREE_E2E_*` define keys, and asserts set-equality with `STRIPPED_BY_BUILD`. `runGate()` scans every `.js`/`.cjs` under `dist-electron/electron/` recursively and returns `{ ok, errors }` instead of calling `process.exit`, keeping the logic unit-testable.

## Lesson

- **Two hand-maintained lists that must mirror each other WILL drift; the cure is a test that derives one from the other's source at runtime.** The sync test parses `build-main.mjs` with `/["']process\.env\.(DAINTREE_E2E_[A-Z0-9_]+)["']/g` and asserts equality with `STRIPPED_BY_BUILD`. Proof it works: later commit `dfa5ca709` added `DAINTREE_E2E_WORKSPACE_LOAD_DELAY_MS` and was forced to update both in lockstep. The regex itself needed hardening (`d9f6daf11`: match both quote styles — a formatter flipping quotes silently blinds a single-quote parse).
- **esbuild `define` only rewrites literal `process.env.NAME` — any alias defeats the production strip.** A DI-style signature (`opts.env.NAME`), destructuring, or a `const env = process.env` alias keeps the backdoor live in prod despite a correct define key. New `DAINTREE_E2E_*` reads in main-process code must be direct literals — today they live as getters in `electron/setup/runtimeFlags.ts` (e.g. `getIsE2EDeferRendererLoad()`), which read `process.env.NAME` literally; test them with `vi.stubEnv`, never injected env.
- **Scan every emitted bundle, not the entry file.** `splitting: true` places code in shared chunks; `collectMainBundles` recurses `dist-electron/electron/**/*.{js,cjs}`. Missing-file checks must derive from the same dir the scan uses (the `d9f6daf11` fix) or a custom dir validates one tree and scans another.
- **The bundle scan does not cover the renderer — renderer backdoors need the runtime gate `window.__DAINTREE_E2E_MODE__ === true` (strict, not truthy).** #10087 gated the `App.tsx` globals, `E2EFaultInjector` mount, and the `TerminalInstanceService` globals; tests assert `'true'`/`1`/`false` do NOT pass. Gating never breaks suites — `e2e/helpers/launch.ts` always sets `DAINTREE_E2E_MODE=1`. Any new `window.__*` test seam attaching outside this gate ships to production.
- **A string scan goes blind where DCE can't delete the branch.** The preload later gained argv-based activation (`--daintree-e2e-mode`, not statically false in prod), so its `__DAINTREE_E2E_*__` key literals would survive and trip the gate — `preload.cts` now builds them via `e2eGlobalKey()` string-join, which keeps the gate green but means the `!isPackagedBuild` runtime check carries that surface, not the scan. Know which protection actually covers each surface before trusting the green gate.

## Applies when

- Adding any new `DAINTREE_E2E_*` env flag or `window.__daintree*` test seam — it must be a literal `process.env` read (or `runtimeFlags.ts` getter), appear in the `build-main.mjs` define block, and renderer globals must gate on `__DAINTREE_E2E_MODE__ === true`; the sync test fails CI until `STRIPPED_BY_BUILD` matches.
- Touching `scripts/ci/check-preload-backdoors.mjs`, `scripts/build-main.mjs` defines, or `electron/setup/runtimeFlags.ts`.
- Refactoring env reads for testability — an injected-env or aliased signature silently defeats the esbuild strip; use `vi.stubEnv` instead.
- Reviewing any CI gate whose allowlist mirrors a build config, codegen output, or registry by hand — ask where the sync test is that parses the source of truth.
- Assuming a green string-scan gate proves absence — verify DCE can actually delete the branch (argv-activated paths can't be stripped) and that the scan covers the bundle the code lands in (split chunks, renderer assets).
