## Context

Voice input biases live transcription toward project vocabulary: `assembleKeyterms()` (`electron/services/voiceContextKeyterms.ts`) merges the user's custom dictionary, project name, git-branch tokens, and identifiers scraped from terminal output into a priority-ordered term list. Two streaming providers consume it differently — Deepgram nova-3 via URL query params on the WebSocket upgrade, OpenAI realtime via `transcription.prompt` in `session.update`. #9753 (issue #9743) wired the assembler into session start, rebased on sibling #9757 (issue #9744, merged 18 minutes earlier) which it generalized beyond Deepgram-only.

## Problem

The custom dictionary users manage in voice settings had zero effect on live transcription. `assembleKeyterms()` was fully implemented and unit-tested but had no callsite — the only dictionary consumer was the post-transcription correction pass, which partially masked the gap because corrections still landed. The wiring had been parked behind a TODO in `OpenAITranscriptionProvider` referencing #7832, which closed without the wiring ever landing. All tests green, feature dead.

## Root cause

Three independent mechanisms shape the fix, each a transferable trap.

**Latency invariant:** the renderer (`VoiceRecordingService`) starts streaming PCM before the `voice-input:start` IPC resolves, and audio only buffers once a provider instance exists (`PRE_CONNECT_BUFFER_MAX = 100` chunks / 150KB inside `DeepgramTranscriptionProvider`). Assembly costs up to ~1s (two `ASSEMBLY_TIMEOUT_MS = 500` reads: git branch + terminal snapshots — made concurrent via `Promise.all` in this PR, halving worst case). Awaiting it before provider setup drops leading speech unrecoverably. So `handleStart` fires `keytermsPromise` concurrently with subscription/provider setup and awaits it only just before `svc.start()`, freezing the list into the settings snapshot (`VoiceInputSettings.keyterms`, runtime-only via `RUNTIME_ONLY_VOICE_FIELDS`) — also why both providers' reconnects reuse the same list without re-assembly.

**Supersession window:** every await in the start path is a window where a stop or a replacing start can land, guarded by a module-level monotonic nonce (`voiceStartNonce`, bumped on every start AND inside `handleStop`) — a pairing that predates #9753 (sibling #9757's `ac21e7fd9`, merged 18 minutes earlier, for the Deepgram-only path). #9753's real change: making assembly concurrent-and-late-awaited moved the bail-check (`voiceStartNonce !== myNonce`) from before any subscription existed to after the loser had already set up its own `unsubscribe`/`activeEventUnsubscribe`/`activeDestroyListener` — turning a free bail into one needing self-cleanup, identity-guarded (`activeEventUnsubscribe === unsubscribe`, `activeDestroyListener?.fn === onDestroyed`), so the loser never touches the shared globals the winner already reset via `cleanupActiveSubscription()`. This landed in the first commit (`b26590a87`); the second (`18dfdf60c`) is test-only, adding coverage rather than a fix.

**Deepgram nova-3 param trap:** the legacy `keywords` param (common in older docs/examples) 400s on nova-3, failing the WebSocket upgrade itself — the whole session dies, not just the boosting. Correct form: repeated `keyterm=` params in `buildUrl()`. Hard limits are 100 terms / 500 aggregate tokens (syllable-based tokenizer, ~5 tokens/word — term count alone doesn't bound tokens) and >100 chars/term. Any violation kills the connection, so the code defends in three layers: `MAX_KEYTERM_LENGTH = 100` at assembly (dedup AFTER capping, since capping can newly collide terms), `truncateKeytermsForUrl()` at the wire (`MAX_DEEPGRAM_URL_KEYTERMS = 50` / 3000 chars — its comment calls this "tighter than assembly's `MAX_KEYTERMS` (96)", but that's stale: `1e87059d4` lowered `MAX_KEYTERMS` to 50 pre-merge, so both caps are 50, a redundant backstop rather than a real tightening), and #9757's one-shot 400-retry that strips keyterms, distinguishing 400 (overflow) from 401 (bad key) via `res.statusCode`.

## Lesson

- **Any new await in `handleStart` (`electron/ipc/handlers/voiceInput.ts`) must be concurrent-fired and late-awaited, never serial-before-provider-setup** — the renderer streams PCM immediately and only a live provider buffers it, so serial pre-start latency eats leading speech with no recovery. Kick off the promise early, await just before `svc.start()`.
- **Don't assume a guard is new just because a PR's diff touches it — grep for what already exists first.** The `voiceStartNonce` bump-on-stop predates #9753 (sibling #9757 already had it); what #9753 actually added was identity-guarded self-cleanup on the bail path, made necessary by reordering the assembly await later. Reordering an await for latency can silently turn a free bail into a stateful one — re-audit every consumer of the reorder, not just the happy path.
- **Deepgram nova-3 keyterm boosting: repeated `keyterm=` params, never the legacy `keywords` param — `keywords` 400s the WS upgrade and kills the whole session.** Any param-level mistake is session-fatal, so keep all three defense layers when touching keyterm sources: 100-char per-term cap at assembly (dedup after capping), 50-term/3000-char wire truncation, one-shot strip-keyterms retry on 400 (not 401).
- **#9753's own OpenAI wiring was a live landmine, not the safe no-op it assumed.** It spread `formatKeytermPrompt()` unconditionally into `session.update`, believing `gpt-realtime-whisper` silently ignores `transcription.prompt`. It doesn't — the GA Realtime server hard-rejects any `prompt` field and kills the session, so every OpenAI voice session with non-empty keyterms broke until `83c9d2e49` (9 days later, direct to develop) added `MODEL_SUPPORTS_PROMPT = false` to gate it. Verify a field is truly a no-op — check the actual error response — before wiring it unconditionally.
- **A fully-tested subsystem can still be dead code — grep for production callsites, not test coverage.** `assembleKeyterms()` had 100% green tests and zero callers; a partial consumer (correction pass) masked the gap, and its TODO's tracking issue (#7832) closed without the wiring landing.

## Applies when

- Adding any async work (settings reads, git/terminal probes, network) to voice session start in `electron/ipc/handlers/voiceInput.ts`, or reviewing awaits inside `TranscriptionProvider` implementations (the #4850/#4851 session-id re-check family).
- Touching `DeepgramTranscriptionProvider.buildUrl`, keyterm caps, or upgrading/changing the Deepgram model — re-verify param names and limits against current nova-generation docs, not legacy examples.
- Diagnosing "custom dictionary doesn't affect transcription", dropped leading words in dictation, or Deepgram sessions that fail to connect at all (HTTP 400 on the upgrade).
- Writing any IPC handler where async pre-start assembly can interleave with stop/restart — the nonce + identity-guarded-cleanup pattern here is the canonical shape.
- Auditing a feature that "exists" in the codebase — confirm the assembler/service actually has a production callsite before assuming it runs.
