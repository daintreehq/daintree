## Context

Terminal scrollback is persisted to a `.restore` file via a debounced write owned by `SessionSnapshotter` (electron/services/pty/SessionSnapshotter.ts). Hibernation (and app-quit) kill idle PTY processes to reclaim memory, then reconstruct them on demand using the last snapshot.

## Problem

Hibernation silently discarded scrollback. Users who returned to a hibernated terminal saw an empty buffer, even though the persistence system "worked" and the `.restore` file path was known.

## Root cause

Two bugs compounded. First, `kill()` cancelled the pending debounce timer (correctly freeing resources), so the most recent output never reached disk. Second, the persist path was guarded by `wasKilled === false` — so even manually persisting after kill was a no-op. The `wasKilled` guard was originally intended to prevent writes after the process exited naturally, but it also blocked the pre-kill flush path. Net result: the last in-memory state was always lost to the debounce/guard interaction.

## Lesson

For any debounced persistence tied to a process lifecycle, add a synchronous flush path that bypasses the `wasKilled`/`dirty` guard and runs BEFORE teardown. Put it inside `kill()` itself — ahead of teardown and before `wasKilled` is set — not in a per-resource loop owned by the hibernation/quit orchestrator. Once teardown disposes the writeQueue and aborts the process-tree killer, debounced writes are gone, so this is the genuine last chance:

```ts
// TerminalProcess.kill() — TerminalProcess.ts:1006, BEFORE teardown sets wasKilled
this.sessionSnapshotter.flushSyncOnKill(); // synchronous, persistSessionSnapshotSync, no wasKilled guard
if (!this.teardown(exitReason)) return;
terminal.wasKilled = true;
this.sessionSnapshotter.dispose();
```

`flushSyncOnKill()` (SessionSnapshotter.ts:97) is unconditional w.r.t. the guard — it serializes via `serializeForPersistence()` (banner-aware so a hibernate→restore→hibernate cycle doesn't bake the prior restore banner in) and calls `persistSessionSnapshotSync()` (terminalSessionPersistence.ts:182).

Cover the timer-never-fired path too. The alive→`dispose()` route (LRU eviction, app shutdown without an explicit kill) has its own variant `flushSyncOnDispose()` (SessionSnapshotter.ts:115), called from `TerminalProcess.dispose()` (TerminalProcess.ts:1405). Unlike the kill path it _keeps_ the `wasKilled` guard and adds a `dirty` guard — if kill/natural-exit already handled persistence, the guard correctly skips the rewrite.

Guards like `wasKilled` should gate _future_ writes, not the explicit flush-on-shutdown path. Test the sequence explicitly (SessionSnapshotter.test.ts): flush writes snapshot synchronously, then kill sets the guard, then a later debounced/event-driven write is blocked.

## Applies when

Any debounced write tied to a resource that can be killed: terminal scrollback, unsaved editor drafts, pending telemetry events, in-flight log batches. Also applies to the `before-quit` and hibernation paths of Electron apps — both are the last chance to get state to disk.
