## Context

Forge (GitHub) PR polling runs inside the per-project workspace-host UtilityProcess (`PullRequestService.checkForPRs` → `ForgeBridge` → main's `forgeRpcServer.dispatchForgeRpc` → provider GraphQL). Since #4647 each Electron window forks its **own** workspace-host per project, so two windows on the same repo run two independent pollers.

## Problem

N windows watching the same project meant N identical GraphQL round-trips per poll cycle — multiplying GitHub API usage and rate-limit burn by the window count, with no shared result. The per-host `inFlightByArgs` dedup in `forgeBridge.ts` only collapses calls _within one host_; it cannot see the sibling host's identical call.

## Root cause

Process isolation (#4647) is what _causes_ the fan-out: the pollers are deliberately separate UtilityProcesses with no shared memory, so the natural place to coalesce — the host that does the polling — physically cannot, and a renderer can't either because `electron-store` is main-only (#8316). The only process that sees every host's traffic is **main**, the boundary they all cross. So arbitration has to live there, expressed in two layers:

- **Layer 1 — cross-window singleflight** (`forgeRpcServer.ts`): an `inFlight` Map keyed by `method\0namespacedId\0stringifyArgs(args)` (deterministic `safe-stable-stringify` so property order can't split the key) joins concurrent identical RPCs from any host onto one provider call; evicted on settle, with a 35s `FORGE_INVOKE_TIMEOUT_MS` ceiling so a hung third-party provider can't wedge the entry and leak waiters.
- **Layer 2 — per-project poll lease** (`forgePollLeaseService.ts`): a `Map<projectId, {holderId, expiresAt}>` in main. One host wins the lease and polls; siblings short-circuit `checkForPRs` and get PR data via the _existing_ `sys:pr:detected`/`sys:pr:cleared` main→renderer fan-out — there is no separate result broadcast.

Two subtleties that are easy to get wrong: (1) the lease key (`generateProjectId(projectPath)`) and holder identity (`serviceName`, a per-host sha1 hash) are derived in main from the `WorkspaceHostProcess` instance — **never trusted from the host's own self-report**, so a confused host can't claim a peer's lease. (2) `acquirePollLease` in `forgeBridge.ts` **fails open** (resolves `true`) on its 5s IPC timeout and on dispose, so a lost lease message can't permanently wedge polling — Layer 1's singleflight is the backstop that keeps the fallback from doubling GraphQL calls.

## Lesson

When isolation (separate UtilityProcess per window/project) makes a _shared upstream_ (an API, a poll, a rate-limited resource) get hit once per process, the dedup/arbitration layer belongs in the **one process every isolated peer crosses — main**, not the polling process and not a renderer.

- Don't try to coalesce in the workspace-host: peers share no memory, and it can't read `electron-store` (#8316).
- Use a **lease** (one elected poller + TTL safety net), not a mutex: TTL (here 90s = 3× the 30s poll cadence) auto-reclaims a crashed/wedged holder; the live holder renews every cycle so it never expires under itself. Eagerly free leases on `dispose` and on the process `exit` handler (`releaseAllLeasesForHolder(serviceName)`) so a sibling takes over immediately instead of waiting out the TTL.
- Derive the lease key and holder identity in **main** from the trusted process handle, never from the host's payload.
- Make lease acquisition **fail-open** on IPC timeout, and keep a cross-window singleflight underneath so the open-fail path still collapses duplicate calls instead of un-deduping them.
- `release` must verify holder ownership (`existing.holderId === holderId`) so a late/stale release from a preempted prior holder can't free a sibling's fresh lease.
- For the singleflight key, use a deterministic serializer (`safe-stable-stringify`) — but know it renders `Map`/`Set` as `{}`; primitives/`RepoRef`/arrays are safe, a future Map/Set arg must be keyed explicitly.

## Applies when

- Adding any periodic poll or rate-limited upstream call (GitHub/forge, git status, CI status, notifications) that runs inside the per-project workspace-host or any other per-window UtilityProcess.
- You see N× API traffic / rate-limit burn that scales with open-window count for the same project.
- You reach for a lock/mutex/dedup and the natural owner is an isolated UtilityProcess that can't share state with peers or read `electron-store` (#8316) — push arbitration up to main.
- Touching `forgePollLeaseService.ts`, `forgeRpcServer.ts` (`dispatchForgeRpc`/`inFlight`), `forgeBridge.ts` lease methods, or `PullRequestService.checkForPRs`.
- Adding a new `ForgeRpcMethod` whose args include a `Map`/`Set` (the singleflight key will silently collide).
- Designing any "one elected worker, others stand down" coordination across multiple Electron windows/processes.
