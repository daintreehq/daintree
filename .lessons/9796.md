## Context

An agent IDE's worst failure mode is a visible terminal that silently stops painting agent output. The #9777–#9781 investigation found the render chain is gated by multiple _independent_ suppression layers — pty-host producer gate (activity tier / backpressure), renderer ingest hold, store visibility + computed refresh tier, xterm's core render pause / WebGL context loss, and (at the time) hibernation — each with its own writers across three processes, and each able to freeze an on-screen terminal on its own. #9782, #9784, #9786, and #9787 closed the four _known_ holes; #9796 added the systemic backstop.

## Problem

"Frozen until clicked": a fully visible terminal shows stale output indefinitely, then instantly recovers on click. The recovery was an accident — `setFocused` unconditionally ran the wake path — and it wiped every piece of state that would have identified the guilty layer, so each recurrence restarted diagnosis from zero.

## Root cause

This is a failure-class capstone, so the mechanism is architectural: visibility/tier state has many writers in three processes with no single owner, so divergence between "DOM says on-screen" and "some layer says suppressed" is inevitable. Two sibling fixes carry layer-specific traps worth knowing on their own. (1) #9782: agent terminals were excluded from all three reflow-recovery paths on the false assumption that WebGL bypasses xterm's IntersectionObserver render pause — it does not; the pause gate lives in the renderer-agnostic core `RenderService`, and after `webglcontextlost` the terminal falls back to DOM anyway. Worse, `terminal.refresh()` is _silently dropped_ while paused, so the only mechanism that reaches a paused terminal is `forceXtermReflow` (sub-pixel padding jitter that forces a geometry pass). (2) #9786: bytes held during a pending `BACKGROUND` downgrade strand forever if the tier flaps back inside `TIER_DOWNGRADE_HYSTERESIS_MS` — the debounce keeps the _applied_ tier constant, so the edge-triggered `resumeFlush` never fires; only new PTY data self-heals, and a quiet producer never sends any. The fix hooks `applyRendererPolicy` to call `onResumeFlush` whenever a pending downgrade is cancelled.

#9796's answer: `TerminalReconciliationWatchdog` sweeps every `WATCHDOG_INTERVAL_MS` (3s), takes fresh DOM geometry as ground truth, and for each genuinely on-screen terminal verifies the full chain in causal order — service visibility → computed/applied tier → backend tier → stranded ingest bytes (`getStalledBytes` distinguishes the zero-in-flight hold signature from normal backpressure) → xterm render pause → WebGL context — repairing at most ONE divergence per terminal per tick (upstream fixes cascade downstream), with a 6s cooldown and heavy repairs (wake/WebGL) capped at 2/tick, skipping terminals under legitimate suppression (drag, layout transition, attach/detach, project-switch resize, docked, off-screen). The evidence gap is filled by a document-level _capture-phase_ `pointerdown` listener that snapshots the whole chain for the clicked terminal before `setFocused`/wake destroy the state — one click on a frozen terminal names the guilty layer.

## Lesson

- **Any new gate on the terminal output path is a new freeze layer and must be watchdog-visible.** If you add a hold, pause, tier, or suppression mechanism to the render chain, wire its state into `TerminalReconciliationWatchdog`'s check chain and the pointerdown snapshot — otherwise you have recreated "frozen until clicked" with zero diagnostics.
- **Recovery destroys evidence; capture diagnostics at capture phase, before recovery runs.** Focus/wake handlers repair state as a side effect, so snapshot the full chain on `pointerdown` (capture, on `document`) ahead of them. Generalizes to any self-healing path: log the broken state before healing it.
- **`terminal.refresh()` is a silent no-op while xterm's core render pause is active, and WebGL is NOT immune to that pause** — the gate is in `RenderService`, renderer-agnostic (#9782). Recovery of a possibly-paused terminal must use `forceXtermReflow` geometry jitter, never `refresh()`.
- **A hysteresis debounce also debounces every edge-triggered side effect.** If an action fires on applied-state _transitions_ and a debounce can swallow a transition (flap within the window), the action must also fire on cancel-of-pending (#9786's `onResumeFlush` hook in `applyRendererPolicy`).
- **Watchdog repairs must be narrow, causal-ordered, cooldowned, and must not fight policy.** One repair per terminal per tick; cooldowns turn a persistent diverger into periodic logs instead of a repair loop. Post-merge history proves the danger: #10416 added the guard distinguishing BACKGROUND-_by-policy_ (completed/exited agent — repairing it fights the store every tick forever) from real divergence, and #10909 added a circuit breaker (`WATCHDOG_MAX_GEOMETRY_REPAIR_ATTEMPTS = 3`) for never-converging geometry.
- The watchdog lives on but has evolved: hibernation (one original layer) was removed wholesale in #10811 (`TerminalWakeManager` deleted; the watchdog's `hasInFlightWake` dep is stubbed `() => false` in `TerminalInstanceService`), and #11212 fixed multi-window on-screen scoping — read the current check chain before extending it.

## Applies when

- Adding any suppression/hold/pause/tier mechanism to the terminal output or render path — renderer, store, or pty-host side.
- Diagnosing "visible terminal frozen until clicked" or stale agent output that recovers on focus — check the pointerdown snapshot log first; it names the layer.
- Touching `TerminalReconciliationWatchdog`, `TerminalRendererPolicy` hysteresis, `TerminalReflowController`, or ingest hold/flush logic in `TerminalOutputIngestService`.
- Assuming WebGL terminals bypass xterm's render pause, or reaching for `terminal.refresh()` to recover a non-painting terminal.
- Designing any self-healing/reconciliation loop — the evidence-before-repair, one-repair-per-tick, cooldown, circuit-breaker, and don't-fight-policy rules transfer whole.
