## Context

Dev preview servers started in different worktrees were reporting identical ports/URLs. The user could not tell which worktree's changes they were actually seeing.

## Problem

PtyPool warms shell terminals ahead of time. Originally pooling warmed at a single `defaultCwd` (e.g. home dir) and the caller issued a "cd &lt;worktree&gt;" after acquiring — for cwd-sensitive services that raced, so the dev server could execute from the wrong directory, or two worktrees could pull pooled PTYs that briefly shared state and the first "cd" won. Pooling is now keyed by `(cwd, envHash)` (entries warm at the right cwd via node-pty's kernel-level `cwd` option, no shell-level cd), but a dev server still must not reuse a pooled shell: it forks subprocesses and reads files relative to cwd before any per-spawn setup, so it has to spawn fresh.

## Root cause

A service that MUST start in a specific cwd with side effects on first launch cannot safely reuse a pooled shell. Even with per-cwd pool keying, a pooled entry is a shell that has already started (banner/prompt emitted, env established) — reusing it for a process that forks subprocesses or reads files relative to cwd before any per-spawn setup is unsafe. The dev-preview case made this visible because each worktree needs a distinct port and the symptom (duplicate ports/URLs across worktrees) was impossible to mistake.

## Lesson

PtyPool is a latency optimization for shell-style terminals where an extra "cd" on acquire is harmless. Any terminal whose behaviour depends on the initial cwd — dev servers, any command that reads files relative to cwd before the first "cd" runs, anything that forks subprocesses before the cd — must bypass the pool and spawn fresh with the correct cwd from the start. Enforce this with a runtime assertion on the spawn path (e.g. assert kind !== "dev-preview" when acquiring from the pool) so it cannot regress silently. Also log panelId/ptyId/generation/cwd for anything worktree-scoped so future pool-reuse bugs are diagnosable.

## Applies when

Adding a new panel kind that spawns a PTY with side effects tied to cwd. Reviewing PtyPool changes. Debugging "why does this terminal act like it is in the wrong directory?" Debugging duplicate ports/URLs across worktrees.
