## Context

Demo screen capture (`src/components/Demo/DemoCaptureBridge.tsx` + `electron/ipc/handlers/demo.ts`) replaced a `capturePage()` poll loop (which pushed ~2GB/s of raw BGRA over IPC at 60fps and dropped frames) with renderer-side `getDisplayMedia` + `MediaRecorder`, streaming VP9 WebM chunks to main over `DEMO_CAPTURE_CHUNK`, finalized via `DEMO_CAPTURE_STOP`.

## Problem

Two non-obvious traps for any `getDisplayMedia` + `MediaRecorder` pipeline in Electron. (1) `recorder.stop()` fires `onstop` synchronously after the last `BlobEvent`, but `ondataavailable` is **async** — it `await`s `e.data.arrayBuffer()` before the IPC send. Naively dispatching the stop/finalize signal inside `onstop` races ahead of the final chunk's IPC send, so the write stream is `.end()`-ed before the last WebM chunk lands → truncated/corrupt video. (2) `navigator.mediaDevices.getDisplayMedia()` rejects in Electron unless a display-media request handler is installed, and it pops a system picker the demo can't drive.

## Root cause

`MediaRecorder` chunk delivery and chunk _transmission_ are decoupled: the Blob is handed over synchronously, but converting it to a transferable `Uint8Array` (`arrayBuffer()`) is a promise. `onstop` only signals that recording stopped, not that all chunks have been serialized and sent. Finalization must wait on the _last sent chunk_, not the _recorder state_. For (2), Electron gates `getDisplayMedia` behind `session.setDisplayMediaRequestHandler`; with no handler the promise rejects, and the default opens a picker.

## Lesson

Finalize on a **drain barrier**, not on `onstop`. Track `pendingChunks` (incremented before `await arrayBuffer()`, decremented in `finally`) and a `stopped` flag set by `onstop`; only emit the stop/finalize IPC when `stopped && pendingChunks === 0` (`maybeSendStop` in `DemoCaptureBridge.tsx:29`). Both the `onstop` path and the per-chunk `finally` must call the barrier check, because either can be the last to complete. For Electron capture, register `displaySession.setDisplayMediaRequestHandler((req, cb) => cb({ video: req.frame }), { useSystemPicker: false })` on the **same session partition the renderer uses** (`persist:daintree`, `demo.ts:95`) to grant the in-app surface with no picker, and tear it down with `setDisplayMediaRequestHandler(null)` on cleanup. Match chunks to the active capture by `captureId` on the main side (`onCaptureChunk` drops stale/mismatched ids) so a late chunk from a previous session can't corrupt a new file.

## Applies when

Streaming `MediaRecorder` output (audio/video/screen) chunk-by-chunk over IPC, a worker, or the network; or any "stop then flush" pipeline where the producer's stop event fires before in-flight async sends complete; or calling `getDisplayMedia`/`getUserMedia` from an Electron renderer.
