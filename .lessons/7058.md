## Context

`electron/utils/hardenedGit.ts` exposes four `simpleGit()` factories used by background workspace monitoring and user-initiated git: `createHardenedGit` (status/log/diff polling), `createAuthenticatedGit` (clone/push/fetch with system creds), `createBackgroundFetchGit` (wraps `createAuthenticatedGit` + adds lock-friendly config), and `createWslHardenedGit` (Linux git inside a WSL distro via `wsl.exe git`). These run in the main and workspace-host processes against worktrees the user is simultaneously hitting from embedded terminals.

## Problem

Two distinct failure shapes. (1) Read-mostly status polling and background fetches silently _write_ to the repo as side effects — git refreshes the index stat-cache (`.git/index.lock`) on `status`, and writes `FETCH_HEAD` on `fetch` — contending with the user's foreground git in the embedded terminal (spurious lock errors, "another git process" failures). (2) Any embedded git op that touches a credential helper can block forever on a hidden interactive prompt that no one can answer, because the Electron/utility-process has no TTY.

## Root cause

- Git's "read" commands are not pure reads: `status` opportunistically rewrites the index, `fetch` writes `FETCH_HEAD`. Both are cross-process-visible files. `-c credential.helper=` blanking does not stop a clone/fetch/push from invoking a credential helper or GCM dialog on some platforms, and the built-in TTY prompt hangs indefinitely in a headless process.
- The sharpest trap is in `createBackgroundFetchGit`: simple-git's `git.env(obj)` does `this._executor.env = obj` — it **replaces the env object wholesale, it does not merge** (verified in `node_modules/simple-git/dist/cjs/index.js`: `Git2.prototype.env` → `this._executor.env = name`). So when a wrapping factory calls `.env()` a second time on an instance the inner factory already configured, every flag from the first `.env()` (locale, `GIT_OPTIONAL_LOCKS`, `GCM_INTERACTIVE`, `GIT_TERMINAL_PROMPT`) is dropped unless re-stated. This is a silent regression vector — code looks like it "adds" one env var but actually erases all the others.

## Lesson

When configuring a hardened simple-git factory:

- Set `GIT_OPTIONAL_LOCKS=0` on every factory that touches a worktree the user shares. It suppresses only opportunistic index.lock writes (stat-cache refresh); mandatory locks for `git add`/`commit` are unaffected, so it is safe even on write paths. (Now also folded into `getGitLocaleEnv()` so it rides along with locale.)
- Pass `--no-write-fetch-head` on background `git fetch` (see `RepoFetchCoordinator.ts`) so background fetches don't contend on `FETCH_HEAD` with foreground ops. Requires git ≥ 2.29; all supported platforms ship ≥ 2.34, so no version guard.
- Block hangs with `GIT_TERMINAL_PROMPT=0`; add `GIT_ASKPASS=true` on POSIX as defense-in-depth (helpers that ignore the prompt flag still exec ASKPASS; `true` exits 0 with empty stdout → git fails fast). Do **not** set `GIT_ASKPASS` on Windows — there is no `true` on PATH — and do **not** set it on `createAuthenticatedGit`, where legitimate credential helpers must resolve. On Windows use `GCM_INTERACTIVE=Never` to stop Git Credential Manager GUI dialogs.
- If you call `.env()` on an instance another factory already configured (the `createBackgroundFetchGit` wrapping pattern), you MUST re-state the full env object — `.env()` replaces, never merges. Treat a second `.env()` call as "redeclare everything," and assert it in tests (`hardenedGit.test.ts` checks the _last_ `.env()` call still carries `GIT_OPTIONAL_LOCKS`/`GCM_INTERACTIVE`).
- WSL git is Linux git: `createWslHardenedGit` needs the same POSIX hardening (`GIT_ASKPASS=true`, etc.) even though the host is Windows.

## Applies when

- Adding or modifying any factory in `electron/utils/hardenedGit.ts`, or wrapping an existing simple-git instance with a second `.env()` call.
- Diagnosing spurious `.git/index.lock` / `FETCH_HEAD` / "another git process is running" errors that correlate with background status polling or fetch while the user runs git in a terminal.
- Diagnosing a background git operation that hangs forever (no error, no completion) in the main or workspace-host process — suspect a credential/ASKPASS prompt with no TTY.
- Any new background `git fetch` in `electron/workspace-host/` (e.g. `RepoFetchCoordinator`).
- Windows-specific git auth dialogs popping up from background processes (GCM).
- Code review of a diff that adds one env var to a simple-git `.env()` call on an already-configured instance — check it isn't silently dropping the others.
