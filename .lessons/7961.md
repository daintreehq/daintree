## Context

When the user launches an agent (Claude/Gemini/Codex/Copilot), the terminal spawn handler (`electron/ipc/handlers/terminal/lifecycle.ts`) must run a launch command in a fresh interactive shell. `buildCommandLaunchShell` (`commandLaunch.ts`) turns the command into shell + startup args; if it returns `null`, the caller falls back to typing the command into the PTY input stream. A separate warm-start path, the PTY pool (`acquirePtyProcess` in `electron/services/pty/terminalSpawn.ts`), gives instant spawns for plain terminals.

## Problem

On Windows the launch command was echoed into the PTY buffer instead of run as startup work, so long absolute launch commands scrolled across the screen before the agent started. The naive fix — pass the command as a normal argv element — is fragile: node-pty's Windows agent re-joins argv into a single command line for `CreateProcess`, and PowerShell/cmd each re-parse quoting and backslashes differently, so paths with spaces or embedded quotes break. Separately, the obvious refactor (resolve one concrete shell and reuse it everywhere) silently disabled the PTY pool for every plain terminal.

## Root cause

Two distinct platform/architecture traps:

- **Quote-nesting through CreateProcess is unreliable.** Passing a command string through node-pty → `CreateProcess` → PowerShell's `CommandLineToArgvW` mangles embedded quotes/backslashes. The fix bypasses the parser entirely: PowerShell gets `-NoLogo -NoExit -EncodedCommand <base64-of-UTF16LE-bytes>` (`encodePowerShellCommand` = `Buffer.from(script, "utf16le").toString("base64")`), which PowerShell decodes directly with no further parsing. cmd.exe uses `/K <command>` (single argv element; cmd does `%VAR%`/`^` parsing, so callers must pre-quote with `escapeWindowsArg`). Unknown Windows shells (git-bash) return `null` rather than guess.
- **A shell identity resolved for quoting must not become the spawn shell.** Each `quoteCommandArg(value, shell)` call needs a _concrete_ shell to pick the right escaping (PowerShell `''` doubling vs cmd `"` escaping vs POSIX `'…'`), so `quotingShell = validatedOptions.shell || projectShell || getDefaultShell()` always falls back to a real shell. But the PTY pool gate is `canUsePool = … && !options.shell && !options.args` (`terminalSpawn.ts:161-166`). If that same concrete `quotingShell` were passed as the spawn `shell`, `!options.shell` would always be false and the pool would never match — every plain terminal would pay a full cold spawn (plus `where pwsh.exe` PATH probes on Windows). So `spawnShell` deliberately preserves the original `validatedOptions.shell || projectShell` (undefined when unset); only a successful `buildCommandLaunchShell` (i.e. an actual command launch, never a plain terminal) overrides it.

## Lesson

- To run a command as a fresh shell's startup work, route through shell startup args, never echo into the PTY: PowerShell `-EncodedCommand` (UTF-16LE → base64) to sidestep `CommandLineToArgvW`; cmd `/K`; POSIX `-lic`/`-i -c` with a `trap : INT` wrapper. Return `null` for shells you don't recognize so the PTY-write fallback handles them.
- Keep two separate shell values when one is for **quoting** and one is for **spawning**. The quoting shell must always be concrete (default-fallback) so escaping is correct; the spawn shell must preserve `undefined`-when-unset, because `acquirePtyProcess`'s pool gate keys off `!options.shell`. Collapsing them into one `resolvedShell` silently disqualifies plain terminals from the warm pool.
- `command` is interpolated raw into the shell payload (shell metacharacters are intentional for QuickRun/resource-connect). Any new call site that interpolates user-controlled data into `command` MUST quote its fragment via `quoteCommandArg(value, quotingShell)` — do not rely on the launch layer to sanitize.
- Match Windows shells by exact basename (`isPowerShellShell`/`isCmdShell`), not substring — `pwsh.exe` must not match a `powershell.exe` substring test.

## Applies when

- Touching agent launch / command-launch in `electron/ipc/handlers/terminal/lifecycle.ts` or `commandLaunch.ts`, or adding a new agent whose CLI args get appended to `safeCommand`.
- Adding or refactoring shell-resolution logic in the terminal spawn path and you're tempted to compute one `resolvedShell` and reuse it — check whether it feeds `ptyClient.spawn`'s `shell` option (it must stay undefined for plain terminals) vs quoting.
- Changing the PTY pool eligibility gate (`canUsePool` / `acquirePtyProcess` in `electron/services/pty/terminalSpawn.ts`), or debugging why plain terminals stopped hitting the warm pool / why Windows spawns got slow.
- Passing commands with spaces, embedded quotes, or Windows paths through node-pty on Windows and seeing mangled quoting — reach for `-EncodedCommand` / `/K` instead of argv quoting.
- Adding quoting helpers in `shared/utils/shellEscape.ts` (`quoteCommandArg`, `quotePowerShellArg`, `escapeWindowsArg`, `isPowerShellShell`, `isCmdShell`) or classifying a Windows shell by name.
