## Context

PR #3417 fixed OpenCode's Bubble Tea TUI rendering as plain ASCII with no chrome. It made two unrelated changes: flipped `blockAltScreen` to `false` so the SMCUP/alt-screen switch was allowed through, and added `opencode: ["CI", "NONINTERACTIVE"]` to `AGENT_ENV_EXCLUSIONS` in `electron/services/pty/terminalShell.ts` so `buildNonInteractiveEnv` would stop injecting `CI=1`/`NONINTERACTIVE=1` (which made Go's `termenv` degrade to ASCII and skip OSC queries).

## Problem

Only half of PR #3417 still exists. The env-exclusion mechanism it touched is gone. Commit `0506b3ccb` ("refactor(terminal): collapse identity model to launchAgentId/detectedAgentId pair", 2026-04-24) removed `buildNonInteractiveEnv` and `AGENT_ENV_EXCLUSIONS` entirely as part of the terminal-identity unification. All PTY-backed panels now spawn identical interactive login shells with no per-agent env tiering — there is no longer any `CI=1` injection to exclude OpenCode from. A code-shaped tombstone comment remains at `electron/services/pty/terminalShell.ts:85-89` pointing at `docs/architecture/terminal-identity.md`.

## Root cause

The CI-env half of the fix was a workaround layered on a now-deleted assumption: that Daintree shapes a distinct "non-interactive agent" environment per launch hint. Once terminal identity collapsed to `launchAgentId` (spawn hint, non-identity) + `detectedAgentId` (live chrome driver) and every terminal became a plain interactive shell, the entire env-injection layer — and its exclusion list — was the wrong place to encode TUI requirements. The `blockAltScreen` half survived because it is a genuine per-agent _capability_, not an env hack: it lives on `AgentConfig.capabilities.blockAltScreen` and is consumed at parse time by `TerminalParserHandler`, independent of how the shell env is built.

## Lesson

`blockAltScreen` is the durable, still-live mechanism. It is a per-agent capability in the agent config (`shared/config/agents/opencode.ts:87` sets `blockAltScreen: false`; `codex`/`gemini` set `true`), read by `TerminalParserHandler` (`src/services/terminal/TerminalParserHandler.ts:61`, default `false`) which only registers the CSI `?...h` alt-screen-blocking handler when the capability is `true`. To let a full-screen TUI agent (Bubble Tea, Ink) render, leave `blockAltScreen` unset/`false`; to keep an inline-mode agent from clobbering scrollback, set it `true`. The CI-env exclusion lesson is dead. There is no `AGENT_ENV_EXCLUSIONS`, no `buildNonInteractiveEnv`, and no per-agent env injection — do not reintroduce a CI-env exclusion list to fix a TUI. If a TUI degrades to ASCII, the cause is no longer Daintree poisoning `CI`; check the alt-screen capability and the real terminal env, not a non-existent injection layer. General trap: a two-part fix can be silently half-dissolved by an unrelated refactor. When one half lived on a structural concept (env tiering) that later got unified away, only the half anchored to a stable abstraction (a typed capability) survives.

## Applies when

Onboarding or debugging a TUI agent (Bubble Tea, Ink) that renders as plain ASCII or fails to enter full-screen — fix it via `capabilities.blockAltScreen` in the agent's `shared/config/agents/*.ts`, not env vars. Also when you find a reference to `AGENT_ENV_EXCLUSIONS`, `buildNonInteractiveEnv`, or per-agent `CI=1` injection — those were removed in `0506b3ccb`; terminals now spawn identical interactive shells (`docs/architecture/terminal-identity.md`).
