## Context

Utility processes (`pty-host`, `workspace-host`) start from a thin bootstrap (`electron/pty-host-bootstrap.ts`, `electron/workspace-host-bootstrap.ts`) that does `await import("./<host>.js")`. The host module installs its own `uncaughtException`/`unhandledRejection` handlers during evaluation (`pty-host.ts:84`, `workspace-host.ts:258`) and posts `ready` to the parent. The parent gates on `waitForReady()` (`WorkspaceHostProcess.ts:132`, `PtyClient.ts:350`), recovering from death via an `exit`/`child-process-gone` listener that calls `readyReject` (`WorkspaceHostProcess.ts:351`).

## Problem

If a native module fails to load during `await import()` (node-pty `ERR_DLOPEN_FAILED` from an arch mismatch / bad electron-rebuild, or `better-sqlite3` / `@parcel/watcher` dlopen failure in workspace-host), the host never finishes evaluating, so it never installs its own handlers and never posts `ready`. The parent's `waitForReady()` hangs forever and the app freezes on startup with no observable error.

## Root cause

The host's own error handlers run only AFTER the module body evaluates — they cannot catch a failure DURING the `import()` of that module. That gap was previously masked: pre-Electron-37 an unhandled rejection in a utility process CRASHED it, so the parent's `exit` handler fired and `readyReject` recovered. From Electron 37 onward, utility processes only WARN on unhandled rejections instead of crashing (they crashed in v36 and earlier) — so the failed `import()` rejection just logs a warning, the process stays alive as a zombie, no `exit` event fires, and the hang becomes silent and permanent. (This is the inverse of the stale claim in lesson #4156, which #8833 also corrected in CLAUDE.md.)

## Lesson

- For any utility-process bootstrap that dynamically `import()`s its host module, install `uncaughtException`/`unhandledRejection` handlers BEFORE the import, via `installBootstrapErrorGuard()` (`electron/utils/bootstrapErrorGuard.ts`). The guard logs to stderr, posts a typed `{type:"error",...}` event to `process.parentPort` (PTY adds `id:"system"` to match `PtyHostEvent`; workspace matches `WorkspaceHostEvent`), then `setImmediate(() => process.exit(1))` so Mojo IPC flushes before death.
- The deliberate exit converts a silent hang into a fast, observable exit that the parent's existing exit→`readyReject` path recovers from. Do NOT rely on the old "unhandled rejection crashes the utility process" mental model — from Electron 37 it only warns.
- Keep the guard module dependency-free: its entire job is to be in place before the import phase that may fail, so it must not import anything that could itself fail to load.
- Tear the guard down (call the returned cleanup) immediately after a successful import, because the host installs its own lifetime handlers during evaluation — leaving the bootstrap guard active would double-report every later crash, one with a misleading `[…Bootstrap]` label.

## Applies when

- Adding or refactoring any utility-process / `utilityProcess.fork` bootstrap entry (`*-bootstrap.ts`) that does `await import()` of a host module.
- Diagnosing an app that hangs on splash / `waitForReady()` never resolves, with a "unhandled rejection" warning in host stderr but no `exit` or `child-process-gone` event.
- Touching native modules loaded in a host (node-pty, better-sqlite3, @parcel/watcher) where a dlopen / arch-mismatch / electron-rebuild failure can surface during module load.
- Reasoning about Electron 37+ behavior: unhandled rejections in utility processes WARN, not crash — any code that assumed self-termination needs an explicit exit path.
- Adding new process-level error handlers in a host and deciding ordering relative to the `import()` that pulls in the host body.
