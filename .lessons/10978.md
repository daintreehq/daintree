## Context

`WorkspaceService` polls git status per worktree into `createWorktreeStore.ts`'s `worktrees: Map<string, WorktreeSnapshot>`, a whole-map subscription `App` and ~20 other components read directly. Several hooks always mounted at the `App` root regardless of visibility — the quick-switcher/send-to-agent/panel/resume-sessions palettes, plus `useContextInjection` and `useAccessibilityAnnouncements` — held live reactive selectors over `panelsById`/`focusedId`/`worktrees` even while their own UI was closed. #10978 continues the bug class #10915 found: every poll or state flip the app can't eliminate still costs whatever renderer fanout multiplies it into.

## Problem

At 50 worktrees, a quiet git-status poll — nothing changed on disk, the single most common event in the app — re-rendered ~1,385 components, the same magnitude as a poll that actually changed something. Idle re-render volume at 50 worktrees was 46,902 renders per 10 seconds. This never surfaced as a bug report; it only showed up once the PR built a bench (`scripts/perf/render-fanout-probe.js`) to measure render count per event, because nothing about a "no-op" poll should cost anything.

## Root cause

Two mechanisms stacked. First, `WorktreeSnapshot.lastGitStatusCheckedAt` advances on every completed poll — including no-op ones — and `snapshotsEqual()` in `createWorktreeStore.ts` compared it alongside real content fields. Any field inside an equality check that's always unequal defeats the check: `applyPoll` minted a fresh `worktrees` Map identity every tick, and every whole-map subscriber (`App` included) re-rendered regardless of whether anything real changed. Second, hooks mounted unconditionally at `App` subscribed reactively to slices they only needed while their own UI was open or their callback actually ran, so even after fixing the Map-identity churn those hooks kept re-rendering `App` on every panel-map or focus change.

The fix for (1) moved the freshness stamp into a side map, `statusCheckedAt: Map<string, number>`, updated only when the incoming stamp differs; `lastGitStatusCheckedAt` still exists on the stored snapshot but now reflects only the last _content_ change, and freshness consumers (`WorktreeHeader`'s pill, `WorktreeCard`'s hover-revalidate gate) read the side map per-id instead of the whole map. The fix for (2) is `useWorktrees({ enabled })` plus per-hook `paletteIsOpen`/`isOpen` gates: each selector becomes `(state) => (open ? state.slice : EMPTY_SENTINEL)`, where `EMPTY_SENTINEL` is a module-level `new Map()`/`[]` constant, NOT an inline literal (that would allocate a fresh reference every render and defeat the gate). `useContextInjection`'s `inject()` went further, dropping selectors entirely for `usePanelStore.getState()` reads inside the callback since it only needs state at call time.

## Lesson

- **Never let a monotonically-advancing "last polled/checked" field participate in an equality function that gates a Map/object identity swap.** `snapshotsEqual` comparing `lastGitStatusCheckedAt` is the exact bug — track that stamp in a separate side map (`statusCheckedAt`) and have only the few consumers needing per-id freshness (not whole-map subscribers) read it.
- **Always-mounted hooks (palettes, App-root effects) must gate their OWN selectors, not just their consumption, behind visibility** — `(state) => (open ? state.slice : EMPTY_SENTINEL)` with a module-level empty constant. An inline `{}`/`[]` fallback is not equivalent: it's a fresh reference every render and defeats the gate. `useWorktrees({ enabled })` and the four palette hooks are the template to copy.
- **Reads that only happen inside a callback or effect don't need a reactive subscription at all.** `useContextInjection`'s `inject()` only touches `focusedId`/`panelsById` when invoked, so `usePanelStore.getState()` at call time is fresher AND removes the re-render (mounted in `App` AND every `TerminalPane`, so it scales with terminal count too); `useAccessibilityAnnouncements` renders nothing, so its 5 reactive selectors became one transient `store.subscribe` outside React, diffed via refs, with debounce/first-mount semantics preserved exactly.
- **Don't guess at render fanout — measure it.** `scripts/perf/render-fanout-probe.js`, inlined as a classic `<head>` script only under `DAINTREE_RENDER_PROBE=1` (`npm run build:e2e:bench`), installs a DevTools hook before `react-dom` evaluates and walks each commit's fiber tree with DevTools' own reused-subtree pruning (`fiber.child !== fiber.alternate.child`) to attribute exact per-component render counts and self-time. Run `e2e/full/panels/store-fanout-perf.spec.ts` (`RUN_PERF_STORE_FANOUT=1`) before/after touching any O(worktrees) subscription; it's a deliberate opt-in tripwire, not wired into PR CI.
- **This didn't close every fanout path.** Agent-state flips still re-render the full App chain unchanged (1,845 components at 50 worktrees) because the flip advances `lastActivityTimestamp`, a real content change the sidebar recency sort needs, and `App` consumes the worktree map directly for JSX — narrowing that subscription is future work, not solved here.

## Applies when

- Adding or auditing a snapshot field that advances on a timer/poll independent of user-visible content (heartbeats, `lastChecked`/`lastPolled` stamps) — check whether any equality function compares it before gating a Map/object identity swap.
- Adding a hook or palette mounted unconditionally at `App` that only needs live store data while open/visible/focused — copy the `paletteIsOpen ? state.slice : EMPTY_SENTINEL` pattern from `usePanelPalette.ts`, `useQuickSwitcher.ts`, `useSendToAgentPalette.ts`, or `useResumeSessionsPalette.ts`.
- Diagnosing "app feels janky with many worktrees/terminals" or a profiler shows a huge commit fanout from an event that changed nothing visible — suspect a snapshot-equality function comparing a monotonic field before auditing every subscriber.
- Reviewing a callback/imperative helper that destructures store state via a reactive selector purely to read it later inside the callback — `getState()` at call time is cheaper and fresher.
