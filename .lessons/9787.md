## Context

The pty-host throttles per-terminal output by activity tier: the renderer tells the host which terminals are `active` vs `background`, and `TerminalRendererPolicy` dedupes those outbound sends against the last tier it believes the host holds (`lastBackendTier`) to keep the hot path quiet. Independently, the host's `recomputeActivityTiers()` (`electron/pty-host.ts`) re-derives tiers itself on window connect/disconnect and project switch. This was one of the five freeze layers in the #9777–#9781 investigation (capstone: #9796).

## Problem

A fully visible terminal's output froze after project switches or window churn, repaired only by the accidental click-wake path. Renderer-side state looked perfectly correct — store visible, tier active, no held bytes — because the renderer _was_ correct about itself; the desync lived in its belief about the host. Nothing in either process was individually wrong, which is what made it invisible: the host had silently demoted the terminal to `background` and was suppressing bytes, while the renderer, believing the host was still `active`, deduped away every re-send that would have fixed it.

## Root cause

A dedupe optimization carries an implicit invariant: the deduping side's model of the peer must track every mutation of the peer's actual state. `recomputeActivityTiers()` violated it — it called `setActivityTier` directly inside the host on connect/disconnect/project-switch without telling the renderer. Once the renderer's `lastBackendTier` said `active`, it never sent `active` again; the desync was _permanent_ by construction, not a transient race. A second latent bug compounded it: terminals with `undefined` `projectId` were demoted whenever any window had a project mapping — an unset scope key was treated as "matches nothing" instead of wildcard.

The fix has three load-bearing parts. (1) After every `setActivityTier` inside `recomputeActivityTiers`, the host broadcasts `{type: "tier-changed", id, tier}` (`PtyHostToRendererMessage` became a discriminated union in `shared/types/pty-host.ts`). (2) The broadcast rides each per-window **MessagePort** — the same channel as data chunks — so it is FIFO-ordered with the bytes it governs; routing it through Main-process IPC would race the direct data path (a `tier-changed` could arrive before/after the chunks it explains). (3) The renderer's `onTierChanged` handler (`terminalClient.ts` → `TerminalInstanceService`) calls the pre-existing `initializeBackendTier`, which re-arms `lastBackendTier` _without echoing back to the host_ — an acknowledging re-send would loop or re-race. Follow-ups hardened the class: #9832 added a `tier-transition` observability metric at the `BackpressureManager.setActivityTier` chokepoint (gated on `DAINTREE_TERMINAL_METRICS=1`, no-op writes deduped, emit wrapped in try/catch so a detached port during shutdown can't abort tier application); #9841 added regression guards (single-port FIFO-ordering test, 200-iteration connect/set-active-project order-independence fuzzer, force-resume-never-mutates-tiers guard, plus the #9799 dedupe-sequence and #9798 host/renderer-agreement tests); #9839 added `useForceResumeCycleWatchdog` (3 consecutive ≥9900ms bounded-pause force-resumes → Tier-3 `InlineStatusBanner` with a Reset queue action).

## Lesson

- **Dedupe-against-peer-state creates a notification obligation on the peer.** Before adding "skip send if unchanged" against a remote's last-known state, enumerate every writer of that state on the remote side; each silent writer is a permanent-desync bug. Here the missed writer was the host's own `recomputeActivityTiers`.
- **Reconciliation messages must ride the channel whose ordering they explain.** `tier-changed` goes over the per-window MessagePort because FIFO only holds within one channel — a parallel Main-IPC route would race the data chunks the tier governs. Any control message whose meaning is relative to a data stream belongs on that stream.
- **Re-arm a dedupe baseline without acknowledging.** `initializeBackendTier` updates the renderer's belief silently; an echo back to the host would create a feedback loop or a fresh race. Reconciliation is one-way: authoritative side broadcasts, deduping side re-arms.
- **`undefined` scope keys are wildcards, not non-matches.** A terminal with no `projectId` must stay active under every window's project filter; treating unset as "matches nothing" silently demotes a whole category.
- **Give silent mutation paths a chokepoint metric.** All tier mutations flow through `setActivityTier`, so one instrumented call site (#9832, with a `reason` tag: `recompute-activity-tiers` / `set-activity-tier` / `wake-terminal`) covers every future writer — including ones that don't exist yet.

## Applies when

- Touching `recomputeActivityTiers`, `setActivityTier`, `TerminalRendererPolicy` dedupe/`initializeBackendTier`, or the `tier-changed` path in `electron/pty-host.ts` / `terminalClient.ts`.
- Adding any "skip if unchanged" / last-sent-value dedupe on a cross-process boundary (renderer↔pty-host, renderer↔main, plugin host) — enumerate the peer's silent writers first.
- Deciding which channel a new control/reconciliation message should use when a MessagePort data path exists alongside Main IPC — ordering relative to data decides it, not convenience.
- Diagnosing frozen terminal output after project switch, window open/close, or multi-window churn where renderer-side state all looks correct — compare the host's actual tier (`DAINTREE_TERMINAL_METRICS=1` tier-transition metrics) against the renderer's `lastBackendTier` belief.
- Writing filters keyed on optional scope fields (`projectId`, worktree ids) — decide explicitly whether unset means wildcard, and test the unset case.
