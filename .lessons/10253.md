## Context

The app shell (`src/App.tsx`, palette wiring since extracted to `src/hooks/app/usePaletteWiring.ts`) hosts ~15 lazily-loaded palettes and dialogs — QuickSwitcher, ActionPalette, ThemePalette, SettingsDialog, GitInitDialog, CrossWorktreeDiff, etc. Each is a `lazy()` chunk wrapped in `<Suspense fallback={null}>` and gated on its open flag: `{quickSwitcher.isOpen && <LazyQuickSwitcher isOpen={...} />}`. Inside, `AppPaletteDialog`/`AppDialog` drive an entry+exit transition via `useAnimatedPresence` (`src/hooks/useAnimatedPresence.ts`), a hook whose entire purpose is to keep DOM alive for one exit-animation duration after close.

## Problem

Every command palette and several dialogs closed instantly — the exit animation (Tier-2 120ms for dialogs, Tier-2-fast 100ms for palettes) never played. Enter animations worked and focus restored correctly, so the symptom read as "the exit transition is missing." It was fully implemented (`UI_PALETTE_EXIT_DURATION` opacity+scale in `AppPaletteDialog`) — it just never executed from these hosts, i.e. dead code reachable only through a render the app shell never produced.

## Root cause

`useAnimatedPresence`'s exit branch only runs when the component receives a COMMITTED render with `isOpen === false`: its `else if (hasOpenedRef.current)` path schedules `doClose()`, which flips `isVisible` false and, after `getUiAnimationDuration()`, sets `shouldRender` false. But `{isOpen && <Comp/>}` unmounts `<Comp/>` in the SAME React commit that flips `isOpen` false — the closed render never happens, so `doClose()` never fires. The child's own `hasOpenedRef` latch is worthless here: **a child cannot animate its own exit if the PARENT stops rendering it.** That is the crux — the keep-alive latch must live in the HOST. `useKeepMounted(isOpen)` (`src/hooks/useKeepMounted.ts`) returns `isOpen || hasOpened`, latching `true` on first open and never resetting, so the host keeps rendering the component; the component still receives the real `isOpen` and gates its own DOM removal via `shouldRender`. The latch stays `false` until first open, so the lazy chunk is still deferred (code-splitting preserved). This was never a regression — the exit machinery was inert from the app shell since written; `SettingsDialog`/`PluginManagerView` already used an ad-hoc `(isOpen || hasOpened)` latch, which #10253 generalized into the shared hook.

## Lesson

- **The exit-animation keep-alive latch belongs to the HOST that conditionally renders the component, never inside the component.** `useAnimatedPresence` already carries its own `hasOpenedRef`, but it is inert if the parent unmounts the child in the close commit. Wrap the mount gate with `useKeepMounted(isOpen)` (`isOpen || hasOpened`) and pass the real `isOpen` through unchanged so the child runs its own exit phase.
- **Keep-mounting opens a window where the component renders AFTER the store cleared the data it needs.** `GitInitDialog`'s `directoryPath` is non-nullable, but `closeGitInitDialog()` clears `gitInitDialogOpen` AND `gitInitDirectoryPath` in one `set()`; the fix latches the last non-null path separately (`effectiveGitInitPath = gitInitDirectoryPath ?? latchedGitInitPath`, `src/App.tsx`). Any prop cleared in the same `set()` as `isOpen` must be latched too, or the exit render blanks/crashes.
- **Once mounted-while-closed, effects that were "safe because unmounted" now fire against a closed surface.** `SearchablePalette`'s result-count screen-reader announcer had to add `if (!isOpen) return;` (and `isOpen` in its deps, `src/components/ui/SearchablePalette.tsx`) so a late filter pass resolving after close doesn't announce to an invisible palette. Audit announcers, fetches, timers, and subscriptions after adding the latch.
- **Keep-mount is NOT universal — skip components that rely on unmount to reset internal state.** `WorktreeOverviewModal` and `ProjectSwitcherPalette` were deliberately excluded: they use CSS-only entry (no `useAnimatedPresence`, so no exit phase to preserve) AND keep-mounting broke their `selectedIds` reset, which depended on the unmount. No `useAnimatedPresence` exit phase → no reason to latch, and latching can actively break stateful reset-on-unmount.
- **The latch preserves `lazy()` + `Suspense fallback={null}` — it returns `false` until first open, so the chunk stays unfetched.** This is load-bearing: `ReviewHubContent` uses `useKeepMounted` specifically to defer a ~223KB DiffViewer/editor chunk until a diff row is clicked. The pattern has since spread to 11 files (Sidebar, Toolbar, NotificationCenter, WorktreeDialogs, ReviewHub).

## Applies when

- Hosting any `lazy()`/`Suspense` palette or dialog gated on `{isOpen && <Comp/>}` where the component uses `useAnimatedPresence` / `AppDialog` / `AppPaletteDialog` — the exit animation silently never plays unless the host wraps with `useKeepMounted`.
- A modal or palette "closes instantly" with no exit transition even though the transition code exists — inspect the host's mount gate before the component's animation code; the closed render is what is missing.
- Adding `useKeepMounted` to a new surface — verify no prop is cleared in the same store `set()` as `isOpen` (latch it if so), and gate every side-effecting effect on `isOpen`.
- Deciding whether to keep-mount a component that resets selection/scroll/query state on unmount — if it has no `useAnimatedPresence` exit phase, or relies on unmount for reset, do NOT latch it (see `WorktreeOverviewModal`, `ProjectSwitcherPalette`).
- Touching `src/hooks/app/usePaletteWiring.ts` or the dialog latches in `src/App.tsx`.
