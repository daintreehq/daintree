## Context

The sidebar and assistant (`HelpPanel`) panels in `AppLayout` have a 250ms `ease-out-expo` `transition-[width]` on their container so collapse/expand toggles and double-click resets animate smoothly. Both panels also support pointer drag-resize: a handle's `mousedown` attaches `mousemove`/`mouseup` listeners that write a new width on every move.

## Problem

During a drag-resize the rendered panel edge lagged behind the pointer. The 250ms width transition was firing on _every_ `mousemove` — each move set a new target width that the transition then eased toward over 250ms, so the edge chased the cursor through a continuous animation instead of tracking it 1:1. The intended fix is to gate the transition class off only while a drag is in progress (`!isSidebarResizing && "transition-[width] ..."`), keeping it for toggles.

## Root cause

Two non-obvious traps, both in `AppLayout.tsx` / `Sidebar.tsx`:

1. **React 19 batching defers the class strip past the first move frame.** The drag-start setter `setIsSidebarResizing(true)` runs inside the `mousedown` handler, but React 19 batches the resulting re-render. The transition-gating class is therefore still in the DOM when the first synthetic `mousemove` writes the first new width — producing one eased frame at the start of every drag. Wrapping the setter in `flushSync(() => setIsSidebarResizing(true))` forces the re-render (and class removal) to commit synchronously inside the `mousedown` handler, before any move fires.

2. **Unmount-mid-drag leaves the parent's gate flag stuck `true` forever.** The drag listeners live on `document` and `onResizeEnd` is only called from the `mouseup` handler / `stopResizing`. If `Sidebar` unmounts mid-drag (e.g. `currentProject` becomes null on project switch), the listener-cleanup effect removes the `document` listeners but `mouseup` never arrives, so `onResizeEnd` never fires and `AppLayout`'s `isSidebarResizing` stays `true` — silently killing the collapse/expand animation for the rest of the session. The fix is an unmount-only effect that calls `onResizeEnd` if a drag is live. It cannot read `isResizing` state (the cleanup closure captures a stale value) nor `onResizeEnd` directly (empty-dep effect would close over a stale prop), so both are mirrored through refs: `isResizingRef` (set synchronously in `startResizing`/`stopResizing`) and `onResizeEndRef` (updated each render in a separate no-dep effect).

## Lesson

- When a CSS transition must be _suppressed for the duration of a pointer drag_, the class that gates it must leave the DOM before the first `mousemove`. A plain `setState` in the `mousedown` handler is not enough under React 19's automatic batching — wrap the drag-start setter in `flushSync` (from `react-dom`) so the gate is gone synchronously. This is the inverse of the usual advice to avoid `flushSync`; here the synchronous commit is load-bearing for the first frame.
- A drag whose end signal fires only from a `document` `mouseup` listener can be silently skipped if the component unmounts mid-drag. Always pair such a drag with an unmount-only effect that fires the same end/cleanup callback when a drag is still live. Mirror the live-drag flag and the callback through refs (not state/props) so the empty-dep cleanup reads current values without stale closures and without disabling exhaustive-deps.
- Keep the gated transition narrow (`transition-[width]`), never widen to `transition`/`transition-all` (lesson #4738). This drag-gating is renderer-side only — do NOT route it through the terminal SIGWINCH suppression machinery (`suppressSidebarResizes` / `lockResize`, lesson #4170); those are timed for the fixed-duration toggle animation and would block the final PTY dimension flush.

## Applies when

- Adding or debugging pointer drag-resize on a panel/sidebar/splitter that _also_ has a CSS width/height transition for non-drag changes (`AppLayout.tsx`, `Sidebar.tsx`, `HelpPanel.tsx`, any future resizable region).
- A resize handle "chases" or lags the cursor, or there's one eased/janky frame at the very start of a drag.
- Wiring `onResizeStart`/`onResizeEnd` (or any drag-lifecycle) callbacks from a child handle up to a parent that toggles a gating flag/class.
- A toggle animation (collapse/expand, double-click reset) mysteriously stops animating for the rest of a session after a project switch or component teardown — suspect a drag/transition flag left stuck `true` because an unmount skipped its end callback.
- Any React 19 code where a state update inside an event handler must be reflected in the DOM _before_ a subsequent synchronous event in the same gesture — candidate for `flushSync`.
