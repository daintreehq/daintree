## Context

`files:read` (`electron/ipc/handlers/files.ts`) reads a renderer-supplied file path for the file viewer, gated by a containment check that the file must live under `rootPath`. The original guard normalized both paths with `path.normalize` and did a `startsWith(root + path.sep)` string-prefix comparison, then `fs.readFile`'d the path.

## Problem

The string-prefix containment guard let a renderer escape the project root via symlinks: a symlink _inside_ the root pointing at `/Users/me/.ssh/id_rsa` passes the prefix check (its own path is under root) but `readFile` follows the link and returns secrets. Even with canonicalization, a symlink swapped in on the final path component _after_ the check still wins the read (classic TOCTOU). Null bytes in the path reached the OS as a raw `ERR_INVALID_ARG_VALUE` instead of being rejected up front.

## Root cause

Three independent gaps, each requiring a different layer to close:

- **Symlink traversal:** a lexical `startsWith` check only inspects the string, not what the path resolves to. `fs.realpath` on _both_ `rootPath` and `filePath` before the prefix check forces OS-level canonicalization, so a symlinked file resolves to its real target and fails containment.
- **Final-component TOCTOU:** realpath closes the window for intermediate components but not the last one — between `realpath(filePath)` and `open`, an attacker can replace the final component with a symlink. Opening with `fs.constants.O_RDONLY | fs.constants.O_NOFOLLOW` makes the _kernel_ refuse a final-component symlink at `open()` time, raising `ELOOP`, which is mapped to `OUTSIDE_ROOT`. Note `open` uses the original `filePath` (not `realFile`) so O_NOFOLLOW actually guards the user-supplied path. On Windows `O_NOFOLLOW` is `0` (no-op); realpath containment is the only line of defense there.
- **path.normalize was a liability, not just dead code:** once realpath is present, `path.normalize` is redundant — and removing it incidentally removes the Windows legacy device-name bypass surface (CVE-2025-27210), where normalize can collapse paths in ways that defeat prefix containment. Null-byte rejection belongs at the schema layer (`FileReadPayloadSchema` in `electron/schemas/ipc.ts`, `regex(/^[^\x00]*$/)`), not as an OS error catch.

## Lesson

For any IPC handler that reads a renderer-supplied path under a containment root:

- Canonicalize **both** root and target with `fs.realpath` before comparing; never trust a lexical `startsWith`/`path.normalize` containment check against raw strings — it ignores symlinks.
- Close the final-component TOCTOU window by opening with `O_RDONLY | O_NOFOLLOW` and mapping `ELOOP` (from both realpath circular-link and O_NOFOLLOW open rejection) to your `OUTSIDE_ROOT` failure. Open the original user path, not the realpath, or O_NOFOLLOW guards the wrong thing.
- Reject null bytes (and cap length) at the Zod schema layer so the FS never sees them; don't rely on catching `ERR_INVALID_ARG_VALUE`.
- Distinguish error provenance: a missing **root** is a caller misconfiguration → `INVALID_PATH`; a missing **file** → `NOT_FOUND`. Don't let a generic `fsErrorToAppError` downgrade a bad root to NOT_FOUND.
- Handle the `root === path.sep` degenerate case explicitly (`realRoot + path.sep` becomes `"//"` and never prefix-matches).
- `O_NOFOLLOW` is `0` on Windows — treat realpath as the sole containment guarantee on that platform.

## Applies when

- Adding or auditing any IPC handler that reads/writes a renderer- or agent-supplied filesystem path constrained to a project root (`files:read`, file diff, copy-tree, recipe/preset import, plugin file access).
- Reviewing a path-containment check that uses `path.normalize` + `startsWith` / substring matching — flag it; it is symlink-blind and (with normalize) carries the CVE-2025-27210 Windows device-name surface.
- Writing code that reads a file after a path-validation check (TOCTOU between check and open).
- Touching `FileReadPayloadSchema` or other path-bearing IPC payload schemas in `electron/schemas/ipc.ts` — null-byte and length limits belong here.
- Cross-platform path-security work where O_NOFOLLOW behavior differs (no-op on Windows).
