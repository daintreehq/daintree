## Context

Daintree runs a local MCP server (`electron/services/McpServerService.ts`, now split into the `electron/services/mcp-server/` module) bound to `127.0.0.1` so external agents (Cursor, Claude Desktop, Codex) can drive the Actions system over SSE and Streamable HTTP. It exposes a `/sse` GET, a `POST /messages`, and a `/mcp` endpoint, guarded by an auto-generated persisted bearer token.

## Problem

A loopback-only HTTP server feels safe, but a malicious web page the user visits can POST to `http://127.0.0.1:45454` from the browser (the browser resolves a hostile domain to 127.0.0.1 — classic DNS rebinding) and drive the agent. Naively rejecting that by enforcing an allowlisted `Origin` would break every legitimate non-browser MCP client, because those clients send **no `Origin` header at all**. A plain string bearer comparison also leaks token length/prefix via a timing side-channel.

## Root cause

- DNS-rebinding protection on a localhost server is real and required; binding to 127.0.0.1 only stops remote network access, not a browser on the same machine.
- Browsers always send `Origin`; CLI/desktop MCP clients (Cursor, Claude Desktop) send none. So the gate must be: `Host` must equal `127.0.0.1:<port>`/`localhost:<port>`, and `Origin` must be **absent OR loopback** — never "Origin required". See the authoritative manual gate at `httpLifecycle.ts:763-780` (`handleRequest`): bare `127.0.0.1` with no port is now rejected too.
- The MCP SDK's `SSEServerTransport`/`StreamableHTTPServerTransport` `{ enableDnsRebindingProtection, allowedHosts, allowedOrigins }` options are **deprecated as of SDK ^1.27.1** (inline comment at `httpLifecycle.ts:985-986`). They're still passed for belt-and-suspenders, but the app's own `handleRequest` check is authoritative — relying on the SDK option alone is a future footgun.
- Constant-time compare must hash both sides first (`createHash("sha256")...digest()` then `timingSafeEqual` on the digests, plus an explicit `length === length` guard) so a length mismatch doesn't throw or short-circuit — see `tierAuth.ts:isAuthorized`/`resolveTokenTier`.
- Node's server-level `requestTimeout` kills long-lived SSE connections indiscriminately. The fix is an **app-level idle timer per session that resets on each JSON-RPC message** (`MCP_SSE_IDLE_TIMEOUT_MS` in `mcp-server/shared.ts`, `createIdleTimer`/`resetIdleTimer` in `sessionStore.ts`), with `timer.unref()` so it never pins the event loop.
- Secret config files (`~/.daintree/mcp.json` and its dir) must be `0600`/`0700`, and the chmod is applied to the temp file **before** the atomic rename (`electron/utils/fs.ts:111-133`, `resilientAtomicWriteFile`'s `{ mode }` option) so the destination is never briefly world-readable under the default umask.

## Lesson

- A localhost-bound HTTP server is NOT exempt from DNS-rebinding defense. Validate `Host` against the exact loopback host:port, and validate `Origin` as "absent or loopback" — never require `Origin`, or you break non-browser clients.
- Do the DNS-rebinding/Origin gate in your own request handler. Treat any MCP-SDK `enableDnsRebindingProtection` option as deprecated/advisory only; your code is authoritative.
- Compare secrets in constant time by hashing both sides to fixed-length digests and using `timingSafeEqual` with an explicit length guard — never `===` on the raw header, never `timingSafeEqual` on raw unequal-length buffers (it throws).
- For long-lived streams (SSE), don't use Node's `requestTimeout`; implement a per-session idle timer that resets on activity and `unref()`s.
- When atomically writing a sensitive file, pass `{ mode }` to `resilientAtomicWriteFile` so the chmod lands on the temp file pre-rename; `chmod` the parent dir to `0700`. Skip silently on Windows (`process.platform === "win32"`) — POSIX modes are ignored there, no platform branch needed at the call site beyond the helper's own guard.

## Applies when

- Adding or hardening any local HTTP/SSE/WebSocket server in the main or a utility process (MCP server, `DevPreviewProxyService`, OAuth loopback, dev-preview proxy, any `http.createServer` bound to 127.0.0.1).
- Touching `electron/services/mcp-server/` — especially `httpLifecycle.ts` (`handleRequest`, `/sse`, `/messages`, `/mcp`), `tierAuth.ts` (bearer/tier auth), or `sessionStore.ts` (idle timers).
- Implementing bearer/token/HMAC verification anywhere — reach for hash-then-`timingSafeEqual`, not `===`.
- Reasoning about why MCP clients are getting 403/401 (a client that sends no `Origin` should pass; a browser page hitting the loopback port should 403).
- Writing secrets or credentials to disk and needing 0600/0700 — use `resilientAtomicWriteFile`'s `{ mode }` option (`electron/utils/fs.ts`).
- Choosing a timeout strategy for a long-lived connection where Node's blunt `server.requestTimeout` would sever a healthy stream.
