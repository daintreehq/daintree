## Context

The pty-host runs as an Electron UtilityProcess. Daintree once designed a zero-copy terminal I/O path over `SharedArrayBuffer` + `SharedRingBuffer`: visual render buffers, a signal buffer, and a per-terminal analysis buffer that a renderer Web Worker (`src/workers/semantic.worker.ts`, driven by `SemanticAnalysisService`) polls for agent-state / artifact detection. PR #10338 was a per-subsystem steady-state memory audit; among ~20 small wins it removed the wasted spawn of that semantic Worker.

## Problem

On every app/view boot a renderer Web Worker was constructed and immediately terminated, for nothing. `useSemanticWorkerLifecycle` calls `semanticAnalysisService.initialize()` unconditionally on mount, so it looked like a semantic-analysis pipeline was running — but it never had data to process, so the Worker construction + teardown was pure per-boot waste. Nothing crashed or was user-visible; only a memory audit surfaced it.

## Root cause

**SharedArrayBuffer cannot be transferred to/from an Electron UtilityProcess via `postMessage`** — Chromium's structured clone throws "An object could not be cloned," on all platforms (documented inline in `electron/services/PtyClient.ts`). Because the pty-host _is_ a UtilityProcess, the **entire SAB transport is dead in production**: `PtyClient.getSharedBuffers()` hardcodes empty, `getAnalysisBuffer()` hardcodes `null`, `isSharedBufferEnabled()` hardcodes `false`, so IPC handler `terminal.getAnalysisBuffer` always resolves `null`.

`SemanticAnalysisService.doInitialize()` used to `new Worker(semantic.worker.ts)` **first**, then `await getAnalysisBuffer()`, then `worker.terminate()` when the buffer came back null — spinning the Worker up and tearing it down every boot. The fix fetches the buffer first and `return`s before constructing the Worker when it's null. Since the buffer is _always_ null in production, the Worker is now never constructed — the renderer semantic pipeline is dormant, and agent-state detection actually runs in the pty-host's `AgentStateService` (passive heuristics via `shared/utils/agentFsm.ts`), not this Worker.

## Lesson

- **SharedArrayBuffer never crosses the Electron UtilityProcess `postMessage` boundary — structured clone throws "could not be cloned," on every platform.** The pty-host is a UtilityProcess, so any design handing a SAB to/from it (zero-copy render buffers, analysis buffers, ring buffers) is a non-starter in production. `getSharedBuffers()`/`getAnalysisBuffer()`/`isSharedBufferEnabled()` are hardcoded empty/null/false for exactly this reason — treat them as source of truth, not stubs to fill in.
- **The SAB zero-copy path is intentionally-preserved dead skeleton, tagged `FUTURE_SAB` — do NOT delete it in a dead-code sweep.** `electron/pty-host/backpressure.ts` (`FUTURE_SAB_MAX_*` caps), the pty-host Priority-2 SAB branch in `electron/pty-host.ts` (~L985, "This entire branch is unreachable in production"), and `SharedRingBuffer` are kept for a potential Worker-thread migration reviving per-consumer-isolated zero-copy. Production routes terminal I/O through MessagePort (Priority 1) with IPC fallback; the SAB init-buffers message only fires from adversarial tests.
- **When a precondition is effectively always-null in production, check it BEFORE allocating the expensive resource, not after.** The bug was the classic "allocate-then-validate" inversion: construct the Worker, discover the buffer is null, terminate it. Ordering the cheap async check first turned a guaranteed per-boot Worker spawn+teardown into one IPC call. Any `initialize()` that eagerly creates a Worker/subscription/timer before confirming it has data to feed deserves this reorder.
- **The renderer `semantic.worker.ts` + `SemanticAnalysisService` are dormant in production — don't route new agent-detection features through them.** They only run if a real analysis buffer arrives, which the UtilityProcess constraint guarantees never happens; passive detection already lives in the pty-host's `AgentStateService`.
- **A memory audit's biggest wins are often "runs then no-ops," not leaks.** #10338 also stopped returning the full generated copytree string over IPC (structured-cloned in, then dropped by the renderer), bounded/swept `forgeQueryCache`, and pruned per-owner maps on owner-death events. Reusable shapes: prune a map in the handler that fires when its key's owner disappears; never send data across a boundary the receiver drops.

## Applies when

- Designing or "reviving" any SharedArrayBuffer / zero-copy path touching the pty-host or any Electron UtilityProcess — it fails with "could not be cloned"; use MessagePort/IPC, or migrate the consumer to a Worker thread first.
- Doing a dead-code / unused-export sweep and finding `FUTURE_SAB`-tagged constants, the pty-host SAB branch, `SharedRingBuffer`, or the semantic Worker — deliberate skeleton, keep it.
- Touching `SemanticAnalysisService`, `useSemanticWorkerLifecycle`, or `getAnalysisBuffer`, or adding agent-state/artifact detection — the renderer Worker never gets data in production; route through the pty-host `AgentStateService`.
- Reviewing any `initialize()`/setup that constructs a Worker, subscription, or buffer before awaiting the check that decides whether it's needed, or auditing steady-state memory for resources spawned-then-torn-down and state cloned-then-dropped across IPC.
