## Context

Daintree's E2E shards emit machine-readable failure artifacts so `stabilize.yml` (and the `stabilize` skill) can tell real regressions from flakes. Two scripts fed this over the shared `test-results/report.json`: `scripts/ci/extract-failures.mjs` builds the "failing specs" list with dedup signatures, and the now-removed `scripts/ci/classify-e2e-failures.mjs` bucketed each failure Infrastructure / Test-Logic / Product-Logic. PR #10199 fixed the extractor (issue #10059); PR #10207 fixed the classifier (issue #10037).

## Problem

Three independent CI-triage defects, all pointing the wrong way. (1) Windows shards' `failure-report.json` was never uploaded — the artifact silently vanished, so Windows failures never appeared in the triage list. (2) Tests that failed then passed on retry were reported as hard failures, dragging every recovered flake in a red shard into the issue indistinguishable from real breakage. (3) A re-run of failed jobs couldn't refresh the report (409), leaving stale attempt-1 data. Separately, the classifier bucketed the failure class that matters most — a renderer crash — as a benign harness flake or dropped it entirely.

## Root cause

The extractor walked every result _attempt_ and pushed a row for any `status !== "passed"/"skipped"`, so recovered flakes and `interrupted` teardown kills counted as failures. The fix gates on the test-level outcome instead: `test.status === "unexpected"` (falling back to the final attempt only when `status` is absent). Playwright resolves each test to `expected` / `unexpected` / `flaky` / `skipped`, but a flaky test's individual attempts still carry `status: "failed"`, so per-attempt logic can never distinguish it. The Windows drop was a `/tmp` trap: the bash step wrote `/tmp/failure-report.json`, but on `windows-latest` bash is Git Bash (MSYS `/tmp`) while `actions/upload-artifact@v7` is a Node action resolving that POSIX path against the current drive root — and `if-no-files-found: ignore` swallowed the miss; every sibling artifact already used workspace-relative paths. The 409 was `upload-artifact` v4+ per-run immutability: a same-named re-upload conflicts, so `failure-report-*` needed the `-attempt-${{ github.run_attempt }}` suffix its `failed-specs-*` sibling already carried, plus dedupe-by-latest-attempt downstream. A bonus signature bug: `normalizeError` flattened backslashes (`BSLASH_RE`) _before_ matching `WIN_PATH_RE`, so drive-letter paths (`C:\a\<repo>`) never normalized and one failure signed differently on Windows vs. Linux — fixed by `.replace(PATH_RE,"<path>")` before flattening and again after.

The classifier's defect (#10207) is the same family — reasoning over the wrong signal — and its three sub-bugs are captured in the classifier Lesson bullet below. The classifier was later removed wholesale in `69069ac31` as unconsumed (emitted every shard, read by nothing), so its _code_ is gone — but the traps recur on any re-implementation (the commit explicitly defers "a working classifier later").

## Lesson

- **Gate CI failure reporting on Playwright's resolved `test.status`, never per-attempt `result.status`.** `test.status === "unexpected"` is a real failure; `"flaky"` is a recovered flake to skip; a flaky test's individual attempts still read `"failed"`, so per-attempt logic reports noise. Fall back to the last attempt only when `test.status` is absent.
- **Bash writes to `/tmp` that a Node action (`actions/upload-artifact`) later reads do not survive `windows-latest`** — Git Bash `/tmp` is an MSYS mapping the Node action can't resolve. Always write CI artifacts to workspace-relative paths (`test-results/…`); mirror the sibling steps rather than inventing a `/tmp` path, and don't trust `if-no-files-found: ignore` to be loud about a miss.
- **`upload-artifact` v4+ artifacts are immutable per workflow run; a same-named re-upload 409s.** Any artifact that must survive "Re-run failed jobs" needs an `-attempt-${{ github.run_attempt }}` suffix plus `continue-on-error: true`; consumers dedupe by latest attempt per shard or stale attempt-1 rows survive a green re-run.
- **When building a failure _classifier_, verify every match string against the harness source, not the platform you assume produced it.** Playwright puts `Page crashed` / `Navigation failed because page crashed!` / `Target crashed` on `error.message` (`playwright-core/coreBundle.js`); Electron's own `WebContents crashed` never reaches the report. Under first-match-wins, order rules by _diagnostic severity_ (crashes before stale-ref/timing noise), not just specificity, and keep `interrupted` in the status guard — the worker-death crash class, most severe and easiest to drop.
- **Normalize before you flatten.** Matching `WIN_PATH_RE` after `BSLASH_RE` flattened `\`→`/` left drive-letter paths un-normalized, diverging dedup signatures across OS. Run the path replacement before _and_ after the backslash flatten.

## Applies when

- Touching `scripts/ci/extract-failures.mjs` / `extract-failed-specs.mjs` or the "Extract failure signatures" step in `e2e.yml`, or adding any consumer of `failure-report-*` / `failed-specs-*` artifacts.
- Reasoning about Playwright test outcomes in tooling — distinguishing hard failures from recovered flakes (`test.status`: `unexpected` vs `flaky`), or handling `interrupted` results.
- Writing a bash step whose output a Node-based Actions step later uploads, on any matrix including `windows-latest` — the `/tmp` path won't resolve.
- Naming a re-uploadable artifact, or debugging a `409`/stale-report on "Re-run failed jobs" — check for the `-attempt-${{ github.run_attempt }}` suffix.
- Re-implementing or extending the E2E failure classifier (removed in `69069ac31`; #10207 / #10037 hold the design) — verify crash regexes against `playwright-core`, order first-match rules by severity, keep `interrupted` in scope.
