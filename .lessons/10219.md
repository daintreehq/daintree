## Context

The quick switcher ranks terminals and worktrees by an MRU list (`terminal:<id>` / `worktree:<id>` ids, capped at `MRU_MAX_SIZE = 50`). Focus flows through `rendererStoreOrchestrator` subscription 1c → `recordMru(...)` → a debounced `persistMruList`; deliberate worktree selections call `persistMruList` immediately. Persistence originally wrote one global `appState.mruList`, and `useQuickSwitcher` prunes stale entries against whatever items the current project view has built.

## Problem

For anyone with more than one project, saved MRU ordering silently regressed: switch to project A and project B's entries vanished; deliberately promoting a worktree could be lost inside the debounce window; focusing a browser or dev-preview pane quietly evicted real terminal entries. No crash, no error — just persisted state you couldn't trust across multi-project use. #9922 bundled all four, each small alone but compounding.

## Root cause

Four independent coordination defects in the record → prune → persist pipeline:

1. **Stale-args debounce clobbers a fresher immediate write.** `debounce(persistMruList, …)` fires with args captured at schedule time, not live state. A focus scheduled the persist with a snapshot; a deliberate worktree selection then called `persistMruList` immediately with the fresher list; the debounce fired last with the stale snapshot and overwrote it (the dedupe guard saw it differed from last-persisted and wrote it through).

2. **Global list pruned against a single view's items self-destructs.** `appState.mruList` was one global list, but each view's `useQuickSwitcher` prunes every entry not in _its own_ items. Hydrating project A strips project B's entries in-memory, and the next focus persist writes the gutted list globally — permanent. The fix scopes storage to the validity check: MRU moved to per-project `ProjectState.mruList`, read on hydrate and on switch (`buildSwitchHydrateResult`), written via `enqueueProjectStateUpdate` to the IPC-resolved project.

3. **Pruning a category before it hydrates guts restored order.** Panels and worktrees hydrate on different ticks — the worktree provider applies snapshots via `startTransition`, `hydrateMru` is a direct set — so one category loads while the other is still empty. The old prune ran against that partial set and dropped the unloaded category. The fix (`useQuickSwitcher.ts`): skip while `items.length === 0`, and protect a whole category (`terminal:` / `worktree:`) until at least one item of that type exists (`hasTerminalItems` / `hasWorktreeItems`).

4. **Recording filter didn't mirror the consumer filter.** Subscription 1c recorded `terminal:<focusedId>` for _every_ focused panel, but the switcher only shows `isPtyPanel` panels. Browser/dev-preview/review focus (and `excludeFromPersistence` help/overlay terminals) wrote entries the switcher never shows, eating the 50-cap and evicting real ones. The fix guards 1c on `isPtyPanel(panel)` + `excludeFromPersistence !== true` + `hasPty !== false`.

## Lesson

- **A debounced write called with a state snapshot is a stale-capture bug the moment any other path writes the same target immediately.** `debounce(fn, ms)` fires with the _last args passed_, not current state, so a concurrent immediate write gets overwritten by a later flush carrying an older snapshot. Use a zero-arg thunk reading live state at fire time (`() => fn(store.getState().field)`).
- **Never prune a global/shared persisted list against a partial or scoped view of what's valid.** If the validity check is per-view but the storage is global, opening one scope destroys every other scope and the next persist makes it permanent. Scope the _storage_ to the _validity check_ — here per-project `ProjectState.mruList`.
- **Writing per-project state from an IPC handler needs the IPC context to resolve which view sent it** (the same channel arrives from different project `WebContentsView`s): resolve via `resolveProjectForHydration(ctx)` and register with `typedHandleWithContext`, not `typedHandle`.
- **During async hydration, an "invalid because absent" check fires against a half-loaded set — protect not-yet-loaded categories.** `items.length === 0` or a single-category set is a hydration artifact, not ground truth; gate destructive prune/reconcile on "at least one item of this category exists." And in migration, distinguish "not yet migrated" (`undefined` → fall back) from "legitimately empty" (`[]` → authoritative), or a fallback resurrects deleted state.
- **A recorder must apply the same filter as its consumer, or it pollutes a capped list with unrenderable entries.** Recording `terminal:<id>` for panels the switcher (`isPtyPanel`) never shows wastes the 50-cap and evicts real entries — mirror the consumer's predicate at the record site.

## Applies when

- Touching `rendererStoreOrchestrator` MRU persistence (`debouncedPersistMruList`, subscription 1c), or any `debounce(fn, ms)` where a separate path also writes the same persisted target — check for stale-args capture.
- Moving persisted state between global (`appState.*`) and per-project (`ProjectState.*`) scope, or wiring a handler that writes per-project state (needs `IpcContext` + `typedHandleWithContext`).
- Writing a prune/reconcile effect that removes entries "not in the current set" while the set hydrates asynchronously.
- Diagnosing "my MRU / recent-list ordering silently reset after switching projects," or recording focus into any capped list (`MRU_MAX_SIZE`) whose record predicate may not match the consumer's display predicate.
