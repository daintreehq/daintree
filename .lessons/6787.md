## Context

`FixedDropdown` (`src/components/ui/fixed-dropdown.tsx`) supports a `keepMounted` mode that wraps the dropdown body in React 19.2 `<Activity mode={visible ? "visible" : "hidden"}>` instead of unmounting on close. The comment at lines 39-44 spells out the contract: state (Virtuoso scroll, filter selections) survives across open/close cycles, while effects re-fire on each reveal so SWR revalidation still runs. `GitHubListItem` rows render inside this dropdown and own a transient `copied` flag that flips a checkmark for ~2s after the user copies an issue/PR number.

## Problem

After copying a number, closing the GitHub dropdown, and reopening it, the success checkmark was still showing on the previously-copied row even though nothing was copied this session. The transient "copied" indicator leaked across reopen.

## Root cause

Under `keepMounted`, hiding the dropdown sets the `<Activity>` subtree to `mode="hidden"` (`display: none` + paused effects) rather than unmounting it. Pre-Activity, hiding a dropdown unmounted the body, which reset `useState` for free; that reset was an implicit side effect of unmounting, not anything anyone wrote. With Activity the component stays mounted, so `const [copied] = useState(false)` keeps its last value across the hide/reveal. The fix adds `setCopied(false)` to the effect _setup_ (not the cleanup) so it runs on every reveal — Activity re-fires effects on reveal, so setup is the place that reliably re-runs while the component itself never remounts.

## Lesson

- When a component lives inside an `Activity`/`keepMounted` subtree, the "unmount resets my state" assumption is gone. Any transient/ephemeral UI flag (copied checkmark, just-saved badge, one-shot armed state, transient error) must be explicitly reset in an effect's setup body so it clears on each reveal.
- Reset in the effect _setup_, not the cleanup return. Activity pauses then re-fires effects on reveal; setup runs on reveal, cleanup runs on hide. Resetting in cleanup would clear it on the way out (cosmetically fine here) but the canonical, reveal-time reset belongs in setup.
- Auditing trigger: any component rendered under `keepMounted`/`<Activity>` that holds `useState` representing a moment-in-time flag rather than durable data is suspect. Durable selection/scroll state is exactly what `keepMounted` is for — don't reset that; only reset the ephemeral flags.
- This is the same class of leak as #8001 (Activity-hidden portaled tooltips strand ghosts) — Activity's "hidden but mounted" semantics keep surfacing state that previously died with the unmount.

## Applies when

- Adding or modifying any component that renders inside `FixedDropdown` with `keepMounted` (GitHub dropdowns, toolbar dropdowns, filter popovers) or directly inside a `<Activity>` wrapper.
- A transient UI indicator (copy checkmark, "saved", armed/confirm state, inline transient error) persists incorrectly after a dropdown/popover is closed and reopened.
- Reviewing `useState` for boolean/transient flags in components under an Activity subtree — confirm there's a setup-time reset.
- Converting an existing unmount-on-close dropdown to `keepMounted` and reasoning about what state will now survive across open/close cycles.
