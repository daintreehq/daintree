## Context

Dev Preview parses the first URL a dev server prints on stdout (e.g. `Local: http://localhost:5173/`) and immediately points the Electron webview at it.

## Problem

Intermittent white-screen on panel startup. The webview fired `did-fail-load` with `ERR_CONNECTION_REFUSED` and never recovered.

## Root cause

Every major dev server — Vite, Next.js, Webpack Dev Server — prints its URL _before_ its HTTP listener is ready to accept connections. The gap is tens to hundreds of milliseconds and widens on cold starts. Pointing the webview at the URL the instant it appears in the terminal is a guaranteed race on fast machines with slow server startups.

## Lesson

After detecting a URL, poll the server before transitioning to `running`. The readiness logic lives in `electron/services/DevPreviewReadinessProbe.ts` (`waitForServerReady`, `READINESS_TIMEOUT_MS=30000`, `READINESS_POLL_INTERVAL_MS=500`); `DevPreviewSessionService.pollServerReadiness` wires it onto the session. Use GET, not HEAD — GET sidesteps the "405-to-HEAD" quirk entirely, so classify by status: 2xx–3xx is ready, 5xx is "still warming" (re-probe, since dev servers transiently 5xx mid-compile), and 4xx (plus connection errors/timeouts) is fail. Do NOT treat 4xx as ready. Build a multi-host candidate list — when the URL host is `localhost`, also probe `127.0.0.1` and `[::1]`, because the server may bind only one stack. Once an HTTP probe reports ready, confirm with `probeHmrWebSocket` (tries `vite-hmr` subprotocol on `/`, `/_next/webpack-hmr`, `/ws`) so the page won't load against a half-started HMR socket. Cancel the poll on session stop, restart, terminal exit, or new URL detection via the session's `readinessAbort: AbortController`. The `waitForServerReady(...).then(...)` continuation must guard with BOTH a generation check (`session.generation !== generation`) and a signal-identity check (`session.readinessAbort?.signal !== signal`) so a stale poll completion cannot flip a newer session to running. When dead terminals are respawned, clear stale readiness state (`pendingUrl`, `readinessAbort`, `markerSeen`) so the new session re-polls from scratch.

## Applies when

Wiring any component to a local dev server URL discovered from stdout, or debugging intermittent white-screen / `ERR_CONNECTION_REFUSED` on Dev Preview startup.
