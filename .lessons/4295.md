## Context

Canopy writes session snapshots, terminal state backups, and config files continuously during normal operation. Running out of disk space can silently corrupt these files.

## Problem

No proactive warning existed. Users would hit corruption or silent write failures only after their disk was already full.

## Root cause

Not a bug fix — this is a pattern lesson from the implementation design.

## Lesson

**Hysteresis is required for threshold-based warnings.** Without it, a disk hovering around the warning boundary generates a notification storm: warn → user frees space → falls back below → warn again. The `DiskSpaceMonitor` uses separate enter/exit thresholds: escalation uses the enter values (`WARNING_MB` 2000, `CRITICAL_MB` 500); de-escalation requires crossing back above the exit values (`WARNING_EXIT_MB`/`CRITICAL_EXIT_MB`, each enter + 50MB), plus a 30-minute notification cooldown.

**Suppress non-essential writes at critical level** rather than showing another notification. At the critical level (<`CRITICAL_MB`) `DiskSpaceMonitor` sets a process-wide `writesSuppressed` flag via `setWritesSuppressed` in `electron/services/diskPressureState.ts`; non-essential main-process writers (`logger`, `ProjectStore`, `TelemetryService`, `GitHubStatsCache`/`GitHubFirstPageCache`, `ScratchCleanupService`, and `db.ts` backups) re-read `getWritesSuppressed()` at write time and bail. This preserves the write budget for critical config saves.

**Cross-process propagation is a known gap, not yet wired.** `diskPressureState` is explicitly per-process (see its header comment): `DiskSpaceMonitor` only runs in the main process, so the utility-process hosts (pty-host, workspace-host) currently keep their own `writesSuppressed = false` and keep writing. Forwarding the flag to those hosts via IPC is a tracked follow-up (issue #6271). When implemented, propagate via IPC — never shared memory across the process boundary.

`fs.statfs()` (Node.js 18+) is the correct API for available bytes; it's available in Electron's main process without additional native modules.

## Applies when

- Any threshold-based monitoring (disk, memory, CPU)
- Deciding whether to skip non-critical writes during degraded conditions
- Propagating degraded-mode flags across the main/utility-process boundary (when the consumer lives in a host process, the per-process flag must be forwarded via IPC)
