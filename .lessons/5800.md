## Context

A terminal panel spawned with `kind="terminal"` (no `agentId`) gets a plain shell: `DEFAULT_SCROLLBACK`, pool-stripped env, no `FORCE_COLOR`, cursor-blink on. Later the `AgentPatternDetector` may see an agent (Claude/Gemini/Codex) appear inside that live shell. Cold-spawned agent panels (`agentId` set at spawn) already start with the agent profile, so they need no repair.

## Problem

When detection promotes a plain terminal to "hosting an agent", the natural instinct is to make it equivalent to a cold-spawned agent panel — set env vars (`FORCE_COLOR`, larger buffers), maybe respawn. Both are wrong: env written into a live PTY does not propagate to the already-running agent child process, and a transparent respawn would SIGHUP the in-flight agent and lose its work.

## Root cause

The PTY environment is _spawn-sealed_: env and the child process tree are fixed at spawn and cannot be mutated for a running child. Promotion is therefore split — the parts owned by the renderer's xterm instance are repairable in-process; the parts baked into the PTY at spawn are not. `applyAgentPromotion(id, agentId)` (`src/services/terminal/TerminalInstanceService.ts:2208`) is the in-process repair surface: it sets `runtimeAgentId`, applies the cursor-blink policy, grows scrollback (`restoreScrollback`), and re-evaluates WebGL eligibility. It deliberately does NOT touch env — there is no API that could. The promotion decision is gated in `identityReducer.ts` (`shouldPromoteAgentId`, line 94) and dispatched from `src/store/listeners/panel/identity.ts:229`; the inverse `clearAgentPromotion` restores plain-terminal policy on agent exit.

## Lesson

Treat a runtime-promoted terminal as permanently _partially_ repaired, never fully equivalent to a cold-spawned agent panel. Only renderer-side xterm policies (scrollback, cursor-blink, WebGL context) are mutable post-spawn; PTY env and color flags are sealed. The correct UX for full parity is an explicit user-initiated respawn-with-`agentId` (the `convertTerminalType` path), not a silent env patch or transparent respawn. Distinguish the two terminal classes by presence of a spawn-time `agentId` vs a runtime-only `detectedAgentId`/`runtimeAgentId` — they are not interchangeable.

## Applies when

Adding any behavior that should differ for "a terminal running an agent" — before applying it, ask whether the property was sealed at PTY spawn (env, color flags, child process tree) or lives in the renderer xterm instance (scrollback, cursor, renderer addons). Sealed properties can only be fixed by a user-initiated `convertTerminalType` respawn; wire renderer-mutable ones through `applyAgentPromotion`/`clearAgentPromotion` so background promotions and agent-to-agent switches stay consistent.
