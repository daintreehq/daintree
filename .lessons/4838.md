## Context

Daintree runs multiple polling services in the main process (WorkspaceService git status, ProjectStatsService, process-tree polling). These poll at fixed intervals regardless of whether the app window is focused or the device is on battery.

## Problem

Background polling consumed unnecessary CPU/battery when the user was working in another app. All polling services ran at full rate even when the window was minimized or out of focus.

## Root cause

No backgrounding/throttling logic existed. The polling services had a binary `setPollingEnabled()` suspend/resume (for when the window is completely hidden) but no intermediate throttle for "backgrounded but still alive" state.

## Lesson

Electron provides app-level `browser-window-blur`/`browser-window-focus` events and `powerMonitor` battery events (`on-battery`/`on-ac`) as the canonical mechanism for background throttling. The pattern:

1. Wire `setupWindowFocusThrottle(deps)` (`electron/window/powerMonitor.ts`) to the `app.on("browser-window-blur")`/`app.on("browser-window-focus")` events (blur is debounced via a `blurTimeout` so alt-tab churn doesn't thrash).
2. Register polling services via the `WindowFocusThrottleDeps` getters; each exposes its own poll-interval setter (`updatePollInterval`, `updateMonitorConfig`, `setProcessTreePollInterval`).
3. On blur, `applyThrottle()` multiplies each service's normal interval by `THROTTLE_MULTIPLIER` (5); on focus, `removeThrottle()` resets the interval and fires a one-shot `refresh()`.
4. Layer on top of the existing binary suspend/resume (`setPollingEnabled(false)`) — don't replace it.

Battery-state throttling is handled separately in `ResourceProfileService` (`electron/services/ResourceProfileService.ts`), which listens to `powerMonitor` `on-battery`/`on-ac` and adapts the resource profile.

For UtilityProcess services (PTY host), drive the interval via an IPC call (`ptyClient.setProcessTreePollInterval`) since the UtilityProcess doesn't share event subscriptions with the main window.

The one-shot refresh on refocus is critical for UX: users expect stale data to update immediately when they switch back.

## Applies when

- Adding a new polling service: register it via `WindowFocusThrottleDeps` in `setupWindowFocusThrottle` and expose a poll-interval setter that `applyThrottle`/`removeThrottle` can drive.
- Any service that polls at a fixed interval — background throttling should be the default, not an afterthought.
