## Context

`TerminalPane` uses an `IntersectionObserver` (rooted at the grid scroll container, or the viewport in dock/popout mode) to drive per-terminal visibility: the callback writes `isVisible` to the store, which feeds the computed refresh tier. A terminal marked hidden is capped at the `BACKGROUND` tier — output ingest is throttled and rendering effectively stops. This was one of the five freeze layers in the #9777–#9781 investigation (capstone watchdog: #9796).

## Problem

Terminals that were plainly, fully on-screen would freeze their output until clicked. The trigger correlated with load, not layout: nothing had scrolled, resized, or re-parented. The store showed `isVisible=false` for an element whose bounding rect was entirely inside the grid — i.e. the observer had reported something visibly untrue, which is not a failure mode most code accounts for.

## Root cause

`IntersectionObserver` computes intersection geometry at frame-end and delivers callbacks asynchronously; under main-thread contention a delivered entry can reflect geometry from several frames prior. So a terminal that was momentarily occluded/mid-layout frames ago produces `isIntersecting=false` _now_, when it is fully visible. The old callback wrote that value straight to the store — one stale `false` capped the terminal at `BACKGROUND` and nothing ever re-reported (IO only fires on threshold _changes_, and from the observer's stale viewpoint nothing changed). The freeze persisted until click-wake.

The fix (#9780 → this PR) is `isStaleHiddenReading` in `src/components/Terminal/visibilityReadingGuard.ts`: on a `false` reading only, re-measure synchronously and suppress the write iff the element's fresh rect genuinely overlaps the observation root (axis-aligned bounding-box test). Every design detail exists to dodge a specific counter-trap: (1) `true` readings are always committed immediately — only hides get double-checked, so promotion latency is untouched. (2) The AABB test is against the _root_, not merely "has a layout box" — a terminal scrolled off the grid keeps its full width/height, so a dimensions-only test would wrongly suppress legitimate hides and strand hidden terminals at a high tier. (3) Geometry, not `intersectionRatio` — sub-pixel rounding reports ratio < 1 for fully visible elements. (4) `getBoundingClientRect` is read BEFORE any visibility write — measuring after `setVisible(false)` would force a redundant layout reflow. (5) The callback consumes only the _latest_ batched entry per invocation (`entries[entries.length - 1]`) — processing the whole batch replays stale history. (6) No rect / zero-size / unmeasurable root all fall through to trusting the reading, so the guard fails toward the observer, never toward suppressing real hides.

## Lesson

- **Treat `IntersectionObserver` hidden readings as unverified claims under load.** IO geometry can be frames stale; any consumer that _demotes_ on `isIntersecting=false` (visibility tiers, lazy-unmount, virtualization, render throttling) must confirm against fresh synchronous geometry before committing.
- **Verify against the observation root, not element dimensions.** An element scrolled out of a scroll-container root keeps its layout box; only an element-rect × root-rect overlap test distinguishes "stale false" from "genuinely scrolled away".
- **Asymmetric trust: commit shows immediately, double-check hides.** The failure cost is asymmetric (a wrong hide freezes output; a wrong show costs a few frames of rendering), so only the dangerous direction pays the re-measure.
- **Order reads before writes in the same handler** — a `getBoundingClientRect` issued after a store write that dirties layout forces an extra reflow. The guard takes rect-getter thunks precisely to keep measurement ahead of mutation.
- **Use the last entry of an IO callback batch.** Chromium batches entries per target; iterating them all re-applies superseded states. Only `entries[entries.length - 1]` reflects the newest observation.

## Applies when

- Building or reviewing anything that gates rendering, mounting, polling cadence, or data flow on `IntersectionObserver` — terminal tiers, lazy panels, virtualized lists, image/dev-preview lazy-load.
- Diagnosing an element that stops updating while visibly on-screen, correlated with heavy load, and recovers on interaction — check for a stale `isVisible=false` committed to the store.
- Touching `TerminalPane`'s visibility observer or `visibilityReadingGuard.ts` — every branch of `isStaleHiddenReading` guards a distinct counter-trap; removing one reintroduces a specific bug listed above.
- Assuming a platform observer API reports current truth at delivery time — IO, ResizeObserver, and rAF-batched measurements can all lag the DOM under main-thread contention.
- Writing tests for visibility logic: the interesting cases are stale-false-on-screen, scrolled-off-with-full-dimensions, zero-size, unmounted, and unmeasurable-root (see `visibilityReadingGuard.test.ts`).
