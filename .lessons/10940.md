## Context

The Daintree Assistant is a `location: "overlay"` panel hosting a CLI agent (Claude Code by default) in a slide-out sidebar. Every PTY spawn goes through one shared path, `addPanel.ts`, and every pane's reveal geometry goes through `TerminalResizeController.reconcileGeometryFresh` plus its backstop, `TerminalReconciliationWatchdog`. #10940 is the second and final fix for #10863 (`5272596ab` only closed the switch-back half); it builds on #10632's `isAltBuffer` guard and the reveal-repaint machinery from #9637/#10693.

## Problem

Opening the Assistant on a main-buffer CLI intermittently painted its startup banner, MCP-auth lines, and tips blockquote TWICE, with box-drawing characters composited straight through existing words. The same CLI worked fine in a standalone terminal and in the grid, which correctly pointed at the terminal layer but wrongly suggested an Assistant-only bug — the actual defect (`addPanel.ts` hardcoding `cols: 80, rows: 24` for every spawn) is completely universal, it just never manifested anywhere else.

## Root cause

`addPanel.ts` spawns every PTY at a hardcoded 80x24 and lets the renderer's own attach-fit correct it afterward. Grid and dock panels never notice: `TerminalPane.tsx` only mounts `XtermAdapter` once `spawnStatus === "ready"` (unless `eagerAttach`), so their fit-driven resize always targets an already-registered PTY. The Assistant sets `eagerAttach` and mounts immediately, so its `XtermAdapter` can attach and fit while `terminalClient.spawn()` is still an in-flight promise — the resulting resize can race the spawn. `PtyManager.pendingResizes` (added months earlier, `3c8b4c6fc`/`eca717980`, "buffer pre-spawn resizes to fix renderer/spawn race") already buffers a resize arriving before an id is registered and applies it as boot dims — but it clearly didn't close this repro, since the bug shipped and needed this separate renderer-side fix, and #10940's body never references that buffer.

Compounding: even once the grid is right, `reconcileGeometryFresh` re-measures on every reveal and resizes xterm when cols/rows drifted. Ink-style CLIs repaint their sticky region with cursor-relative erase math that assumes a stable width; a genuine column delta landing AFTER the startup block is committed re-wraps that scrollback and duplicates/garbles it instead of cleanly overwriting it.

## Lesson

- **A shared code path's bug can be invisible everywhere except the one caller that violates an implicit ordering invariant.** Every panel spawns through the same `addPanel.ts` 80x24 default; only the overlay panel's `eagerAttach` (mount-before-`spawnStatus:"ready"`) exposed it. When one panel/location misbehaves and siblings on the same code path don't, look for what ordering guarantee that location alone skips, not what's special about its code.
- **When racing a debounced resize path, bypass the debounce for the compensating call, don't just retry through it.** The fix's post-spawn re-assert calls `terminalClient.resize()` directly instead of `sendPtyResize()`, because `sendPtyResize`'s settled-strategy path defers 500ms — exactly the window the CLI paints its banner in. Retrying through the same debounced entry point would have reproduced the race it was meant to close.
- **A write-quiescence predicate used by two different reconcilers must be the exact same function, not two similar checks.** `hasStreamingWrites()` (300ms `REVEAL_REWRAP_QUIESCENT_MS`, or `pendingWrites > 0` for a still-parsing first batch) is shared verbatim between `TerminalResizeController.reconcileGeometryFresh` and `TerminalReconciliationWatchdog`'s deferral check; if they diverge, the watchdog either burns breaker attempts on ticks `reconcileGeometryFresh` was always going to no-op, or repairs panes it should have deferred.
- **A deferred repair attempt is not a failed attempt — don't charge it against a circuit breaker.** The watchdog's `streamingDeferred` check skips `WATCHDOG_MAX_GEOMETRY_REPAIR_ATTEMPTS` accounting and the repair-cooldown stamp entirely, and still falls through to the cheaper render-pause/WebGL recovery layers below it — deferring the expensive check must not starve the unrelated cheap ones.
- **Before adding a new defensive layer for a race a prior PR already patched at a different process boundary, say explicitly why the old one doesn't cover your case.** Two independent "buffer/re-assert a raced resize" mechanisms now coexist (pty-host `pendingResizes`, renderer `addPanel.ts` re-assert) with no cross-reference — a future reader can't tell if they're redundant or each close a different sub-window without re-deriving it, which is what this lesson had to do.

## Applies when

- Adding a panel kind/location whose renderer mounts `XtermAdapter` before `spawnStatus` flips to `ready` (i.e. sets `eagerAttach`) — the 80x24 `addPanel.ts` spawn default is only safe under the "attach after ready" invariant every other panel relies on.
- Diagnosing duplicated or garbled CLI startup output, or Ink-style TUI repaint artifacts, after a project-view reveal, panel reopen, or slide-out animation.
- Touching `TerminalReconciliationWatchdog.ts`'s geometry-repair breaker or `TerminalResizeController.ts`'s `reconcileGeometryFresh`/`hasStreamingWrites` — a change to one predicate must be checked against the other's consumer.
- Investigating "a resize was silently dropped because the terminal didn't exist yet" — check `PtyManager.pendingResizes` (`electron/services/PtyManager.ts`) first, then confirm empirically it actually covers your repro before layering a renderer-side workaround on top.
