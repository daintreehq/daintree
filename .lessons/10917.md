## Context

`IdentityWatcher`/`ProcessDetector` passively infer whether a terminal runs an agent CLI from output text and `ps`-based process-tree/foreground-group probes — Daintree never touches user-owned agent config, so detection is purely observational (CLAUDE.md "Agent config boundary"). Detected identity drives the panel icon, activity state, and the scrollback policy (`TerminalScrollbackController`, which sizes xterm's `options.scrollback` differently for agent vs. plain terminals). #10917 (issue #10911) hardened that pipeline after Codex 0.142.5 was observed flapping detected↔plain every few seconds. #10928 fixed a sibling flap in the same `ActivityMonitor` family: mouse-wheel scroll in a full-screen TUI flipping idle→working.

## Problem

A Codex terminal's icon/activity indicator flickered between the OpenAI logo and a generic terminal icon, and every flip destroyed most of the scrollback (view jumped to top mid-scroll). Reproduced reliably on slow hardware, once unreproducibly on fast hardware via a `cx!` alias launch. Separately, wheel-scrolling inside a running full-screen TUI (mouse reporting on) briefly flipped state to "working" while the user was only reading — the SGR mouse-report bytes made the TUI redraw, and `ActivityMonitor`'s content-delta heuristic read the redraw as agent work.

## Root cause

Four independent fail-open defects in the same pipeline, any one sufficient to flap:

1. **Stale probe read.** The foreground-process-group probe (`ps -o pgid=,tpgid=`) times out at 750ms/goes stale after 1500ms; a null reading unconditionally mapped to `{ shellIdle: true, supported: false }` — the exact gate a false prompt match needs to demote a live agent. Fix: a latched `sawForegroundSnapshot` flag, set only on a real (non-`INITIAL_FOREGROUND_SENTINEL`) reading. Once set and an agent is committed, a later null read fails **closed** (`shellIdle: false`); a terminal where the probe never worked (Windows) still falls open, unchanged.
2. **Regex couldn't distinguish agent chrome from a shell prompt.** `DECORATED_SHELL_PROMPT_PATTERN` (`/^\s*[➜➤➟➔❯›]\s+.*$/`) exists for oh-my-zsh-style prompts, but Codex 0.142.5 renders in the normal buffer with its composer placeholder and every echoed message starting `› `. Fix: while an agent identity is committed, matching swaps to `DECORATED_SHELL_PROMPT_PATTERN_NO_AGENT_GLYPHS` (drops `❯`/`›`, keeps `➜➤➟➔`) — a state-gated exclusion since those glyphs are legitimate elsewhere.
3. **Typed/aliased agents were never anchored.** A terminal where the user typed `codex` directly (no `launchAgentId`) starts `isLaunchAnchored = false`, so any transient process-tree gap could demote it via the off-streak. Fix: once tree evidence (`process_tree`/`both`) corroborates a runtime-promoted agent, `ProcessDetector.setLaunchAnchored(true)` latches it; shell-command-only evidence deliberately does not anchor.
4. **Asymmetric guards on a shared destructive write.** Every demotion calls `restoreScrollback()`, shrinking `options.scrollback` from the agent ceiling (~5000) to the plain policy (~300-2000). In xterm 6.1 that shrink triggers `Buffer.resize`, which `trimStart()`s the excess **immediately and irreversibly** — re-promotion restores the option, not the lines. `restoreScrollback` had none of sibling `reduceScrollback`'s guards (focus, scrolled-back, alt-buffer, selection, cooldown), so any flap destroyed history. Fix: apply the same guards, but only when the write would actually evict used lines; growth stays unguarded.

#10928 is the same shape: `ActivityMonitor`'s content-delta heuristic had 8 promotion sites gated on `isFocusSuppressed`, but the mouse-report-redraw path wasn't also gated on `isRecentUserInput` — even though `InputTracker` already stamped `lastUserInputAt` from those same bytes via `notifyInput`. The signal existed, it just wasn't consulted at every site.

## Lesson

- **A "no reading" result from a flaky external probe is not evidence of the state you fall back to — track whether the probe has EVER worked, then fail closed once it has.** `sawForegroundSnapshot` latches on the first genuine (non-sentinel) reading and only changes behavior once a wrong guess would be destructive.
- **A regex meant to detect "the other program's UI" needs re-auditing every time a new program joins the roster — glyph overlap is not a corner case.** `❯`/`›` are legitimate oh-my-zsh chrome AND Codex's composer marker; gate the exclusion on state (`agentCommitted`), don't strip the glyph globally.
- **A destructive side effect and its trigger conditions age at different rates — audit siblings together, not just whichever one you're editing.** `reduceScrollback` had focus/scroll/selection/cooldown guards; `restoreScrollback`, the same underlying write on the demotion path, had none because it was added later and never diffed against its sibling.
- **When a heuristic gates on "recent input" or "recent focus," enumerate every promotion/demotion call site and grep for the check at each one.** #10928 added `isRecentUserInput` to the one branch among 9 similar `ActivityMonitor.ts` sites missing it, plus two direct-promotion paths (`TerminalProcess`/`AnalysisSession` `noteAgentOutputActivity`) that bypass `ActivityMonitor` entirely.
- **Anchoring must key on the evidence tier that corroborated a commit, not on the commit existing.** `setLaunchAnchored(true)` fires only on `process_tree`/`both` evidence; shell-command-only evidence stays unanchored so a mistyped/aliased command can still demote normally.

## Applies when

- Touching `IdentityWatcher.ts`, `ProcessDetector.ts`, or `ForegroundProcessGroupProbe.ts` — prompt-pattern matching, foreground-probe interpretation, or launch-anchoring.
- Diagnosing an agent's detected identity/icon/activity-state flapping, especially for a CLI rendering in the normal buffer (no alt-screen) with lines resembling a shell prompt.
- Adding or reviewing promotion/demotion heuristics in `ActivityMonitor.ts`, `AgentStateService`, or `TerminalProcess`/`AnalysisSession` — confirm `isRecentUserInput`/`isFocusSuppressed` is checked at every site, not just the primary one.
- Reviewing any path that shrinks `terminal.options.scrollback` or trims a buffer as a state-transition side effect — verify it carries the same guards as its sibling in `TerminalScrollbackController.ts`.
- Writing a probe/poll wrapper where "no result" and "confirmed-negative" collapse into one fallback branch — consider whether a latched "ever got a real reading" flag changes the correct fallback.
