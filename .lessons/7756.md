## Context

`GitFileWatcher` (`electron/utils/gitFileWatcher.ts`) watches each worktree's working directory to drive event-based git status refresh (the mechanism from #3623). With multiple worktrees open, every worktree spins up its own recursive watcher in the workspace-host utility process.

## Problem

On macOS, worktree watching hit `EMFILE` (too many open files) under multi-worktree load and silently stopped delivering events — stale git status with no actionable error. The previous mitigation (#3623) was retry-with-backoff and a timer fallback, which treated the symptom rather than the fd leak.

## Root cause

Node's `fs.watch({ recursive: true })` looks fd-cheap but on macOS libuv's FSEvents backend allocates a file descriptor **per watched directory** in the subtree. A large repo × several worktrees blows past the per-process fd ceiling. Two compounding costs were invisible until scale:

1. **Per-directory fd allocation** — recursive `fs.watch` is not "one watch = one fd"; deep trees consume hundreds of descriptors each.
2. **JS-side ignore filter pays the cross-boundary cost** — the old `IGNORED_WORKTREE_DIRECTORY_NAMES` Set filtered `node_modules`/`dist`/`.git` events _in the JS callback_, meaning every ignored event still crossed the native→V8 boundary and ran string-prefix checks before being discarded.

`@parcel/watcher` 2.5.6 (`subscribe()`) uses native FSEvents through N-API: **one stream per subtree, zero per-directory fds**, and its `{ ignore: [...globs] }` option filters natively so `node_modules`/`.git`/build-output events never cross into V8. The fix replaces the recursive `fs.watch` with `parcelWatcher.subscribe(path, cb, { ignore: WORKTREE_IGNORE_GLOBS })`.

The tradeoff: `@parcel/watcher` **silently drops overflow events on every platform** (macOS `kFSEventStreamEventFlagMustScanSubDirs`, Linux `IN_Q_OVERFLOW`, Windows `ERROR_NOTIFY_ENUM_DIR`) and has **no equivalent to `fs.watch`'s null-filename "global dirty" signal**. That null-filename path was the old code's way of forcing a full rescan on coalescing/overflow. `WorktreeMonitor`'s polling fallback (`electron/workspace-host/WorktreeMonitor.ts`) is what now catches missed events — it is mandatory, not optional.

## Lesson

- Never use `fs.watch({ recursive: true })` for large/deep trees on macOS — it leaks per-directory fds and silently dies with `EMFILE` under multi-instance load. Use `@parcel/watcher` (one native FSEvents stream per subtree).
- Push ignore filtering **into the native layer** (`{ ignore: glob[] }`), not a JS callback. A JS-side filter still pays the full native→V8 crossing cost for every event it discards. Globs are `**/node_modules/**` form; include both `**/.git` (the linked-worktree pointer file) and `**/.git/**`.
- When migrating off `fs.watch`, you **lose the null-filename "global dirty" overflow signal**. `@parcel/watcher` drops overflow events silently on all three platforms. A periodic polling fallback (here `WorktreeMonitor`) becomes load-bearing, not a nice-to-have safety net — do not remove it.
- `subscribe()` is async (returns a Promise); the watcher is fire-and-forget. Startup failures (ENOSPC/EMFILE) arrive via the Promise rejection, not a synchronous throw — route them through the same error callback chain. Guard the resolved subscription against a `disposed`-during-startup race (call `unsubscribe()` if disposed before the Promise settles).
- macOS fd-ceiling errors from native FSEvents may surface as a CoreServices **error string, not an `errno` code** — gate on `code === "EMFILE"` first, then fall back to message matching (`/file.*descriptor|descriptor.*limit/i`).
- `@parcel/watcher` is a native N-API module: add it to the esbuild `external` array in `scripts/build-main.mjs` (alongside `node-pty`, `better-sqlite3`) so it isn't bundled, and it rebuilds via the `postinstall` hook like other native modules.

## Applies when

- Adding or modifying file-system watching anywhere in `electron/` (worktree, project root, dev-server output, plugin asset dirs).
- Diagnosing `EMFILE` / "too many open files" on macOS, or stale git status / worktree panel not updating under many open worktrees.
- Considering `fs.watch({ recursive: true })` over a directory that may contain `node_modules` or be deeply nested.
- Touching `GitFileWatcher.startWorktreeWatcher`, `WORKTREE_IGNORE_GLOBS`, or `handleWorktreeWatcherError`.
- Adding a new native N-API dependency (must be externalized in `scripts/build-main.mjs` and rebuilt for Electron).
- Relying on a watcher to deliver every change — remember overflow events are dropped silently; pair with a polling fallback.
