## Context

Sidebar toggle animates a slot width over 250ms (`SIDEBAR_TOGGLE_LOCK_MS`). The panel-grid `<main flex:1>` reflows every frame as the flex container redistributes space, so any component that measures its own width via a `ResizeObserver` and commits that width into inline/`grid-template-columns` styles fires once per frame during the slide. `src/lib/layoutTransitionLock.ts` is the process-wide signal (`isSidebarLayoutTransitionLocked()` + `subscribeSidebarLayoutTransitionUnlock()`) introduced in #6979 to suppress those mid-animation renders for the multi-panel grid (`useContentGridContext`).

## Problem

`TwoPaneSplitLayout` (the exactly-two-panel split) was a _third_ consumer of the same reflow signal and had never been wired to the lock. It kept committing mid-transition `leftWidth`/`rightWidth` values into the panes' inline `width` styles, re-snapping the right pane edge every frame and producing visible right-edge jitter on sidebar toggle (#7825) — the identical symptom #6979 had already fixed elsewhere.

## Root cause

The lock is a _subscription_ pattern, not an ambient global that auto-suppresses observers — each ResizeObserver consumer must individually check `isSidebarLayoutTransitionLocked()` inside its rAF callback and skip the `setState`, then re-measure on the unlock subscriber. When a new consumer is added without that wiring, it silently regresses. Two corners are easy to miss:

- **Stranded width on unlock.** While locked the observer drops all entries, so after the animation completes no further RO entry fires unless the outer container changes again. The unlock subscriber must force one final `clientWidth` re-measure or the pane widths stay frozen at their pre-animation value.
- **Drag in flight at unlock.** If a divider drag is active when the lock releases, resyncing `containerWidth` shifts the `minRatio`/`maxRatio` clamp bounds and snaps the live ratio. The unlock resync must defer (set `pendingResyncAfterDragRef`) and run on the next drag-end edge instead.

Note the lock is only half the suppression: `sidebarToggle.ts` fires _both_ `lockSidebarLayoutTransition()` (stops React layout re-renders) **and** `terminalInstanceService.suppressResizesDuringLayoutTransition()` (stops xterm from resizing the PTY host). They address different layers — neither subsumes the other.

## Lesson

Any new component in the panel-grid region that derives geometry from a `ResizeObserver` (grid width, column count, pane pixel widths) and commits it into layout styles MUST subscribe to the sidebar transition lock, not assume it inherits suppression:

- Inside the rAF-deferred RO callback, early-return on `isSidebarLayoutTransitionLocked()` before `setState`.
- Skip the initial `clientWidth` measurement if the lock is already active at mount.
- Register a `subscribeSidebarLayoutTransitionUnlock()` listener that forces one final re-measure (rAF-deferred), re-checking the lock inside the rAF (a second toggle can start within the ~16ms gap).
- If your component has an in-flight interaction (divider drag, manual resize) whose clamp bounds depend on the measured width, defer the unlock resync until that interaction ends rather than overriding it mid-gesture.
- Reuse the established gate-and-resync shape from `useContentGridContext.tsx` — don't reinvent it per consumer.

## Applies when

- Adding or modifying any component under `src/components/Terminal/` (or the panel grid generally) that uses `ResizeObserver` / `useResizeObserverRaf` to measure its own width and write it into inline `width` or `grid-template-columns`.
- Investigating jitter, flicker, or edge-snapping of panes/grid columns on sidebar collapse/expand.
- Touching `src/lib/layoutTransitionLock.ts`, `src/lib/sidebarToggle.ts`, `useContentGridContext.tsx`, or `TwoPaneSplitLayout.tsx`.
- Symptoms where pane/grid widths stay frozen at a pre-animation value after a sidebar toggle (missing unlock resync), or where a live divider drag snaps when a sidebar transition completes mid-gesture.
- Adding a new split/layout variant that participates in the flex `<main>` reflow — it is a new lock consumer by default and will regress #6979/#7825 if not wired.
