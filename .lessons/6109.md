## Context

The renderer talks to the main process via `window.electron.namespace.method()`, all of which return promises. Many call sites are genuinely fire-and-forget (telemetry, console-capture start/stop, dev-server pokes, settings setters). The idiomatic way to silence the no-floating-promises lint was `void window.electron.X()`. A global `unhandledrejection` handler already existed (`reportRendererGlobalError`, PR #3678).

## Problem

`void window.electron.X()` rejections were vanishing with no stack, no log, nothing in Sentry. Even when a rejection did escape to the global handler, the reported stack pointed inside Electron's IPC plumbing — the original call site that fired the IPC was already gone. Debugging a "failed silently" report was guesswork about which of ~30 call sites fired it.

## Root cause

Two independent gaps, neither solved by the existing global handler:

1. `void` explicitly marks a promise as intentionally ignored, so its rejection is often not even routed to `window.addEventListener("unhandledrejection")` reliably — the rejection is swallowed at the `void` boundary.
2. The async hop is fatal to the stack. By the time a promise's `.catch` runs, the synchronous call frame that fired the IPC has unwound; the rejection's stack reflects where the promise settled (inside Electron), not where it was launched. You cannot recover the call site after the microtask boundary.

The fix in `src/utils/safeFireAndForget.ts` snapshots the call site **synchronously, at fire time**: `const callsiteAnchor = new Error(...)` plus `Error.captureStackTrace(callsiteAnchor, safeFireAndForget)` (which trims the helper itself off the top of the frame). When the promise later rejects, the helper stitches that anchor onto the rejection (`error.stack = ${error.stack}\nCaused by: ${anchorStack}`) before handing it to `reportRendererGlobalError`. A re-entry guard (`!error.stack?.includes("Caused by:")`) prevents double-stitching when the same shared Error constant rejects multiple concurrent callers — otherwise they'd cross-contaminate each other's call sites in the report.

## Lesson

- For fire-and-forget renderer IPC, never write `void window.electron.X()`. Use `safeFireAndForget(window.electron.X(), { context: "..." })`. It is lint-enforced: `eslint.config.js` has a `no-restricted-syntax` rule at **error** level whose selector matches `UnaryExpression[operator='void'] > CallExpression > MemberExpression:has(... window.electron ...)`. The `:has` is scoped to the callee chain on purpose so it doesn't false-positive on `void (async () => { await window.electron.X() })()` IIFEs (wrap the IIFE's promise instead).
- When you want a usable stack across an async boundary, capture it synchronously at launch with `new Error()` + `Error.captureStackTrace(anchor, fn)` and stitch it onto the eventual rejection. After the microtask boundary the originating frame is unrecoverable — a global `unhandledrejection` handler alone cannot tell you where the call came from.
- A global rejection handler (PR #3678) is necessary but not sufficient: it catches escapees but loses call-site provenance, and `void`-marked rejections may never reach it at all.
- If a shared/broadcast Error can reach your stitcher more than once, guard against re-stitching (sentinel substring check) so concurrent callers don't inherit each other's stacks.
- `no-floating-promises` was added in `src/**` at **warn** as a ratchet (with `allowForKnownSafeCalls` for `safeFireAndForget` and `ignoreVoid: true`); the `void window.electron.*` ban at error is what actually forces IPC through the wrapper. Don't "fix" a floating-promise warning by adding `void` to an IPC call — that re-introduces the swallowing.

## Applies when

- Adding or reviewing any fire-and-forget `window.electron.*` call in the renderer; seeing the lint error pointing at `safeFireAndForget`.
- A renderer async failure is reported as "silent" / "no stack" / lands inside Electron IPC internals with no app frame.
- Designing any cross-async-boundary error reporting where you need the originating call site (worker postMessage, setTimeout callbacks, event-listener-fired promises) — snapshot the stack synchronously at launch.
- Touching `rendererGlobalErrorHandlers.ts` / `reportRendererGlobalError`, or wiring renderer rejections into Sentry.
- Refactoring an IIFE-style `void (async () => {...})()` in the renderer — wrap the IIFE's returned promise, don't leave the `void`.
