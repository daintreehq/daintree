## Context

`daintree-cli.sh` is a bundled shell script that allows opening projects in Daintree from the terminal. It needs to locate the Daintree binary to pass the project path to the running app. The `--status` flag worked, but the project-opening path failed on all Linux installs.

## Problem

The Linux fallback used `command -v daintree` to locate the binary. This fails in both distribution formats:

- **AppImage**: The binary runs from a FUSE-mounted path (`/tmp/.mount_*/daintree`) — not in `$PATH`. The AppImage runtime sets `$APPDIR` (and `$APPIMAGE` to the outer image path), but the script didn't use them.
- **.deb**: Installs to `/opt/Daintree/daintree` — the package created no symlink in `/usr/bin/` so `command -v` found nothing.

The failure message was "Daintree executable not found" with no indication of which lookup strategy failed.

## Root cause

Single-strategy binary discovery assumes `$PATH` is always populated — valid on macOS (the .app bundle is in a well-known location) but wrong for Linux's diverse distribution formats.

## Lesson

Linux binary discovery needs a **multi-strategy ordered candidate list**:

```bash
for candidate in \
  "$(dirname "$(dirname "$SCRIPT_PATH")")/daintree" \
  "${APPDIR:-}/daintree" \
  "/opt/Daintree/daintree" \
  "/opt/Daintree/daintree-app"; do
  if [[ -n "$candidate" && -x "$candidate" ]]; then
    DAINTREE_BIN="$candidate"
    break
  fi
done
command -v daintree  # final PATH fallback
```

For `.deb` packages, always include a `postinst.sh` (`build/linux/postinst.sh`) that creates a `/usr/bin/daintree` symlink, and a `postrm.sh` (`build/linux/postrm.sh`) that cleans it up on remove/purge. Wire both into `electron-builder`'s deb config via `afterInstall`/`afterRemove` (`electron-builder.config.cjs`). Without a PATH symlink, users must know the exact install path.

## Applies when

Any Electron app distributed on Linux via AppImage and/or .deb. The AppImage runtime sets `$APPDIR` (the mounted root) and `$APPIMAGE` (the outer image path) automatically — derive the binary from the script's own location or `$APPDIR` rather than relying on `$PATH`.
