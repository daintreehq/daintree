## Context

Daintree's copy-tree path writes `text/uri-list` buffers to the clipboard so users can paste files into file managers (`electron/ipc/handlers/copyTree.ts:401`). It also watches git worktree directories to detect external changes (`electron/utils/gitFileWatcher.ts`).

## Problem

Pasting into Nautilus/Dolphin/Thunar silently failed. Separately, on busy repositories the file watcher stopped firing with no actionable error.

## Root cause

Two distinct issues. (1) `text/uri-list` requires RFC 2483 format: each URI must be a proper `file:///` URL (not a raw absolute path) and each line must be terminated with CRLF (`\r\n`). Using plain paths with `\n` is rejected by GTK and Qt file managers. (2) File watching on Linux consumes inotify watches from two limits — `fs.inotify.max_user_watches` AND `fs.inotify.max_user_instances`. When either is exhausted, watch creation throws `ENOSPC` synchronously OR the watcher emits an `error` with that code. There is a parallel macOS failure: FSEvents exhausts the per-process file-descriptor ceiling and surfaces `EMFILE`. Silent catches left watchers dangling and users with no clue why nothing updated.

## Lesson

For Linux clipboard `text/uri-list`: always produce URIs via `pathToFileURL()` from `node:url`, and terminate each entry with CRLF (`electron/ipc/handlers/copyTree.ts:400-401`). For directory watching: handle the limit error in both the synchronous throw (startup) path AND the async `error` event, and log an actionable message naming both `fs.inotify.max_user_watches` and `fs.inotify.max_user_instances` with the `sysctl -w` transient fix and `/etc/sysctl.d` persistent fix. In `gitFileWatcher.ts` this is centralized in `GitFileWatcher.handleWorktreeWatcherError(error, phase)`, which branches on `process.platform`/`code` and emits `LINUX_INOTIFY_LIMIT_HELP` (ENOSPC) or `MACOS_EMFILE_LIMIT_HELP` (EMFILE). The recursive worktree watch now uses `@parcel/watcher` (native FSEvents on macOS, so per-directory fd exhaustion is eliminated — the EMFILE guard remains as a fallback gated on `code === "EMFILE"` plus a message regex); plain `fs.watch` is still used for the individual git metadata files (HEAD, packed-refs, logs/HEAD, config, index) via the `watchFile()` helper. The dual-limit (watches + instances) and dual-phase (sync throw + async error event) guidance is what stays load-bearing.

## Applies when

Writing to the system clipboard with file URI payloads on Linux, or creating any recursive directory watch (parcel/watcher or fs.watch) that may run on developer machines with large repositories, on Linux (inotify) or macOS (FSEvents fd ceiling).
