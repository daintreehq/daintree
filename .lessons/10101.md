## Context

`sanitizeEvent` in `electron/services/TelemetryService.ts` is the single Sentry `beforeSend` scrubber for both main- and renderer-originated events (renderer events forward to main via `@sentry/electron` `^7.10.0`). It deep-walks string leaves with `sanitizeStringsDeep` (secret patterns + home-dir paths). Issue #10047 audited it after #6399/#7095 and found three gaps; #10101 closed them. Sibling PR #10084 fixed the analogous IPC-boundary leak (see `.lessons/10084.md`).

## Problem

Three routes past the scrubber: (1) parsed `request.url` — the `new URL()` success branch cleared search/hash/username/password then assigned `u.toString()` back unscrubbed, while the catch branch (unparseable input) ran `sanitizeString` — so absolute URLs preserved `/Users/alice/...` and token-shaped path segments while relative ones got scrubbed, an inverted safety gradient; (2) `event.tags` / `event.user` / `event.contexts` were deliberately skipped, justified by a prose comment (from #6399) listing the conditions under which skipping was safe; (3) nothing mechanical enforced those conditions.

## Root cause

The comment contract had already rotted by the time it was audited. `ErrorBoundary.componentDidCatch` and `onUncaughtError` (`src/utils/reactRootErrorCallbacks.ts`) inject `tags: { source, component }` and `contexts: { react: { componentStack } }`, and `CaptureOptions` in `src/utils/rendererSentry.ts` accepts `tags`/`contexts` from any renderer caller. Crucially, `@sentry/electron`'s renderer→main event forwarding merges renderer scope into the event BEFORE main's `beforeSend` runs — so by the time `sanitizeEvent` sees the event, the "we never set these" fields already carry caller-supplied data (React 19 builds `componentStack` from native `Error().stack` frames, URLs included). The omission was safe only under an invariant list no tooling checked, and renderer code had violated it silently — exactly the failure mode the original comment warned about.

The fix deep-walks `tags`/`user`/`contexts` with `sanitizeStringsDeep`, scrubs the normalized URL (`sanitizeString(u.toString())` in the try branch), and converts the comment contract into a `no-restricted-syntax` ESLint ban on `setTag`/`setUser`/`setContext` outside TelemetryService. The flat-config mechanic that makes the ban non-trivial: `no-restricted-syntax` options are last-write-wins PER RULE across config blocks — a later block configuring the rule completely replaces an earlier block's selector array — so the ban had to be replicated verbatim into all six blocks in `eslint.config.js` (still six today; grep `sentry-scope-setter`). The sole authorized site, `setOnboardingCompleteTag`, carries `// eslint-disable-next-line no-restricted-syntax -- sentry-scope-setter: ok`.

## Lesson

- **Scrub after normalization, in every branch.** The URL try-branch felt safe because it "cleaned" the URL (search/hash/auth), but path segments carry user paths and tokens; only the failure branch scrubbed. Any sanitize path that transforms-then-assigns must end in the scrub, and a success branch must never be weaker than its catch.
- **Renderer scope reaches main's beforeSend pre-merged.** With `@sentry/electron`, `tags`/`user`/`contexts` set in the renderer (ErrorBoundary, onUncaughtError, `CaptureOptions`) are already on the event when `sanitizeEvent` runs — a main-side scrubber can never assume those fields are process-controlled.
- **A prose invariant list guarding a scrub omission is a leak with a delay.** #6399 documented conditions instead of enforcing them; renderer error paths violated them with no warning at the call site. Either walk the field (cheap — these objects are small and `sanitizeString` is a no-op on values like `darwin`/`arm64`) or lint-ban the writes. #10101 did both.
- **Flat-config `no-restricted-syntax` is last-write-wins per rule.** A repo-wide syntax ban must be copied into EVERY block that configures the rule (six in `eslint.config.js`), or later blocks silently drop it. Same replication pattern as the notify `error`+`priority: "low"` ban.
- **Sentry's `normalizeDepth` (default 3) flattens nested containers to `"[Object]"` BEFORE `beforeSend`** — Daintree pins it to `MAX_DEEP_SANITIZE_DEPTH` (10) so the scrubber sees real values; `sanitizeStringsDeep` stops descending past the cap but still scrubs scalar strings at any depth. (The PR-era limitation that the path scrubber required a trailing slash after `/Users/<name>` was fixed later — current `electron/utils/pathScrubber.ts` matches bare trailing segments.)

## Applies when

- Touching `sanitizeEvent`, `sanitizeStringsDeep`, or any Sentry init/`beforeSend` wiring in `electron/services/TelemetryService.ts`.
- Adding renderer capture surfaces — new `CaptureOptions` callers, ErrorBoundary/onUncaughtError tags or contexts — everything attached lands in main's scrub path and must survive it.
- Wanting `Sentry.setTag`/`setUser`/`setContext` anywhere: lint-banned outside TelemetryService; annotate a reviewed site with `-- sentry-scope-setter: ok` plus rationale.
- Adding any repo-wide `no-restricted-syntax` ban to `eslint.config.js` — replicate it into every block configuring the rule or it silently vanishes.
- Reviewing a sanitizer or scrubber whose safety rests on "no call sites currently do X" comments rather than a walked field or a lint rule.
