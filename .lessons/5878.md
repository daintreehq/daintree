## Context

`TerminalWebGLManager` decides WebGL-vs-DOM by counting how many terminals currently "want" WebGL against a hysteresis threshold (`upperThreshold = 12`); it does not evict individual contexts (see #3358, #3243 for the cap rationale). The manager is dumb on purpose — its comment says "the consumer (visibility/agent gating in `TerminalInstanceService`) decides what 'wants' means; the manager just counts." `setVisible()` in `TerminalInstanceService` is that consumer, driven by the per-pane `IntersectionObserver`.

## Problem

With 10-30 agent terminals open across a grid/tab layout but only a handful actually on-screen, the want-count equals the _open_ count, not the _visible_ count. It sits permanently above the threshold, so the whole fleet is stuck in DOM mode — including the visible terminals that have GPU headroom to spare. The naive fix (release on hide, re-acquire on show) reintroduces the churn #3243 warned about: a panel/tab toggle thrashes `WebglAddon` load/unload, and each cycle reallocates GPU resources. Worse, a same-tier reparent (project switch, grid reflow) strands a terminal that released WebGL on the DOM renderer **permanently**, because the show path that would re-arm restore returns early during attach.

## Root cause

Two independent traps. (1) Want-membership must be keyed on _visibility_, not just tier — `setVisible(false)` calls `webGLManager.releaseContext(id)` (drops the want) and `setVisible(true)` calls `ensureContext(id)` (re-adds it), so the count tracks the visible fleet and the mode flips back to WebGL for what's actually on screen. (2) The reparent gap: `setVisible(true)` returns early when `managed.isAttaching` is set (`TerminalInstanceService.ts:639`), so no restore timer is armed; if the tier also didn't change, `applyRendererPolicy` is a no-op — nothing re-adds the want. The terminal is invisibly demoted to DOM forever.

## Lesson

When a count-based renderer-mode switch is driven by a consumer-defined "wants" set, the consumer MUST update membership on **visibility** transitions, not only tier transitions — otherwise the count reflects open panels, not on-screen panels, and the threshold never recovers. Guard the churn with an **asymmetric debounce**: hold the context for a dwell window on hide (`WEBGL_HIDE_DWELL_MS = 500`, `webGLHideTimer`) and wait before re-acquiring on show (`WEBGL_RESTORE_DEBOUNCE_MS = 100`, `webGLRestoreTimer`); cancel both on the opposite transition and in `destroy()`. Critically, add a **post-attach reconciliation** in the reparent path (`TerminalInstanceService.ts:1351`): after a same-tier reparent where `setVisible(true)` returned early on `isAttaching`, explicitly re-check `isVisible && !isActive(id) && shouldRestoreWebGL(managed)` and re-call `ensureContext`, or the terminal stays on the DOM renderer permanently. `shouldRestoreWebGL()` must re-validate agent identity / tier / not-attaching / not-hibernated _inside the debounce callback_, because an agent can demote during the dwell window.

## Applies when

Any per-pane GPU/heavy-resource lease driven by an `IntersectionObserver` plus a global count threshold (terminal WebGL, future canvas/WebGPU panels): membership in the "wants" set has to follow visibility, the show/hide paths need asymmetric debounce to survive rapid toggles, and every early-return on the show path (attach, hibernation, stale generation) needs a reconciliation point that re-arms the lease — early returns are where the lease silently leaks into permanent fallback.
