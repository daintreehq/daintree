## Context

`ErrorBoundary`/`ErrorFallback` (`src/components/ErrorBoundary/`) render the crash UI and let users file a GitHub issue (`buildReportIssueUrl.ts` builds the issue URL body, with a clipboard fallback when the body exceeds GitHub's 8 KiB URL cap). The "Technical details" `<details>` disclosure shows the JS stack and React component stack. `shared/utils/reportScrubbers.ts` (`scrubReportText` = path scrub + secret scrub) is the renderer-safe redaction pass — its own header says "apply at the viewer / report-builder boundary — never at the capture layer."

## Problem

The "Technical details" block was gated behind `import.meta.env.DEV`, so production builds showed only the error message and Error ID — no stack trace. Every production bug report, and every crash reporter, arrived with zero trace. The thing that makes a crash actionable was invisible exactly where it mattered most.

## Root cause

Gating diagnostic detail on `DEV` is the reflexive "safe" move (don't leak internals to users), but it's backwards for a crash fallback whose entire job is to help the user file an actionable report. The real concern isn't _whether_ to show the stack — it's _what's in it_: user home paths and secret sigils. That's a redaction problem, not a visibility problem. Two scope decisions are load-bearing and non-obvious:

- **Where to scrub:** at the viewer/report-builder boundary (`ErrorFallback` display, `buildReportIssueUrl` entry), never at capture. The main-process action-breadcrumb ring stays raw; redaction happens only when content is rendered or built into a shareable report.
- **What to scrub:** `stack` and `componentStack` only — NOT `error.message` or `context`. Scrubbing the message destroys diagnostic signal (the message is the most human-readable line of the report) and those fields were out of the leak's scope.
- **All three public destinations need the same scrub from one source:** the visible disclosure, the issue-URL `body`, and the clipboard `fullBody` fallback all end up pasted into a public issue. `buildReportIssueUrl` scrubs `stack`/`componentStack` once at function entry so the full-body, component-stack-placeholder, and middle-truncated-stack branches all inherit it.

## Lesson

- Don't `import.meta.env.DEV`-gate diagnostic output (stack traces, component stacks) on user-facing crash/report surfaces. Surface it in production, collapsed by default, and **redact** instead of hide. Keep dev raw, scrub prod via `scrubReportText`.
- Apply `scrubReportText` at the **viewer / report-builder boundary**, not the capture layer — capture stays raw so internal logs keep full fidelity.
- Scope redaction to the fields that actually carry paths/secrets (`stack`, `componentStack`). Do not scrub `message`/`context` — that costs diagnostic signal for no leak benefit.
- When the same data has multiple public exits (rendered disclosure + issue-URL body + clipboard fallback), scrub once at the single entry point so every downstream branch inherits it; don't sprinkle scrubbing per-branch.
- Render the disclosure only when `error.stack || errorInfo?.componentStack` exists, and guard the component-stack block independently so a stack-only or component-stack-only crash still renders.

## Applies when

- Touching `src/components/ErrorBoundary/` — `ErrorFallback.tsx`, `ErrorBoundary.tsx`, `buildReportIssueUrl.ts`.
- Adding or changing any user-facing crash/error/report surface that includes a stack trace, component stack, log dump, or plugin-diagnostics block destined for a public GitHub issue or clipboard.
- Reaching for `import.meta.env.DEV` to hide technical/diagnostic content from production users — reconsider whether redaction (`scrubReportText` from `@shared/utils/reportScrubbers`) is the right answer instead of hiding.
- Deciding where to apply `scrubReportText`/`scrubReportPath`/`scrubSecrets` — keep it at the render/report-build boundary, not at capture; scope it to path/secret-bearing fields only.
- Building a report body that has both a URL-embedded path and a clipboard fallback path (the 8 KiB GitHub URL cap branch in `buildReportIssueUrl`) and needing every branch to stay redacted.
