## Context

The plugin subsystem (`electron/services/PluginService.ts` plus the six collaborators under `electron/services/plugin/`, `electron/services/WhenClauseService.ts`, and `electron/services/plugin-mcp/`) was built across ~40 separate PRs (#9227–#9528). Each PR passed its own review. A dedicated consolidation pass over the integrated whole then surfaced a cluster of defects that no single-PR review could have caught, because each defect lives at the seam _between_ features: shared global state, multi-window targeting, and cross-lifecycle security state.

## Problem

Four integration-level defects, each invisible at single-PR scope:

- `WhenClauseService` evicted compiled `when`-clause AST entries from a process-global `astCache` on plugin unregister without checking whether another loaded plugin still referenced the same expression string — unloading plugin A silently broke plugin B's clause evaluation.
- `PluginService.dispose()` did not run the per-plugin disposer cascade, so service teardown / test reuse leaked contribution registrations (next load fails with duplicate-id) and never tore down event/MCP cleanups.
- `host.dispatch()` (plugin-sourced action with no source window) resolved the renderer by scanning windows in insertion order, so every dispatch landed in the _oldest_ window's project view instead of the focused one (#4641 territory).
- MCP TOFU consent pins (`PluginMcpConsentStore`) survived uninstall. Because `pluginId` is author-controlled, a same-name reinstall inherited prior "approved-and-pin" decisions and never re-prompted — a consent bypass.

## Root cause

The unifying mechanism: **state whose scope is wider than the single plugin/PR that introduced it.** A process-global AST cache keyed by expression string is shared across plugins, so deletion must be reference-counted, not owner-scoped. Renderer targeting in a multi-window app must resolve the _focused_ view (`WindowRegistry.getPrimary()`), not the first-in-iteration window. Disposal must walk every loaded plugin's full cascade with per-step containment (`PluginService.dispose` iterates `this.plugins.keys()` calling `unloadPlugin`, each wrapped so one throwing disposer doesn't strand the rest). Security/consent state keyed by an author-controlled identity must be purged on uninstall, and the purge must report flush durability (`revokeAllForPlugin` returns `boolean`) so a failed persist surfaces instead of silently rehydrating stale pins on next launch.

## Lesson

When a subsystem is assembled from many independently-authored PRs, do a deliberate holistic pass focused on **cross-feature seams**, not feature behavior:

- **Shared/global caches** (`astCache` in `WhenClauseService`): any per-owner eviction must reference-count across all current owners before deleting a shared entry. Loop over remaining `pluginExprs.values()` to confirm no other plugin still references the key.
- **Multi-window renderer targeting:** plugin/agent/MCP dispatches that carry no source window must resolve via `getWindowRegistry().getPrimary()` (focused) first, then fall back to scanning `registry.all()`, then the global `ProjectViewManager`. Never let insertion order pick the target — it picks the oldest window. Mirror the resolution order across all such bridges (`PluginRendererDispatcher.resolveActiveWebContents`).
- **Disposal:** `dispose()` must run the full per-plugin disposer cascade for every loaded plugin with per-step `try/catch` containment, so one throwing disposer doesn't leak the rest's registrations.
- **Identity-keyed security state:** when a key component is author-controlled (here `pluginId`), purge all of it on uninstall — pins _and_ orphaned revoke tombstones — and return whether the durable flush succeeded so the caller can retry/escalate rather than rehydrate stale grants. A same-name reinstall must start from `first-use`.
- Keep duplicated capability classifications in lockstep with an explicit comment cross-reference (`HIGH_RISK_CAPABILITIES` in `PluginMcpTierAuth.ts` ↔ `CONFIRM_TRIGGERING_CAPABILITIES` in `PluginService.ts`).

## Applies when

- Adding/unloading anything keyed in a process-global or cross-plugin cache (`astCache`, contribution registries, keybinding/context-menu registries under `electron/services/plugin*`).
- Writing or reviewing any main→renderer dispatch that lacks a source window (`host.dispatch`, MCP renderer bridge, agent-sourced actions) — verify it targets the focused view, not the oldest.
- Implementing `dispose()`/teardown for a service that owns N sub-entities (plugins, panels, subscriptions) — confirm every entity's cascade runs with per-step containment.
- Touching install/uninstall/upgrade flows where security or trust state (TOFU consent pins, tokens, scopes) is keyed by an author-controlled identity — confirm uninstall purges it and reports flush durability.
- Reviewing the integration of many separately-built PRs into one subsystem: audit the seams (shared state, multi-window, lifecycle, security-state survival) rather than re-reviewing each feature.
- Duplicated risk/danger capability lists that must stay synchronized between the MCP tier model and the action-danger model.
