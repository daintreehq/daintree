## Context

`TerminalProcess` had four entry points that all tore down a PTY — `kill()`, `dispose()`, `gracefulShutdown`, and the node-pty `onExit` callback — each clearing collaborators/timers and running inline forensics + `agent:completed` + fallback classification. PR #5948 collapsed them onto one `teardown(reason)` plus a `terminal:exited` event, backed by an explicit `PtyState` machine (`alive → shutting-down → exited → disposed`). Today the machine lives in `TerminalProcessLifecycle.ts` and the event fan-out in `TerminalExitObservers.ts`; `TerminalProcess` orchestrates ordering.

## Problem

Two non-obvious traps that the old implicit-boolean design papered over. First, idempotency: kill() then dispose() then a late OS-delivered onExit all reach teardown, and each must run cleanup exactly once without re-emitting `agent:killed` / re-flushing persistence. Second, id reuse: `terminal:exited` is emitted on the single process-wide `events` bus and every `TerminalProcess` subscribes to it; a respawn under the same terminal id (the prior PTY killed, a new one spawned with the same id) means the OLD PTY's exit, delivered late, would match the NEW instance's `terminalId` filter and consume its one-shot listener — silencing the new terminal's real exit.

## Root cause

Idempotency is encoded in the state machine, not a boolean guard: `lifecycle.transition({kind:"shutting-down", reason})` returns `false` for any illegal progression (same-kind, or anything past `alive`), and `teardown()` bails on `false` (`TerminalProcessLifecycle.ts:39-67`, `TerminalProcess.ts:575`). So the second caller into teardown is a structural no-op — there is no separate "already torn down?" flag to keep in sync. The id-reuse trap is solved by a per-spawn session token: `terminalInfo.spawnedAt` (a `Date.now()` set once at construction) is carried in the `terminal:exited` payload, and subscribers filter on `terminalId AND spawnedAt` (`TerminalExitObservers.ts:80-82`). The same `spawnedAt` guard is mirrored in `AgentStateService.emitAgentCompleted` (`AgentStateService.ts:270-277`) and `TerminalAgentDetection.ts:40` — id alone is never a sufficient identity for a PTY session. Third subtlety: `recentOutput` for forensics/fallback must be captured from `forensicsBuffer.getRecentOutput()` BEFORE `disposeHeadless()` and threaded through the event payload — once the headless buffer is torn down the subscriber cannot re-read it.

## Lesson

Make multi-entry teardown idempotent by gating it on a state-machine transition that returns false on illegal progression, rather than a hand-maintained boolean — the FSM is the single source of truth and the second caller becomes a no-op for free. Any singleton event bus that fans out to many same-typed instances needs a per-instance identity richer than the reused logical id; for PTYs that identity is `spawnedAt`, and every cross-cutting subscriber (exit, agent-completed, agent-detection) must filter on it or a late stale event will hijack the live instance's handler. When teardown destroys a buffer that a downstream subscriber needs, snapshot it into the event payload before destruction — don't expect the subscriber to read live state after the source is gone.

## Applies when

Adding any new code path that kills/disposes a `TerminalProcess`, or any new subscriber to `terminal:exited` (or a similar process-wide event on `electron/services/events.ts`). Reusing terminal/session ids across respawn, or debugging a "the new terminal's exit/completion event never fired" symptom after a kill+respawn under the same id. Reading exit-time terminal output (forensics, fallback classification) and finding the buffer already cleared.
