## Context

A terminal/agent panel's `worktreeId` is which worktree column the panel lives in. Users can drag a panel to a different worktree at runtime, so that placement is pure UI layout state owned by the renderer (saved panel data, persisted `appState.terminals`). The PTY backend (`PtyManager`, `TerminalProcess`, pty-host) also carried a `worktreeId` field, threaded through spawn options, snapshots, terminal info, and every `agent:*` event payload — a parallel copy of the same value frozen at spawn time.

## Problem

On reconnect/hydration the backend's stale `worktreeId` won the merge. `statePatcher`'s build functions used `saved.worktreeId ?? backendTerminal.worktreeId`, so a panel the user had dragged to another worktree mid-session snapped back to its spawn worktree after a backend restart or project switch. Two sources of truth for one piece of layout state, with the wrong one (the immutable backend copy) as the fallback authority.

## Root cause

The backend never needs `worktreeId` for terminal mechanics — node-pty only cares about `cwd`. `worktreeId` was emitted purely so consumers could route/dedup. But it duplicated state the renderer already owns and mutates, and any duplicated mutable state eventually desyncs. The two legitimate main-side consumers actually keyed on the _path_, not the id: `PreAgentSnapshotService` uses the worktree root as its git stash target, and in this codebase `worktreeId` IS the normalized absolute path — identical to the terminal's `cwd`. So `cwd` was always a sufficient, non-duplicated substitute.

## Lesson

Establish a single owner for any mutable UI-layout value and never let a process that can't author the mutation carry a copy as a fallback authority. The fix is narrower than "delete the field everywhere": `worktreeId` stays renderer-owned for layout/placement, the backend may _accept_ it once at spawn for session-history persistence, but it must never re-emit it on events as a routing source nor win a hydration merge. So PR #5176 stopped the backend _emitting_ `worktreeId` on `agent:*` events and removed the `saved.worktreeId ?? backendTerminal.worktreeId` fallback in the `statePatcher` build functions (now plain `worktreeId: saved.worktreeId` at `src/utils/stateHydration/statePatcher.ts:226,292,443,478`) — but deliberately _kept_ it as a one-time spawn input: it's still typed on `PtyHostSpawnOptions` (`shared/types/pty-host.ts:51`) and `PtyHostTerminalInfo` (`:371`), read by `PtyManager.persistAgentSession` (`electron/services/PtyManager.ts:420`) and the diagnostic `TerminalInfoPayload` build (`:560`), and carried (documented as renderer-originated, not backend-emitted) on `AgentStateChangePayload` (`shared/types/ipc/agent.ts:28`) and `ArtifactDetectedPayload` (`:115`). Main-side runtime consumers no longer trust that copy: `PreAgentSnapshotService` keys on the `cwd` threaded through `agent:state-changed` (the worktree root is its git-stash target, and `worktreeId` IS the normalized absolute path); `AgentNotificationService.resolveWorktreeIdForTerminal` (`electron/services/AgentNotificationService.ts:165`) looks it up from the IPC-synced `store.get("appState").terminals` (a brief lag behind a drag is acceptable because the failure mode is "notification not suppressed", not "fires wrongly"). For the orphan-reconnect path where no saved entry exists, `inferWorktreeIdFromCwd` (`src/utils/stateHydration/statePatcher.ts:512`) does segment-aware longest-prefix matching of `cwd` against loaded worktree paths — `normalizeForComparison` collapses `\`→`/` and trims trailing slashes (Windows node-pty returns backslashes, simple-git returns forward slashes), and the match requires `cwd === wtPath || cwd.startsWith(wtPath + "/")` so `/repo/wt-long` does NOT match worktree `/repo/wt`. Falls back to `activeWorktreeId` when inference fails so the panel still appears in the grid filter.

## Applies when

You're adding a field to a PTY/IPC/agent-event payload that the renderer also stores as layout/placement state; you see a `saved.X ?? backend.X` fallback in `statePatcher` hydration builders; a panel snaps back to a stale position after reconnect or project switch; or you need a worktree id on the main side but only have a path — derive via `inferWorktreeIdFromCwd` instead of re-emitting the id from the backend.
