## Context

Daintree recovers from GPU-process crashes on Linux Wayland hybrid-GPU machines (NVIDIA paired with Intel/AMD), where Chromium frequently picks the wrong driver and crashes. Beyond the existing 3-strike "disable hardware acceleration" fallback (#3629), this adds a softer first response: `electron/utils/gpuDetection.ts` probes `/sys/class/drm` vendor IDs, and `electron/setup/environment.ts` applies `--use-angle=vulkan` + `--use-cmd-decoder=passthrough` + `--ignore-gpu-blocklist` either proactively (hybrid detected) or reactively (after the first crash). `GpuCrashMonitorService` orchestrates the escalation via two persisted flag files.

## Problem

A single-tier "N crashes → disable acceleration" recovery is too blunt: it kills all GPU rendering on machines that only needed a different ANGLE backend. But adding a relaunch-to-apply-flags soft tier introduces two new failure modes — infinite relaunch loops (Vulkan itself crashes, or the same hybrid config keeps crashing) and per-session loops when the recovery state can't be persisted (read-only fs, permissions). Detection itself has a trap: scanning only `renderD*` nodes misses dGPUs that expose only a `card*` node, falsely reporting single-GPU.

## Root cause

The fallback works by relaunching the app with new Chromium switches, and the switches are decided at startup purely from persisted flag files (`gpu-angle-fallback.flag`, `gpu-disabled.flag`) — there is no in-memory channel across a relaunch. So correctness depends entirely on flag-file state being written _before_ the relaunch and read _before_ `app.whenReady()`. Two non-obvious consequences:

- If `app.relaunch()` fires but the flag write failed, the next session sees no flag, re-applies the same (crashing) config, and loops forever. The relaunch and the persist are a transaction: relaunch must be gated on the write succeeding.
- The soft tier must be guarded against itself. `isGpuAngleFallbackByFlag` is checked at init; if the flag is already present, the first-crash soft path is skipped so strikes accumulate toward the nuclear path instead of relaunching into ANGLE again and again.
- The ANGLE switches are only appended on Linux+Wayland, so a soft relaunch on macOS/Windows is a pure no-op that burns a session restart — the soft path early-returns on `process.platform !== "linux"` and lets the strike count toward nuclear.
- DRM detection unions `card*` and `renderD*` nodes and dedupes by vendor ID, because NVIDIA configs can expose a `card1` for the dGPU with no matching `renderD129`.

## Lesson

When recovery works by relaunching with persisted config, treat relaunch + persist as an atomic transaction and add a self-guard:

- **Never call `app.relaunch()` unless the flag write succeeded.** Wrap the write in try/catch and `return` (do not relaunch) on failure — otherwise read-only/permission errors loop every session. This rule applies identically to every escalation tier.
- **Guard each tier against re-entering itself.** Read the tier's flag at `initialize()` (before the crash listener fires) and skip that tier's relaunch if its flag is already set; let strikes fall through to the next, harsher tier.
- **Early-return the soft tier on platforms where its flags are no-ops** (here, non-Linux), so you don't spend a restart for zero behavior change.
- For Linux multi-GPU detection, read both `card*` and `renderD*` under `/sys/class/drm`, dedupe by `device/vendor`, and require `XDG_SESSION_TYPE === "wayland"`; vendor IDs are Intel `0x8086`, AMD `0x1002`, NVIDIA `0x10de`; "hybrid" = NVIDIA + (Intel or AMD).
- Keep a separate predicate (`isGpuAngleFallbackApplied`) for UI/diagnostics that returns true only when ANGLE was _actually_ engaged (Linux+Wayland, acceleration still on), distinct from the raw flag-file check, so non-Linux sessions don't show a misleading "running in ANGLE mode" state.
- On manual re-enable from Settings, clear _all_ recovery flags (both `gpu-disabled` and `gpu-angle-fallback`) so the next launch starts clean.

## Applies when

- Touching `GpuCrashMonitorService`, `gpuDetection.ts`, or the GPU/Wayland switches in `electron/setup/environment.ts`.
- Adding or modifying any Electron recovery that works by `app.relaunch()` + `app.exit()` driven by persisted flag files read before `app.whenReady()` (GPU disable, safe-mode, watchdog restart).
- User reports of relaunch loops, "app keeps restarting", or GPU crashes specifically on Linux Wayland hybrid NVIDIA+Intel/AMD laptops.
- Designing multi-tier escalation (soft retry → hard disable) where each tier relaunches; needing per-tier loop guards.
- Detecting GPU vendors via `/sys/class/drm`, or deciding whether a Linux machine is multi-GPU/hybrid.
- Any "if write fails, what happens on next launch?" reasoning around persisted recovery state on read-only or permission-restricted filesystems.
