## Context

`TerminalScrollbackController.reduceScrollback` shrinks `terminal.options.scrollback` on unfocused background terminals under memory pressure. It previously announced this by writing a yellow `\r\n\x1b[33m[Daintree] Scrollback reduced to N lines due to memory pressure...\x1b[0m\r\n` line directly into the xterm buffer via `managed.terminal.write(...)` so curious users would see why old history vanished.

## Problem

That human-facing notice landed in the live xterm buffer (`buffer.active`), and the buffer is not a write-only display surface — it is read back as an _input source_ for agent context. The injected `[Daintree]` line then surfaced in agent transcripts as if it were program output the agent had emitted, polluting the model's context on every loop.

## Root cause

`TerminalInstanceService.captureBufferText(id)` (and the identical loops at `TerminalAgentStateController.ts:264` and `TerminalInstanceService.ts:2535`) walk `managed.terminal.buffer.active`, call `line.translateToString(true)` on each line, and `stripAnsiAndOscCodes` the result. The strip removes the `\x1b[33m` color, but the _text_ `[Daintree] Scrollback reduced to N lines...` survives. That captured text feeds agent restart history (`src/store/slices/panelRegistry/restart.ts:730` captures it for agent terminals) and context injection paths in `TerminalPane.tsx` (lines 1046/1061). So anything `terminal.write()`-ed into the renderer buffer becomes indistinguishable from real PTY output to the agent — a diagnostic write silently became fake program output. The fix routes the signal to `logInfo` from `@/utils/logger` with structured fields (`targetLines`, `scrollbackUsed`, `previousScrollback`, `rows`, `kind`, `force`) and leaves the buffer untouched; discoverability moved to a sentence in `TerminalSettingsTab.tsx`. Mirrors the c41d0ab50 FD-leak demotion (toast → `console.warn`).

## Lesson

- The renderer xterm buffer is bidirectional: `terminal.write()` is also `captureBufferText` input. Treat any app-authored write into a terminal buffer as content the agent will re-read and treat as its own output.
- Route operational/diagnostic signals (memory mitigations, resource downshifts, lifecycle notices) to `logInfo`/`logWarn` from `@/utils/logger`, never `terminal.write()`. Stripping ANSI does not make the text disappear — only the styling.
- This maps onto CLAUDE.md's Runtime Signals ladder: ambient, auto-recovering, no-recovery-action states (memory-pressure scrollback reduction) are Tier 0 silent log, not inline buffer text. The panel border already signals memory pressure; the buffer line was redundant _and_ harmful.
- If a behavior genuinely needs to stay discoverable, document it in the relevant Settings tab description — not in the live transcript.

## Applies when

- Adding any `managed.terminal.write(...)` / `terminal.write(...)` for an app-authored message (banners, `[Daintree]` notices, status lines, lifecycle warnings) rather than for PTY data passthrough.
- Working in `src/services/terminal/` controllers (scrollback, resize, restore, agent-state, hibernation) that touch `ManagedTerminal.terminal`.
- Touching `captureBufferText`, `translateToString` loops, agent restart history capture (`restart.ts`), or context-injection paths in `TerminalPane.tsx`, and reasoning about what counts as "agent output."
- Deciding the surface for an ambient/diagnostic terminal signal — choosing between `terminal.write`, `notify()`, an inline banner, and `@/utils/logger`. Default away from the buffer.
- Debugging unexplained `[Daintree]`/app-authored lines appearing in agent context, copy-tree output, or restored terminal history.
