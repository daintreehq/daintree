## Context

When a terminal pane restores from serialized scrollback (project-view reveal, wake-from-hidden), `TerminalWriteController.write()` defers live PTY output arriving mid-restore into `managed.deferredOutput`, and `TerminalRestoreController.replayDeferred()` writes it back through the normal path once `terminal.write(serializedState, callback)` settles. Every host-to-renderer chunk also registers a pending-ack FIFO entry via `acknowledgePortData`/`notifyWriteComplete`, which `PortQueueManager`/`IpcQueueManager` on the pty-host use to track queued bytes and pace/pause a flooding terminal. #10933 wrote an integration stress suite first (`electron/pty-host/__tests__/portPipeline.stress.test.ts`, real `PortBatcher`+`PortQueueManager`+`PtyPauseCoordinator` together), which surfaced a cluster of accounting bugs each correct-looking in isolation.

## Problem

Once a scrollback restore had happened at least once on a terminal under heavy output, every subsequent backpressure pause on that terminal degraded to the pty-host's fixed 10 second safety timeout (`IPC_MAX_PAUSE_MS`) instead of resuming promptly the moment bytes drained. Nothing crashed and the non-restore write path looked completely correct in isolation — the bug was invisible unless a terminal was flooded, restored mid-flood, then flooded again.

## Root cause

The old deferral did `managed.deferredOutput.push(data)` and, in the same breath, called `acknowledgePortData(id, deferredBytes, chunkCount)` — settling the ledger as if the chunk had already reached the renderer, when it was sitting in `deferredOutput`. When the restore finished, `replayDeferred()` pushed that data back through the normal `write()` path, which issued its _own_ ack on completion. Each deferred chunk acked twice against the host's pending-ack FIFO, and the second ack popped an entry belonging to a _different, later_ chunk that arrived after the restore — that chunk's real completion then had nothing to settle. The queued-byte ledger ends up permanently inflated with no reconciliation path, so every future pause computes wrong pending-bytes and rides out the full 10s timeout instead of resuming on ack.

The fix never settles at defer time: `deferredOutput` now holds `{ data, chunkCount }` pairs, and the ledger (FIFO entry, host queued-byte total, ingest `inFlightBytes`) stays charged until the one write that actually delivers the bytes — the replay. Carrying `chunkCount` per entry, not synthesizing one at replay time, is what makes "settle exactly once" reachable across batches of different sizes. Corollary: `replayDeferred()` must run on every path that can end a restore — success, a sync `reset()`/`write()` throw, a snapshot fetch that rejects or resolves `null`, and (inverted) NOT on a stale generation superseded by a newer restore, which owns the entries instead. Miss one and the ledger strands forever: `inFlightBytes` stays nonzero and the stall watchdog reads that as healthy, not stalled.

Two sibling bugs, same harness, same "only covers the normal event" pattern: (1) the aggregate-watermark resume sweep in `PortQueueManager`/`IpcQueueManager` only ran from `removeBytes()` (the ack path) — a terminal paused by the aggregate gate can have an empty queue of its own and get no more acks, so a drain via the safety-timeout force-resume or `clearQueue` (exit/teardown) left it paused until its own independent 10s timeout. Both managers now route every drain source through a shared private `sweepAggregateResume(previousTotal)`. (2) `pty-host.ts`'s `disconnectWindow` called `portQueueManager.resumeAll()` (clears the pause map) then iterated `getPausedTerminalIds()`, a live iterator over that same now-cleared map — visiting nothing, leaking per-window pause-source entries and leaving a stale "paused" pill on other windows. Fix: snapshot `[...getPausedTerminalIds()]` before `resumeAll()`.

## Lesson

- **Never settle a ledger at both the diversion point and the completion point for the same unit of work.** If code defers/buffers data around a normal completion path and replays it later, the defer point must not ack — only actual delivery (the replay) may, exactly once. Trace every call site of the ack function and confirm one settlement per chunk, not "at most one intended, but a second is reachable."
- **Carry replay context on the deferred entry itself, not derive it generically later.** `deferredOutput` moved from bare `string | Uint8Array` to `{ data, chunkCount }[]` so replay settles exactly the FIFO entries that batch owns.
- **Enumerate every exit from a "must eventually resettle" state.** `replayDeferred()` needed success, sync throw, fetch-reject, fetch-null, and NOT stale-generation supersession. A missed path leaves `inFlightBytes` charged forever and the stall watchdog reads that as healthy — a silent, permanent hang that looks fine.
- **A "resume paused peers" sweep triggered by one drain event (acks) must fire on every other event that shrinks the same total** (safety-timeout force-resume, `clearQueue`/teardown), or terminals paused only by an aggregate watermark strand until their own unrelated timeout. `portQueue.ts` and `ipcQueue.ts` had this bug in parallel — check both when touching either.
- **Snapshot a shared map before a call that clears it, if you still need its pre-clear membership.** `resumeAll()` clearing `pausedTerminals` before `getPausedTerminalIds()` iterated it ran zero iterations silently — no exception, just a leak, invisible unless a test asserts the post-state.
- **Order-of-operations pipeline bugs, not obviously-wrong code, need a real integration stress test.** The whole cluster was invisible to per-unit tests of `PortBatcher`/`PortQueueManager`/`PtyPauseCoordinator` alone; `portPipeline.stress.test.ts` exercising them together with adversarial chunk shapes surfaced it.

## Applies when

- Touching `TerminalWriteController.write()`, `TerminalRestoreController.replayDeferred()`, or any code that defers/buffers PTY output during a restore or pause and replays it later.
- Diagnosing a terminal that pauses under heavy agent output and takes exactly ~10s (`IPC_MAX_PAUSE_MS`) to resume instead of resuming promptly on ack — especially after a scrollback restore earlier in the session.
- Adding or reviewing a "sweep all paused terminals" resume in `electron/pty-host/portQueue.ts` or `ipcQueue.ts` — confirm it fires from every drain path, not just `removeBytes`/acks.
- Writing teardown code (`disconnectWindow`-style) that both clears a shared pause/tracking map and needs the pre-clear membership — snapshot before the clearing call, not after.
- Reviewing any byte-counter, FIFO ack queue, or pending-count ledger where data can be diverted around its normal completion path — check for double-settlement or dropped-without-accounting paths.
