## Context

Daintree externalizes React from third-party plugin bundles (`packages/plugin-vite`'s `reactExternals`, matching `^react($|/)` and `^react-dom($|/)`) and injects a production `<script type="importmap">` (`hostImportMapPlugin` in `vite.config.ts`) so plugin panels resolve `react`/`react-dom` at load time against the host's single React instance — a second copy triggers `Invalid hook call`. `HOST_IMPORTMAP_SPECIFIERS` in `packages/plugin-vite/src/index.ts` lists the five specifiers plugins can import: `react`, `react/jsx-runtime`, `react/jsx-dev-runtime`, `react-dom`, `react-dom/client`.

## Problem

Every one of the five specifiers mapped to the same target: the internal `vendor-react` code-split chunk that Rolldown's `codeSplitting` groups produce. Any third-party plugin doing `import { useState } from "react"` died at load in the packaged app with `SyntaxError: The requested module 'react' does not provide an export named 'useState'`. This had been broken in every release since v0.15.0 (#11208). It was invisible to the team because `npm run dev` worked fine (a different, correct mechanism — `hostImportMapDevPlugin` used a virtual `export * from "react"` module) and the only `plugin://`-loaded sample view (`rich-panel-view.js`) deliberately imported no React, so the full-plugins E2E exercised the protocol path but never the React contract.

## Root cause

A code-split chunk is not an entry point. Its export statement is whatever OTHER chunks in the app happen to import from it — Rolldown's private, mangled cross-chunk interface (`export{n as a,i,c as n,o as r,f as t}`), not the package's public API. Pointing an import map at `vendor-react`'s `.fileName` therefore only ever exposed the handful of names Daintree's own app code imports, never `useEffect`/`jsx`/`createRoot`. The first fix attempt copied dev mode's approach — a virtual module doing `export * from "react"` — and it built clean but emitted only a `default` export, every named export elided. React ships CJS, and a star re-export from CJS has no statically-known name set at bundle time, so Rolldown emits nothing for it; dev mode only worked because Vite's dev server pre-bundles React into real ESM before that virtual module ever runs. The real fix (`hostReactFacadePlugin`) emits one dedicated ENTRY chunk per specifier via `this.emitFile({ type: "chunk", id: "virtual:daintree-host-react/<specifier>", preserveSignature: "exports-only" })`, with named exports enumerated explicitly (read at build time via `createRequire`) rather than star-re-exported — only an entry's export list survives `preserveSignature`, and only an explicit `export { useState, useEffect, ... }` clause forces Rolldown to keep those bindings. All five facades still import the one shared `vendor-react` runtime chunk underneath, so the single-instance guarantee holds; the import map points at the facades now, never at `vendor-react` directly.

## Lesson

- **Never point an import map, alias, or public re-export at a code-split/chunk file's output.** A chunk's exports are the private cross-chunk interface derived from what other chunks in THIS build happen to import — not the wrapped package's public API. If external code needs to import from a bundled dependency, emit a dedicated entry chunk for it (`emitFile({ type: "chunk", preserveSignature: "exports-only" })`) and point consumers at that.
- **`export * from <cjs-package>` silently emits nothing for a CJS target under Rolldown/Rollup.** A star re-export needs a statically known name set at bundle time; CJS modules don't have one. It fails clean, no error, just a chunk exporting only `default`. Enumerate names explicitly — read them from the real installed package at build time (`Object.keys(require(specifier))`) rather than hand-maintaining a list, so the facade stays correct across upgrades.
- **Dev and prod diverging in HOW they resolve the same specifier is a trap, not a coincidence.** Vite's dev server pre-bundles deps into real ESM before your virtual-module code runs, so a dev-mode trick (`export *`) can work for reasons that don't hold in a production Rolldown build. Share ONE generator function (`renderHostReactFacade` here) between the dev plugin and the prod plugin instead of writing the logic twice.
- **A guard that only checks "did the generator's own output survive" passes vacuously if the generator itself regresses.** `hostReactFacadePlugin`'s `generateBundle` runs two independent checks: every name the generator asked for survived tree-shaking (catches `lazyBarrel` pruning, #8850 precedent), AND a hand-written per-specifier `HOST_REACT_REQUIRED_EXPORTS` minimum is present regardless of what the generator derived. Only the second would have caught this exact bug — the broken generator's own output matched itself perfectly.
- **Emitting extra entry chunks breaks any code that assumes "first `isEntry` chunk = the app entry."** The five facade chunks are entries but never referenced by `index.html`. `findEntryKey` in `check-first-render-chunk-budget.mjs`, `check-renderer-import-budget.mjs`, the bundle-size report, and the first-render preload closure all needed an explicit exclusion (`isHostReactFacadeChunk`) added wherever a `chunk.isEntry` scan lived.

## Applies when

- Adding or auditing an import map, module alias, or any mechanism that points external/third-party code at part of the host bundle.
- Using `codeSplitting` groups or manual chunks in Rolldown/Rollup/Vite and considering whether a shared chunk's exports can be relied on by anything outside the build.
- Writing `export * from` against a dependency and the resulting bundle mysteriously exports only `default` (or nothing) — check whether the source package is CJS.
- Touching `vite.config.ts`'s `hostReactFacadePlugin`, `hostImportMapPlugin`, `hostImportMapDevPlugin`, or `HOST_IMPORTMAP_SPECIFIERS`/`HOST_REACT_REQUIRED_EXPORTS` — adding a specifier requires declaring its contract in both places (typed to fail closed if you don't).
- Adding a new emitted entry chunk anywhere in the Vite config and seeing a budget script, bundle-size report, or preload-closure computation pick the wrong chunk as "the entry."
