## Context

Daintree's motion system is built on shared Tailwind transition-property lists (`docs/themes/interaction-state-recipes.md`) so overlays enter/exit at the tiered durations the project's motion rules require (dialogs, palettes, dropdowns, pills). Since the Tailwind v4 migration, `translate-y-*`, `scale-*` etc. utilities compile to the standalone `translate` / `scale` CSS properties (v4 split the legacy single `transform` property apart), not to `transform` the way they did under v3.

## Problem

PR #10963 found nine overlay surfaces — `AppDialog`, `AppPaletteDialog`, the `ActionPalette` status chip, `fixed-dropdown`, `ScrollPill`, the notification jump pill, `ReEntrySummary`, `GeneralTab`'s chevron, `GettingStartedChecklist` — that had been fade-only snaps for months: they faded in/out smoothly but their rise/zoom/slide motion just snapped instantly with zero transition. Nothing errored, no lint or type check caught it, and the code read as correct: each one had an explicit `transition-[opacity,transform]` class sitting right next to `translate-y-*`/`scale-*` utilities that looked like exactly what it should cover.

## Root cause

`transition-[opacity,transform]` is an **arbitrary value list** — Tailwind emits `transition-property: opacity, transform` literally, verbatim. But `translate-y-1`, `scale-[0.98]`, etc. no longer set `transform` in v4; they set the standalone `translate` / `scale` properties directly. A CSS `transition-property` list only interpolates properties it names, so `transform` in the list matched nothing being changed, and the browser applied the geometry change instantly while the named `opacity` still animated — the fade-only-snap symptom. The one place `transform` was correct is the toaster, which composes an inline `style={{ transform: ... }}` string rather than using `translate-*`/`scale-*` utilities — `transform` in a transition list only helps when something actually writes to the `transform` property. The reduced-motion neutralizer had the identical trap: `motion-reduce:transform-none` resets `transform`, not `translate`/`scale`, so it silently failed to freeze the geometry too — the fix pairs it with `translate-none`/`scale-none`. The one utility that is NOT a trap is the **named** `transition-transform` class: Tailwind v4 special-cased it to expand to `transition-property: transform, translate, scale, rotate`, so it stays safe — the trap is specific to writing your own arbitrary `transition-[...]` list and reaching for the old v3 mental model of `transform`.

## Lesson

- **In any arbitrary `transition-[...]` list, name the actual longhand property Tailwind v4 emits for the utility you used** — `translate` for `translate-*`, `scale` for `scale-*`, `rotate` for `rotate-*` — never the umbrella word `transform` unless the element also has an inline `style={{ transform: ... }}` string.
- **The named utility `transition-transform` is safe and stays as the default recommendation**; v4 expands it to cover `transform, translate, scale, rotate` together. Reach for it over hand-rolling an arbitrary list unless you need to omit one of those four.
- **Reduced-motion / instant-state overrides need the same longhand split**: `transform-none` does not reset `translate`/`scale`, use `translate-none scale-none` (see `AppDialog.tsx`'s `motion-reduce:` classes) or the frozen geometry will still animate under `prefers-reduced-motion`.
- **This class of bug produces zero errors and zero lint failures** — the only signal is visual: a fade plays but the rise/zoom/slide doesn't. When auditing or writing any dialog/dropdown/palette/pill entrance-exit animation, actually watch it render (or check the DevTools computed `transition-property`) rather than trusting that the Tailwind class list "looks complete."
- **The authoritative table is `docs/themes/interaction-state-recipes.md`** (the "Tailwind v4 trap" callout added by this PR) — check new transition-property lists against it before shipping, and update it if a future Tailwind bump reshapes another utility's emitted properties the same way.

## Applies when

- Writing or reviewing any `transition-[...]` arbitrary-value list that sits next to `translate-*`, `scale-*`, or `rotate-*` utilities.
- An overlay/dialog/dropdown/pill fades in or out correctly but its rise, zoom, or slide motion snaps instantly with no visible animation.
- Bumping Tailwind CSS to a new major/minor and re-verifying which utilities' emitted CSS properties changed (mirrors the xterm options-surface trap in `.lessons/9546.md` — a version bump silently reshaping what a config/class actually does, with no build-time signal).
- Adding a `motion-reduce:` or performance-mode override meant to freeze geometry — confirm it resets the same properties the base state animates (`translate-none`/`scale-none`, not just `transform-none`).
- Touching `src/components/ui/AppDialog.tsx`, `fixed-dropdown.tsx`, `ScrollPill.tsx`, `ReEntrySummary.tsx`, or any component listed in `docs/themes/interaction-state-recipes.md`'s transition table.
