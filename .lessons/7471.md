## Context

Daintree runs many xterm 6.0 panes at once and demotes off-focus/off-screen ones through a refresh-tier ladder (FOCUSED → BURST → VISIBLE → BACKGROUND) via `TerminalInstanceService.onTierApplied`. Two per-pane costs were leaking in background panes: the cursor blink timer and scrollback buffer churn. PR #7471 gated both behind a central policy.

## Problem

- Every _visible_ plain terminal blinked its cursor regardless of focus, paying xterm's `CursorBlinkStateManager` `setInterval` + GPU repaint per-pane-per-tick even in non-focused splits and background tabs.
- Rapid tab-flipping (≈1s cadence) fired `reduceScrollback` on every `BACKGROUND` transition, reallocating xterm's internal buffer on each flip and producing GC pressure.

## Root cause

Two non-obvious xterm-6.0 internals:

- **`cursorBlink` is a live `setInterval`, not a pure render flag.** It ticks per pane irrespective of focus or visibility. Worse, `BASE_TERMINAL_OPTIONS` (`src/config/xtermConfig.ts:34`) carries `cursorBlink: true`, and theme/font updates spread that object straight into `terminal.options`, so any global theme/font change silently re-arms the blink timer on backgrounded panes. There is no single place xterm enforces a focus-aware blink policy.
- **Assigning `terminal.options.scrollback` triggers a full `BufferSet.setup()` that recreates the internal `CircularList`** — on _every_ assignment, not just net reductions. So tab oscillation that repeatedly drops a pane to `BACKGROUND` rebuilds the buffer each time. The existing 500ms `TIER_DOWNGRADE_HYSTERESIS_MS` lives inside `TerminalRendererPolicy` (debounces the _tier decision_); it does not stop `reduceScrollback` from re-firing once the tier actually lands as `BACKGROUND`. A second, per-terminal time gate is required.

## Lesson

- Treat `cursorBlink` as a stateful resource (a timer), not cosmetic. Resolve it through one helper — `TerminalInstanceService.applyCursorBlinkPolicy(managed)` — and call it from _every_ path that can touch options: `createTerminal`/reattach, `onTierApplied`, `updateOptions`, `applyGlobalOptions`, and `applyAgentPromotion`/`clearAgentPromotion`. Anything that spreads `BASE_TERMINAL_OPTIONS` must re-clamp afterward, or a font/theme change re-enables the timer on a background pane. Policy: agent terminals (`runtimeAgentId` set) always off; plain terminals on only at FOCUSED/BURST. Fall back to the live `getRefreshTier()` when `lastAppliedTier` isn't recorded yet (initial-create path before the first `applyRendererPolicy` cycle).
- Gate `terminal.options.scrollback` writes behind a dedicated per-terminal cooldown (`SCROLLBACK_REDUCE_COOLDOWN_MS = 2000`, stamped in `lastScrollbackReduceAt`), **separate from and additive to** the tier-downgrade hysteresis — they protect different layers (buffer rebuild vs tier decision) and must remain independently tunable. Clear the cooldown on tier _upgrade_ in `onTierApplied` so `restoreScrollback` is unconditional and the next genuine BACKGROUND dwell isn't artificially delayed by a stale stamp.
- Give deliberate bulk shrinks (resource-profile downshift / explicit purge via `reduceScrollbackAllBackground`) a `{ force: true }` bypass — the cooldown only exists to absorb tab-flip oscillation, not coordinated memory-pressure actions.

## Applies when

- Touching cursor-blink, theme, or font handling on xterm panes, or anything that spreads `BASE_TERMINAL_OPTIONS` into `terminal.options` (`src/config/xtermConfig.ts`).
- Adding or changing any code that assigns `terminal.options.scrollback` — expect a full `BufferSet`/CircularList rebuild on each write; never assume only reductions cost anything.
- Working in `TerminalInstanceService.onTierApplied`, `applyRendererPolicy`, `updateOptions`, `applyGlobalOptions`, `applyAgentPromotion`/`clearAgentPromotion`, or `reduceScrollbackAllBackground`.
- Diagnosing GPU/CPU churn, GC pressure, or jank tied to rapid tab/split switching or worktree/project switching that oscillates panes through refresh tiers.
- Adding a new debounce/hysteresis to terminal tiering: check whether the existing `TIER_DOWNGRADE_HYSTERESIS_MS` already covers the layer you mean, or whether you need a second per-terminal gate like `SCROLLBACK_REDUCE_COOLDOWN_MS`.
