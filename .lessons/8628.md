## Context

`GridPanel` / `GridTabGroup` render each terminal cell in the content grid. They were `React.memo`'d with hand-written comparators (`gridPanelPropsAreEqual`, `gridTabGroupPropsAreEqual`, ~75 lines each) that received the whole `TerminalInstance` as a `terminal` prop and compared it field-by-field against the field set that `buildPanelProps` (`src/utils/panelProps.ts`) reads.

## Problem

The comparator is a second, duplicate list of the fields the render actually consumes. It drifts. #8621 had to patch six missing fields (`exitCode`, `agentPresetColor`, `agentPresetId`, `agentLaunchFlags`, `browserHistory`, `browserZoom`) plus several missing per-tab fields, because when `buildPanelProps` grew new field reads the comparator wasn't updated — so panel chrome went stale (didn't re-render) until something else forced a render. #8621 even added a Proxy-based "drift test" that records every field `buildPanelProps` touches at runtime and asserts the comparator returns false for each — i.e. it built a CI tripwire to police a list that should never have existed.

## Root cause

Passing the parent's full object down as a prop forces the child to either accept whole-object reference instability (re-render whenever any sibling mutates the parent's array) or re-derive equality manually. The manual comparator inherently mirrors `buildPanelProps`'s field reads, and nothing structurally ties the two lists together — drift is the default state, not the exception. The Proxy test treats the symptom; the disease is the fat-object-prop + custom-comparator shape itself.

## Lesson

When a memoized child only needs one store entity, **pass its id, not the object**, and let the child subscribe by id:

```ts
const terminal = usePanelStore(useShallow((state) => state.panelsById[terminalId]));
```

- The `useShallow` selector becomes the single, colocated field list. The component re-renders only when fields of THIS entity change; sibling mutations no longer cascade. Default `React.memo` shallow comparison of the remaining primitive/stable props is then sufficient — delete the custom comparator (and its drift test) entirely. #8628 removed ~150 lines of comparators plus ~738 lines of test.
- Keep callback props stable so default memo holds: pass the parent's already-stable handler (`onAddTabForPanel={ctx.handleAddTabForPanel}`) and compose the bound, no-arg shape inside the child against the subscribed entity — never an inline `() => ctx.handleAddTabForPanel(terminal)` closure at the call site (new reference every parent render).
- Id-based subscription introduces a transient unmount race: the entity can be removed from the store while the cell is still in React's commit queue. Selecting `panelsById[id]` yields `undefined`; guard with `if (!terminal) return null` (the parent removes the grid cell on the same tick).
- This is the inverse escalation of the "make the comparator work" lessons (#3760 cache the assembled object, #3709 stabilize callbacks, #4749 pass `isSelected` not `selectedIndex`): the durable fix is to remove the second list, not to police it.

## Applies when

- Adding or reviewing a `React.memo` with a custom `propsAreEqual` comparator that field-checks an object prop (especially a `TerminalInstance` / `PanelInstance` / store entity).
- A memoized grid/list child receives a whole store object as a prop and the parent holds an array of them (sibling-mutation cascade).
- Panel chrome / list-item state goes stale (doesn't update until an unrelated render) — suspect a comparator missing a field that `buildPanelProps` (or the equivalent props builder) reads.
- You're tempted to write a Proxy/reflection "drift test" to keep a comparator in sync with a props builder — that's a signal to delete the comparator and subscribe by id instead.
- Working in `src/components/Terminal/Grid*.tsx`, `src/utils/panelProps.ts`, or any `usePanelStore(useShallow(...))` selector.
