## Context

The main `BrowserWindow` was created with `backgroundThrottling: false` to keep the renderer running at full speed when Daintree was hidden. A global per-second ticker hook fired every second regardless of window visibility. `XtermAdapter` could also receive resize events while the window was invisible, producing zero-size fit calls.

## Problem

Three sources of unnecessary CPU usage when Daintree was backgrounded:

1. `backgroundThrottling: false` prevented Chromium from throttling JS timers and RAF loops
2. The 1Hz global ticker kept polling for state updates with no user visible
3. xterm fit calls on hidden windows could produce zero-dimension layouts

## Root cause

`backgroundThrottling: false` is a blunt override that disables Chromium's built-in power-saving for the entire renderer. It was added to prevent timer drift but is far too aggressive — PTY I/O routes through a UtilityProcess and is unaffected by renderer throttling, so the override provided no benefit.

## Lesson

- **Remove `backgroundThrottling: false`** unless there is a concrete, measured reason to keep it. PTY output is handled in a UtilityProcess; renderer throttling only affects JS timers and RAF in the renderer.
- **Gate polling hooks on Page Visibility API**: every periodic hook adds/removes a `visibilitychange` listener and start/stops its `setInterval` on `document.hidden`. The original always-on `useGlobalSecondTicker` was replaced by two visibility-aware patterns — `src/hooks/useGlobalMinuteTicker.ts` (a shared 30s-cadence singleton for relative-time labels that only needs minute-boundary fidelity) and `src/hooks/useVisibilityAwareInterval.ts` (a per-component hook for consumers that genuinely need per-second updates, e.g. live countdowns/elapsed timers). Both pause while hidden and re-emit immediately on restore so labels snap to wall-clock time.
- **Guard `fit()` calls** in `XtermAdapter` (`src/components/Terminal/XtermAdapter.tsx`, ~line 200) with a `container.clientWidth === 0 || container.clientHeight === 0` check (clientWidth/Height return 0 on hidden windows) to prevent layout thrash on resize events that fire before the window is visible.

## Applies when

Any Electron app with periodic renderer-side polling, timers, or layout recalculations. Especially relevant for xterm.js fit addon calls, which should always validate container dimensions before executing.
