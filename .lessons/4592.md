## Context

Canopy runs many agent terminals concurrently. After an agent session completes, its xterm.js instance stayed at the VISIBLE tier indefinitely, holding scrollback buffers, addons (fit, search, weblinks), and canvas allocations in memory.

## Problem

Completed agent terminals were never downgraded from VISIBLE to BACKGROUND tier. The BACKGROUND tier has a lower scrollback limit and can be eligible for full hibernation (destroying the xterm instance and reclaiming all memory). With 10+ completed agents, this held tens of MB of xterm state unnecessarily.

Additionally, `ProcessMemoryMonitor` thresholds were too relaxed, giving too little headroom before the renderer approached OS memory limits. (Thresholds have since been refactored from absolute MB values to fractions of total device RAM in `electron/services/ProcessMemoryMonitor.ts`, so they scale across machines.)

## Root cause

The hibernation system used an idle timer approach: terminals were only considered for downgrade after a period of inactivity. Completed agent terminals were not treated as a special case that should immediately drop to BACKGROUND tier regardless of their last activity time.

The fix wires agent completion directly into the refresh-tier computation: the tier function in `src/store/panelStore.ts` keeps active agent terminals at `VISIBLE` but drops `completed`/`exited` agents to `BACKGROUND`, which makes them eligible for hibernation (scheduled via `TerminalHibernationManager` / `scheduleHibernation` in `TerminalInstanceService`). This is a **push** model rather than a **poll** model — the store knows exactly when an agent finishes (via `agentState`) and triggers the downgrade proactively instead of waiting for an idle timer.

## Lesson

- xterm.js instances are expensive: each holds scrollback (configurable line buffer), addon state, and canvas context. Downgrading to BACKGROUND tier frees most of this.
- Don't rely solely on idle timers for memory reclamation when you have precise lifecycle events (agent completed, panel hidden) — use those events to trigger immediate tier downgrades.
- Drop completed/exited agent terminals to the `BACKGROUND` tier in the refresh-tier computation (`src/store/panelStore.ts`) so they become hibernation-eligible after any agent lifecycle event (completion, exit, error). The store already tracks `agentState` per terminal session; use it.
- Memory monitor thresholds should scale with device RAM (fractions of `os.totalmem()`, as `ProcessMemoryMonitor` now does) so headroom holds across machines, rather than hard-coding absolute MB limits.

## Applies when

- Adding new agent lifecycle events (completion, cancellation, error)
- Any code that checks `AgentStateMachine` state transitions
- Tuning `ProcessMemoryMonitor` thresholds for different workloads
