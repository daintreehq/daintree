## Context

Each project runs in its own `WebContentsView` (`ProjectViewManager`). On project switch or window close the outgoing view is detached (`removeChildView`, hidden) and, later, destroyed by LRU eviction (`destroyView`). The Settings dialog has tabs with their own local dirty buffers — `EnvironmentSettingsTab`, `WorktreeSettingsTab`, `DaintreeAssistantSettingsTab` — plus a debounced project-form autosave (`useProjectSettingsForm`). None of these ride the project-switch IPC payload (unlike the panel-state snapshot in #5009); they are purely dialog-local.

## Problem

The settings dialog silently dropped unsaved edits when the project view detached mid-edit (project switch with a dirty env-var row or worktree pattern). The dialog had only wired `beforeunload`-style flushes via `handleClose`/`handleBeforeClose`, which never fire on view detach.

## Root cause

Electron 41's `WebContentsView` detach does **not** fire `beforeunload` — that guarantee web devs rely on simply doesn't exist for detached views. The reliable signal is `visibilitychange` (the view goes `document.hidden`). The non-obvious second half: detach is NOT destruction. The view's `webContents` (and its IPC channels) survive detach and live until a _later_ LRU eviction in `ProjectViewManager.destroyView`. That is why an **async** flush kicked off from `visibilitychange` actually completes here — superficially contradicting #5009's "IPC destroyed mid-flight," which applied to a fire-and-forget switch that destroyed the old view immediately. Two more traps: (1) a fast switch can leave the document already `document.hidden` before the listener registers, so the effect must re-check `document.hidden` synchronously on mount; (2) `visibilitychange` can fire while a save is already in flight, so each tab's flush needs an in-flight `isSaving` guard to avoid overlapping IPC writes.

## Lesson

For renderer-local dirty state that is NOT part of the project-switch IPC payload, persist it on `visibilitychange`, not `beforeunload`. Use the canonical `useFlushOnHide(fn, enabled)` hook (`src/hooks/useFlushOnHide.ts`):

- It registers a `visibilitychange` listener AND re-checks `document.hidden` immediately on effect run, covering the already-hidden race.
- It holds the callback in a ref (updated in `useLayoutEffect`) so unstable closures always invoke the latest state — do not depend on `fn` in the effect deps.
- Async flushes are safe because IPC survives detach until LRU eviction — but each callback must own its own validation gate AND an in-flight `isSaving` guard (`EnvironmentSettingsTab.handleSave` returns early `if (isSaving)`), since hide can fire during a user-initiated save.

For collecting multiple tab buffers, mirror the validation-registry shape: a context provider (`SettingsFlushProvider`) where each dirty tab registers a flush via `useSettingsTabFlush(tab, fn, enabled)`, and the dialog calls `flushAll()` (Promise.all, errors swallowed per-tab) before its own `projectForm.flush()`. The unregister closure must check `current === fn` so a re-register from the same tab doesn't blow away the newer callback. Tolerate a missing provider (return when `register` is null) so tabs stay renderable in isolation/tests.

This is the complement to #5009: #5009 covers state that can ride the switch payload (capture synchronously, write in the main handler before swap); #6927 covers dialog-local state that cannot, so it flushes async on hide while the view is detached-but-alive.

## Applies when

- Adding any renderer-side feature that holds unsaved/dirty state inside a `WebContentsView` and must persist it before project switch or window close (settings tabs, editors, draft buffers, debounced autosaves).
- You reach for `beforeunload` / `unload` / `pagehide` in the renderer to flush state — stop; in Electron 41 detach those don't fire reliably, use `useFlushOnHide`.
- Debugging "edits silently lost on project switch" or "dialog state didn't save when I clicked away."
- Wiring overlapping async IPC writes triggered by lifecycle events (need an in-flight guard).
- Working in `ProjectViewManager` detach vs. `destroyView`/LRU-eviction timing, and reasoning about whether an async IPC initiated at detach can complete.
