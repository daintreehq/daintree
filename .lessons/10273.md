## Context

Each supported agent CLI ships a per-agent `AgentDetectionConfig` in `shared/config/agents/*.ts` (roster in `shared/config/agentRegistry.ts`) that feeds the passive output-based state machine (`ActivityMonitor`, `AgentPatternDetector`, `BootDetector`). The schema advertises tuning knobs — `debounceMs`, `promptFastPathMinQuietMs`, `primaryPatterns`, `fallbackPatterns`, `bootCompletePatterns` — that authors set expecting them to shape idle/working/waiting detection. #10273 (issue #9877) audited the schema against its actual consumers, found the contract dishonest in two orthogonal ways, and deleted the dead values / rewrote the comments with NO behavioral change.

## Problem

17 per-agent config values did literally nothing, and two agents shipped empty pattern arrays with comments claiming the opposite of what the code does. 15 of the 16 built-in configs with a `detection` block set `debounceMs: 6000` (cursor and mistral also `promptFastPathMinQuietMs: 6000`); the doc comment even claimed a `4000`/`3000` default and told authors that agents "with deterministic completion markers (e.g. Cursor) can use shorter values." None of it took effect. Separately, `amp.ts` and `antigravity.ts` shipped `primaryPatterns: []` with comments saying an empty array means the state machine "simply doesn't mis-classify rather than firing on the wrong glyphs" — i.e. an opt-out. It is the opposite.

## Root cause

Two independent config-contract violations, both invisible because the loose optional-field types never fail the build.

1. `buildActivityMonitorOptions` (`electron/services/pty/terminalActivityPatterns.ts`) clamps both tunables to a hard floor: `idleDebounceMs = Math.max(detection?.debounceMs ?? AGENT_WAITING_QUIET_MS, AGENT_WAITING_QUIET_MS)`, and `promptFastPathMinQuietMs = Math.max(detection?.promptFastPathMinQuietMs ?? idleDebounceMs, idleDebounceMs)`. `AGENT_WAITING_QUIET_MS = 8000` is the #3606 jitter guard. Any override ≤ 8000 is a no-op; every agent's `6000` was inert. The floor is the intended design — the field docs and the per-agent values were the lie.

2. Empty pattern arrays are fallthrough, not opt-out. `buildPatternConfig` returns `undefined` when `compilePatterns(primaryPatterns)` is empty — and it returns BEFORE compiling `fallbackPatterns`, so a config declaring only fallbacks silently loses them. `AgentPatternDetector`'s constructor then resolves `buildPatternConfig(...) ?? UNIVERSAL_PATTERN_CONFIG`, so `primaryPatterns: []` makes the agent inherit the universal glyph/pattern set (the Claude/Codex/Gemini ranges those comments explicitly declined to copy). Same shape in `BootDetector`: empty/missing `bootCompletePatterns` inherits its hardcoded `BOOT_COMPLETE_PATTERNS` (Claude/Codex boot banners). So "ship empty to be safe" is strictly MORE aggressive than intended, not a no-op.

The floored tunables also spawned a tautological test (`expect(...promptFastPathMinQuietMs).toBe(6000)`) pinning the dead value — #10273 replaced it with a shape check asserting the field is now `undefined`.

## Lesson

- **A tunable field clamped by an invariant elsewhere is dead config — delete the fake knob and document the floor at the field.** 17 `debounceMs`/`promptFastPathMinQuietMs` overrides were silently `Math.max`'d up to `AGENT_WAITING_QUIET_MS` (8000). Before adding a per-agent detection override, grep `buildActivityMonitorOptions` for `Math.max(..., FLOOR)`; any value under 8000ms is inert by construction.
- **The #3606 jitter guard (8s) is load-bearing, not a default you may lower per agent.** Agents fall silent 1-5s between tool calls; a sub-8s idle debounce would flap working→waiting→working. It's a hard floor precisely so a well-meaning per-agent override can't reintroduce the flap.
- **`primaryPatterns: []` (or missing `bootCompletePatterns`) means "inherit the UNIVERSAL/built-in set," never "opt out."** `buildPatternConfig` returns `undefined` for empty primaries → `AgentPatternDetector` substitutes `UNIVERSAL_PATTERN_CONFIG` (whose glyph ranges cover Claude/Codex/Cursor/Gemini/Goose/OpenCode); `BootDetector` substitutes its own hardcoded Claude/Codex `BOOT_COMPLETE_PATTERNS`. Shipping empty arrays to "avoid mis-classification" does the opposite — it applies the broadest patterns. A real opt-out (empty distinct from `detection: undefined`) does not exist in this pipeline; don't write comments implying it does.
- **Empty `primaryPatterns` also silently discards `fallbackPatterns`** — `buildPatternConfig` bails before compiling fallbacks, so fallback-only detection can't be expressed today.
- **A test asserting a config literal equals its source value (`toBe(6000)`) is tautological, and worse when it pins a floored/ignored value — it enshrines dead config as live.** Assert observable behavior (field absent, or the computed floored result) instead.

## Applies when

- Adding or editing a per-agent `AgentDetectionConfig` in `shared/config/agents/*.ts` — especially setting `debounceMs`, `promptFastPathMinQuietMs`, or pattern arrays and expecting them to change idle/working/waiting timing.
- Reasoning about why an agent's busy→idle transition won't go faster than ~8s regardless of config — it's the `AGENT_WAITING_QUIET_MS` floor in `buildActivityMonitorOptions`, not a bug.
- Shipping an agent with empty `primaryPatterns`/`fallbackPatterns`/`bootCompletePatterns` assuming it detects conservatively — it inherits the universal / built-in banner set instead.
- Reviewing any config schema where a field is optional-typed but a consumer floors, clamps, or ignores it — confirm the advertised range is the honored range, or the doc lies.
