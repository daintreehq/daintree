## Context

The PTY host runs as an Electron `utilityProcess`; when it exits, the lifecycle owner schedules an auto-restart with exponential backoff. The original delay was deterministic: `Math.min(1000 * 2^n, 10000)`.

## Problem

When the host failed for a consistent startup reason (bad memory limit, missing binary, env issue), every restart attempt fired at the same deterministic interval, amplifying the crash loop in lockstep instead of spreading attempts out.

## Root cause

Two distinct retry-scheduling traps, neither obvious until you reason about the instant-fail case:

1. **Deterministic backoff amplifies synchronized crash loops.** Identical attempts at identical times waste CPU and give a transient cause no chance to clear at a randomized moment. The fix is AWS-style full jitter: `random() * min(cap, base * 2^n)`.
2. **Naive full jitter (`random() * cap`) can return a near-zero delay.** For a host that fails _synchronously_ on fork, a ~0ms delay means the exit handler reschedules instantly — a tight respawn loop that pins a CPU core. Full jitter alone makes the worst case (instant fail) _worse_, not better. The fix is a 100ms floor: `RESTART_FLOOR_MS + floor(random() * max(0, cap - RESTART_FLOOR_MS))`.

The PR also added an `isDisposed()` guard _inside_ the restart `setTimeout` callback — without it, a dispose during the backoff window respawns a host that nothing owns (orphan).

## Lesson

A self-restart backoff for a process/socket that can fail _synchronously_ needs three things together: full jitter (break lockstep), a hard floor (instant-fail can't busy-spin), and a disposed/already-respawned guard re-checked at timer-fire (the world can change during the wait). The live code at `PtyHostLifecycle.ts:519-536` also checks `this.child !== null` inside the callback so a concurrent `manualRestart()` during the defer window doesn't orphan its host. Same full-jitter+floor pattern is now mirrored in `AutoUpdaterService`, `AgentConnectivityService`, and `OpenAITranscriptionProvider` — copy the floor, not just the jitter.

## Applies when

Scheduling auto-restart/reconnect backoff for anything that can fail near-instantly (a `utilityProcess.fork`, a WebSocket reconnect, a spawn that rejects on bad config). Always pin a floor under the jitter and re-check disposed/already-alive state at timer-fire, not just at schedule-time.
