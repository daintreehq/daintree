## Context

`electron/preload.cts` exposes three `contextBridge.exposeInMainWorld` bridges used by the Playwright harness — `__DAINTREE_E2E_IPC__`, `__DAINTREE_E2E_MODE__`, `__DAINTREE_E2E_SKIP_FIRST_RUN_DIALOGS__` — each gated by a `process.env.DAINTREE_E2E_* === "1"` check. The preload is esbuild-bundled (separately from the renderer) into `dist-electron/electron/preload.cjs`.

## Problem

The bridges shipped in packaged production builds. An env-var check is not a security boundary in a distributed app: anyone launching the binary with `DAINTREE_E2E_MODE=1` (etc.) got the test backdoors exposed in the renderer's main world — IPC listener introspection and onboarding side-effect suppression that should never reach end users.

## Root cause

Runtime env-var gating leaves the gated code physically present in the shipped bundle; the gate is only as strong as control over the launch environment, which the attacker owns. The real fix is to make the code not exist in production at all. Two interacting mechanisms make that work, plus one esbuild trap:

- esbuild `define` of `process.env.DAINTREE_E2E_* → JSON.stringify("")` replaces the reads with the literal `""`. With `minify: isProd` already set, esbuild constant-folds `"" === "1"` to `false` and dead-code-eliminates the entire `exposeInMainWorld` block (and the matching main-process guards).
- The trap: a `define` value of bare `undefined` stringifies to the literal string `"undefined"`, NOT to the JS value — that would break the branches in dev/test (where the harness must still get the bridges). So the defines are applied via **conditional spread** (`...(isProd ? {...} : {})`) that omits the keys entirely in dev/test, rather than a ternary that sets them to `undefined`.
- Defense-in-depth runtime guard: a shared `isPackagedBuild = process.argv.some(a => a.includes("app.asar"))` const, with `&& !isPackagedBuild` appended to each gate. `process.resourcesPath` is **undefined** in sandboxed preloads (`sandbox: true`), so `argv`'s `app.asar` segment is the reliable packaged-build signal (reuses the existing `isDemoMode` pattern).
- Safety net: `scripts/ci/check-preload-backdoors.mjs` greps the built `preload.cjs` for the six forbidden strings (both the exposed global keys and the gating env-var names) and hard-fails (no `continue-on-error`) in `ci.yml` and all three release workflows, after build and before packaging.

## Lesson

- Env-var gating is not a security boundary for code in a packaged/distributed build — the user controls the launch env. To keep dev/test-only code out of production, strip it at build time so it physically does not exist in the shipped bundle.
- The esbuild pattern: `define` the env reads to a string constant (`JSON.stringify("")`), rely on `minify` to constant-fold the comparison and DCE the block. Verify by grepping the built artifact for the dead symbols, not by trusting the build flag.
- Never `define` a key to bare `undefined` to "turn it off" — esbuild emits the literal text `undefined`, which silently changes branch behavior. Use a conditional spread to **omit** the key when you want the original `process.env` read preserved (e.g. dev/test).
- In sandboxed preloads, use `process.argv` (`app.asar` segment) — not `process.resourcesPath`, which is undefined — to detect a packaged build.
- Back any "stripped at build time" security claim with a CI grep gate on the built artifact, wired as a hard failure into both PR CI and every release workflow. The strip can silently regress if `NODE_ENV`/minify drift.

## Applies when

- Adding any dev-only or E2E-only `contextBridge.exposeInMainWorld` bridge, debug global, or backdoor to the preload or main process.
- Using esbuild `define` to gate/strip code by build mode — especially when tempted to set a define to `undefined`.
- Detecting packaged vs dev runtime inside a sandboxed preload.
- Reviewing what dev/test surface area survives into a packaged Electron build.
