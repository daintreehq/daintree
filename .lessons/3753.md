## Context

High-throughput agent output (code generation, large diffs, log streams) was suspected of causing visual tearing because each `terminal.write()` triggered an independent xterm paint. PR #3753 tried to fix this by wrapping every write in DEC Mode 2026 (Synchronized Output) begin/end sequences (`\x1b[?2026h` ... `\x1b[?2026l`) inside `writeToTerminal()`, via an exported `wrapWithSyncOutput()` helper handling both string and Uint8Array paths.

## Problem

The wrapping corrupted terminal output. PTY data arrives in arbitrary chunks — node-pty does not align chunk boundaries to ANSI escape-sequence boundaries. When an escape sequence straddled two chunks, `wrapWithSyncOutput()` injected `\x1b[?2026h` bytes _into the middle_ of that sequence, splitting it. The fragments then rendered as raw escape text on screen instead of being parsed. Reported as #3767 and reverted in 8545b1e0a.

## Root cause

The premise was wrong twice over. (1) xterm.js 6.0 already supports DEC 2026 natively and already batches grid mutations into a single rAF-driven paint — the manual wrapping was redundant. (2) Wrapping at the _chunk_ level is structurally unsafe: you cannot inject control bytes around a chunk without risking insertion mid-escape, because chunk boundaries are not sequence boundaries. Any prefix/suffix byte injection on the raw PTY stream has this hazard.

## Lesson

Never inject control sequences (DEC 2026 or otherwise) into the raw PTY-to-xterm write path. Chunk boundaries split ANSI sequences arbitrarily, so wrapping bytes around `terminal.write()` will eventually land inside an escape and produce garbage on screen. xterm 6.0 handles synchronized output and frame batching itself; the writer's job is to pass bytes through untouched.

The correct use of DEC 2026 is to _detect_ it, not emit it. xterm exposes `terminal.modes?.synchronizedOutputMode` (a boolean reflecting an active BSU/ESU block opened by the agent itself). `TerminalReflowController.maybeReflow()` reads it and skips forcing an IntersectionObserver reflow while 2026 is open, so it doesn't interleave a jitter-paint mid-block — it reflows on the next tick after ESU. `TerminalInstanceService.getSynchronizedOutputMode(id)` exposes the same mode read-only for diagnostics (it lags writes by one parser tick, so it must not gate writes synchronously).

## Applies when

- Tempted to inject prefix/suffix control bytes around any `terminal.write()` or raw PTY chunk
- Working on `writeToTerminal()` in `TerminalInstanceService.ts` or buffering/flow-control in the PTY-to-xterm path
- Seeing raw escape fragments (e.g. `[?2026h`) render as visible text
- Gating reflow/refresh/jitter on synchronized-output state — read `terminal.modes.synchronizedOutputMode`, don't emit 2026 yourself
