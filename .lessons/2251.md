## Context

Daintree protects the main worktree from deletion and treats it specially in cleanup and PR flows, so `isMainWorktree` must be set correctly on every entry parsed out of `git worktree list --porcelain` in `WorktreeListService.list()`.

## Problem

This PR replaced the original positional rule (first entry = main) with a canonical-path comparison: resolve `currentWorktree.path` and `projectRootPath` through `fs.realpathSync`, lowercase on Windows, and set `isMainWorktree` only when they matched. It then fixed a real symptom (main worktree terminals closed during PR review), but the path-comparison approach backfired and was reverted in `405db4eae` ("use first-entry detection for isMainWorktree", closes #3946).

## Root cause

The canonical-path rule failed _closed_: when `projectRootPath` was null/unavailable, or `realpathSync` threw, or the two canonical strings diverged for any reason (symlink vs realpath asymmetry, Windows case, a stale stored root), `isMain` stayed `false` for **every** worktree. With no entry flagged as main, the main worktree lost its delete protection — git itself then rejected the operation with `fatal: '<path>' is a main working tree` (#3946). The premise that git output order is "an unreliable heuristic" was wrong: `git worktree list --porcelain` _guarantees_ the main worktree is the first record, so the positional rule has no failure mode that path-matching avoids, and path-matching introduced several new ones.

## Lesson

Identify the main worktree by its position in `git worktree list --porcelain` — `isMainWorktree: isFirstEntry`, set once and flipped to `false` after the first `pushWorktree()`. This is a documented git contract, not a heuristic. Do NOT re-derive it by canonicalizing and comparing against a stored project root: that adds `realpathSync`/Windows-case/symlink failure surface, and any miss flips the protected flag to `false` for the _whole_ list, removing the very safeguard it was meant to harden. When a contract already pins the answer (git's ordering), prefer it over a "more correct" derivation that can fail open or closed on the protective signal.

## Applies when

Parsing `git worktree list --porcelain`, deciding which worktree is the deletion-protected main, or any time you're tempted to replace a documented tool-output contract with cross-platform path canonicalization (`realpathSync`, Windows lowercasing) — especially where a comparison miss silently clears a protective boolean for all rows.
