## Context

Tier D3 destructive actions (delete repo, force-delete a protected/main worktree, rotate the MCP API key, bulk worktree removal) gate their primary button behind a typed-name confirmation: the user must type the entity name and the button stays disabled until `typedValue === target`. `ConfirmDialog` exposes this via the `typedNameTarget` prop, rendering the shared `TypedNameConfirmInput` primitive (`src/components/ui/TypedNameConfirmInput.tsx`). The match is a strict `===` equality check.

## Problem

The strict-equality gate can be defeated by an empty target. `WorktreeDeleteDialog` computed `confirmTarget = worktree.branch ?? worktree.name`. For a detached-HEAD or branchless worktree, `worktree.branch` is the empty string `""`, not `null`/`undefined` — so `??` (nullish-coalescing) preserves `""` instead of falling back to `worktree.name`. The gate then becomes `"" === ""`, which is true the instant the dialog opens with an empty input: the highest-tier D3 force-delete confirm clears itself with zero keystrokes. A second leak shape: `typedNameTarget` could be attached to a non-`destructive` ConfirmDialog variant, putting a confirm gate on an action never classified as destructive.

## Root cause

`??` only falls back on `null`/`undefined`; it treats `""` as a valid value. When the gate value can legitimately be an empty string (a missing git branch, an unloaded API key), a strict `===` comparison against an empty input passes vacuously. This is precisely the "silent-fallback default" class CLAUDE.md bans (the #7880 root cause): a derived value substitutes into a destructive submission path without the user ever confronting it. The fix is twofold and the live code goes further than the PR's first cut:

- `confirmTarget = worktree.branch || worktree.name` — `||` falls back on any falsy value including `""`.
- The non-destructive leak was first guarded by a DEV-only `console.error` sniffer, then hardened into a **type-level** discriminated union plus a **runtime coercion** in `ConfirmDialog.tsx`: `ConfirmDialogProps` types `typedNameTarget?: never` for `variant: "default" | "info"`, and the body recomputes `const typedNameTarget = variant === "destructive" ? rawTypedNameTarget : undefined` so even a cast can't smuggle a gate onto a non-destructive variant.

## Lesson

- For any gate/equality check whose operand can legitimately be an empty string (git branch, API key, name field), use `||` not `??` for the fallback. `??` silently lets `""` through; a strict `===` against empty input then passes with zero user action.
- Treat "the typed-name confirm matched on an empty target" as a D3-gate bypass, not a cosmetic glitch. Add a test that opens the dialog with the empty/falsy edge value and asserts the confirm button stays **disabled** (PR added exactly this for the empty-branch case).
- When a destructive affordance must never attach to a non-destructive action, enforce it at the type level (discriminated union `typedNameTarget?: never`) AND coerce at runtime (`variant === "destructive" ? target : undefined`). A DEV-only `console.error` sniffer is a weaker first line — it warns but still renders the gate.
- Reuse `TypedNameConfirmInput` / `ConfirmDialog`'s `typedNameTarget` for D3 flows rather than rebuilding the match input — it carries the sr-only live region, error ring, Enter-to-submit, and the close-reset `useEffect` that clears stale typed state.

## Applies when

- Adding or reviewing a Tier D3 typed-name confirmation (delete repo/project, force-delete protected or main worktree, rotate API key, bulk worktree removal) — anything wiring `ConfirmDialog`'s `typedNameTarget` or `TypedNameConfirmInput`.
- Writing any `x ?? fallback` where `x` is a git branch name, API key, entity name, or other field that can be an empty string rather than null/undefined — especially when that value feeds a `===` match, disabled-gate, or destructive submission.
- Reviewing a destructive-submission path for silent-fallback defaults (the #7880 / CLAUDE.md "no silent fallback" rule): any "if X is empty, use Y" chain on a confirm/commit/delete path.
- Touching `WorktreeDeleteDialog.tsx`, `ConfirmDialog.tsx`, `DaintreeAssistantSettingsTab.tsx` (rotate key), `McpServerSettingsTab.tsx`, `WorktreeOverviewModal.tsx`, or `useWorktreeBulkRemove.ts`.
- Designing a prop that must only ever appear on one variant of a component — prefer a discriminated-union `?: never` plus runtime coercion over a DEV console warning.
