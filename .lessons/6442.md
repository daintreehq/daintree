## Context

`daintree-file://` (registered via `ses.protocol.handle` in `registerProtocolHandlers`, `electron/setup/protocols.ts`) serves project files to the renderer. The handler validates containment by `realpath`-resolving both the file and the project root, then checking `path.relative(realRoot, realFile)` is not a parent-escape. This is the documented defense against in-root symlinks pointing outside root (CVE-2025-53109 / CVE-2025-54794 class).

## Problem

The realpath containment check passed, but the actual read was done via `net.fetch(pathToFileURL(realFile))`. `net.fetch` opens the path again, independently re-resolving symlinks at read time. An attacker who swaps the final path component for a symlink in the window between the `realpath` check and `net.fetch` gets the fetch to follow the freshly-injected link out of the sandbox. The handler also emitted only `Content-Type` — no CSP/CORP/nosniff — so a polyglot HTML/SVG file served through the scheme could execute, and error responses (400/404/405/413/500) carried no hardening at all.

## Root cause

A containment check and a separate read are two distinct filesystem operations against a path string, not against a pinned inode. Re-opening by path (which is exactly what `net.fetch(file://...)` does) discards the work the `realpath` check did — the second open re-walks and re-resolves every component, so the check is only advisory. There is no way to make `net.fetch` reuse the resolved handle. The only way to bind check-to-read is to open the path **once** and read from that handle: `fs.open(normalizedFile, O_RDONLY | O_NOFOLLOW)` then `fileHandle.readFile()`. `O_NOFOLLOW` rejects a final-component symlink with `ELOOP`, so a swap injected after the realpath check fails the open instead of escaping. Crucially the open targets the **user-supplied `normalizedFile`, not the realpath-resolved `realFile`** — opening `realFile` would re-follow the very link you are trying to guard against. `fs.stat` is still done on `realFile` (accurate size for the 413 cap), but `Content-Length` is set from `buffer.length` after the read, because the file can grow between `stat` and `readFile` and `stat.size` would be a stale, body-mismatched length.

## Lesson

For any custom Electron protocol handler (or IPC) that reads sandboxed files:

- Do NOT use `net.fetch(pathToFileURL(...))` after a `realpath` containment check — it reopens the path and reintroduces the TOCTOU. Read through a single handle instead.
- Open the **user-supplied normalized path** with `fs.open(path, fs.constants.O_RDONLY | fs.constants.O_NOFOLLOW)` and call `fileHandle.readFile()` on that handle. Map `ELOOP`/`ENOENT` from `open` to 404. `O_NOFOLLOW` is `0` (no-op) on Windows — realpath containment still covers that platform.
- `await fileHandle.close().catch(() => {})` in a `finally` so a close error never masks a preceding `readFile` failure.
- Set `Content-Length` from `buffer.length`, never `stat.size`.
- Emit the hardened header set on **every** path including errors: `Content-Security-Policy: sandbox; default-src 'none'`, `Cross-Origin-Resource-Policy: cross-origin` (the `app://` renderer and `daintree-file://` are different schemes/sites; same-origin would block legitimate loads), `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`. Use shared `buildDaintreeFileHeaders` / `buildDaintreeFileErrorHeaders` helpers so error branches can't drift.
- This pattern is the parity contract shared by the `files:read` IPC handler (`electron/ipc/handlers/files.ts`, `FILE_SIZE_LIMIT`) and the `plugin://` handler — keep all three in sync.

## Applies when

- Editing or reviewing `electron/setup/protocols.ts` (`daintree-file://`, `plugin://`, app:// handlers) or `electron/ipc/handlers/files.ts`.
- Adding a new custom protocol or IPC that serves files from a sandboxed root, or any handler that does a `realpath`/containment check followed by a separate read.
- You see `net.fetch(pathToFileURL(...))`, or a read by path string after a security check — flag the re-open TOCTOU.
- Reviewing response headers on a custom scheme: success path has CSP/CORP/nosniff but an error branch (404/413/500) is missing them.
- Setting `Content-Length` from a pre-read `stat.size` rather than the bytes actually read.
- Auditing symlink-escape / path-traversal defenses in the main process.
