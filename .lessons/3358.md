## Context

`TerminalWebGLManager` keeps live WebGL contexts attached to focused/visible terminals. The cap was set to 16, matching Chromium's documented limit. (The manager has since dropped the per-context LRU pool in favour of a count-based mode switch — a hysteresis between an upper and lower threshold flips the whole fleet between WebGL and DOM at once rather than evicting individual contexts — but the headroom reasoning below is unchanged.)

## Problem

When terminals filled the pool, the first non-terminal WebGL consumer in the renderer — a Notes editor embed, a dev-preview overlay, a future chart, anything — would force Chromium to drop an existing context via `webglcontextlost` on a random terminal. The evicted terminal silently fell back to DOM rendering mid-session.

## Root cause

Chromium enforces a hard limit of 16 simultaneously active `WebGLRenderingContext`s per renderer process. The cap is per-process, not per-document, and it's shared with any other WebGL consumer in the same renderer. Hitting 16 triggers Chromium's own LRU eviction (not ours), which fires `webglcontextlost` on the oldest context regardless of whether it's terminal or not. `<webview>` partitions have their own budget, but anything in the main renderer document shares this pool.

## Lesson

Never claim Chromium's full WebGL budget in a single consumer. Reserve headroom (4 slots is a reasonable default) so other renderer-resident WebGL code can attach without triggering eviction. Document the Chromium limit inline so the next person doesn't bump the cap back up. The current upper threshold lives in `src/services/terminal/TerminalWebGLConfig.ts` (`upperThreshold = 12`, with the rationale comment), and `TerminalWebGLManager` consumes it via `UPPER_THRESHOLD`/`LOWER_THRESHOLD`:

```ts
// Chromium hard-caps active WebGL contexts at 16 per renderer process and
// silently evicts the oldest on overflow (webglcontextlost). The upper
// threshold must stay comfortably below 16 to leave headroom for devtools,
// OffscreenCanvas, and any future non-terminal WebGL consumer.
let upperThreshold = 12;
let lowerThreshold = 10;
```

## Applies when

Any renderer-process code that keeps long-lived WebGL contexts: terminal renderers, canvas chart libs, 3D previews. `<webview>` and `WebContentsView` each have their own renderer process with an independent budget, so the concern only applies within one document.
