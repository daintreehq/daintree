## Context

The hybrid input bar dictation flow streams interim (provisional) speech-to-text deltas as the user speaks, then commits a finalized transcript per utterance. `VoiceRecordingService` receives `onTranscriptionDelta`/`onTranscriptionComplete` events; the CodeMirror editor in `HybridInputBar` renders the input. Interim text is volatile — it churns and gets corrected 30-50 times per utterance before the model settles.

## Problem

Each interim delta was written into the editor document via `setDraftInput` + a slice-back-and-replace, producing 30-50 `doc.replace` transactions per utterance. Every one of those `docChanged` transactions landed in CodeMirror's undo history (so one Ctrl-Z undid a single mid-word interim revision, not the whole dictation) and caused visible document churn as text was rewritten on each delta. Separately, a final-transcript drop bug (#9172): `sendFromEditor` sometimes ran against the pre-stop document because the draft hadn't propagated to the editor yet.

## Root cause

Volatile preview text does not belong in the document model. In CodeMirror 6, any transaction with `tr.docChanged` is recorded by the history extension and remaps decorations — so streaming preview text through `changes` both pollutes undo and forces re-measurement. The fix renders interim text as a `Decoration.widget` (an `InterimGhostWidget extends WidgetType` DOM node appended at `doc.length`, `side: 1`) driven by a `StateField<string>` updated via an effect-only `setInterimText` transaction. Effect-only transactions carry no `docChanged`, so they never enter history and never mutate the doc. The widget field's `provide` guards on `view.composing` and returns `Decoration.none` during IME composition, mirroring the xterm guard from #4379 — a live ghost node would otherwise displace the composition overlay. The dropped-final-transcript race: `stop()` writes the final transcript to the input store and bumps `voiceDraftRevision`, but `HybridInputBar`'s sync `useEffect` doesn't fire until the next React render, which is AFTER the `stop()` continuation microtask that calls `sendFromEditor`. `useVoiceWaitSubmit` closes this by reading the draft from `terminalInputStore` and dispatching it into the editor synchronously, before `sendFromEditorRef.current()` runs.

## Lesson

- For any volatile/preview/streaming text overlaid on a CodeMirror 6 editor (dictation interim, ghost-completion, inline AI suggestion), render it as a `Decoration.widget` driven by an effect-only `StateField`, never by writing into the document. Only commit to the document once, on finalization. An effect-only transaction (`{ effects: [...] }` with no `changes`) is invisible to the history extension.
- Guard widget decorations that sit at the caret/end-of-doc on `view.composing` so they don't fight the IME composition overlay (same class of bug as #4379, now applied on the CodeMirror side).
- When a store write must reach the editor before a synchronous send, don't rely on the React render that syncs store→editor — it lands a render too late relative to a microtask continuation. Read the store and dispatch into the editor synchronously at the send site.
- A mid-stream stop must still flush the accumulated preview (`liveText`) into the doc as the final commit; with no interim text in the doc, skipping the flush silently drops the partial transcript.

## Applies when

- Adding streaming/preview/ghost text to the hybrid input bar or any CodeMirror 6 editor (`src/components/Terminal/inputEditorExtensions/`): dictation interim, autocomplete ghosting, inline AI suggestions.
- Debugging polluted undo history, "one Ctrl-Z only undoes a tiny piece", or visible document churn while text streams in.
- Touching `VoiceRecordingService` `onTranscriptionDelta`/`onTranscriptionComplete`/`stop()`, or `useVoiceDecorations` / `useVoiceWaitSubmit`.
- A final value computed in a store fails to reach the editor before a send fires (store→editor sync lag vs microtask ordering).
- Adding any caret-anchored or end-of-doc widget that could overlap IME composition.
