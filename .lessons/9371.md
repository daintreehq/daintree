## Context

`PortalManager` (`electron/services/PortalManager.ts`) manages the AI-host overlay tabs (`claude.ai`, `chatgpt.com`, `gemini.google.com`) as main-process `WebContentsView` instances attached to `window.contentView`. The overlay opens (`showTab`) and closes (`hideAll`) repeatedly during a session. This is the main-process Electron API surface — distinct from the renderer-side `<webview>`/React-portal path covered by #1705.

## Problem

Two user-visible defects: (1) a white flash on every overlay open while the embedded page made its first paint; (2) embedded page state — chat scroll position, in-flight streaming responses, WebSocket/SSE connections — was wiped every time the overlay closed and reopened.

## Root cause

Two independent main-process Electron behaviors, plus a re-show race:

- `WebContentsView` defaults to an **opaque white** background. The first composited frame before `loadURL`'s content paints is white, regardless of the app theme. The fix mirrors the main app view (`createWindow.ts:268` `appView.setBackgroundColor(windowBg)`): call `view.setBackgroundColor(...)` **before** `loadURL`, deriving the color from `resolveAppTheme(...).tokens["surface-canvas"]` (`perWindowInit.ts:346`).
- `hideAll()` used `contentView.removeChildView(view)`. Detaching a `WebContentsView` from the child list silently tears down live renderer state. Reattaching via `addChildView` reloads from scratch. The fix keeps the view attached and moves it offscreen: `setBounds({x:-99999, y:-99999, width:1, height:1})`. Negative coords are required because `validateBounds()` clamps x/y with `Math.max(0, …)` — the parked bounds must bypass that path, so `OFFSCREEN_BOUNDS` is a module constant set directly, not routed through `validateBounds`.
- Re-show race: the renderer's `PortalDock` `ResizeObserver` + window-resize listener fire `updateBounds` and gate only on `activeTabId`, which `hideAll()` deliberately keeps set (so the same tab re-appears on reopen and `destroyHiddenTabs()` still protects it from LRU eviction). Without a guard, a window resize while the overlay is open would call `setBounds` with real bounds and yank the parked view back on top of the overlay. Fixed with a `hidden` flag that makes `updateBounds()` a no-op while parked.

## Lesson

When hiding a main-process `WebContentsView` you must keep alive, **park it offscreen with `setBounds` negative coords — never `removeChildView`/`addChildView`**. Detach only on real destruction. Specifics:

- Set `setBackgroundColor()` **before** `loadURL` on any new `WebContentsView`; the default is opaque white, not transparent. Source it from the theme's `surface-canvas` token.
- Track attachment in an explicit `attachedViews` set: `addChildView` throws if the view is already a child, and a parked view is still attached, so an `activeView !== view` check is no longer a safe attach guard.
- Detach (`removeChildView`) on `destroyView`/`destroy`/`webContents.destroyed` for **any** attached view (active or parked) before closing `webContents`, or the compositor holds a dangling reference.
- If any resize/bounds path is gated on a "current tab" id that survives hide, add an explicit `hidden` flag and early-return from the bounds updater while parked, or a resize will re-show the parked view.
- `removeChildView` implicitly blurred the view; parking does not, so explicitly return focus to the app `webContents` (`getAppWebContents(window).focus()`) on hide, or keyboard input still goes to the hidden page instead of the overlay's renderer focus-trap.

## Applies when

- Showing/hiding/switching any main-process `WebContentsView` (portal overlay tabs, project views, browser panels) that must preserve scroll, in-flight network, or socket state across visibility cycles.
- A white/blank flash appears on first paint of a `WebContentsView` or `BrowserWindow` content view.
- Embedded-page state is lost across overlay/dock open-close cycles and the code path calls `removeChildView`/`addChildView` to toggle visibility.
- A `ResizeObserver` or window-resize listener drives `setBounds` on a view that can be in a hidden-but-attached state.
- Working in `PortalManager`, `perWindowInit.ts`, or `createWindow.ts` on `WebContentsView` attach/detach/bounds/background logic.
