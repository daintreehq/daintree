## Context

A terminal can host an agent two ways: spawned with an agent hint (`launchAgentId`), or a plain shell where the user types `claude`/`gemini`/`codex` mid-session and runtime detection promotes it. `TerminalProcess.shouldPreserveOnExit` decides whether a terminal that exits cleanly (code 0) stays around for the user to inspect final output, or gets trashed.

## Problem

`shouldPreserveOnExit` keyed only on the spawn-time `isAgentTerminal` flag. A plain terminal that ran an agent mid-session had that flag false, so it was silently trashed on clean exit even though it held live agent output worth reviewing (#5765). Spawn-time classification cannot capture runtime promotion — the flag was decided before the agent ever appeared.

## Root cause

The terminal's "is this an agent terminal" identity was treated as a static spawn-time property when it is actually a monotonic runtime fact. Agent detection fires in `handleAgentDetection` long after spawn, and the agent can later exit (the live `detectedAgentType` clears), so no transient runtime field survives to exit time — only a sticky one does.

## Lesson

Model "ever hosted an agent" as a sticky boolean (`everDetectedAgent`) set once in `handleAgentDetection` and never cleared, distinct from transient state like `detectedAgentType` that goes away when the agent exits. `shouldPreserveOnExit` now ORs it with the spawn hint: `if (!launchAgentId && !everDetectedAgent) return false`. Because the flag is live-session-only (not in `PanelSnapshot`) it must be threaded through every read path that crosses a process boundary — all 5 snapshot handlers in `electron/ipc/handlers/terminal/snapshots.ts`, the 4 inline pty-host payloads, `TerminalPublicState`, `PtyHostTerminalInfo`, `BackendTerminalInfo`, and all 3 `statePatcher.ts` builders — or it silently resets to undefined on reconnect. On reconnect/snapshot merge always combine with `||` (`addPanel.ts`: `ptyTerminal.everDetectedAgent || existing?.everDetectedAgent`) so a backend payload that lags the renderer can never downgrade a `true` back to undefined. The renderer mirrors the flag from the `agent:detected` event independently of snapshot IPC, so its exit guard survives even if snapshot delivery is reordered relative to the exit event. The flag has since become the canonical "this was an agent terminal" signal — it also gates default-title derivation (`panelRegistry/helpers.ts`) and trash-focus behavior — so any new agent-vs-plain branch should consult it, not the spawn hint alone.

## Applies when

Adding any exit/trash/preserve/title/focus logic that asks "is this an agent terminal" — OR `everDetectedAgent` with `launchAgentId`, never test spawn-time classification alone. Adding a new field to `TerminalPublicState` that is live-session-only: enumerate every snapshot handler, pty-host payload, reconnect path, and statePatcher builder, and merge with `||` so process-boundary races can't clear it.
