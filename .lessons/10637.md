## Context

Switching away from a project and back left agent terminals (Claude/Codex/Gemini — alt-buffer + DEC 2026 synchronized-output TUIs) showing stale/garbled content until the user clicked the manual "Redraw" pane action. This had been "fixed" ~7 times over a month (#7762, #8003, #8564, #9646, #9704, #10160, #10369, #10418, #10488, #10508 — full archaeology in tracking issue #10632). Each fix added another open-loop repair: a double-rAF defer, 1s/3s repaint backstops, and a 10s "hard guarantee" that runs `resetRenderer` when the `PROJECT_SWITCH_RESIZE_SUPPRESSION_MS = 10_000` window clears. The only continuous closed loop, `TerminalReconciliationWatchdog`, deliberately **excluded** alt-buffer/DEC-2026 terminals — i.e. exactly the agents that break.

## Problem

The pane came back with wrong column wrapping, a paused renderer, or stale WebGL glyph blocks, and stayed that way. The tell that misled everyone: manual **Redraw** _always_ worked. That made it look like a timing problem to be solved by firing the same repair at a better moment — so every fix added more triggers. It kept recurring because the human clicking Redraw was the missing piece: a late, unguarded, "is it correct _now_" verifier. No amount of guessed-time one-shots reproduces a closed loop.

## Root cause

Two independent mechanisms, both invisible unless you look at where a repair _doesn't_ run. (1) **Obligations evaporated.** The 10s `resetRenderer` "guarantee" is armed on the OUTGOING terminals and immediately followed by detach. On a dwell longer than the suppression window the timer fires while the host is still detached / occluded / content-visibility:hidden / a transitional sub-50px box; `resetRenderer` self-skips on its `>=50px` guard and the one-shot recovery is **silently spent** — nothing is left to redraw on the eventual switch-back. (2) **The watchdog excluded the failure population.** It skipped alt-buffer/DEC-2026 terminals wholesale "for safety," but the real hazard is narrow — interleaving a paint into an _open_ synchronized-output block — not the whole class. So when the reveal path no-op'd, the one component that could have retried was carved out of exactly the terminals that needed it.

A third, cross-cutting invariant leaked: `TerminalReflowController.maybeReflow` already refused to reflow mid-DEC-2026-block, but `repaintForReveal` / `fullWakeForVisibilityRestore` / `setVisible` all ran `forceXtermReflow` with no `synchronizedOutputMode` check, so a reveal could interleave a torn frame into an open block — the same invariant, bypassed on every sibling repaint path.

## Lesson

- **When a manual action reliably fixes something automation can't, the automation is missing a convergence VERIFIER, not more triggers.** The multi-month failure was adding rAF/1s/3s/10s one-shots. The fix converted `TerminalReconciliationWatchdog` from an excluder into a closed-loop verifier: it compares `terminal.cols/rows` against `fitAddon.proposeDimensions()` every tick for EVERY on-screen terminal and repairs via an alt-buffer-safe atomic reconcile until they match. The divergence IS the proof it converged wrong; the loop ticks until it doesn't.
- **A one-shot recovery must REPORT whether it actually ran, and the obligation must transfer, not evaporate.** `resetRenderer` now returns `boolean` (false when it self-skips on disconnected/hibernated/sub-50px). `suppressResizesDuringProjectSwitch` (`TerminalInstanceService.ts:651`, gated by `hostHasRenderableDims`) hands the unfulfilled obligation to the watchdog via `revealPendingRepair` + `revealPendingGeneration` (`types.ts:137`) instead of assuming it fired. Any fire-and-forget "guaranteed" repair on a possibly-offscreen surface needs this same ran/didn't-run handshake.
- **Own recovery obligations by a generation counter so rapid re-entry supersedes stale work.** The pending repair is owned by `attachGeneration` (`types.ts:230`); a re-entrant A→B→A→B switch that re-runs its own reveal cancels the older obligation (`revealPendingGeneration > attachGeneration` → drop) rather than double-repairing a since-replaced instance.
- **An exclusion carved "for safety" that removes the exact failure population defeats the mechanism.** The watchdog's `!managed.isAltBuffer` skip was over-broad. Replace whole-class exclusions with the NARROW real hazard: gate only on `inSynchronizedBlock` (an _open_ DEC-2026 block), and let the repair run for alt-buffer agents once the block closes (the window is short; the next 3s tick converges).
- **When you enforce an invariant on one path, audit every sibling path doing the same op.** The never-interleave-mid-block guarantee lived only in `maybeReflow`; reveal/wake/visibility paths bypassed it. Now `synchronizedOutputMode` is re-checked on all of them — and the DATA path (geometry sync, byte-pull, buffer restore) stays unconditional; only the PAINT defers. Re-check the flag on BOTH sides of an `await`: a block can open or close across the async `wakeAndRestore`.
- **A lock-bypassing "fresh fit" is itself a hazard for streaming/alt-buffer panes — this PR is head of a regression chain.** Broadening where `reconcileGeometryFresh` runs (dropping the `isVisible` guard, adding `reconcileRevealGeometry` to more paths) later caused the OpenCode alt-buffer clobber (#10805): a fresh `fit()` re-wraps committed scrollback under a CLI mid-paint. It's now explicitly guarded `#10632 / #10805` at `TerminalInstanceService.ts:1907` — grid-changing fits are deferred for still-streaming panes (`deferGridChangeForStream` / `proposalDivergesFromGrid`); alt-buffer panes never reach the fit at all.

## Applies when

- Diagnosing "agent terminals come back stale/garbled after project switch-back and manual Redraw fixes it" — the mechanism is an open-loop recovery spent on a detached host plus a watchdog that excluded alt-buffer TUIs; check `revealPendingRepair`/`attachGeneration` ownership and the watchdog's `proposeDimensions()` convergence branch.
- Touching `TerminalRevealController.ts` (`repaintForReveal`, `fullWakeForVisibilityRestore`, `reconcileRevealGeometry`), `TerminalReconciliationWatchdog.ts`, or `TerminalInstanceService.resetRenderer`/`suppressResizesDuringProjectSwitch` — reveal logic was split out of `TerminalInstanceService` into `TerminalRevealController.ts`, and a `resizeTransitioning` guard was later added to the watchdog reveal-pending/geometry branches.
- Adding any "guaranteed" one-shot repair (rAF, timer, backstop) to a surface that might be detached/occluded/zero-box when it fires — make it report whether it ran and transfer the obligation to a closed-loop verifier owned by a generation counter.
- Running `forceXtermReflow` / atlas repair / `terminal.refresh` on any reveal, wake, or visibility path — gate on `synchronizedOutputMode`, keep the data path unconditional, and re-check the flag across every `await`.
- Excluding a "risky" class of resource from a recovery/reconcile loop — verify the excluded class isn't the exact population that fails; prefer gating on the narrow hazard (an open synchronized block) over the whole category.
- Relying on a green DOM-renderer E2E for a rendering fix — E2E runs WebGL off, so the stale-atlas variant (#9679/#9894) is structurally invisible; a true recurrence assertion needs a WebGL-on `gl.readPixels`/`capturePage` lane.
