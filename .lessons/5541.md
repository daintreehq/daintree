## Context

`setupWindowServices` (`electron/window/windowServices.ts`) bootstraps each newly-created window: it sets the PTY active project, registers the initial WebContentsView with `ProjectViewManager`, loads worktrees, and initializes the task queue. It receives per-window `opts.initialProjectId` / `opts.initialProjectPath` describing what that specific window should open with.

## Problem

Cmd+N (a deliberately _unbound_ new window meant to show the project picker) opened with the previously-focused window's project already loaded — terminals, worktrees, and the registered view all came from another window. #5492.

## Root cause

The bootstrap derived its project from the **global** main-process singleton, `projectStore.getCurrentProjectId()` / `getCurrentProject()`, rather than from the per-window `opts.initialProjectId`. The project store is one shared instance across all windows, so "current project" reflects whatever the last-focused window set — not the identity of the window being constructed. Every downstream action (`ptyClient.setActiveProject`, `registerInitialView`, worktree load, `taskQueueService.initialize`) keyed off that global, so an unbound window silently inherited the global's project. There was also no explicit unbind path: nothing cleared the PTY binding for a window that should have none.

## Lesson

In a multi-window Electron app, per-window bootstrap must read per-window inputs, never a global "current X" singleton — the singleton tracks focus/recency, not the window being built. Thread the identity through `opts` and gate every project-scoped side effect on a single locally-derived `restoreProject = opts.initialProjectId ? projectStore.getProjectById(...) : undefined`. Crucially, the unbound case needs an _explicit_ negative action: `pty.setActiveProject(win.id, null)` rather than just omitting the call, so the new window starts genuinely empty. A missing project in the store (stale `initialProjectId`) must fall through to the same unbound path, not crash or inherit.

## Applies when

Adding or auditing any per-window initialization in `electron/window/` (PTY active-project, ProjectViewManager view registration, worktree load, task queue, agent stores); any time bootstrap code reaches for `projectStore.getCurrentProjectId()` / `getCurrentProject()` instead of a window-scoped opt; or when a new window inherits state it should not.
