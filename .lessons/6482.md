## Context

`WorkspaceService.createWorktree` runs `git worktree add -b <newBranch> ...` to spin up a worktree on a fresh branch. Deleting a worktree does NOT delete its branch, so a leftover local branch with the same name can survive a worktree teardown. Bulk creation (the GitHub issue/PR "create N worktrees" flow) resolves a batch of branch names up front in `bulkCreatePrequery` before firing the actual creates.

## Problem

Two distinct failures. (1) Single create: after deleting a worktree but keeping its branch, recreating with the same name hit `fatal: a branch named '...' already exists` because `-b` demands a non-existent branch. (2) Bulk create: branch names were resolved in parallel via `Promise.all`, so two siblings in the same batch could both see "name-X is free in git" and both claim it — the second worktree create then collided at write time.

## Root cause

A stale local branch is ambiguous and the two cases need OPPOSITE handling, which `-b` cannot express on its own:

- **Stale (exists locally, not checked out in any worktree)** → reuse it via `git worktree add <path> <branch>` (drop `-b`, the `useExistingBranch` arg form). Preserves the user's chosen name.
- **Live (checked out in another worktree)** → cannot reuse; suffix `-2/-3/...` (`nextAvailableBranchName` scans existing names for the max `-N`, handling non-contiguous gaps and regex-metacharacter branch names via `escapeBranchRegex`) and create fresh with `-b`.

Disambiguation requires probing `git worktree list --porcelain` (`parseCheckedOutBranches`). If that probe FAILS (e.g. `.git` lock contention under bulk creation), the safe move is to suffix, never reuse — reusing a possibly-live ref is the worse error. `fromRemote` (PR mode) ALWAYS suffixes: reuse would drop `--track`, stripping the `@{u}` upstream that ahead/behind badges (`WorktreeMonitor`) depend on, and pin the worktree to the stale tip instead of origin's current tip.

The bulk TOCTOU is a classic check-then-act across siblings: git-level uniqueness is checked once per item against a snapshot that doesn't reflect names already claimed earlier in the same batch. The fix resolves branch names through a sequential loop threading a shared `assignedBranches` Set (`applyUniqueSuffix`), so each item sees prior in-batch claims — no mutex needed. Note the deliberate split: branch-name resolution is sequential (mutates shared claimed-set), but the subsequent PATH resolution stays parallel via PQueue because paths derive from already-unique branch names and carry no cross-item dependency.

## Lesson

- Never feed `git worktree add -b <name>` a name without pre-flighting `git branchLocal()` — a stale branch from a deleted worktree will fail the create.
- Disambiguate stale-vs-live by probing `worktree list --porcelain`; reuse only when NOT checked out anywhere. On probe failure, fail-safe to SUFFIX, never reuse.
- `fromRemote`/PR-mode must always suffix (never reuse) to keep `--track` and the upstream ref the badges read.
- When a batch resolves names/IDs that must be mutually unique, parallel `Promise.all` is a TOCTOU trap — each sibling checks the same pre-batch snapshot. Resolve sequentially through a shared claimed-set. Only the dependent later phase (paths here) may go parallel once the unique keys are fixed.
- Keep the happy-path pre-flight inline (not behind a wrapper promise) when downstream tests assert microtask timing — adding a helper changes the await chain and the tick count tests flush.

## Applies when

- Adding or modifying `WorkspaceService.createWorktree`, `bulkCreate`, or any `git worktree add` call site.
- Symptom: `fatal: a branch named '...' already exists` on worktree creation, or branch-name collisions during bulk/batch worktree creation.
- Touching `electron/workspace-host/worktreeUtils.ts` helpers (`nextAvailableBranchName`, `parseCheckedOutBranches`, `escapeBranchRegex`) or `plugins/builtin/github/renderer/components/bulkCreatePrequery.ts`.
- Any batch operation that assigns mutually-unique names/IDs/paths and currently uses `Promise.all` for the resolution phase.
- Work touching `--track`/`fromRemote`/PR-mode worktrees where ahead/behind badges or `@{u}` upstream resolution matter.
- Writing tests that assert `git.raw` call shape after a `createWorktree` pre-flight (account for the extra `branchLocal` microtask hop).
