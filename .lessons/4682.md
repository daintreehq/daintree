## Context

Electron exposes Chromium feature flags via `app.commandLine.appendSwitch('enable-features', ...)` and `app.commandLine.appendSwitch('disable-features', ...)`. These must be set before `app.ready`.

## Problem

Default Chromium settings include features that are suboptimal for an IDE-style Electron app: `BackForwardCache` consumes memory for browser-style navigation that the app never uses, and memory reclamation/throttling features are not enabled by default.

## Root cause

Chromium's defaults are tuned for a web browser, not a long-lived multi-`WebContentsView` IDE. `BackForwardCache` retains entire page states in memory to make browser back/forward navigation instant — a single-page Electron app never navigates this way, so the cache is pure overhead. Conversely, aggressive memory reclamation (`PartitionAllocMemoryReclaimer`) is off by default because returning freed pages to the OS trades a little CPU for lower RSS, a trade-off browsers don't make eagerly but a memory-conscious IDE wants. These knobs are only reachable through `enable-features`/`disable-features` switches appended before `app.ready`.

## Lesson

Useful feature flags for Electron apps that manage multiple `WebContentsViews`:

**Enable** (set in `electron/setup/environment.ts` via the `enabledFeatures` array, line ~101):

- `PartitionAllocMemoryReclaimer` — returns freed memory to the OS more aggressively (stable since Chromium 110+)

**Disable** (set in `electron/main.ts` via the `disabledFeatures` array, line ~149):

- `BackForwardCache` — caches entire page states for browser back/forward navigation; not useful in single-page Electron apps and wastes memory

Note: `IntensiveWakeUpThrottling` was originally enabled here too, but as of Chromium 146 (Electron 41) the related throttling (`QuickIntensiveWakeUpThrottlingAfterLoading`) is default-on, so it no longer needs an explicit `enable-features` switch. The ~60s background-timer throttling it imposes is now assumed throughout the codebase (see `electron/services/pty/types.ts`, `src/services/terminal/TerminalAgentStateController.ts`).

One flag that did NOT work: `V8FlushBytecodeOnContextDispose` — this is an internal V8 flag, not a Chromium feature flag. It must not be passed via `enable-features`.

Keep the flag sets as named module-level arrays (`enabledFeatures` / `disabledFeatures`) rather than inlining the strings into the `appendSwitch` call, so the configuration is greppable and assertable without launching the full app.

## Applies when

- Electron apps managing multiple `WebContentsViews` or renderers
- Memory optimization at the Chromium level
- Apps that don't use browser-style back/forward navigation
