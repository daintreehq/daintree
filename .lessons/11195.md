## Context

Chromium hard-caps active WebGL contexts per renderer process at 16 and silently evicts the oldest on overflow (`webglcontextlost`), so `TerminalWebGLManager` runs a whole-fleet WebGL-to-DOM mode switch keyed on how many terminals currently want a context (`upperThreshold`/`lowerThreshold` in `TerminalWebGLConfig.ts`). At some earlier point `electron/setup/environment.ts` raised Chromium's actual per-renderer ceiling to a RAM-tiered 24/28/32 via the `max-active-webgl-contexts` switch, but `TerminalWebGLConfig.ts` and the per-profile variants in `shared/types/resourceProfile.ts` were left at the old 16-cap-era values (12/10 balanced, 14/12 performance, 8/6 efficiency).

## Problem

The terminal fleet force-flipped every pane to the slower DOM renderer on a moderately busy grid — around 13 panes wanting WebGL — even though the GPU could hold 24-32 contexts. Nothing crashed; it just looked like the mode switch fired "too eagerly," because the two limits live in different files and neither one, read alone, looks wrong. Issue #11192 diagnosed it by diffing the switch value against the threshold constant directly.

## Root cause

`getMaxWebGLContexts()` in `environment.ts` (main process, Chromium command-line) and `upperThreshold`/`lowerThreshold` in `TerminalWebGLConfig.ts` (renderer, plus per-profile copies in `RESOURCE_PROFILE_CONFIGS`) both encode "how many WebGL contexts can this renderer safely hold" as two separate literals, one process apart, with no shared derivation. Someone raised the Chromium switch to fix a real headroom problem with no way to know the renderer-side throttle needed the same edit; nothing connected the two, so nothing broke the build when they drifted. General shape: two guards independently approximating the same physical limit eventually disagree, invisibly, in either file's diff.

Fix: a single derivation, `getMaxWebGLContextCeiling()` in the new `electron/utils/webglContextBudget.ts`, that both `environment.ts`'s switch and `resolveWebglThresholds()` (per-profile ratios — performance 14/16·12/16, balanced 12/16·10/16, efficiency 8/16·6/16 — applied against the _new_ ceiling, not 16) call into. `RESOURCE_PROFILE_CONFIGS` can no longer even hold a stale WebGL literal: it's typed `BaseResourceProfileConfig = Omit<ResourceProfileConfig, "webglUpperThreshold" | "webglLowerThreshold">`, so those two RAM-dependent fields are structurally absent from the table and only ever produced by `resolveResourceProfileConfig()`. That resolver also closed a narrower drift one level down: the push path (`ResourceProfileService.applyProfile`) and pull path (`getResourceProfile` IPC handler, for a late-created renderer) used to compute the config independently.

`TerminalWebGLConfig.ts`'s bootstrap defaults (used before the first push/pull resolves) went from 12/10 to 18/15 — balanced's value at the guaranteed-minimum ceiling of 24 — because a large restored fleet cold-starting under the stale 12 would flip to DOM before real thresholds arrived, and DOM→WebGL only re-flips once count falls to the _lower_ threshold, so a fleet could get stranded on DOM even after correct values landed.

## Lesson

- **When two guards independently approximate the same physical ceiling, they will drift — derive both from one function, never two literals.** Here it was a Chromium command-line switch (main process) and a renderer-side JS threshold (plus per-profile copies); applies to any paired limit referencing the same underlying resource from two files or processes.
- **Use the type system to make the stale value unreadable, not just untuned.** Typing `RESOURCE_PROFILE_CONFIGS` as `Omit<ResourceProfileConfig, "webglUpperThreshold" | "webglLowerThreshold">` means a future edit literally cannot add those fields back to the static table — the compiler catches what a review comment would miss. Reach for `Omit` whenever a value must be computed, never hand-authored, on a table other code already reads.
- **A push (broadcast) and pull (on-demand IPC) path for the same computed value need one shared resolver, not two call sites that happen to agree today.** `resolveResourceProfileConfig` exists purely so `ResourceProfileService.applyProfile` and the `getResourceProfile` handler can't diverge later.
- **Bootstrap/default values that exist "until the real value arrives" must be sized against the new ceiling too, and check which direction the hysteresis re-arms.** The 12→18 bump mattered because DOM→WebGL only re-flips at the _lower_ threshold — a fleet stuck on a stale-low bootstrap value stays on DOM even after correct thresholds land.
- **Don't stop at the number — grep for every comment asserting the old constant as fact.** This PR corrected "must stay below 16" comments across `TerminalWebGLConfig.ts`, `resourceProfile.ts`, and `TerminalWebGLManager.ts`; a stale comment re-anchors the next reader to the wrong ceiling even after the code is fixed.
- **A companion change riding the same headroom (#11196: standard terminals now keep WebGL at any visible tier, not just focused) was scoped in its issue (#11193) as depending on this fix landing first** — widening eligibility without the retuned thresholds would trip the fleet flip even sooner; PR #11196 shipped after this one but its own description frames the ordering as a soft preference, not a hard gate (a busier grid tripping the flip sooner "isn't a regression") — check whether an issue's "depends on" note survived into the implementing PR as an actual blocker or was quietly relaxed.

## Applies when

- Touching `electron/utils/webglContextBudget.ts`, `electron/utils/resourceProfileConfig.ts`, `environment.ts`'s `max-active-webgl-contexts` switch, or `TerminalWebGLConfig.ts`/`TerminalWebGLManager.ts`/`TerminalWebGLPolicy.ts` thresholds.
- Raising or lowering any hardware/OS-level resource cap (GPU contexts, file descriptors, process limits) that a separate in-app throttle was tuned against — check for a second, uncoordinated guard on the same resource first.
- Diagnosing "the terminal grid drops to DOM rendering / loses glyph fidelity earlier than expected" or any fleet-wide WebGL→DOM flip that looks premature relative to visible GPU headroom.
- Reviewing a resource-profile or config change with both a push (broadcast) and pull (on-demand IPC) delivery path — confirm both derive from the same function.
- Adding a new RAM-tiered or hardware-tiered constant — consider `Omit`-typing the static config table to structurally exclude the computed fields, rather than trusting future editors not to hand-add a stale literal.
