## Context

`AgentHelpService`, `AgentVersionService`, and `AgentInstallService` spawn agent CLIs (`claude --help`, `aider --version`, `npm install -g`, `pipx install`) via `execFile`/`spawn` and surface their stdout/stderr into the renderer. None of these `--help`/`--version` probes authenticate. `WorktreeLifecycleService.buildSpawnEnv()` does the same for recipe lifecycle commands.

## Problem

All three call sites passed `process.env` wholesale to the spawned child. Every probe inherited `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `AWS_*`, `GITHUB_TOKEN`, and any other ambient credential — handed to processes that have no reason to see them, with output also piped straight back to the renderer unscrubbed.

## Root cause

Two structurally separate leak surfaces, both of which must be closed:

- **Input (env inheritance):** A denylist of known-bad keys is insufficient — the universe of secret env-var names is unbounded (`MY_SERVICE_TOKEN`, `APP_DB_PASS`, ...). Only an allowlist is a real boundary. `electron/utils/spawnEnv.ts` builds env from `buildAllowlistEnv(allowed)`, keeping only well-known non-credential keys (`PATH`, `HOME`/`SYSTEMROOT`+`USERPROFILE`, locale) plus `LC_`/`DAINTREE_` prefixes. Dangerous loader/injection vars (`LD_PRELOAD`, `DYLD_INSERT_LIBRARIES`, `NODE_OPTIONS`, `ELECTRON_RUN_AS_NODE`) are excluded _by virtue of not being on the list_ — no explicit strip step needed.
- **Output (captured stdout/stderr):** The input sandbox can't catch a secret the child itself prints. `scrubSecrets()` (from `shared/utils/secretScrubber.js`) must also run at every output boundary: cache-store return (`AgentHelpService` stdout/stderr), chunk-stream emit (`AgentInstallService` per-chunk `onProgress`), and spawn-error messages (`AgentVersionService` `Command failed: ${scrubSecrets(error.message)}`, `AgentInstallService` `err.message`).

Probe and install commands need **two different allowlist tiers**: probes get the minimal `buildProbeEnv()`; installs get `buildInstallEnv()`, which adds proxy/CA/version-manager/XDG/pipx keys. Dropping `HOME` (or `APPDATA`/`USERPROFILE` on Windows) from the install tier silently breaks `npm`/`pipx` user-config resolution (`.npmrc`, `~/.config/pipx`) and private-registry auth behind corporate proxies — a too-tight env is its own regression.

## Lesson

When spawning a child whose output is surfaced to the user, sandbox env with an allowlist and scrub the output — both, not either:

- Build env from `buildProbeEnv()` / `buildInstallEnv()` in `electron/utils/spawnEnv.ts`; never spread `...process.env` into a probe/install/recipe spawn. New spawn call sites in the agent or recipe path must route through these factories.
- Allowlist, never denylist: secret key names are unbounded. Loader vars fall out for free by omission.
- Pick the right tier: probes (`--help`/`--version`) use the minimal probe env; package-manager installs need the broader env or they break user-config/proxy/registry resolution. Adding a new install backend may require a new key in `INSTALL_EXTRA_KEYS`.
- Always also `scrubSecrets()` at cache-store, chunk-emit, AND error-message boundaries — a sanitized env doesn't stop the child from echoing a secret.
- These factories read `process.env.PATH` directly, so call them only after `app.ready` and after `kickOffEarlyPathRefresh()` has settled (IPC-handled service methods are safe by construction).

## Applies when

- Adding or modifying any `execFile`/`spawn`/`exec` call in `electron/services/Agent*Service.ts` or `electron/workspace-host/WorktreeLifecycleService.ts`, or any new agent-CLI probe / installer / recipe-lifecycle command.
- Reviewing a diff that spreads `...process.env` into a spawned child whose output reaches the renderer.
- Supporting a new agent install backend (new package manager) and a previously-working install path breaks under the tighter env — check whether a needed key is missing from `INSTALL_EXTRA_KEYS` in `spawnEnv.ts`.
- Auditing for credential leakage (`ANTHROPIC_API_KEY`, `GITHUB_TOKEN`, `AWS_*`) into non-authenticating subprocesses, or for loader-var injection (`LD_PRELOAD`, `DYLD_INSERT_LIBRARIES`, `NODE_OPTIONS`, `ELECTRON_RUN_AS_NODE`) into spawned children.
