## Context

`IdentityWatcher` (`electron/services/pty/IdentityWatcher.ts`) gates agent-badge demotion: after an agent is detected on a terminal, it decides when to drop the agent identity back to a plain shell. One demotion signal is "the launched command failed" — e.g. the user typed `claude` but the binary isn't on PATH, so the agent never actually started. `hasRecentCommandFailureOutput()` (line 368) scans the last N visible lines for a failure phrase and feeds it into the demotion branches at lines 508–546.

## Problem

The original detector matched only four English phrases (`command not found`, `not found`, `no such file`, `permission denied`) compiled with the `i` flag. Anyone running zsh/bash in a non-English locale (French, German, Japanese, Chinese, Russian, etc.) silently got no failure detection, so a mistyped/missing agent command left the agent badge stuck on a shell that had already returned to a prompt. PowerShell users got partial detection at best.

## Root cause

The intuitive fix — "stop regex-sniffing output, just read POSIX exit code 127" — does not work for the dominant case. Exit code 127 lives in `$?` _inside_ the shell process. When a missing command is typed in an **interactive** shell, the shell stays alive, so `node-pty`'s `onExit` never fires and `exitCode` is never 127 — the host process simply doesn't observe it. Exit-code detection is only feasible on the non-interactive agent-spawn path (`pty.spawn('bash', ['-c', 'claude ...'])`) where the shell exits and propagates the child's status. For interactive shells, parsing the terminal output is the only viable signal, and that output is locale-dependent: the shell prints the "command not found" message in the user's `LC_MESSAGES` language. So the detector must carry localized phrases, not rely on a numeric code.

## Lesson

For interactive-shell failure signals, parse output, not exit codes — `node-pty.onExit`/`exitCode` only fires when the shell process itself dies, which it doesn't on a failed interactive command. When the signal is a shell message, it is localized: enumerate the major-locale phrases (`commande introuvable`, `Befehl nicht gefunden`, `コマンドが見つかりません`, `未找到命令`, `команда не найдена`, …) in `COMMAND_NOT_FOUND_PATTERNS` and compile with `iu` (case-insensitive + Unicode). Prefer locale-independent anchors where they exist — PowerShell's `CommandNotFoundException` `FullyQualifiedErrorId` is emitted regardless of UI culture, and is a more robust match than the human-readable `is not recognized as the name of a cmdlet` (kept only as a tail-window fallback for when the structured error line scrolls past the scan window).

## Applies when

Adding or extending any heuristic that detects shell-command outcomes (command-not-found, permission-denied, non-zero exits) from terminal output in `IdentityWatcher`, `AgentStateMachine`, or `ActivityMonitor`; reaching for `pty.onExit`/exit-code 127 to detect a failure in an interactive (long-lived) shell; or writing any English-only regex against shell-emitted message text where the user's locale governs the wording.
