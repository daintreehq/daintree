## Context

Terminal hibernation eligibility is driven by `applyRendererPolicy(tier)` in `TerminalInstanceService`. A terminal only becomes hibernation-eligible at `TerminalRefreshTier.BACKGROUND`, and `isSafeToHibernate` (`TerminalHibernationManager.ts`) decides whether an active-agent panel may be torn down. PR #8998 added a new policy input: user-backgrounded panels (`usePanelStore.getState().backgroundedTerminals`) should bypass the `AGENT_IDLE_SILENCE_MS` window so an explicitly-hidden panel with a live agent can still reclaim memory under pressure.

## Problem

A panel that was already offscreen at `BACKGROUND` tier, then explicitly backgrounded by the user, would not get the new bypass. Its hibernation timer was armed by the earlier tier drop as a one-shot eligibility re-check that waits out the full `AGENT_IDLE_SILENCE_MS`. Backgrounding it again did not shorten that wait — the memory wasn't reclaimed until the silence window expired anyway, defeating the point of the explicit-background bypass.

## Root cause

The eligibility path is entered through tier _transitions_: `applyRendererPolicy(BACKGROUND)` reschedules hibernation. But `applyRendererPolicy` is idempotent — a same-tier call is a no-op (documented in `TerminalInstanceService.ts` around the WebGL-restore debounce, "same-tier applyRendererPolicy is a no-op"). The new bypass depends on a _non-tier_ input (`backgroundedTerminals` membership), so changing only that input while the tier stays `BACKGROUND` never re-enters `scheduleHibernation`. The pending eligibility timer, armed before the bypass existed, keeps running on the old silence-window logic. There is no tier edge to trigger re-evaluation.

## Lesson

- When a tier/state-gated decision starts depending on an input that is NOT the gating key itself, mutating that input does not re-trigger the gated path — the idempotent tier setter swallows the change. You must add an explicit re-arm hook fired by whatever mutates the new input.
- The fix is `onPanelBackgrounded(id)` on `TerminalInstanceService`: it cancels the pending hibernation/eligibility timer and reschedules, but only for a panel that is `!isVisible` and already at `lastAppliedTier === BACKGROUND` (the visible→background transition already arms correctly via the detach → `setVisible(false)` → tier path). Wired from `backgroundTerminal` and `backgroundPanelGroup` in `background.ts`.
- Read the new input _live_ at every eligibility check, never captured into the timer closure: `getIsBackgrounded: (id) => usePanelStore.getState().backgroundedTerminals.has(id)`. A restore between schedule and fire must drop the bypass so `hibernate()` bails instead of tearing down a now-foreground live agent (verified by the `BACKGROUNDED_BYPASS_DROPPED_WHEN_RESTORED_BETWEEN_SCHEDULE_AND_FIRE` adversarial test).
- Keep the unconditional `pendingWrites === 0` burst guard even when bypassing the silence window — the bypass relaxes only the agent-activity exemption, never the mid-write guard.

## Applies when

- Adding a new input to `isSafeToHibernate` / `isHibernationEligible` / `scheduleHibernation` that is not the `TerminalRefreshTier` itself (e.g. user intent flags, pin state, snapshot state).
- Any policy gated by an idempotent tier/state setter where you later add a same-tier-relevant condition — audit whether mutating that condition needs an explicit re-arm; a same-tier `applyRendererPolicy` will silently no-op.
- Wiring renderer store actions (`background.ts`, panel-group actions) that change terminal lifecycle state without changing the refresh tier.
- Debugging "the bypass/policy change didn't take effect until a timer expired" or "memory not reclaimed after backgrounding an already-hidden panel."
- Threading a renderer-store lookup into `HibernationManagerDeps` — read it live per-check, do not snapshot it into a `setTimeout` closure.
