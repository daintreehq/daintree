## Context

On startup, terminals restore their scrollback from a `.restore` file by writing the serialised buffer back into xterm before the new PTY spawns.

## Problem

If the terminal was in an interactive full-screen program (vim, htop, less, tmux) when the previous session ended, the restored content was a frozen snapshot of that TUI's alt-screen state — with no running process behind it, so every keystroke went to the wrong place or did nothing. Users saw a ghost vim they couldn't close.

## Root cause

Alt-screen programs write `\x1b[?1049h` (enter alt-screen) on start and `\x1b[?1049l` (exit) on quit. xterm's buffer serialiser captured whatever buffer was active. If the process crashed or the app was killed mid-alt-screen, the serialised bytes included `\x1b[?1049h` but never the matching exit sequence. On restore, xterm dutifully re-entered alt-screen and painted the dead TUI.

Second compounding issue: restore banners (separator marks injected after restore) were serialised back into the next snapshot, so they accumulated across restart/restore cycles.

## Lesson

Write the restored content into the headless xterm parser, then ask xterm itself whether it landed in the alternate buffer (`headlessTerminal.buffer.active.type === "alternate"`) rather than regex-scanning the raw bytes for an unmatched `\x1b[?1049h` (or the older `\x1b[?47h` / `\x1b[?1047h`). If it did, emit the matching exit sequence (`\x1b[?1049l`) to drop back to the primary buffer and append a plain-text "previous session was in a full-screen app" banner instead of leaving the dead TUI on screen. Also keep restore banners out of the next snapshot — they are tracked as xterm markers and excluded by `serializeForPersistence()` — so they don't compound across restart/restore snapshot cycles. (Per-terminal hibernation itself was torn out in PR #10811; the surviving trigger for this is the ordinary app-restart snapshot/restore round-trip, plus the rarer user-initiated "Close Them" project hibernation path that still calls `writeHibernatedMarker()`.)

```ts
// restoreSessionFromFile (electron/services/pty/terminalSessionPersistence.ts)
headlessTerminal.write(content);
const wasInAlternateScreen = headlessTerminal.buffer.active.type === "alternate";
if (wasInAlternateScreen) {
  headlessTerminal.write("\x1b[?1049l"); // exit alt-screen, fall back to primary buffer
  // append "...previous session was in a full-screen app..." banner
}
```

## Applies when

Any code that persists and replays xterm buffers across restarts. Also applies to any feature that serialises a terminal state for later viewing (session recording, sharing). Look for `\x1b[?1049h`, `\x1b[?1047h`, and `\x1b[?47h` — they all trigger alt-screen.
