## Context

The WSL git fast-path routes git through `wsl.exe git` (5-10x speedup) for worktrees on `\\wsl$\<distro>\...` UNC paths. Two pieces of per-worktree state drive it: a persisted opt-in map `wslGitByWorktree` in `electron/store.ts` (`Record<string, {enabled, dismissed}>`, keyed by the worktree's normalized filesystem path — `worktree.id` IS that path), and a computed eligibility flag (does the worktree's distro match the WSL default). `enrichWorktreeWithWsl` in `WorkspaceService.ts` reads the map on every `loadProject` and folds eligibility into each `WorktreeMonitor`; `wslInvocation` gates routing on both. #10304 and sibling #10264 fixed two independent silent-staleness bugs here, both against pre-existing latent code (neither a regression of a specific PR).

## Problem

Two silent symptoms (no banner, no error). (1) Opt in to WSL git, `git worktree remove` it, later recreate a worktree at the same path — the new worktree silently inherits `wslGitOptIn: true, wslGitDismissed: true` and routes git through WSL with the banner never shown (#9926). (2) Run `wsl --set-default Debian` mid-session — opted-in worktrees keep routing git through `wsl.exe` (now Debian) while their filesystem is still on Ubuntu, the renderer says nothing is wrong, and new worktrees get a stale verdict (#9924).

## Root cause

Two lookalike-correct patterns, each silently destroying state.

1. **The persisted map was write-only.** `setWslGit`/`dismissWslBanner`/`writeWslGitEntry` only wrote; no removal path deleted entries. The three monitor-removal sites (`syncMonitors` stale loop, external-removal handler, `deleteWorktree`) dropped the monitor but left the opt-in behind, and because the map is keyed by a **reusable identifier** (the filesystem path) a fresh worktree on a recycled path hit the stale row. Fix: unify all three into one `removeMonitor(id)` chokepoint that deletes the in-memory entry and emits `clear-wsl-git-opt-in`; main's `WorkspaceHostEventRouter` calls `clearWslGitEntry`. Per-removal pruning isn't enough (an external `git worktree remove` or a mid-clear crash leaves orphans), so `loadProject` also runs a bulk self-heal `pruneStaleWslGitEntries`. The trap: `wslGitByWorktree` is a **single global electron-store key** with no per-project namespace, so a naive self-heal dropping every key absent from the live set erases _other projects'_ opt-ins on every load/prewarm/host-restart. So it must be **project-scoped** — prune only keys at or under this project's parent dir (`isPathKeyAtOrUnder`); foreign keys wait for their owner's next load.

2. **Eligibility was a two-state boolean serialized with truthiness shorthand.** `wslGitEligible: boolean` snapshotted as `this._wslGitEligible || undefined` collapsed `false` (ineligible: distro mismatch) and `undefined` (unprobed: failed/pending) into one absent value, and the banner had only "enable" / "runs via Windows" variants. Worse, the default-distro probe (`getDefaultWslDistro`, parsing `wsl --list --verbose` for `*`) was cached per-host and invalidated **only on project switch**, and `_wslGitEligible` had no setter — so a mid-session `wsl --set-default` was never observed and monitors never re-checked. #10264 replaces the boolean with `WslGitEligibility = "eligible" | "ineligible" | "unprobed"` (`shared/types/worktree.ts`), emits the raw three-state for WSL paths, adds a `setWslEligible` runtime setter, a 60s Windows-only poll (`pollWslDefaultDistro` diffs `wslLastKnownDefaultDistro` → `refreshWslEligibilityForAllMonitors`), a `reprobeWsl` IPC + "Re-check" button, and a monotonic `wslProbeSeq` guard so a slow probe resolving after a newer probe or a project switch (`stopWslDistroPoller` bumps the seq) discards its stale result.

## Lesson

- **Persistence keyed by a reusable identifier (filesystem path, recycled slot id) is a time bomb unless every removal path prunes it.** Write-only map + key reuse = a new entity silently inherits the old one's state. Don't scatter the delete across N inline removal sites — funnel through ONE chokepoint (`removeMonitor`) that prunes the side map in lockstep, plus a bulk self-heal for orphans created outside those paths.
- **A self-heal over a GLOBAL single-instance persisted map must be owner-scoped, or it erases everyone else.** `wslGitByWorktree` has no per-project namespace; dropping every key absent from project A's live set nukes project B's opt-ins on A's load. Prune only keys provably under the current project (`isPathKeyAtOrUnder`); leave foreign keys for their owner's next load.
- **Never truthiness-shorthand (`x || undefined`, `!!x`) a value with THREE meaningful states.** `bool || undefined` collapses "explicitly false" into "unknown", so a consumer can't offer "re-check" instead of showing a wrong verdict. Model it as an explicit union (`"eligible" | "ineligible" | "unprobed"`), not boolean-plus-absence.
- **A cache invalidated on only ONE lifecycle event goes stale on every other mutation path.** The distro probe cleared only on project switch, so mid-session OS changes were invisible. With no OS event to subscribe to, poll and diff (60s, `unref`'d, Windows-only) and guard the async probe with a monotonic sequence so a project switch / newer probe supersedes a slow one before it mutates state.
- **electron-store v11: `set(undefined)` throws and every `set` re-serializes the whole file.** Mutating one key = batched read-mutate-set writing a real (possibly empty) object, never `undefined`; make it idempotent so a duplicate event or mid-clear crash can't corrupt the file. Legacy Windows UNC keys may be mixed-case — match case-insensitively on win32.

## Applies when

- Adding to or removing from a persisted map keyed by a reusable/recyclable identifier (worktree path, project path, `wslGitByWorktree`, LRU slot maps, path-keyed caches) — verify every removal path prunes and a global map's self-heal is owner-scoped.
- Serializing or diffing a flag that can be true / false / unknown (eligibility, probe results, feature-detection) — use a string union, never `bool || undefined` or `!!value`.
- Touching WSL git state: `enrichWorktreeWithWsl` / `removeMonitor` / `pruneStaleWslGitEntries` / the distro poller, `WorktreeMonitor.setWslEligible` / `wslInvocation`, `store.ts` `clearWslGitEntry`, or `WslGitBanner.tsx`.
- Caching an OS/environment fact (default distro, PATH tool, platform capability) a user can change mid-session with no event to subscribe to — add a poll + diff and a supersede guard, not a single-trigger invalidation.
- Diagnosing "a setting I removed came back on its own" or "stale environment state until I restarted / switched projects" — suspect a write-only side map or a cache pinned to one invalidation trigger.
