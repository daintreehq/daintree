## Context

The assistant figure pipeline lets the help assistant surface documentation images: main assigns sequential per-session figure numbers (`sessionStore.nextFigureNumber`, #9828), #9860 teaches the assistant to call `help.displayImage` and reference results as plain-text `[image #N]`, #9861 adds the renderer UI (`FigureRail` thumbnails between the assistant terminal and the bottom info bar, `FigureLightbox` full-size view, figures accumulated in `useHelpPanelStore.figures`), and #9863 makes `[image #N]` tokens in the terminal clickable via `ImageLinksAddon`. All of it still exists as shipped.

## Problem

No bug — the lesson is the three innocuous-looking design alternatives the arc had to reject, each of which fails mechanistically in Daintree and none of which is obvious from the feature spec: let the rail size itself to content, build the lightbox on native `<dialog>`, and keep figures alive across session resets. A future agent building any panel-adjacent strip, modal overlay, or session-scoped cache would plausibly reach for all three.

## Root cause

Three separate mechanisms, one per rejected alternative.

**Terminal-adjacent height churn.** `FigureRail` sits in the HelpPanel flex column directly under the live xterm terminal. Any height change in a sibling resizes the terminal container, which fires `XtermAdapter`'s ResizeObserver → fit → cols/rows change → PTY resize. In this codebase a terminal resize is not a cheap reflow: resize/reveal cascades on the assistant terminal specifically have produced visible scrollback re-wrap and duplicated output (`reconcileGeometryFresh`, #10863), and resize storms have wedged whole renderers (#10471 reveal-resize backlog). So the rail is hard-fixed at `h-[88px]` with `overflow-x-auto`, renders `null` at zero figures (exactly one resize when the first figure arrives, none after), and deliberately has no per-image dismissal — removing figures would both dead-link `[image #N]` references and reintroduce height churn.

**Native `<dialog>` vs the app escape stack.** Daintree routes Escape through a single LIFO stack (`src/lib/escapeStack.ts`): overlays register via `useEscapeStack`, and one window-level keydown listener (`useGlobalEscapeDispatcher`) pops only the top entry and `preventDefault()`s. HelpPanel itself is on that stack (`useEscapeStack(isOpen, handleEscape)` in `HelpPanel.tsx`). A native `<dialog>`'s Escape cancel is browser-internal — it never joins the stack and doesn't mark the keydown consumed — so one keypress would close the native dialog AND dispatch the stack top, which is the HelpPanel: the lightbox and its host panel both vanish. `FigureLightbox` therefore wraps `AppDialog`, which registers on the stack (LIFO ordering makes Escape consume only the lightbox) and brings the focus trap and focus restoration along.

**Cross-process counter restart.** `sessionStore.figureCounters` is per-help-session and cleared at every session teardown/replacement (`clearFigureCounter`, five call sites in `httpLifecycle.ts`), so a new session's first figure is figure #1 again. `ImageLinksAddon` resolves link targets live — its getter reads `useHelpPanelStore.getState().figures` on every `provideLinks` call. If `clearTerminal` didn't drop `figures` (and `activeFigureNumber`), a stale figure #1 from the previous session would satisfy the new session's `[image #1]` link and open the wrong image — mis-resolution, not just a leak. Both `clearFigures` and `clearTerminal` reset both fields, and `activeFigureNumber` is never persisted.

## Lesson

- **Anything sharing a flex column with an xterm pane must have a fixed height** (or change size only on discrete user actions, never per-content-arrival). Growth re-fires fit → PTY resize per event, and assistant-terminal resizes have separately caused visible buffer re-wrap corruption (#10863). Copy `FigureRail`: fixed `h-[88px]`, internal `overflow-x-auto`, render `null` when empty.
- **Never build an overlay on native `<dialog>` or a hand-rolled Escape keydown listener — wrap `AppDialog`** so it joins the LIFO stack in `src/lib/escapeStack.ts`. Any Escape handling outside the stack double-fires against whatever panel is registered beneath it; the dispatcher can only serialize handlers it knows about.
- **When main restarts a per-session counter, flush every renderer cache keyed by it on the same lifecycle edge.** Restarting numbering makes stale entries collide with fresh ones (wrong-image resolution), which is worse than leaking. `clearTerminal` → drop `figures` + `activeFigureNumber` is the pattern; the store test names the invariant.
- **For non-URL link tokens, resolve validity through a live getter and omit hover/leave callbacks.** The getter lets links activate/go inert as state changes without re-registering the provider; hover callbacks feed `ManagedTerminal.hoveredLink`, which would offer "Open link" / "Copy link address" for something that isn't a URL. Register scoped (`useHelpPanelStore.getState().terminalId === id` in `ensureDeferredAddons`) and dispose at every teardown site (tier drop, hibernate, destroy) — undisposed providers are GC roots (see #9546).
- **A component that imports `AppDialog` drags the `@/hooks` → panelPersistence module chain into any test that renders it**, breaking suites whose store mocks don't cover that chain — stub it like the other heavy children (`vi.mock("../FigureRail", () => ({ FigureRail: () => null }))` in the HelpPanel suites).

## Applies when

- Adding or modifying any strip/banner/rail in a terminal pane's or HelpPanel's layout column that could change height as content streams in.
- Building any modal, lightbox, or popover and considering native `<dialog>`, or adding a component-local `keydown` Escape listener instead of `useEscapeStack`/`AppDialog`.
- Caching main-process-assigned identifiers (figure numbers, MCP session ids) in a renderer store — check what happens to the cache when the assigning session restarts its counter.
- Registering a new xterm `ILinkProvider` in `TerminalInstanceService.ensureDeferredAddons`, especially for tokens that are not URLs or file paths.
- Writing tests for components near `HelpPanel` that transitively import `AppDialog` and hit "mock not defined" failures from the panelPersistence chain.
