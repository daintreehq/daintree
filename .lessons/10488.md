## Context

Switching away from a project and back reveals the backgrounded `WebContentsView`; the terminal reveal path (`repaintForReveal`, now in `TerminalRevealController`) reacquires WebGL, repairs the atlas, unpauses IO, and re-fits the xterm grid so agent panes come back live. Switching also installs a per-terminal resize lock (`RESIZE_LOCK_TTL_MS = 5000` in `TerminalResizeController`) plus a longer suppression window, to damp the ResizeObserver storm the layout thrash would cause.

## Problem

Agent terminals returned with garbled line wrapping — the buffer wrapping at the wrong column. Clicking Redraw (three-dots menu → `resetRenderer`) rescued a pane, so it read as a cosmetic repaint bug. It had been "fixed" and returned repeatedly: #10362, a retry-until-stable reveal sweep, and the hibernation rehydration path each added more repaint/unpause/retry machinery, and each time the garble came back.

## Root cause

The garble is a stale _column count_, and repaint/unpause/atlas-refresh cannot fix that — only re-fitting the grid to the live box can. The reveal path never re-fit, for two reasons both rooted in the switch-time locks. (1) The reveal fires ~0.5–1.5s after the switch, inside the 5s resize lock, so the shared `fit()` returns `null` under `isResizeLocked` and falls back to a PTY-only resize — xterm's grid is never reflowed. (2) For settled-strategy agents (Codex, Gemini, Cursor — Ink TUIs that can't tolerate a split xterm-then-PTY resize), the wake path skipped `fit()` entirely and only re-sent _cached_ PTY dims. Either way a container resize that happened while backgrounded left xterm wrapping at the old column. Manual Redraw worked only because the user clicks it seconds later, after the lock expired and `fit()` finally runs — masking the gap and making every prior "repaint harder" fix look plausible.

The fix (#10488) is `TerminalResizeController.reconcileGeometryFresh(id)`: a one-shot reconcile that measures the live box _fresh_ (`fitAddon.proposeDimensions()`, cell-metric fallback), then resizes xterm and the PTY atomically. It is deliberately lock-exempt — the reveal is the one legitimate resize moment in the window — but does **not clear** the shared lock, so ResizeObserver-storm damping survives elsewhere. It returns `false` on an unmeasurable box so `revealUntilStable` retries. `repaintForReveal` now drives it instead of the cached-dims wake path.

#10508 hardened the arc, because a _single_ reveal frame-sweep (~130–160ms) fires before the compositor presents the view, before xterm's `IntersectionObserver` un-pauses, and still inside the lock. It added a timed cadence `REVEAL_BACKSTOP_DELAYS_MS = [1000, 3000]` after `app:view-revealed` (in `WorktreeStoreContext` for grid panes, `HelpPanel` for the Assistant) re-running the same idempotent repaint; and a hard guarantee once the ~10s suppression clears — `suppressResizesDuringProjectSwitch`'s timer runs `resetRenderer(id)` on each switched terminal — the only pass that reaches an agent TUI, since the `TerminalReconciliationWatchdog` deliberately skips alt-buffer / DEC-2026 synchronized-output panes (_why_ nothing retried the repaint on its own).

## Lesson

- **A garbled line wrap on reveal is a stale grid dimension, not a stale paint — repaint/unpause/atlas-refresh/`forceXtermReflow` can never fix a wrong column count.** If a "redraw harder" fix keeps regressing (#10362 and two others), stop adding paint machinery and check whether anything re-fits the grid to the live box on that path.
- **The project-switch resize lock silently swallows `fit()`: it returns `null` under `isResizeLocked` and callers fall back to a PTY-only resize.** Any correction that must run inside the switch window has to be explicitly lock-exempt. Make it one-shot and **do not clear the shared lock** (`reconcileGeometryFresh` keeps `isResizeLocked` true), or you lose the ResizeObserver-storm damping the lock exists for.
- **Settled-strategy agents (Codex/Gemini/Cursor) skip `fit()` on wake by design** to avoid a jittery xterm-then-PTY split; the correction must resize xterm _and_ PTY atomically in one synchronous step. Verify a geometry fix covers the settled path — a bug that only hits Ink TUIs is easy to miss.
- **A single reveal frame-sweep lands before compositor present, before the `IntersectionObserver` un-pauses, and inside the lock — so it can't stick.** Back it with an idempotent timed cadence (`[1000, 3000]`) plus a post-suppression `resetRenderer` hard guarantee; visibility-/box-guard each pass, cancel stale timers on rapid switch-back, and measure fresh — never trust cached `latestCols/latestRows` for a backgrounded view. This lock-exempt reconcile must also never re-wrap a live TUI: later hardening skips alt-buffer panes (#10632) and mid-stream main-buffer panes (#10863), which race the app's own SIGWINCH redraw.

## Applies when

- Diagnosing garbled/wrong-width terminal wrapping after switching projects, revealing a backgrounded view, or toggling the sidebar/Assistant — and a manual Redraw fixes it (the tell: Redraw runs after the 5s lock expires).
- Touching `reconcileGeometryFresh`, `repaintForReveal`, `TerminalRevealController`, `suppressResizesDuringProjectSwitch`, or the `REVEAL_BACKSTOP_DELAYS_MS` cadence in `WorktreeStoreContext` / `HelpPanel`.
- Adding any resize/geometry correction inside the project-switch resize lock or suppression window — check `isResizeLocked`, the settled-strategy `fit()` skip, and whether you're re-wrapping an alt-buffer or actively-streaming pane.
- Reviewing a "just repaint it again" fix for a terminal display bug — confirm it re-fits the grid, not just unpauses the renderer.
