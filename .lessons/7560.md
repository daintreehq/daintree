## Context

Help-session PTYs (the agent shells Daintree spawns for Claude/Codex help) spawn process trees. Daintree already had two cleanup tiers: cooperative kill on close (`taskkill /T /F /PID` on Windows — lesson #3322 — and process-group SIGKILL on POSIX), and a persisted-PID startup orphan sweep (`TrashedPidTracker` — lesson #3762). `HelpSessionJobService` (`electron/services/HelpSessionJobService.ts`) adds a third tier wired through `PtyEventRouter.onTerminalPid` → `PtyClient` → `helpSessionService.isHelpTerminal(id)`.

## Problem

Both existing tiers have the same gap: they assume the main process either runs the cleanup code (cooperative) or gets a clean _next_ launch to run the sweep (persisted PIDs). A hard crash, force-quit, or OOM kill of the main process bypasses every cooperative path, and if the user never relaunches (or relaunches much later) the persisted-PID sweep never fires either. The full help-session shell tree leaks — on macOS each orphan also burns one of ~511 system PTY fds.

## Root cause

There is no JS-level path that survives the process dying _for any reason_ — `process.kill`, `taskkill`, `atexit`, `before-quit`, and unref'd timers all require the main process to still be executing. The only thing the OS guarantees to act on at hard-death is the teardown of a kernel resource owned by the dying process:

- **Windows** (`win_job_object.cc`): one global Job Object created with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; PIDs are added via `AssignProcessToJobObject`. The kernel closes the HANDLE when the process dies and reaps every assigned process _and its descendants_. The HANDLE is **intentionally never closed in JS/C++** — closing it on quit would either no-op or kill agents prematurely; letting it die with the process _is_ the trigger.
- **POSIX** (`posix-pty-reaper`): a detached, `unref`'d supervisor process; main holds the **write end of its stdin pipe** as a "death pipe." On hard death the kernel closes the fd, the supervisor reads EOF and SIGKILLs every registered tree. libuv sets CLOEXEC on the parent's pipe end, so node-pty children can't inherit and hold it open.

## Lesson

For process-tree cleanup that must survive a hard crash, the cooperative kill and the persisted-PID startup sweep are necessary but **not sufficient** — add an OS-owned death channel whose teardown the kernel performs unconditionally when the main process dies:

- Windows: a single global Job Object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; add PIDs, never close the handle.
- POSIX: a detached `unref`'d supervisor + a death-pipe (main holds the write end; EOF ⇒ reap). On a _clean_ quit, send `DISARM` before closing so it stands down and lets cooperative teardown own the kill.
- Make it **purely additive** on top of existing cooperative paths, and degrade to a logged no-op (warn once, not per-event) when the native binary is missing or `AssignProcessToJobObject` fails (CI/MDM non-nesting jobs return `ERROR_ACCESS_DENIED`).
- Native-addon packaging gotchas: `binding.gyp` must gate sources on `OS=="win"` so macOS/Linux installs don't try to compile Windows-only code; `electron-rebuild -w <addon>` in `postinstall`; `asarUnpack` the `.node`; verify presence in `afterPack.cjs`.
- Insert the PID into the dedupe set _eagerly_ before the native call — `AssignProcessToJobObject` on a PID already in the same job is undefined to repeat, and a transient failure must not retry on every `terminal-pid` event.

## Applies when

- Adding crash-safe cleanup for any spawned process tree (PTYs, dev servers, agent subprocesses) where cooperative kill or a startup orphan sweep leaves a hard-crash/force-quit/OOM gap.
- Working in `HelpSessionJobService`, `electron/native/win-job-object`, `electron/native/posix-pty-reaper`, or wiring `PtyEventRouter.onTerminalPid` / `PtyClient` PID handoff.
- Considering whether `taskkill /T` (#3322) or `TrashedPidTracker` (#3762) is enough — it isn't if the requirement is "no orphans even if the app is killed and never relaunched."
- Shipping a new Windows-only or POSIX-only native N-API addon: `binding.gyp` OS gating, `electron-rebuild` in postinstall, `asarUnpack`, `afterPack` presence check.
- Designing a detached supervisor / watchdog process that must reap on parent hard-death — use a death-pipe (EOF on the inherited fd), rely on libuv CLOEXEC so PTY children don't pin it open, and add a DISARM handshake for clean shutdown.
