## Context

`CcrConfigService` (`electron/services/CcrConfigService.ts`) polls `~/.claude-code-router/config.json` every 30s and rebroadcasts the derived agent presets to renderers via `broadcastToRenderer(CHANNELS.AGENT_PRESETS_UPDATED, …)`. The loop was started fire-and-forget (`void poll().catch(() => {})`) and `stopWatching()` only called `this.watchAbortController?.abort()` synchronously.

## Problem

`stopWatching()` returned before the loop actually stopped. If the loop was mid-`loadAndApply()` (a `readFile` + broadcast), it could finish and broadcast to renderers _after_ teardown returned — broadcasting into half-disposed windows during shutdown/project-teardown, with teardown in an undefined state. A caller that `await`ed `stopWatching()` got no guarantee the work had drained. Aborting during the 30s sleep also did nothing useful: the bare `setTimeout` sleep ignored the signal, so the loop sat out the full wait before noticing `signal.aborted`.

## Root cause

`abort()` only flips a flag; it does not unwind an `await` that is already past the `if (signal.aborted) break;` check. Two gaps:

1. The loop promise was untracked, so nothing could be awaited to know it had exited.
2. The sleep was non-abortable, so the abort latency was up to 30s. The fix captures the loop in a `pollPromise` field, makes `stopWatching()` async and `await`s it, and replaces the sleep with `abortableSleep(ms, signal)` that rejects the moment the signal fires. Critically, `stopWatching()` snapshots `controller`/`promise` into locals and nulls the fields _before_ `abort()` + `await`, so a `startWatching()` racing in during the await installs a fresh loop without its fields being clobbered by the still-running teardown (the start→stop→start case).

## Lesson

A backend poll/watch loop only has a real teardown contract if (a) the loop promise is stored on the instance and `await`ed by `stop()`, and (b) every blocking wait inside the loop is signal-aware so abort latency is bounded. A `signal.aborted` check between iterations is insufficient — an `await` already in flight has passed the check and will still complete its side effects. Pattern: store `pollPromise`; make `stop()` async; use an `abortableSleep` that wires `signal.addEventListener("abort", …, { once: true })` to `clearTimeout` + reject; in `stop()`, copy controller+promise to locals and null the fields before aborting/awaiting so a concurrent `start()` is never trampled. (Aside: this PR also wired the call into the last-window-close handler — the wrong lifecycle hook. That half was later moved to before-quit in `electron/lifecycle/shutdown.ts`; see lesson #8637. The service-internal mechanism here is the durable part.)

## Applies when

You have a long-running `while (!signal.aborted)` poll/watch loop in any `electron/services/*` or utility-host service that performs IPC broadcasts or filesystem side effects, and a lifecycle hook needs to _await_ clean shutdown — especially if `start()`/`stop()` can be re-invoked across window or project teardown and reactivation.
