## Context

`WatcherController` (`electron/workspace-host/WatcherController.ts`) tiers the git file watcher by focus state: the focused worktree gets a recursive worktree watcher (`@parcel/watcher`, `watchWorktree:true`), background worktrees stay on the cheap `.git/`-only `fs.watch` set. Focus flips rotate granularity; a self-trigger cooldown prevents the watcher from re-firing on the writes its own `git status` produces. Poll cadence (`pollIntervalMs`) is mode-aware: recursive coverage relaxes the safety-net poll to 5min (`WATCHER_FALLBACK_POLL_INTERVAL_MS = 300_000`), git-only-active tightens to 60s.

## Problem

Two distinct issues. (1) Rapid focus flips between worktrees tore down and re-armed the recursive watcher synchronously on every toggle. On Linux the recursive arm registers per-directory inotify watches across the whole tree — churning them on quick back-and-forth is expensive and can brush ENOSPC. (2) The self-trigger cooldown branch in `handleGitFileChange` set `gitWatchRefreshPending = true` and `return`ed without arming any timer. An isolated `.git/` event landing inside the 1s cooldown window (`GIT_WATCH_SELF_TRIGGER_COOLDOWN_MS`) had nothing to drain it, so it surfaced only on the next poll — up to 60-300s later depending on mode. A silent latency bug, invisible in tests that don't assert on timer arming.

## Root cause

Granularity rotation cost is asymmetric with respect to value, but the code treated it symmetrically. Upgrading (background→focused) is high-value and should be immediate; downgrading (focused→background) is low-value and only needs to happen once focus genuinely settles. A symmetric "rotate on any mode disagreement" reconciler (`ensureState`, also driven periodically by `WorktreeMonitor.updateWorktrees`) re-tears-down on every transient pass. Separately, the cooldown branch relied on some _other_ future event to re-trigger the flush — but an isolated event has no follow-up, so the pending flag sat until a poll. The drain has to be self-scheduled at the cooldown's own expiry, not deferred to ambient activity.

## Lesson

- For focus/state-tiered watchers where one direction is cheap and the other expensive to (re)arm, use **asymmetric hysteresis**: upgrade immediately, delay the downgrade behind a settle timer (`WATCHER_FOCUS_DOWNGRADE_DELAY_MS = 3_000`, `.unref()`'d). Route the flip through a dedicated `handleFocusChange(isCurrent)` that returns whether it rotated _synchronously_, so the caller only re-derives downstream cadence (poll timer) when something actually changed.
- A periodic reconciler that rotates on "mode != desiredMode" will defeat the hysteresis the instant focus drops. Guard it: `ensureState` must skip the rotation while `downgradeTimer !== null`. Re-focus must `clearTimeout` the pending downgrade.
- **Any cooldown/backpressure branch that sets a pending flag and returns MUST arm a bounded drain timer**, or an isolated event waits for the next ambient trigger (here, a 60-300s poll). Use calculated expiry: `remainingCooldownMs + epsilon` (here `+10`). Reuse the single shared debounce slot guarded by `if (timer === null)` to preserve the "at most one pending flush timer" invariant and avoid double-arming under bursts. Ensure `stop()`/`dispose()` clears it.
- The recursive watcher is `@parcel/watcher` (native inotify/FSEvents/ReadDirectoryChangesW), NOT `fs.watch({recursive})`. The Linux inotify-watch-per-directory cost is real either way, but cite the actual dependency when reasoning about it.

## Applies when

- Touching `WatcherController.ts` / `WorktreeMonitor.ts` / `gitFileWatcher.ts` in `electron/workspace-host/` — focus tiering, watcher mode rotation, poll cadence, debounce floors.
- Adding any cooldown, self-trigger guard, or backpressure branch that sets a `*Pending` flag and early-returns — verify a drain timer is armed and cleared on teardown.
- Symptom: a file change / git status update surfaces only on the next poll cycle (multi-second to multi-minute delay) instead of promptly, or only "sometimes" depending on subsequent activity.
- Designing focus/visibility-driven rotation of an expensive resource (recursive inotify subscription, FSEvents stream) where rapid toggling causes churn — reach for asymmetric hysteresis with a settle timer plus a reconciler guard.
- Tuning debounce floors against the Doherty Threshold to collapse `tsc --watch` / `eslint --fix` / `prettier --write` write-bursts (here 150ms→250ms, `WATCHER_WORKTREE_MIN_DEBOUNCE_MS`).
