## Context

`ActivityMonitor` classifies agent terminals idle/busy from PTY output. When a TUI enables DEC mode `?1004` (Claude Code and Codex both do), xterm forwards `CSI I` / `CSI O` (`\x1b[I` / `\x1b[O`) focus-in/out reports to the PTY on every click between panes. Lesson #3325 already established that those bytes flow through the same `onData` channel as keystrokes and must be filtered out of _user-input_ detection (`InputTracker.ignoredInputSequences`), while still being forwarded to the PTY so vim's `FocusGained` keeps working.

## Problem

Even with #3325's input-side filtering in place, clicking between idle agent terminals still flipped them to `working`. Filtering the focus report out of _input_ detection did not stop the false promotion.

## Root cause

The focus report has a second-order effect that #3325 didn't address: the agent TUI _responds_ to the focus change by repainting its prompt, and that repaint is real PTY **output**. Two traps compound:

1. **The repaint outlives the echo window.** The normal defense against treating output as work right after input is `InputTracker.isRecentUserInput`, gated by `INPUT_ECHO_WINDOW_MS = 1000` (`electron/services/pty/InputTracker.ts:33`). The agent's post-focus redraw frequently arrives _after_ that 1s window closes, so the echo gate has already expired and the bytes read as fresh output. A dedicated, longer suppression window (2000ms) keyed off the focus event is required — the existing echo gate cannot cover it.

2. **There are two parallel idle→busy promotion paths.** Gating `ActivityMonitor` is necessary but insufficient: `TerminalProcess.noteAgentOutputActivity` (`electron/services/pty/TerminalProcess.ts:~1465`) runs the `agentOutputTemperature` heuristic and calls `agentStateService.handleActivityState(..., "busy")` **directly**, bypassing `ActivityMonitor` entirely. A suppression window only on `ActivityMonitor` leaves this temperature path open.

The fix mirrors the resize-suppression pattern from #2365: a bounded `notifyFocus(2000)` sets `focusSuppressUntil` and gates all five `ActivityMonitor` promotion paths (simple output, structural signal, `becomeBusyFromPattern`, OSC 9;4 progress, `noteAgentOutputActivity`), resets the debouncers and `simpleOutputTemperature`, and — crucially — `TerminalProcess.noteAgentOutputActivity` separately checks `activityMonitor.isFocusSuppressed()` to close the temperature bypass. `handleFocusInput` also resets `agentOutputTemperature` + `agentOutputContentSnapshot` so the redraw becomes a fresh baseline rather than a hot delta.

## Lesson

- When an _input_ event triggers a _delayed output_ response from the running program (focus repaint, resize reflow, mode-change redraw), filtering the input is not enough — you must open an output-side suppression window keyed off that input event. The input-echo gate (`isRecentUserInput`, 1s) will NOT cover responses that arrive after it expires; size the dedicated window to the realistic redraw latency (here 2s).
- `ActivityMonitor` is not the only path that promotes idle→busy. `TerminalProcess.noteAgentOutputActivity` calls `agentStateService.handleActivityState` directly via the `agentOutputTemperature` heuristic. Any new suppression/gating mechanism must cover BOTH the ActivityMonitor paths and this temperature bypass (check `activityMonitor.isFocusSuppressed()` at the call site), or false promotions leak through.
- Suppression windows must be bounded and only block idle→busy, never busy→idle (same rule as #2365 resize). Rapid successive events extend, not reset to a fixed end.
- `isFocusReport(data)` (`electron/services/pty/terminalInput.ts`) tests exact equality `data === "\x1b[I" || data === "\x1b[O"`, not substring, to avoid false positives on payload sequences. Reuse it; don't re-regex.

## Applies when

- Adding any new idle→busy promotion path in `ActivityMonitor` or `TerminalProcess` — audit whether it needs to honor `isResizeSuppressed`/`isFocusSuppressed`, and whether it bypasses `ActivityMonitor` like `noteAgentOutputActivity` does.
- Debugging phantom "working" indicators that correlate with clicking/focusing between terminal panes (DEC `?1004` focus reporting).
- Handling any input-event-triggered TUI redraw (focus, resize, mode toggle) whose output response may arrive after the 1s `INPUT_ECHO_WINDOW_MS` echo window.
- Touching `agentOutputTemperature`, `handleFocusInput`, `notifyFocus`/`notifyResize`, or the `ignoredInputSequences` config for an agent.
- Extending #3325 (focus/mouse input filtering) — remember filtering input alone does not stop the agent's repaint from being read as work.
