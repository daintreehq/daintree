## Context

A 13-PR parallel batch (#11010-#11022, issues #10997-#11009, all merged 2026-07-08 within a two-hour window) split the codebase's biggest god-object files: `PluginService.ts` (5512 lines), `TerminalInstanceService.ts` (4210), `WorkspaceService.ts`/`WorktreeMonitor.ts` (~3700/2249), `ProjectViewManager.ts` (2580), `HelpSessionController.ts` (2573), `TerminalProcess.ts` (2219), and others. Every PR used the same "this-alias getter-proxy host object" pattern first established in #6729 (May): each extracted collaborator gets a `Host` interface whose getters/setters proxy back to the original class's private fields, so code moves to a new file without changing what it can read or write, and the original keeps a one-line delegate for callers.

## Problem

Each PR's correctness proof was "public exports and behavior are unchanged, and all existing tests pass without modification" — a mechanical, tests-untouched discipline standing in for a real behavior-preservation guarantee. PR #11019 (`TerminalProcess.ts`, 2219 -> 1737 lines) landed six of seven planned extractions this way. The seventh — folding the in-thread analysis glue (`ActivityMonitor`, `Osc94Parser`, agent-output temperature) behind an `InThreadAnalysisHost` — was fully implemented, then reverted before merge. On the surface that looks like scope discipline; the actual reason is more specific and recurs.

## Root cause

Several `TerminalProcess.*.test.ts` files do white-box reflection straight into the private fields the extraction wanted to relocate: `TerminalProcess.agentDetection.test.ts` casts `(terminal as unknown as { activityMonitor: {...} }).activityMonitor` (lines ~300-301) to reach the monitor directly, and `TerminalProcess.outputPipeline.test.ts` / `TerminalProcess.submit.test.ts` do the same plus spy on `getAgentOutputContentSnapshot`. Moving that state behind a host object would change what those casts resolve to, so making the extraction work meant editing 4 test files — which breaks the batch's own "tests unchanged" proof and pushes the change outside a mechanical refactor's scope.

This wasn't a fresh discovery. `InThreadAnalysisBackend.ts` was created five days earlier by the unrelated multithreading PR #10920 (2026-07-02, commit `6a70e7bb1`), and its docstring already states the state "stays on TerminalProcess/TerminalInfo where the existing code — and the existing test suite — expects it." #10920 had already declined to fully encapsulate this state for the same reason; #11019 independently re-derived the identical conclusion. Two independent PRs hitting the same wall means it's settled structural debt, not an oversight either author could have tried harder to avoid.

## Lesson

- **The getter-proxy host-interface pattern is the default playbook for splitting Daintree god objects, and it scales**: 13 PRs used it the same day across `PluginService.ts`, `TerminalProcess.ts`, `WorktreeMonitor.ts`, `ProjectViewManager.ts`, `HelpSessionController.ts`, and `TerminalInstanceService.ts` with every existing test passing unmodified. Define a narrow `XHost` interface with getters for the fields the collaborator reads, construct the extracted class with `new X(host)`, keep a one-line delegate in the original file for external callers.
- **"Tests pass unchanged" is the batch's sole proof of zero-behavior-change, and that same discipline is what vetoes some extractions.** Before planning a split, grep the target's test files for `as unknown as {` casts and private-field spies (e.g. `.activityMonitor`) against exactly the fields you intend to move. If a test reflects into that field, the extraction requires editing the test — which is a real scope change, not a mechanical one.
- **This specific wall (`ActivityMonitor` / `Osc94Parser` / agent-output temperature) is already load-bearing debt, confirmed twice.** `InThreadAnalysisBackend.ts`'s own docstring documents the constraint from #10920, and #11019 re-hit it independently. Don't re-attempt the `InThreadAnalysisHost` extraction on `TerminalProcess.ts` without first touching `TerminalProcess.agentDetection.test.ts`, `TerminalProcess.outputPipeline.test.ts`, and `TerminalProcess.submit.test.ts` to stop reflecting into private fields.
- **"Mechanical, zero-behavior-change" has two narrow, legitimate exceptions, both demonstrated by #11022** (`TerminalInstanceService.ts` split): deleting provably dead code as an explicit separate first pass (`isHibernated()` permanently returned false, `subscribeHibernation`/`hibernationListeners` never fired), and preserving — never reordering — call sequences that carry fixes for past incidents (#5878 want-membership ordering, #7762 backgrounded-terminal geometry corruption). Cleanup-during-move on incident-bearing code is the failure mode these exceptions guard against.
- **Pick the host-interface shape to match how the state varies**: a plain getter object (`AgentOutputForwarderHost`, `PtyDataPipelineHost`) suits a collaborator reading live, per-call state; a factory taking a deps-bag (`PluginHostFactory.ts`'s `PluginHostFactoryDeps`, `SessionSnapshotter.ts`'s `createTerminalSessionSnapshotter(host)`) suits one whose wiring only varies at construction time (worker-mode vs. in-thread). #11013 states the rule directly: state read on nearly every call fits a getter host better than a fixed callback set.

## Applies when

- Touching `electron/services/pty/TerminalProcess.ts` (still 1737 lines, the largest file under `electron/services/pty/`) or resuming the deferred `InThreadAnalysisHost` extraction #11019 reverted.
- Planning to extract collaborators from any large service class via the getter-proxy host pattern (`PluginService.ts`, `WorkspaceService.ts`, `ProjectViewManager.ts`, `TerminalInstanceService.ts`, or their successors) — search the class's test files for white-box casts into the fields you intend to move before writing the extraction, not after.
- Reviewing a PR claiming "mechanical, zero-behavior-change" refactor — if it also edits test assertions in the same change, the scope has quietly widened past what "tests unchanged" was supposed to prove.
- Extracting logic from code carrying comments referencing past incidents (grep for issue numbers like #5878, #7762, #10671, #3177) — preserve exact call ordering, don't clean it up as part of the move.
- Choosing between a getter-object host interface and a factory/deps-bag for a new extraction — match it to whether the collaborator needs live per-call state or only construction-time wiring.
