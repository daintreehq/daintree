## Context

#10508 hardens the project-switch terminal-garble fix from #10488 (`reconcileGeometryFresh`; see `.lessons/10488.md` for the resize-lock root cause) with a timed reveal-backstop cadence (`REVEAL_BACKSTOP_DELAYS_MS = [1000, 3000]` in `WorktreeStoreContext.tsx` and `HelpPanel.tsx`) and a hard post-suppression guarantee (`suppressResizesDuringProjectSwitch` calling `resetRenderer(id)` in `TerminalInstanceService.ts`), since the single reveal frame-sweep lands before compositor present and inside the resize lock, so it can't stick alone.

## Problem

The PR needed to prove the fix actually recovers a garbled agent terminal, not just that the new timers fire. Garbled line-wrap is a visual/paint-timing symptom — hard to assert against short of a pixel diff, and its worst variant (WebGL paint staleness, vs. plain grid-vs-container mismatch) only reproduces with a real GPU context.

## Root cause

The PR's own commit history shows the trap and the catch. Commit 1 (`97805a8`) shipped the fix plus a would-be regression guard: `e2e/full/worktree/core-project-switch-redraw.spec.ts`, a fixture `e2e/fixtures/fake-claude-agent.cjs` (a full-screen alt-buffer + DEC-2026 synchronized-output fake CLI, the hardest-to-recover terminal mode), and a new E2E bridge global `__daintreeProposeTerminalDimensions` on `TerminalInstanceService` exposing both the live xterm grid (`cols`/`rows`) and what the container can actually hold (`fitAddon.proposeDimensions()`). Ninety minutes later, commit 3 (`0cb74c5`) deleted the spec and fixture outright, commit message stating the reason plainly: "no real assertions." The spec exercised the switch-back path but never pinned down an invariant that would actually fail on a regression — decorative, not a guard, exactly the "no tautological assertions" trap CLAUDE.md's CI Testing Strategy calls out for unit tests, playing out identically at the E2E layer for a harder-to-assert bug class.

The PR body itself concedes even a correct version of that spec would have been partial: "the E2E runs the DOM renderer (WebGL is off in E2E), so it guards geometry recovery but does not reproduce the WebGL paint-staleness variant." Once the spec and fixture were deleted for having no real assertions, that WebGL-only variant ended up with **zero** automated coverage, and the manual-repro tool for it (the fixture) was gone too.

What actually shipped as regression protection is not visual at all: behavioral unit tests on the scheduling state machine (`WorktreeStoreContext.scheduleWake.test.tsx`, `HelpPanel.revealBackstop.test.tsx`) using fake timers to assert the cadence fires at 1s/3s, cancels on hide/unmount/rapid re-reveal, and never stacks — deterministic invariants about _when a repaint is attempted_, not whether the pixels came out right. The other survivor is `TerminalReconciliationWatchdog.diagnoseGeometryDivergence` (still live, `TerminalReconciliationWatchdog.ts:262`): a dev-only diagnostic gated on `import.meta.env?.DEV` that compares `fitAddon.proposeDimensions()` against the live `terminal.cols/rows` on every onscreen terminal and just `logWarn`s a divergence — it deliberately does not repair (repair is a separate `reconcile()` branch, #10632) and swallows measurement errors so it can never break the sweep it watches. It turns a silent, intermittent grid mismatch into a loud local-dev signal instead of a CI assertion. Notably `__daintreeProposeTerminalDimensions` itself was NOT deleted with the spec that motivated it — still exported today, later reused by an unrelated spec, `e2e/full/terminal/core-terminal-divider-resize.spec.ts`, reading `renderer.proposedCols/proposedRows` alongside real PTY dims for a different geometry invariant.

## Lesson

- **Before trusting an E2E spec as a regression guard for a rendering/paint bug, check it actually asserts an invariant that would fail on regression** — not just that the flow runs without throwing. #10508's own author added and then deleted such a spec in the same PR for exactly this reason ("no real assertions").
- **For a bug whose failure mode is visual/paint-timing, test the mechanism, not the pixels:** the state machine deciding _when_ a repaint is attempted (timer cadence, visibility guards, cancel-on-rereveal) is deterministically assertable with fake timers; the rendered frame usually isn't. That's what actually shipped (`scheduleWake.test.tsx`, `HelpPanel.revealBackstop.test.tsx`).
- **When a divergence is real but hard to assert automatically, add a passive dev-only diagnostic at the suspected point instead of forcing a flaky E2E assertion.** `diagnoseGeometryDivergence` logs (never repairs) an xterm-grid-vs-container mismatch, gated `import.meta.env?.DEV`; loud local signal, no false CI confidence.
- **`e2e/` in this repo runs the DOM renderer with WebGL disabled** (same constraint as `.lessons/9546.md`'s memory-leak case) — an E2E "geometry recovered" assertion structurally cannot reach the WebGL paint-staleness variant here. That variant is manual-only (the deleted `fake-claude-agent.cjs` alt-buffer + DEC-2026 fixture was the intended repro tool) until a GPU-enabled E2E lane exists.
- **A bridge global can outlive the test that motivated it.** `__daintreeProposeTerminalDimensions` shipped alongside the deleted spec, survived the deletion, and was later reused by `core-terminal-divider-resize.spec.ts` — worth keeping even after the test that justified writing it turned out worthless.

## Applies when

- Writing or reviewing an E2E spec meant to guard a terminal-rendering, paint, or geometry regression — verify it asserts a real invariant before counting it as coverage.
- Diagnosing or fixing a bug that only reproduces with WebGL/real GPU compositor timing — plan for manual verification since `e2e/` runs DOM-renderer-only and cannot exercise it.
- Touching `TerminalReconciliationWatchdog.diagnoseGeometryDivergence` or `__daintreeProposeTerminalDimensions`, or deciding how to add coverage for an intermittent visual-race bug — prefer dev-only diagnostic logging plus deterministic timer/state-machine unit tests over a flaky E2E click-and-hope spec.
- Reviewing a PR whose commit history adds and then removes an E2E spec or fixture — that's a signal the author caught a tautological test; read why before assuming it's just churn.
