## Context

Assistant (help panel) visibility in `AppLayout.tsx` is a conjunction of two gates in two stores: `showAssistant = !layout.gestureAssistantHidden && layout.helpPanelOpen`. The toolbar button toggles the persistent preference (`helpPanelStore.isOpen`); the double-click focus-mode gesture layers a temporary mask on top (`focusStore.gestureAssistantHidden`). The gesture runs a Snapshot & Revert state machine: `GestureSnapshot` records `hidSidebar`/`hidAssistant` at entry so exit reverts exactly the deltas the gesture caused — pre-existing suppression stays put (the independent-gestures design from #6659).

## Problem

Issue #9641: with the Assistant open, entering focus mode hid it; the toolbar button then appeared dead (it flipped `isOpen`, but the gesture mask still hid the panel). Worse, exiting focus mode restored the sidebar to its pre-entry state but left the Assistant at whatever `isOpen` had drifted to mid-mode. The sidebar round-tripped perfectly, which made the snapshot machinery look complete — the asymmetry was easy to miss because only the dual-gated surface leaked.

## Root cause

The snapshot only captured flags the gesture itself owns. Reverting `gestureAssistantHidden` restores "unmasked", not "pre-entry": since visibility is `!mask && isOpen` and `isOpen` lives in a different store that its own UI (the toolbar) can mutate during the mode, clearing the mask exposes whatever `isOpen` drifted to. The sidebar had no second gate, so its restore was complete and hid the pattern. The fix adds `assistantWasOpen: boolean` to `GestureSnapshot`: `AppLayout.handleToggleFocusMode` reads `useHelpPanelStore.getState().isOpen` synchronously at gesture entry and passes it as `toggleFocusMode`'s third param; the same live read also derives `assistantVisible` (`!layout.gestureAssistantHidden && assistantWasOpen`), so `hidAssistant` and `assistantWasOpen` cannot diverge the way the render closure's `showAssistant` could if `isOpen` changed since the last render. On exit, `useHelpPanelStore.getState().setOpen(assistantWasOpen)` runs only when `snapshot.hidAssistant` — an assistant the gesture never hid (sidebar-only gesture, then toolbar-open mid-mode) must survive the exit rather than be snapped shut.

Two deliberate design boundaries shaped the fix. The two gates stay separate (locked decision on #9641): the mask is transient gesture state, `isOpen` is the persistent preference — collapsing them would conflate "hidden by focus mode" with "user closed it". And `focusStore` never imports `helpPanelStore`: the foreign value crosses as a plain parameter and rides the snapshot as data, with a `assistantWasOpen ?? assistantVisible` fallback so a caller that omits the arg still restores a logically-open assistant instead of silently closing it. Cross-store coordination lives in `AppLayout`, keeping store isolation intact (the TDZ/store-init discipline in `docs/architecture/store-init-order.md`).

## Lesson

- **Before snapshotting state for a mode toggle, enumerate every mutable term of the render predicate the mode masks — not just the flags the mode itself owns.** `showAssistant = !gestureAssistantHidden && helpPanelOpen` has two terms; snapshotting only your own mask means any drift in the other term leaks through on exit. Grep the actual visibility expression and capture each term another surface can mutate mid-mode.
- **Gate each restore on "did this gesture actually hide it".** `if (snapshot.hidAssistant) setOpen(assistantWasOpen)` — an unconditional restore would clobber legitimate mid-mode actions (a toolbar-opened assistant during a sidebar-only gesture gets snapped shut). The store's own revert already follows this rule ("the snapshot only owns the deltas it caused"); any new restore path must too.
- **Capture snapshot values imperatively via `getState()` inside the event handler, and derive dependent flags from that same read.** The render closure's `showAssistant` can be stale relative to `isOpen`; deriving `assistantVisible` and `assistantWasOpen` from one live read makes divergence structurally impossible.
- **Foreign-store state crosses as parameters, never as store imports.** `focusStore` takes `assistantWasOpen` as an optional arg with a safe fallback; `AppLayout` is the coordinator that reads/writes `helpPanelStore`. Adding a `helpPanelStore` import inside `focusStore` would be the wrong fix even though it "works".
- **Gesture-active means `gestureSnapshot !== null`, never `isFocusMode`.** `isFocusMode` is a compat mirror of `gestureSidebarHidden || gestureAssistantHidden` that also flips for toolbar-only sidebar hides — keying entry/exit on it treats a toolbar hide as a gesture exit and poisons the state machine.
- Note: `src/components/Layout/__tests__/AppLayout.focusAssistant.test.ts` asserts the wiring as source text (including that `showAssistant` stays a compound predicate) — rewiring this path will fail those tests by design; update them with intent, don't loosen them.

## Applies when

- Touching `src/store/focusStore.ts` (`toggleFocusMode`, `GestureSnapshot`, `clearAssistantGesture`, `setSidebarGestureHidden`) or `AppLayout.handleToggleFocusMode`.
- Adding a new surface for the focus-mode gesture to hide (docks, diagnostics, a future panel) — its persistent open-flag must join `GestureSnapshot` and its restore must be gated on a new `hid*` flag, or the same drift bug reappears.
- Diagnosing "toggle button does nothing" or "exiting a mode leaves a panel in the wrong open state" anywhere visibility is a conjunction of a temporary mask and a persistent preference held in different stores.
- Tempted to collapse `helpPanelOpen` and `gestureAssistantHidden` into one source of truth — locked decision on #9641 keeps them independent, and a source-assert test enforces it.
- Reviewing any snapshot/restore mechanism (presentation modes, zen modes, fullscreen toggles) — verify the snapshot covers every mutable term of the hidden thing's render predicate and that restores are ownership-gated.
