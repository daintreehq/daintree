## Context

Claude Code's working state is detected by matching spinner Unicode characters + status verb + "esc to interrupt" in PTY output. The character class and completion format in Daintree's config (the per-agent detection block lives in `shared/config/agents/claude.ts`, aggregated by `shared/config/agentRegistry.ts`) drifted from the actual CLI output.

## Problem

Three classes of drift in Claude detection patterns:

1. **Wrong spinner character class.** The class omitted characters Claude actually animates through (notably `·` U+00B7, the middle dot used as the **first animation frame** — the most-displayed character) while carrying chars Claude doesn't use. Missing the first frame meant the primary pattern failed on the first frame of every spinner cycle, falling back to the slower "esc to interrupt" pattern.

2. **Hardcoded verb list breaks custom spinnerVerbs.** An enumerated verb alternation (`(thinking|working|reading|…)`) couldn't match the custom `spinnerVerbs` users configure in `settings.json`.

3. **Outdated completion format.** The completion pattern matched only the old cost/token summary and missed Claude's current `"Worked for Ns."`-style completion line.

## Root cause

Agent CLI output formats change with CLI releases, and the patterns were hand-edited from a snapshot of an older `cli.mjs`. Hand-maintaining literal char lists and verb enumerations guarantees drift on every CLI bump.

## Lesson

Detection patterns are no longer hand-edited in `claude.ts`. They live in `// @generated:claude:<field>:start … :end` sentinel blocks (`primaryPatterns`, `fallbackPatterns`, `bootCompletePatterns`, `promptPatterns`, `completionPatterns`) and are produced by the corpus-driven pipeline in `scripts/pattern-discovery/`. To re-validate after a CLI change, capture the new CLI output into the `scripts/pattern-discovery/corpus/` fixtures and re-run the generator — `update-registry.ts` replays the corpus (`corpus-replay.ts` + `analyzer.ts`) and rewrites the arrays between the sentinels. Do not hand-edit the patterns inside the generated blocks; edit the corpus instead. Two durable matching principles survive in the generated output and should be preserved when tuning the corpus: match the spinner verb **structurally** (`[^()\n]{2,80}` for the primary line, `\w+` for the fallback) rather than by an enumerated verb list, so custom `spinnerVerbs` still match; and keep **legacy completion patterns alongside the current format** (today the current `[…]\s+\w+\s+for\s+\d` "Worked for N" line coexists with legacy `Total cost:`, `Total duration`, and `$X · X tokens`) since users may run older CLI versions. Note the current spinner class (`[·*✢✳✶✻✽●✼✾⟡◇◆○]`) uses an ASCII `*` (U+002A), not `∗` (U+2217) — U+2217 is not in the class.

## Applies when

Investigating why Claude Code agents show incorrect working/idle state, or refreshing detection after a Claude Code version bump — feed new CLI output into `scripts/pattern-discovery/corpus/` and regenerate, rather than editing `shared/config/agents/claude.ts` directly.
