## Context

Daintree detects an unclean previous exit via on-disk markers: `CrashLoopGuard.markCleanExit()` writes `cleanExit: true` to `crash-loop-state.json`, `PanelSuspectLedger.markCleanLaunch()` ages panel-crash suspicion, and `CrashRecoveryService.cleanupOnExit()` clears `running.lock`. The `before-quit` chain in `electron/lifecycle/shutdown.ts` writes all three after graceful cleanup (agent session journaling, DB WAL checkpoint, audit flushes, subprocess teardown). `AutoUpdaterService` owns the auto-update relaunch: `quitAndInstallIfReady()` (native menu) and the `UPDATE_QUIT_AND_INSTALL` IPC handler (renderer toast) both end in `autoUpdater.quitAndInstall()`.

## Problem

After every auto-update relaunch, the app booted into the "restore previous session" crash-recovery prompt (#9638) — even though nothing crashed and restored agent terminals were still running. Two misleading signals: it appeared correlated with project switching (pure timing noise — `crash-loop-state.json` is a single app-wide file in userData, not per-project), and the update path _looked_ like it did exit cleanup because it already called `cleanupOnExit()`.

## Root cause

Two layers, and the second is the one that transfers.

Layer 1 (what #9645 fixed): on macOS, `quitAndInstall()` hands off to native Squirrel.Mac, which closes every window _before_ Electron emits `before-quit` (it emits `before-quit-for-update` instead, which nothing handled) — so the shutdown chain never ran on an update relaunch. On Windows/Linux, `BaseUpdater.quitAndInstall()` ends in `app.quit()`, which _does_ fire `before-quit` — the bypass is macOS-only, invisible to Linux CI. The update path hand-called only `cleanupOnExit()`, skipping `markCleanExit()` and `markCleanLaunch()`, so `cleanExit` stayed `false` and the next boot read a crash. #9645 copied both missing markers into both call sites — one try/catch each (#7158's isolation rule), synchronous `writeFileSync` before the then-`setImmediate`-deferred install so they committed before exit.

Layer 2 (why #9645 was itself superseded): the marker copy stopped the false prompt but institutionalized the divergence. The release audit (#11104) found the update install still skipped _all_ the heavy shutdown work — session journaling, graceful agent shutdown, WAL checkpoint and backup, audit flushing — while the copied markers now _claimed_ a clean exit for state that was never persisted. PR #11129 (commit `959708dfd`) deleted the hand-copied markers from `AutoUpdaterService` and routed the install through the coordinator: `startQuitAndInstall()` calls `requestGracefulShutdownForUpdate(() => this.executeQuitAndInstall())` (`electron/lifecycle/shutdownCoordinator.ts`), making the install the terminal action of the one real chain. The markers now live _only_ in `shutdown.ts`'s success branch, written after the chain settles clean — and deliberately NOT on the timeout/dirty branch, so a timed-out cleanup still installs but the next boot truthfully gets the dirty marker and its recovery flow.

## Lesson

- **Every path that ends the process is a shutdown path.** New exit routes (updater installs, watchdog `app.exit()`, relaunch flows, signal handlers) must reach `runShutdownChain` via the coordinator (`startShutdown` / `requestGracefulShutdownForUpdate`), not re-implement fragments of it. `registerShutdownHandler` publishes the chain via `setShutdownRunner` precisely so it is reachable without `before-quit`.
- **Never hand-copy clean-exit markers into an alternate exit path.** The markers assert the _outcome_ of the shutdown work; copying them without the work converts a visible bug (false crash prompt) into an invisible one (data loss reported as clean). #9645's copies were correct per-marker and still wrong as a design — they were removed by #11129. If you find yourself replicating marker writes, the actual fix is routing the path through the chain.
- **`quitAndInstall()` bypass is platform-asymmetric:** macOS goes through Squirrel.Mac (windows closed before `before-quit`; `before-quit-for-update` instead), Windows/Linux end in `app.quit()` which fires `before-quit` normally. An update-lifecycle bug can be macOS-only and pass every Linux CI run.
- **Failure signature:** a false crash-recovery / safe-mode prompt on the first boot after a specific flow means some exit path skipped `markCleanExit()` — grep exit paths, don't debug the crash detector. `crash-loop-state.json` is app-wide, so per-project or per-timing correlations in the report are noise.
- **A marker written near process exit must be synchronous** (`writeFileSync`), ordered before any deferred exit call, one try/catch per marker so a single failure can't skip the rest (#7158).

## Applies when

- Adding or modifying any way the Electron main process exits or relaunches: `AutoUpdaterService` install paths, watchdog timers, `app.relaunch()`, signal handling, or new IPC that ends the app.
- Diagnosing "restore previous session" / crash-recovery / safe-mode prompts that appear after an exit the user perceives as normal — especially post-update.
- Touching `electron/lifecycle/shutdown.ts`'s marker block, `shutdownCoordinator.ts`, or `startQuitAndInstall()` — do not re-add marker writes to `AutoUpdaterService`; the chain owns them.
- Tempted to copy a subset of shutdown behavior (markers, flushes, journaling) into a path that can't run the full chain — route it through the coordinator instead.
- Reviewing platform-conditional quit behavior or anything relying on `before-quit` firing — verify it against macOS Squirrel.Mac, not just the `app.quit()` platforms.
