## Context

`Cmd+K` used to be a leader key: press it, a chord overlay flashed up, press a second key to run a command, and it was gone in well under a second. #10874 replaced that with a persistent, searchable command HUD (`useCommandHud.ts`) that lists the curated `Cmd+K` power-command layer and filters as you type, ranked by a rolling 7-day usage count (`shared/utils/actionUsage.ts`'s `pruneUses`, stored via `actionMruStore.ts` / `actionMruSlice.ts`) that replaced the previous frecency-score model. Because the HUD stays open and dispatches on every keybinding press and every typed filter keystroke, it drives `ActionService.dispatch` and the usage-tracking store at a call frequency the old one-shot leader key never reached.

## Problem

Nothing looked broken in isolation, but two infra paths that were "fine" at leader-key call rates broke down under HUD-level call rates: a keybinding whose action takes only optional arguments (`terminal.kill`, which resolves the focused terminal when no id is passed) failed to dispatch at all when fired with no args, and the palette's "recently used" ranking could quietly lose a just-run command whenever two usage writes landed close enough together in time. Both were caught and fixed within #10874 itself, but the persistence bug had existed in the pre-#10874 frecency-based store too — it just never surfaced because usage writes were infrequent enough that the race window was rarely hit.

## Root cause

Two independent, verified mechanisms.

1. `ActionService.dispatch` validates args via `definition.argsSchema.safeParse(args)`. Keybinding and HUD dispatch sites call `dispatch(actionId)` with `args === undefined`. For a Zod object schema where every field is `.optional()` (e.g. `terminal.kill`'s `z.object({ terminalId: z.string().optional(), confirmed: z.boolean().optional() })`), `safeParse(undefined)` still fails — Zod's object parser requires an object type, and `undefined` never satisfies that even with no required properties; only `safeParse({})` succeeds. So every all-optional action failed no-arg dispatch with `VALIDATION_ERROR` until #10874 added a targeted rescue: when `args === undefined` and the schema rejects `undefined` but accepts `{}`, `dispatch()` validates `{}` instead.
2. `src/store/actionMruStore.ts`'s `useActionMruStore.subscribe` callback persists state to `appClient.setState` over IPC and guards against overlapping writes. The pre-#10874 code used a single variable, `pendingPersist`, as both "is a write in flight" and "the payload of that write": `if (pendingPersist !== null) return` dropped any new state seen while a write was outstanding, and on completion ran `lastPersisted = pendingPersist!; pendingPersist = null`. If a second store change landed while the first `setState` call was still awaiting, the subscriber saw `pendingPersist !== null` and returned without recording the new list anywhere — and `lastPersisted` was then set to that first, now-stale snapshot rather than current state, so the second update was gone for good unless some unrelated later change re-triggered the subscriber. #10874 fixed this by splitting the concerns into a boolean `inFlight` flag and a separate `queued` variable holding the latest snapshot seen mid-save, flushed in `.finally()` once the in-flight write settles.

## Lesson

- **Never reuse one variable as both a concurrency lock and the payload it guards.** Keep `inFlight: boolean` and `queued: T | null` separate in any store-to-IPC persist subscriber, and always flush the LATEST queued state on completion, not the snapshot the in-flight call originally captured — see `src/store/actionMruStore.ts`'s pre-/post-#10874 diff for the exact before/after.
- **A version-guard is the alternative correct pattern already in this codebase.** `worktreeStore.ts`'s `persistActiveWorktree`/`persistMruList` guard overlapping writes with a monotonic `requestVersion` counter instead of a coalescing queue; check that pattern before hand-rolling a third persist-guard style.
- **An all-optional Zod `argsSchema` does not need a `.optional()` wrapper to support no-arg dispatch.** `ActionService.dispatch()` already rescues `args === undefined` when `safeParse(undefined)` fails but `safeParse({})` succeeds — don't defensively wrap the whole schema "just in case," since that changes the `requiresArgs` computation (`computeRequiresArgs`, `toManifestEntry`) driving the MCP tool manifest and the palette's arg-prompt UI.
- **Converting a rare, modal, one-shot UI into a persistent/live-filtering surface multiplies call frequency on everything it touches, not just the UI.** The old overlay and the new HUD dispatch the same actions and write the same store, but the HUD does it far more often; re-audit dispatch validation and any debounce/coalesce logic for races that low frequency was hiding.
- **A modifier chord sharing a surface with live-search text must carry the modifier on both keys.** #10874 rebound every `Cmd+K` chord's second key to hold `Cmd` too (`Cmd+K Z` → `Cmd+K Cmd+F`, `Cmd+K W` → `Cmd+K Cmd+O`, see `src/services/defaultKeybindings.ts`) so a bare letter typed into the HUD's filter field doesn't also fire a command.

## Applies when

- Writing or reviewing any Zustand `subscribe()` callback that persists to IPC/disk asynchronously (`appClient.setState`, `electron/store.ts`) with a guard against overlapping writes — check whether the guard variable also carries the payload.
- Adding a new action definition (`src/services/actions/definitions/*.ts`) with an `argsSchema` where some or all fields are optional, especially one meant to be bound to a bare keypress or dispatched via `ActionService.dispatch(id)` with no args.
- Diagnosing "recently used commands don't show up in the palette/HUD ranking" or any MRU/usage list that appears to lose entries under rapid use.
- Converting a rarely-invoked modal UI (leader key, one-shot dialog) into a persistent or live-filtering surface — audit every downstream path it now calls for frequency assumptions, not just the UI layer.
- Adding a new leader-key-style chord (`Cmd+K <key>`) to a HUD/palette that also accepts typed search text.
