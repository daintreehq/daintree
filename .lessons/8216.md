## Context

Docked terminal panels render inside a Radix `Popover.Content`. The popover's `onInteractOutside`/`onPointerDownOutside` handler (`handleDockInteractOutside` in `src/components/Layout/dockPopoverGuard.ts`) must keep the popover open when the user clicks a nested Radix overlay opened from inside the panel — a header `DropdownMenu`, a terminal `ContextMenu`, a `Tooltip`, a `Select`. Those nested overlays portal to `document.body`, so the dock popover's DOM-containment guard (Guard 1) can't see them.

## Problem

Guard 2 matched the click target with `target.closest("[data-radix-popper-content-wrapper]")`. That selector is (a) global — it matches _any_ Radix Popper overlay anywhere in the document, not just descendants of this dock popover, and (b) a Radix-internal implementation detail liable to rename in a minor upgrade. Result: an unrelated overlay elsewhere on screen could suppress the dock popover's dismissal, and any upstream Radix rename would silently break the guard.

## Root cause

There is no DOM signal that says "this portaled overlay descends from _this_ dock popover's React subtree," because Radix portals sever the DOM relationship — the nested content lives under `document.body`, not under the popover. The only durable ancestry signal is the React tree, which you must thread yourself. The fix stamps a project-owned `data-dock-popover-child` attribute onto every Radix content/subcontent primitive (`dropdown-menu.tsx`, `context-menu.tsx`, `tooltip.tsx`, `select.tsx`) gated on `useIsDockPopoverChild()` from `DockPopoverChildContext`, and matches on `[data-dock-popover-child]` instead.

The non-obvious second half: `DockPanelOffscreenContainer.tsx` renders the panel body through `createPortal`. A React Context Provider's value does NOT cross a `createPortal` boundary unless the Provider wraps the portaled subtree — `createPortal` preserves context only from the _render location_, but here the panel body is rendered offscreen and re-homed, so overlays opened inside it would read the default `false` and never get stamped. The container therefore wraps the portaled content in `<DockPopoverChildProvider>` (and `DockedTabGroup`/`DockedTerminalItem` do too). The attribute is also written _after_ `{...props}` in each primitive so a caller can't accidentally clobber it.

## Lesson

- Never write dismissal/containment guards against Radix-internal selectors (`[data-radix-popper-content-wrapper]`, `[data-radix-*]` private attrs). They are global and version-unstable. Stamp your own `data-*` attribute and match on that — the codebase already self-stamps `data-dock-panel-id`, `data-dock-portal-target`, `data-offscreen-slot`.
- A "this overlay belongs to subtree X" signal cannot come from the DOM once Radix portals the overlay to `document.body`. Carry it through a React Context (`DockPopoverChildContext`) and stamp the attribute on the content primitive gated on the context value.
- When you portal a subtree with `createPortal` (offscreen slot re-homing, dock panels), any context the portaled content depends on must be re-provided _inside_ the portal at the new render location — re-wrap with the Provider in `DockPanelOffscreenContainer`, `DockedTabGroup`, `DockedTerminalItem`. Forget this and nested overlays silently fall back to the default context value.
- Stamp the marker attribute after `{...props}` so callers can't override it.

## Applies when

- Touching `handleDockInteractOutside` / `dockPopoverGuard.ts`, or any Radix Popover dismissal/`onInteractOutside`/`onPointerDownOutside` guard logic.
- Adding a new nested Radix overlay (DropdownMenu, ContextMenu, Tooltip, Select, SubContent) that can be opened from inside a docked panel and must not dismiss the host popover.
- Adding a new docked-panel surface or offscreen-portal container, or any new `createPortal` re-homing where context-dependent children render at the destination.
- Seeing a dock/floating popover dismiss unexpectedly when a menu item is clicked, or stay open when an unrelated overlay is clicked.
- Reviewing code that matches against `[data-radix-*]` internal attributes.
