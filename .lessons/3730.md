## Context

`applySnapshot` (in `createWorktreeStore`) is called on every git status poll cycle (every few seconds per worktree). It correctly preserved individual worktree object references via `snapshotsEqual` — if fetched data matched the existing entry, the existing object was kept. However, the function always called `set({ worktrees: new Map(...) })`, so the Map container itself was always a new reference.

## Problem

The new Map reference propagated to all 12+ consumers of the worktree store. `useWorktrees()` ran its `useMemo` sort and produced a new sorted array, causing `SidebarContent`, `ContentGrid`, `AgentButton`, `QuickSwitcher`, `useAgentLauncher`, and 6+ other components to re-render on every poll — even when nothing had changed.

## Root Cause

The function built a fresh Map unconditionally then merged metadata from the existing Map. Even with individual entries preserved by reference, there was no early-out check comparing the incoming snapshots against the existing entries before calling `set`. A new container object triggers Zustand's default equality check (referential equality), causing all subscribers to re-render.

## Lesson

Before building a new Map, add a value-equality early-out and skip the `worktrees` update entirely when nothing changed:

```typescript
// Once hydrated, suppress redundant Map identity churn when every
// incoming snapshot is value-equal to its existing counterpart.
if (
  prev.isInitialized &&
  merged.length === prev.worktrees.size &&
  merged.every((s) => {
    const existing = prev.worktrees.get(s.id);
    return existing !== undefined && snapshotsEqual(existing, s);
  })
) {
  // omit `worktrees` from set() — the existing Map reference is preserved
  set({ version, isLoading: false, isInitialized: true, error: null });
  return;
}
```

This is O(n) where n is the number of worktrees (typically 5-10), so the overhead is negligible compared to the render cascade it prevents. (Cold starts always rebuild so `isInitialized` flips correctly even when the first snapshot is empty.)

The check must account for the `manualAssociations` override path (`mergeIssueState`) — entries modified after the main merge must still trigger a new Map.

Worktree store subscribers use referential equality by default (no `useShallow`), so the Map reference is the sole signal for re-renders. Preserving the existing Map when contents are unchanged eliminates all no-op re-renders.

## Applies when

- Any Zustand store that stores a `Map` and updates it periodically from polling
- Any `merge*` function that builds a new collection from existing + fetched data
- Performance profiling shows excessive re-renders during polling cycles
