## Context

Panels (`PanelComponent` implementations under `src/panels/<kind>/`) are rendered by more than one host: the grid layout's block-level cell wrappers, dock slots, and — the newer host — `PanelDialogHost.tsx`'s `AppDialog.BodyScroll`, a flex column with a `max-h-[85vh]` cap rather than a fixed height; `ContentPanel`'s root and the lazy-loaded pane wrappers in `panels/registry.tsx` all sized themselves with `h-full`, which had worked fine as long as the only host was the grid.

## Problem

Opening a long file through the file viewer dialog (#11254) clipped it: no scrollbar in either Source or Rendered mode, and content past the first screen was unreachable; the same file, opened as a docked grid panel instead, scrolled fine — same `FilePane`, same `overflow-auto` scroller on its body, different host. That made the pane's own scroll setup look correct (because it was), which pointed initial suspicion at `CodeViewer`'s CodeMirror integration rather than at the ancestor chain feeding it a size.

## Root cause

`h-full` (`height: 100%`) only resolves to something concrete when its parent has a _definite_ height: the grid's cell wrappers are block-level with a definite height, so `h-full` fills the cell and the panel's internal `overflow-auto` scroller correctly overflows against that fixed box, but `AppDialog.BodyScroll` (`PanelDialogHost.tsx:124`, `flex min-h-0 flex-1 flex-col overflow-hidden`) is a flex column capped at `85vh`, not a fixed height — an _indefinite_ height from the child's perspective. Under that parent, `h-full` collapses to `auto`, so `ContentPanel`'s root sized itself to the file's own intrinsic content height instead of to the dialog body; with the panel root that tall, its internal scroller never overflowed (nothing to scroll, hence no scrollbar), and the oversized box then got clipped by the dialog's own `overflow-hidden`. Two different CSS mechanisms, two different panel bugs, same symptom class: this is a _percentage-height-under-indefinite-flex-parent_ collapse, distinct from the `overflow:clip`-doesn't-establish-a-scroll-container trap in `.lessons/11025.md` (that one blew the grid row up to content size; this one clips inside an already-bounded dialog).

The fix is `flex-1` (size from the flex line, ignoring the `h-full` percentage) plus `min-h-0` (release the flexbox automatic minimum so the box can shrink below its content), added _alongside_ `h-full` so the same class string still works under the grid's block wrappers. The non-obvious part, called out explicitly as "the substantive catch from review" in the PR body: `panels/registry.tsx`'s `ContentFadeIn` wrapper is a real DOM div, and for every lazy panel kind (file, review, browser, diff) it — not the pane's own root — is the direct child the dialog body sees; fixing only `ContentPanel`'s root would have left that invisible fade wrapper still `h-full`-only, still collapsing to `auto`, and the bug would have persisted with the "real" fix in place and looking complete. `ReviewPane` needed the identical pair for a different reason: it is the one built-in panel kind that renders no `ContentPanel` at all, so it has to carry the dual contract on its own root.

## Lesson

- **A component meant to render under more than one layout host cannot rely on `h-full` alone** — audit every host's parent chain for whether height is definite (block cell, fixed pixel/vh) or indefinite (flex column with a max-height cap, `auto` grid track); if any host is indefinite, add `flex-1 min-h-0` next to `h-full`, not instead of it.
- **Trace the literal DOM parent chain, not the component tree, when a "which host wraps this" question comes up** — `ContentFadeIn` in `panels/registry.tsx` is invisible in the component's own file but is the actual child the dialog body renders; a fix scoped to the pane root alone would have been silently incomplete.
- **When a scroll-owning leaf works in one host and clips in another, suspect the ancestor sizing contract before re-auditing the leaf's own overflow rules** — `FilePane`'s `overflow-auto` scroller was correct in both places; the difference was entirely in what height its ancestors resolved to.
- **`PanelDialogHost`'s outer `overflow-hidden` (added in `edc850cf1` for a padding-inset bug) is deliberately not the thing to touch here** — reverting it risks double scrollbars for panel kinds that already own their internal scroll surface; fix sizing at the panel-root/wrapper level instead.
- **A CSS layout-sizing fix like this generally can't be proven by a unit test** — `jsdom` computes no real layout, so a `toHaveClass("min-h-0")` assertion is a source-literal tautology; the real proof needs an E2E check (`e2e/full/panels/core-file-viewer.spec.ts`) asserting `scrollHeight > clientHeight`, a real computed `overflow-y: auto`/`scroll` (not just programmatic `scrollTop` acceptance, which `overflow: hidden` elements also allow), and that the pane's bottom edge stays within the dialog's rect, not the window's.

## Applies when

- Adding a new host (dialog, dock slot, popover) that can render an existing panel/component whose sizing assumed a single block-level parent.
- Diagnosing "this scrolls fine as a grid panel but clips/doesn't scroll in the dialog/modal" (or the reverse) for any `PanelComponent` — check whether the new host's parent is a flex column with indefinite (`max-h`/`auto`) height rather than a fixed one.
- Touching `src/panels/registry.tsx`'s lazy wrappers, `ContentPanel.tsx`'s root className, or any panel kind (`src/panels/review/ReviewPane.tsx` and siblings) that renders outside `ContentPanel` and so must carry the sizing contract itself.
- Reviewing a "just add `h-full`" sizing fix for a component with more than one render host — confirm every host's parent chain actually has a definite height, or the fix is host-specific and will regress silently in the other host.
- Distinguishing this from `.lessons/11025.md`'s `overflow:clip` trap — that one is about a whole flex/grid row inflating to swallow the app layout; this one is about a percentage-height child collapsing to content size and getting clipped inside an otherwise-correctly-bounded container.
