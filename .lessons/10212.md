## Context

Daintree runs two self-checking CI gates. In the perf harness (`scripts/perf/`, `npm run perf <mode>`), only PERF-004 "Real Cold Start" launches a real packaged Electron binary — the others are in-process simulations that miss main-process boot regressions (#5410). The fix-with-test ratio gate (`scripts/check-test-ratio.mjs` + `test-ratio-lib.mjs`, run by `test-ratio.yml`) is the only _enforcing_ arm of the test-discipline check. Both had reported PASS for their entire lives.

## Problem

Both gates were green while gating nothing. PERF-004 recorded sub-ms samples every nightly and cleared its 8000ms p95 budget — it had never once launched a real binary. The ratio gate ran only because zero release-titled PRs sat in the recent stream; the first `chore(release):`/`v1.0.0` PR would switch it off. A perpetual PASS looks identical to a healthy gate.

## Root cause

Two instances of one pathology (#10212 fixes PERF-004, #10200 the ratio gate): a validity precondition a _normal, expected_ condition can never satisfy, routed to PASS instead of FAIL.

PERF-004 (#10068): `perf-nightly` never built a binary (`release/` is gitignored), so `findPackagedExecutable()` returned null and the scenario returned `durationMs: -1`. That `-1` is a _real harness convention_ — TERM scenarios return negative to mean "I don't self-time, substitute the wall-clock bracket" — and `run.ts` did exactly that: `sample.durationMs >= 0 ? sample.durationMs : wallClockMs`. For the early return, wall-clock is the cost of an `fs.existsSync`, so ~0ms × 30 iterations cleared 8000ms → PASS. The sentinel conflated "doesn't self-time" (legitimate) with "failed to measure" (a failure). Worse, `getPackagedExecutablePath` only looked under `release/daintree-{arch}/linux-unpacked/`, but `electron-builder --dir` writes `release/linux-unpacked/` — so even a built binary would be missed — and `existsSync` accepted a directory at the path.

Test-ratio (#10035): `windowCompleted: eligible.length >= rollingWindowSize`, where `eligible` is the post-skip-filter of a _single_ 100-PR GraphQL fetch (GitHub caps `search(first:)` at 100). `compareToBaseline` short-circuits `return { ok: true }` whenever `windowCompleted === false` — a legitimate tolerance for a repo with <100 eligible PRs. But skipped release/version-bump PRs are subtracted _after_ fetching exactly 100, so one skipped PR → 99 eligible → "incomplete" → gate no-ops. The precondition conflated "not enough eligible PRs exist" with "we fetched 100 raw and dropped some."

## Lesson

- **A gate's "couldn't measure / not enough data" escape hatch must be reachable only by the rare state it was designed for, else fail closed.** Both hatches (PERF-004's `-1`, the ratio gate's `windowCompleted:false → ok:true`) swallowed a _common_ condition. Confirm the common path — missing prerequisite, filtered input, empty result — exits non-zero, not through the tolerance branch.
- **Never let a sentinel value flow into a budget/threshold comparison.** `-1` meant "not measured" but became ~0ms and passed an 8000ms budget. The fix keeps the documented negative→wall-clock sentinel in `run.ts` (TERM scenarios need it) but rejects non-finite `durationMs`, and PERF-004 now _throws_ instead of returning a sentinel. If one value carries two meanings, split them at the source.
- **"Fetch exactly N, then filter" is broken when the filter can drop items.** `search(first:100)` minus any skipped PR can never yield 100 eligible. The fix paginates (`$cursor` + `pageInfo`, capped `MAX_SEARCH_PAGES=10`, 60s over the _whole_ loop) until 100 eligible are collected, then trims to the window. Any "collect N after filtering" must backfill and treat the window incomplete only when the source is genuinely exhausted.
- **A gate that exercises a real artifact needs the workflow to actually produce it — a green nightly with no build step is suspect.** `perf-nightly` never packaged a binary; the harness's own fail-closed throw now surfaces the gap. The workflow builds+packages (`electron-builder --linux --dir`), verifies with `test -f && test -x`, then launches under `xvfb-run`.
- **Cross-platform path resolution wants an injectable `platform` param + `isFile()`, not `process.platform` + `existsSync`.** The injected `platform` makes all three OS layouts unit-testable on one runner; `isRegularFile` stops a directory at the binary path from passing as an executable (as `existsSync` would) and becoming a cryptic Playwright launch error.

## Applies when

- Writing or reviewing any CI gate, budget, or regression check — confirm the missing-prerequisite / incomplete-data / empty-input path fails _closed_ (non-zero exit or thrown), never PASS or `ok:true`.
- Touching `scripts/perf/` (`run.ts` durationMs, `scenarios/startup.ts`, `lib/packagedLaunch.ts`) — a negative `durationMs` has two meanings (self-time sentinel vs. failure); don't collapse them, and never report a sentinel on failure — throw.
- Touching `scripts/check-test-ratio.mjs` / `test-ratio-lib.mjs` — `windowCompleted` is sized by eligible (post-filter) count; changes to fetching or skip-filtering must preserve the paginate-until-N-eligible invariant.
- Seeing a gate green forever that never flagged anything — treat perpetual PASS as possible self-disabling; or resolving a packaged-binary path across OSes (electron-builder `--dir` writes `release/linux-unpacked/`; use `isFile`, not `existsSync`).
