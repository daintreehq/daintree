## Context

`TelemetryService.ts` initializes `@sentry/electron/main` for opt-in error reporting. It runs a `beforeSend` hook (`sanitizeEvent` + a deep-walk scrubber, `normalizeDepth: MAX_DEEP_SANITIZE_DEPTH`) to strip secrets from JS error events before they leave the machine. Secrets like `ANTHROPIC_API_KEY` and `GITHUB_TOKEN` live in `process.env` because they are passed through to spawned agent PTYs.

## Problem

`@sentry/electron` enables `sentryMinidumpIntegration` by default. On a native crash it captures a binary `.dmp` payload containing stack/register memory — which can include environment variables (API keys, tokens) live at crash time — and uploads it to Sentry. The carefully-written `beforeSend` JS scrubber gives false confidence: it never runs against the minidump.

## Root cause

The minidump is a binary native artifact uploaded by the crashpad/crashReporter path, not a JS `Event` object. `beforeSend` only sees JS-side events, so it can neither scrub nor inspect the `.dmp` — it can only drop the whole event. Two adjacent traps make this worse: `enableNative: false` is **not** a valid `@sentry/electron` option (that flag belongs to the Capacitor SDK), and `Electron.crashReporter.start({ uploadToServer: false })` is silently overridden once `sentryMinidumpIntegration` is active. The only effective lever is removing the integration at init time: `integrations: (defaults) => defaults.filter((i) => i.name !== "SentryMinidump")`. The integration's runtime name string is `"SentryMinidump"` (verified against `node_modules/@sentry/electron`), distinct from the JS-friendly factory name `sentryMinidumpIntegration`.

## Lesson

- A JS `beforeSend`/scrubbing hook protects only JS events. It does NOT protect native crash artifacts (minidumps). Never assume a sanitizing hook covers everything a telemetry SDK sends.
- For `@sentry/electron`, drop minidump upload by filtering `defaults` in the `integrations` callback by name string (`"SentryMinidump"`), NOT by `enableNative` (wrong SDK) and NOT by `crashReporter.start({ uploadToServer: false })` (silently overridden by the active integration).
- When secrets are in `process.env` (as they are here for agent PTY pass-through), treat any native-crash upload path as a secret-exfiltration vector by default. The long-term fix is moving secrets out of `process.env` into Electron `safeStorage`; until then, native minidump upload must stay off.
- Trade-off accepted: native crashes still surface as process-exit signals via `globalErrorHandlers.ts` / `main-crash.log`, but without native stack traces or register state. Document the trade-off at the init call site.

## Applies when

- Adding, upgrading, or reconfiguring `@sentry/electron` or any crash-reporting SDK in `electron/services/TelemetryService.ts`.
- Reviewing or auditing what telemetry/crash data leaves the user's machine, especially when API keys or tokens live in `process.env` (agent spawn env, PTY env pass-through).
- Writing or trusting a `beforeSend` / event-scrubbing hook — confirm it actually covers every payload type the SDK uploads (JS events vs native minidumps vs attachments).
- Touching Electron `crashReporter` config and expecting `uploadToServer: false` to fully disable uploads.
- Any task that reasons about "we scrub secrets before sending" as a completeness claim for telemetry.
