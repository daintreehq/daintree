## Context

Vite defaults to the `modules` preset for `build.target`, which targets `['es2019', 'edge88', 'firefox78', 'chrome87', 'safari14']`. Daintree's renderer only ever runs in Electron's bundled Chromium (Chromium 148 in Electron 42). Vite was emitting compatibility shims and polyfills for features the bundled Chromium supports natively.

## Problem

The default Vite target produced larger bundles with unnecessary polyfills (e.g., for features like optional chaining, nullish coalescing, top-level await) that the actual runtime supports natively. Also, the `modulePreload` polyfill was emitted despite native module preload support.

## Root cause

Vite doesn't know which Chromium version will run the output — it defaults to a conservative multi-browser target. The `modules` preset is appropriate for public web apps but overly conservative for Electron, where the exact Chromium version is known.

## Lesson

Always set `build.target` to the actual Chromium version bundled with the Electron version in use:

```ts
build: {
  target: 'chrome148', // match Electron 42's Chromium 148
  modulePreload: { polyfill: false }, // native support available
}
```

Check the Electron release notes for the exact Chromium version. Update `build.target` when upgrading Electron — CLAUDE.md mandates bumping it "in lockstep on each Electron major upgrade."

**Note:** As of Electron 42 the target is `chrome148` (`vite.config.ts` `build.target`). Verify and update on each Electron major upgrade.

## Applies when

Any Electron app using Vite. The default `modules` target is always wrong for Electron — set it explicitly.
