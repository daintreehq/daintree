## Context

An agent panel persists its launch identity (`launchAgentId`/`agentId`, `agentLaunchFlags`, `agentModelId`, `command`) so it can resume the agent across reconnects and cold starts. `restartTerminal` (`src/store/slices/panelRegistry/restart.ts`) rebuilds the spawn payload from those persisted fields. A user can `/quit` an agent inside its panel and keep using the resulting plain shell — the panel is now "demoted" but still carries its agent launch fields.

## Problem

Hitting restart on a demoted panel relaunched the agent instead of restarting the shell (#5764). The restart classifier was `const isAgent = !!effectiveAgentId` — purely launch identity, ignoring whether the agent process was still alive.

## Root cause

Two non-obvious traps stacked:

1. `AgentStateMachine` never transitions `idle → exited` when the PTY dies, so `agentState === "exited"` alone is not a reliable death signal — the FSM often leaves a quit-to-shell panel in `idle` while only `exitCode` gets set. Detecting demotion needs BOTH signals: `agentState !== "exited" && exitCode === undefined` is the live-agent guard (`restart.ts:297-301`).
2. The spawn IPC handler (`electron/ipc/handlers/terminal/lifecycle.ts`) re-derives agent-ness from `type` and `agentId`, not just `kind`. Forcing only `kind: "terminal"` in the payload is not enough — the handler still sees an agent `type`/`agentId` and relaunches. Every agent-adjacent field (`type`, `agentId`, `launchAgentId`, `command`, `agentLaunchFlags`, `agentModelId`) must be cleared on a demoted restart. There is also an idempotency trap: the demoted restart must re-stamp `agentState: "exited"` and clear `command` on the panel, otherwise a _second_ restart sees a cleared `exitCode` and no exit signal, misclassifies as live, and relaunches the agent (`restart.ts:497-509`).

## Lesson

A restart/relaunch decision is a runtime-state decision, not a replay of persisted launch intent. Persisted launch identity must be _preserved_ (so the panel remembers what it was — `onAgentExited` must NOT clear `agentId`, see #5807) but must be _gated_ at restart time by conclusive death signals. When two processes (renderer store + IPC spawn handler) both classify agent-ness from overlapping fields, clearing one field is insufficient — clear the entire field set the downstream re-derivation reads, and re-stamp the demotion marker on the panel so the classification survives repeated restarts.

## Applies when

- Touching `restartTerminal` or any relaunch path that reads `agentId`/`launchAgentId`/`command`/`agentLaunchFlags` from a persisted panel.
- Adding a new "agent vs plain shell" branch — check it gates on both `agentState !== "exited"` and `exitCode === undefined`, never on launch identity alone.
- Building a spawn payload whose agent-ness is re-derived downstream in `electron/ipc/handlers/terminal/lifecycle.ts` — clear `type`, `agentId`, `launchAgentId`, `command`, `agentLaunchFlags`, `agentModelId` together, not just `kind`.
- Any user-quit-to-shell ("demotion") flow that must survive repeated restarts.
