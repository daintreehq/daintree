## Context

PR polling for the worktree sidebar runs in the workspace-host `UtilityProcess` (`electron/workspace-host.ts`) so synchronous git/filesystem work can't stall main. PR detection is forge-provider-driven: `PullRequestService` resolves a provider impl from the forge registry, then calls `findPRByBranch`/`getPR`/etc. Forge providers (built-in `daintree.github`, plus future GitLab/Gitea/Bitbucket) are contributed by plugins, and `PluginService` activates plugins **in main**.

## Problem

The worktree sidebar never showed the linked PR on startup. `PullRequestService` was silently skipping detection on every poll (`Skipping PR check — no forge provider resolved`), with no error surfaced — PR sub-rows just stayed empty.

## Root cause

Two independent silent failures stacked:

1. **The workspace-host has no plugin loader.** A `UtilityProcess` does not inherit main's plugin/service registrations — its `forgeProviderRegistry` was always empty, so `getForgeProviderImpl(...)` returned null and the poll bailed. The first instinct (pre-register the built-in `daintree.github` provider in the host) fixes GitHub but leaves every third-party forge plugin broken in exactly the same way, because they only ever activate in main.
2. **`simple-git`'s `getConfig` returns a `ConfigGetResult` envelope, not a bare string.** `readRemoteUrl` cast `await git.getConfig(...)` straight to `string | null`. The cast compiled and the tests mocked `getConfig` as a string, so it was green — but at runtime in the real host it returned `{ key, paths, scopes, value, values }`, the cast produced a non-null object treated as the URL, and `parseRemote` never matched. So even with a provider present the remote couldn't resolve.

## Lesson

- **Any registry/service lookup running inside a `UtilityProcess` is empty unless explicitly populated.** Plugin activation, IPC-handler registration, auth state, and provider impls live in main and do **not** cross the process boundary. A host that calls `getXImpl(id)` against a registry main owns will silently get null.
- **Don't re-register or re-load plugins in the host to fix this.** Double activation duplicates side effects (IPC handlers, broadcasts, timers), forks auth/rate-limit state across processes, and forces a second host-API surface. Instead, keep main as the single source of truth and give the host a **typed RPC bridge**: the host holds zero provider state and round-trips every call (`resolveProvider`, `findPRByBranch`, `getCIStatus`, …) through `forge:rpc` / `forge:rpc-result` over the parent port. See `ForgeBridge` (`electron/workspace-host/forgeBridge.ts`) and `dispatchForgeRpc` (`electron/services/forgeRpcServer.ts`). Plugin authors get a transparent surface — `host.registerForgeProvider(...)` in `activate()` is the whole contract.
- **Fold synchronous provider methods into the async RPC.** `parseRemote` was synchronous; the bridge folds it into `resolveProvider` so the host never calls a sync provider method across an async transport.
- **The RPC server must handle non-cloneable results.** `child.postMessage` throws on non-structured-cloneable payloads; `forgeRpcServer` catches and replies with an error envelope so the bridge fails fast instead of hanging until its 30s timeout.
- **Cold-start race:** the host starts polling before main's `PluginService.initialize()` finishes, so the first `resolveProvider` legitimately returns null. Re-attempt resolution every poll and cap the next interval at the fast catch-up throttle (5s) while unresolved — but skip that cap when `consecutiveErrors > 0` so a 5s retry can't punch through deliberate circuit-breaker backoff.
- **Never cast a `simple-git` `getConfig` result to a string.** It returns a `ConfigGetResult` envelope; unwrap `.value`. A type cast here lies, and a string mock will hide the bug in tests — pin the envelope shape with a regression test.

## Applies when

- Adding any logic to a `UtilityProcess` (workspace-host, pty-host) that depends on a registry, plugin contribution, or service that main owns.
- Tempted to "just register the built-in" inside a host to make a feature work — that pattern silently excludes all plugin-contributed variants.
- Designing a cross-process call surface that should stay invisible to plugin authors while keeping auth/state in one process.
- Reading git config in main or a host via `simple-git`: expect `ConfigGetResult`, unwrap `.value`, and don't let a string-typed mock mask the envelope.
