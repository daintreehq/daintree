## Context

To keep worktree dashboard ahead/behind counts accurate, `RepoFetchCoordinator` (`electron/workspace-host/RepoFetchCoordinator.ts`) runs automatic background `git fetch origin --prune` on a cadence (focused 30–45s, background 5–10min). The fetch git instance is built by `createBackgroundFetchGit` (`electron/utils/hardenedGit.ts`), layered on top of `createAuthenticatedGit` so the system credential helper still resolves HTTPS remotes. Linked worktrees in the same repo share one `.git/objects` and `packed-refs`.

## Problem

Three independent traps in an automatic, headless, multi-worktree fetch path: (1) N worktrees fetching concurrently race on `.git/packed-refs.lock` and fail sporadically; (2) a credential helper that ignores `GIT_TERMINAL_PROMPT=0` blocks the fetch forever on an invisible TTY prompt; (3) a naive "repo-not-found" failure cache permanently hides a recovered token, because GitHub returns **404 (not 401/403)** for an expired PAT against a private repo.

## Root cause

- **Serialization key is the common-dir, not the git-dir.** Per-worktree `--git-dir` points at `.git/worktrees/<name>`, but the contended resource (`packed-refs.lock`, `objects`) lives at `--git-common-dir`, which all linked worktrees share. Keying the per-repo promise chain on `git-dir` would let siblings still collide. `getGitCommonDir` (`electron/utils/gitUtils.ts`) resolves the shared path; the coordinator chains fetches per common-dir.
- **`GIT_ASKPASS` policy differs between authenticated and background profiles.** `createAuthenticatedGit` deliberately does NOT set `GIT_ASKPASS` (line 271 comment) — user-initiated clone/push need real askpass resolution. A background fetch must never prompt, so `createBackgroundFetchGit` sets `GIT_ASKPASS=true` on POSIX so any helper that bypasses `GIT_TERMINAL_PROMPT=0` fails fast. It is omitted on Windows because `true` is not on PATH there and `GIT_TERMINAL_PROMPT=0` already blocks the Windows credential dialog.
- **404 masking requires a prior-success bifurcation.** In `classifyForCache`, a `repository-not-found` reason maps to a short retriable `repo-not-found-first` entry only when `lastSuccessfulFetch === null`. After any prior success, the same 404 is reclassified as `kind: "auth"` (indefinite suspension, cleared only by `clearAuthFailures()` on token rotation) — because a repo that fetched before can't have vanished; the 404 is GitHub masking a permission/PAT failure.

## Lesson

For any automatic, headless background git operation across worktrees:

- Serialize on `getGitCommonDir(path)`, never the per-worktree git-dir, whenever the operation touches `objects`/`packed-refs`. A single promise chain per common-dir beats lowering global concurrency.
- A background/passive git instance must set `GIT_ASKPASS=true` (POSIX) in addition to `GIT_TERMINAL_PROMPT=0` — the prompt flag alone is not enough; some credential helpers ignore it and hang. Do NOT copy this into the authenticated profile (clone/push need a working askpass). Skip the override on Windows.
- `git fetch` has no native timeout; arm an `AbortController` (60s) per call and pass `core.packedRefsTimeout`/`http.lowSpeedLimit`+`http.lowSpeedTime` config, since the lowSpeed config alone won't cancel a fully half-open connection.
- A failure cache for remote git must be multi-tier: auth = indefinite until explicit re-auth (repeated bad-token retries trip GitHub secondary rate limits); network/transient = short TTL + jitter; repo-not-found = bifurcate on `lastSuccessfulFetch` so a recovered token isn't permanently masked by GitHub's 404-instead-of-403 behavior.
- Guard async completions against teardown with a generation counter that is also bumped at coordinator scope (`baseGeneration`), so a stale pre-`destroy()` fetch can't pass the guard against a freshly-created `state.generation` after the same repo path is reopened on a new project.

## Applies when

- Adding or modifying any background/automatic git operation in `electron/workspace-host/` (fetch, prune, remote-ref refresh) that runs without user interaction.
- Choosing a serialization/lock key for git operations across linked worktrees — reach for `getGitCommonDir`, not `getGitDir`.
- Any new factory in `electron/utils/hardenedGit.ts`, or deciding whether a git instance should carry `GIT_ASKPASS`/`GIT_TERMINAL_PROMPT` — distinguish passive background ops from user-initiated authenticated ops.
- A git operation against a GitHub remote hangs with no error, or a private-repo PAT expiry surfaces as "repository not found" rather than an auth error.
- Designing a retry/failure cache for remote operations where over-retrying triggers provider rate limits, or where a transient-looking error code (404) actually means auth.
- Cleaning up in-flight async work on project switch / host teardown where the same resource key can be re-created immediately afterward.
