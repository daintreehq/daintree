## Context

`App.tsx` defers framer-motion's heavy `domMax` feature set off the first-paint path with `LazyMotion strict features={loadMotionFeatures}`, where `loadMotionFeatures = () => import("./lib/motionFeatures")` and `motionFeatures.ts` is just `export { domMax as default } from "framer-motion"`. The intent: ship only the small motion runtime (`LazyMotion`, `MotionConfig`, `m`) eagerly and pull `domMax` (~43KB gzip) in via a dynamic import after interactive. `vite.config.ts` also declares a `vendor-motion` manual chunk group (`build.codeSplitting` Rolldown groups) matching `framer-motion|motion-dom|motion-utils`.

## Problem

The LazyMotion deferral did nothing. `domMax` was being shipped in the eager first-paint chunk, and worse, the first-render chunk budget script (`scripts/check-first-render-chunk-budget.mjs`) reported no change when the deferral was added or removed — the gated metric never moved, so the regression was invisible to CI.

## Root cause

Two compounding traps:

1. **A manual chunk group overrides dynamic-import code splitting.** A Rolldown `codeSplitting.groups` entry that matches `framer-motion` by `test` regex sweeps _every_ matched module — including the `domMax` subtree only reachable through the `import("./lib/motionFeatures")` boundary — into one named `vendor-motion` chunk. Because the renderer entry statically imports the small motion runtime, that whole merged chunk is statically reachable and lands in the eager closure. The `dynamicImports[]` edge still exists in the manifest, but the code it would have pointed to was already pulled eager by the group. The dynamic import becomes a no-op for bundle size. A plain `$initial` tag is _also_ insufficient: it evicts `domMax` from this group, but the orphaned modules then fall into the eager catch-all `vendor` chunk.
2. **The budget script walked dynamic edges, masking the regression.** `collectClosure()` BFS'd both `imports[]` and `dynamicImports[]`, so its measured total counted deferred code as if it were eager. Deferring code never changed the gated number.

The fix: add `entriesAware: true` + `entriesAwareMergeThreshold: 0` to the `vendor-motion` group so Rolldown splits the group by _importing entry-set_ — the eager runtime stays eager, `domMax` lands in its own deferred subgroup chunk (`vendor-motion~motionFeatures`) off the first-paint path. `entriesAwareMergeThreshold: 0` disables small-subgroup merging so the split actually holds. Separately, `collectClosure()` gained a `followDynamic` option; the budget now gates on `eagerTotals` (static `imports[]` only) and keeps the both-edges `totals` as a report-only signal.

## Lesson

- A manual chunk group (`codeSplitting.groups` `test` regex) **overrides your dynamic-import splitting** — anything it matches that is also statically reachable from an entry gets pulled eager, silently defeating `React.lazy` / `LazyMotion` / `import()` deferral. If you intend a subtree to stay deferred, make the group `entriesAware: true` (+ `entriesAwareMergeThreshold: 0` to stop subgroup re-merge), or don't put that subtree in a coarse vendor group at all.
- A first-paint / bundle budget that walks `dynamicImports[]` measures total reachable bytes, **not** download-before-interactive cost. Gate the regression on a **static-only (`imports[]`) eager closure**; keep the both-edges walk as report-only. Otherwise deferring code looks like a no-op and a regression that pulls deferred code eager looks invisible.
- Verify deferral against the build manifest, not the source: confirm a separate deferred chunk (e.g. `vendor-motion~motionFeatures`) exists and is absent from the eager closure.

## Applies when

- Editing `build.codeSplitting` groups in `vite.config.ts` (vendor-react, vendor-xterm, vendor-motion, etc.) — especially adding/widening a `test` regex.
- Adding or relying on `React.lazy`, `LazyMotion`, or `import()` deferral and a vendor chunk group could match the same modules.
- Touching `scripts/check-first-render-chunk-budget.mjs` or `first-render-chunk-baseline.json`, or any first-paint/import budget that BFS-walks a Vite/Rolldown manifest.
- Investigating why a lazy-load PR didn't reduce first-paint size, or why a chunk-budget metric won't move when you defer code.
- Working with framer-motion `domMax` / `loadMotionFeatures` (`src/lib/motionFeatures.ts`, `src/App.tsx`).
