## Context

`PresetColorPicker` (`src/components/Settings/PresetColorPicker.tsx`) is a Radix `Popover` in agent preset settings for choosing a per-preset accent color. An earlier revision rendered a hidden `<input type="color">` behind a "Custom…" button to reach a full picker.

## Problem

The popover dismissed itself on the first click of the custom picker. Clicking "Custom…" fired the hidden input's `click()`, which opened macOS NSColorPanel — a separate OS-level floating window — and the popover closed instantly, before the user could pick anything (#6118).

## Root cause

`<input type="color">` does not render an in-DOM widget; on macOS it opens NSColorPanel, a heavyweight OS window in a different surface than the renderer. The renderer loses focus, and Radix's `DismissableLayer` (under `PopoverContent`) treats that focus departure as an outside interaction and fires its dismissal path. The prior fix was a fragile workaround: a `customColorOpenRef` guard plus an `onFocusOutside` handler that called `e.preventDefault()` only while `!document.hasFocus()`, with a `window` focus listener to clear the guard. This races OS focus ordering and has a "stuck guard" failure mode. The durable fix replaced the native input with an inline `react-colorful` `HexColorPicker`/`HexColorInput` — no OS window opens, no focus ever leaves the renderer, so DismissableLayer never sees an outside event. A secondary trap surfaced: the validator was 6-digit-only (`/^#[0-9a-f]{6}$/i`) while the preset sanitizer in `src/config/agents.ts` stores 3-digit hex as-is, so a stored `#abc` was rejected and silently overwritten on commit; the fix accepts 3- or 6-digit and `normalizeHex` expands on commit.

## Lesson

- Any OS-native picker invoked from inside a Radix overlay (`Popover`, `DropdownMenu`, `Dialog` — anything wrapping `DismissableLayer`) will collide with focus-outside dismissal: `<input type="color">` (NSColorPanel), native file dialogs, `window.showOpenFilePicker`, OS print/share sheets. The focus shift to the OS window reads as an outside click.
- Don't paper over it with `onFocusOutside`/`onInteractOutside` + `document.hasFocus()` guards — that races the OS focus sequence and leaves stuck-guard failure modes. Keep all interactive UI inside the renderer DOM (here: `react-colorful`). If a native dialog is truly required, trigger it from a surface that is not inside a DismissableLayer.
- When swapping a committing control, check what the persistence/sanitizer layer actually stores. `src/config/agents.ts` keeps 3-digit hex un-normalized, so a stricter validator silently drops valid stored values on the next commit — validate the full set of forms the store can hold, and normalize on write rather than rejecting on read.

## Applies when

- Adding or debugging any color/file/native picker inside a Radix `Popover`, `DropdownMenu`, or `Dialog`, and the overlay dismisses on the first click.
- Seeing `onFocusOutside`/`onInteractOutside`/`document.hasFocus()` guard hacks around OS-window focus loss — treat them as a smell pointing to an in-DOM replacement.
- Touching `PresetColorPicker.tsx` or preset/agent color persistence in `src/config/agents.ts`, especially hex validation/normalization (3- vs 6-digit round-trip).
- Choosing between an OS-native input and an in-renderer widget for any control rendered inside an Electron renderer overlay.
