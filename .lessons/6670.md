## Context

Agent lifecycle state (`idle`/`working`/`waiting`/`directing`/`completed`/`exited`, defined in `shared/types/agent.ts`) is computed in two places: the main process (`electron/services/AgentStateMachine.ts`) and the renderer-side Web Worker (`src/workers/WorkerAgentStateService.ts` → `calculateStateChange`). Both run a `nextAgentState(current, event)` transition function over an `AgentEvent` union (`start`, `busy`, `prompt`, `completion`, `input`, `exit`, `error`, `kill`, `respawn`, `watchdog-timeout`, `output`).

## Problem

The two `nextAgentState` implementations were independent hand-maintained copies. They had drifted: the renderer worker silently treated `completion`, `kill`, `respawn`, and `watchdog-timeout` as no-ops, and its `exit` guard was wrong so idle agents never transitioned to `exited`. No error was thrown — the worker just produced wrong agent states for those events.

## Root cause

Duplicated state machines drift invisibly because each context only ever feeds the subset of events it actually generates, so the missing branches are never exercised. A no-op branch returns `current` (no state change → `calculateStateChange` returns `null`), which is indistinguishable at runtime from "this event correctly caused no transition." There is no crash, no type error, no log — the bug is a missing transition, which is the absence of behavior. The fix extracted the `AgentEvent` union, `VALID_TRANSITIONS` table, `nextAgentState`, and `isValidTransition` into one browser-safe module `shared/utils/agentFsm.ts` (no Node/DOM imports, so the worker can import it); the main-process `AgentStateMachine.ts` is now a thin re-export wrapper.

Two asymmetries in the canonical table look like bugs but are intentional and are documented inline — preserve them:

- `VALID_TRANSITIONS.directing` is `[]`. `directing` is a renderer-only UI state, never produced by the main-process FSM, so it has no outgoing natural-lifecycle transitions in the shared table.
- `kill` is a hard-reset override that returns `idle` from _any_ state and deliberately bypasses `VALID_TRANSITIONS`; kill-driven transitions are NOT enumerated in the table. The FSM invariant test in `shared/utils/__tests__/agentFsm.test.ts` excludes `kill` and `directing` for exactly this reason.

## Lesson

- Any logic that runs in BOTH the main process and a renderer/Web Worker (or any utility-process host) must live in a single `shared/` module that both import — never a hand-copied reimplementation. The worker boundary makes drift undetectable because no shared test exercises both copies and a missing transition is the absence of behavior, not an error.
- For worker-importable shared logic, keep the module browser-safe: no Node (`fs`, `path`, `node:*`) or DOM imports. `shared/utils/agentFsm.ts` is the canonical example — pure data table + pure functions over `shared/types`.
- When a transition table has intentional gaps (`directing: []`, `kill` bypassing the table), document them at the table AND carve them out of any "every result must be in VALID_TRANSITIONS" invariant test — otherwise the next maintainer "fixes" the asymmetry and breaks the renderer-only / hard-reset semantics.
- A no-op `return current` branch and a correct "no transition" outcome are indistinguishable at runtime. Cover every `AgentEvent` variant against every state in tests so a silently-dropped event surfaces as a failing assertion, not a wrong production state.

## Applies when

- Editing `nextAgentState`, `VALID_TRANSITIONS`, or the `AgentEvent` union in `shared/utils/agentFsm.ts`, or touching `electron/services/AgentStateMachine.ts` / `src/workers/WorkerAgentStateService.ts`.
- Adding a new `AgentEvent` variant or a new `AgentState` — you must update the single shared table and add full-coverage transition tests, not patch one consumer.
- Any time the same algorithm/state machine needs to run in both the main process and a worker/utility-process host (pty-host, workspace-host) — reach for a shared browser-safe module instead of reimplementing.
- Debugging agent state that is correct in one context (main process / terminal title) but wrong in another (renderer worker pulse/dashboard), or events like `completion`/`kill`/`respawn`/`watchdog-timeout` appearing to have no effect.
- Reviewing a PR that introduces or "tidies" the `directing` empty row or the `kill` hard-reset — confirm the intentional asymmetry is preserved and excluded from the FSM invariant test.
