## Context

Daintree plugin views render inside the host renderer and must share the host's single React instance — bundling a second copy makes every plugin JSX element belong to a different React, so hooks throw `Invalid hook call`. The mechanism is a two-sided contract: plugin bundles externalize React, and the host `index.html` injects a `<script type="importmap">` that resolves those bare specifiers to the host's `vendor-react` chunk. Chromium (Electron 41) supports import maps natively, no polyfill.

## Problem

Externalizing React and injecting an importmap is deceptively easy to get subtly wrong in three independent ways, each of which fails silently or only at first render: (1) a second React copy sneaks into the plugin bundle, (2) the inline importmap script gets dropped by CSP, (3) the importmap tag is rejected by the HTML parser.

## Root cause

Three distinct platform constraints stack:

- **Subpath externalization.** Rolldown's `external: ["react"]` matches only the literal string `"react"`. The new JSX transform (`jsx: "react-jsx"`) desugars every element to `jsx()`/`jsxs()` imported from `react/jsx-runtime` (and `react/jsx-dev-runtime` in dev mode), which is NOT covered by the bare-package external and gets bundled — a second React instance. You must externalize via regex (`/^react($|\/)/`, `/^react-dom($|\/)/`) or enumerate every subpath.
- **Two-layer CSP hash alignment.** The host CSP forbids `'unsafe-inline'` for `script-src`, so the inline importmap is gated by a SHA-256 hash. Chromium _intersects_ the `<meta http-equiv>` policy and the HTTP `Content-Security-Policy` header — if the two hashes diverge, the importmap is silently dropped and plugins get unresolvable bare `react` specifiers. The hash is computed over the byte-exact compact JSON of the importmap payload; the build (`hostImportMapPlugin` in `vite.config.ts`) writes it into the meta tag via `cspTransformPlugin` AND emits `dist/importmap-meta.json`, which the main process (`loadHostImportMapHashes` in `electron/setup/protocols.ts`) reads at startup to mirror into the header. The two Vite plugins coordinate through shared mutable state and rely on default-order `transformIndexHtml` execution order — `order: "pre"` would run before bundling, leaving `ctx.bundle` undefined and hiding the hashed `vendor-react` filename.
- **Forbidden integrity attribute.** The HTML spec forbids `integrity` on `<script type="importmap">`. SRI for the map's _targets_ lives as a top-level `"integrity"` block inside the JSON payload (Chromium 127+), only relevant for cross-origin chunks — the host vendor chunk is same-origin, so none is emitted.

Trailing-slash mappings (`"react/"`) can't be used as importmap targets here because `vendor-react` is a single concatenated chunk with no subpath structure; every specifier maps to the same hashed filename (`HOST_IMPORTMAP_SPECIFIERS` in `vite.config.ts`).

## Lesson

- Externalizing React for plugin bundles is a **two-sided contract** — the `@daintreehq/plugin-vite` externals preset and the host importmap must list the same set of specifiers. They drift independently; if you add a host-shared module (e.g. `scheduler`), update BOTH the plugin-vite regex and `HOST_IMPORTMAP_SPECIFIERS` in lockstep.
- Use regex externals (`/^react($|\/)/`), never `external: ["react"]` — the bare form silently bundles `react/jsx-runtime` and produces a second React instance.
- An inline importmap under a hash-gated CSP requires the hash to be **byte-identical across the `<meta>` tag and the HTTP header**, computed over the exact serialized bytes the browser receives (compact JSON, no whitespace). A divergence drops the map silently — no error, just unresolvable `react`.
- The build hash must reach the main process: it's emitted to `dist/importmap-meta.json` and read by `loadHostImportMapHashes`. A missing/malformed sidecar must degrade gracefully (warn + empty hashes, host still loads) rather than crash startup.
- Never put `integrity` on `<script type="importmap">` — it's spec-forbidden. Target SRI goes inside the JSON `"integrity"` block.
- When two Vite plugins share build state across `transformIndexHtml`, rely on default-order (post-bundle) execution and reset state in `buildStart` so watch-mode rebuilds don't reuse a stale hash.

## Applies when

- Adding or modifying the plugin externals preset, `HOST_IMPORTMAP_SPECIFIERS`, or the `vendor-react` codeSplitting group.
- Debugging `Invalid hook call` inside a plugin view, or plugins failing to resolve bare `react`/`react-dom` specifiers at runtime.
- Touching the host `script-src` CSP, the importmap meta/header hash wiring, or `electron/setup/protocols.ts` CSP setup.
- Sharing any additional host module (a shared component library, `scheduler`) with externalized plugin bundles.
