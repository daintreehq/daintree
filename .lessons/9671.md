## Context

The Worktrees sidebar header and status line in `SidebarContent.tsx` carried three separate `role="status"` / `aria-live="polite"` regions wrapping continuously-rendered text: the reconnecting indicator (whose "last updated Xs ago" string is rewritten by a 1Hz tick once escalated), and the filter status line combining the result count with a persistent sort-disabled reason. Issues #9662/#9665 caught them in the same a11y sweep; #9671, #9672, and #9678 fixed the class across one week.

## Problem

Screen readers re-announced indefinitely: once the reconnect indicator escalated, VoiceOver/NVDA spoke a polite update every second for the duration of the outage; typing in the worktree search read "3 of 40 worktrees, Sorting disabled while searching" on every keystroke — the persistent sort reason dragged along each time. Separately, the refresh button's native `disabled` while refreshing silently dumped keyboard focus to `<body>`, stranding keyboard users. Each region looked individually correct — "status text, so role=status" is the intuitive-but-wrong default.

## Root cause

An `aria-live` region is a subscription to every DOM mutation inside it, not a label for "status-ish" content. Three variants of the same violation: (1) a ticking relative-time string inside the region = one announcement per second forever; (2) `role="status"` carries an implicit `aria-atomic`, so a region mixing a dynamic count with persistent state text re-reads the whole line on any count change; (3) a count updated per keystroke floods the AT speech queue with intermediate values. The correct model: live regions are delivery channels for one-shot events; continuously-rendered dynamic text must never sit inside one. The codebase-standard replacement is `useAnnouncerStore.getState().announce(msg, priority)` (`src/store/accessibilityAnnouncerStore.ts`), which prefers the native `document.ariaNotify` (Chrome 141+/Chromium 146) — necessary because VoiceOver ignores `aria-live` outside a focused `aria-modal` subtree (Chromium 354736464) — and falls back to the always-mounted `AccessibilityAnnouncer` regions with per-channel delivered-id coordination so late-mounting modal instances don't replay stale entries.

The focus half: natively disabling a focused control drops keyboard focus to the page body. `aria-disabled` keeps the button focusable — but it does NOT block click/Enter/Space, so the JS re-entry guard (`if (isRefreshing) return` in `handleRefreshAll`) is the load-bearing part, and Tailwind's `aria-disabled:` variants (`aria-disabled:opacity-40` etc.) replace the `disabled:` styling.

## Lesson

- **Never wrap continuously-rendered dynamic text in `role="status"`/`aria-live`.** Keep the visible element `aria-hidden` (sighted users still see the 1Hz tick) and fire `useAnnouncerStore.getState().announce()` imperatively on state **rising edges**, detected with prev-value refs (`prevReconnecting.current` pattern in `SidebarContent.tsx` ~line 529).
- **Debounce typing-driven announcements on `UI_DOHERTY_THRESHOLD` (400ms).** The filter-count effect schedules `announce(\`${filteredCount} of ${totalCount} worktrees\`)`in a`setTimeout` cleared on every re-run, so rapid keystrokes coalesce into one post-pause announcement (#9672, WCAG 4.1.3).
- **Initialise the prev-ref to the CURRENT value, not `false`/`null`, to keep mount silent** — a sidebar hydrating with a persisted filter shows the visual text without speaking stale state (`prevDragDisabledReasonRef` is seeded with `dragDisabledReason`).
- **Partition announcement ownership per transition and check for existing owners.** The sort-disabled effect announces null→reason and reason→reason only; reason→null ("Manual reorder available") was already owned by the `isSortDisabledPrevRef` effect — announcing it again would double-speak. Recovery/success transitions can be deliberately silent when visually self-evident (the spinner vanishing needs no "Connected").
- **When two flags gate a base and an escalated announcement, derive both from the same gated value.** `showReconnectingEscalated` reads raw `isReconnecting`, so a component mounting mid-outage could fire "Still reconnecting…" 400ms before "Reconnecting…" — the effect gates escalation on the Doherty-gated `showReconnecting` to preserve order.
- **Busy buttons: `aria-disabled` + Tailwind `aria-disabled:` variants + a JS re-entry guard — never native `disabled` on a control that can hold focus.** `aria-disabled` alone does not prevent activation; without the guard you've traded focus loss for double-fire.

## Applies when

- Adding `role="status"`, `role="alert"`, `aria-live`, or `aria-atomic` to any element whose text can change more than once per user action — counts, relative times, progress, reconnect/retry state.
- Announcing search/filter result counts or any per-keystroke-derived value to screen readers (palettes, sidebars, pickers).
- Rendering a ticking relative-time string ("Xs ago") anywhere near an existing live region.
- Disabling a button/control during an async operation while it may hold keyboard focus — refresh, submit, arm buttons.
- Touching the `SidebarContent.tsx` header/status/reconnect areas, `accessibilityAnnouncerStore.ts`, or `AccessibilityAnnouncer.tsx`, or reviewing any PR that introduces a new live region.
