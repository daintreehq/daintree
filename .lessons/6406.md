## Context

The Daintree renderer (`persist:daintree` session) enforces `require-trusted-types-for 'script'` in its CSP, delivered at two layers — the `<meta http-equiv>` built from `shared/config/csp.ts` and the `Content-Security-Policy` HTTP response header set via `webRequest.onHeadersReceived` in `electron/setup/protocols.ts`. Once that directive is live, every assignment to a TT-gated DOM sink (`Element.innerHTML`, `outerHTML`, `dangerouslySetInnerHTML.__html`) must be a `TrustedHTML` produced by a policy whose name is listed in the `trusted-types` directive, or Chromium throws `TypeError: This document requires 'TrustedHTML' assignment`.

## Problem

Naively, you register ONE named policy (`daintree-svg`) and route the single `dangerouslySetInnerHTML` site (`FileViewerModal`) plus the SVG-icon chip widgets through it. That works for first-party sinks you control — but the app breaks at runtime in places you do not write innerHTML yourself: React DOM and Radix Popper (`SelectViewport` injects an inline `<style>` for layout vars) assign raw strings to internal sinks, and those throw because they never go through a named policy.

## Root cause

Two distinct mechanisms collide. (1) **First-party sinks** you author can be threaded through a _named_ policy via an explicit `createTrustedHTML()` call. (2) **Third-party sinks** (React/Radix) assign raw strings directly — the browser routes those through the implicitly-invoked policy named exactly `default`. If no `default` policy is registered, the assignment throws. So the directive must list `trusted-types daintree-svg default 'allow-duplicates'` and `trustedTypesPolicy.ts` must register _both_ policies. The `default` policy is intentionally pass-through (first-party React/Radix code is trusted; `script-src`/`style-src` remain the real defense). Other live gotchas verified in the code: the policy module throws at import time when `globalThis.trustedTypes` is absent (no silent fallback — that would mask missed sinks), so every jsdom test must stub `globalThis.trustedTypes` (done globally in `vitest.setup.ts`); `'allow-duplicates'` is required so Vite HMR can re-evaluate the module without `Policy with name "x" already exists`; and the bootstrap-error path (`src/utils/renderBootstrapError.ts`) uses `textContent = ""` not `innerHTML = ""` because it runs before the TT policy module is guaranteed loaded and `textContent` is not a TT-gated sink.

## Lesson

- A renderer with `require-trusted-types-for 'script'` almost always needs a pass-through `default` policy in addition to any named policies — third-party libs (React DOM, Radix) write innerHTML you don't control and the browser only accepts those via the policy literally named `default`. List it in the directive: `trusted-types <named> default 'allow-duplicates'`.
- Enforce the CSP at BOTH layers (meta tag + `onHeadersReceived` header) and keep them aligned — the browser intersects divergent policies into a stricter effective one that breaks the app.
- The ESLint `no-restricted-syntax` ratchet on `dangerouslySetInnerHTML` is a code-hygiene ratchet, NOT the security boundary (the runtime CSP is). It deliberately uses a loose selector — `Property[key.name='__html']:not(:has(CallExpression))` — requiring _some_ call expression rather than `callee.name='createTrustedHTML'`, because a name check breaks under re-exports/aliasing.
- Keep TT policy callbacks pass-through — re-sanitizing inside the policy masks regressions in the upstream validator (`sanitizeSvg`). The policy is a brand, not a second scrubber.
- Stub `globalThis.trustedTypes` globally for jsdom tests; the module throws on import otherwise.

## Applies when

- Adding a new `dangerouslySetInnerHTML` site, or any `Element.innerHTML`/`outerHTML` assignment, in `src/` and hitting `TypeError: This document requires 'TrustedHTML' assignment`.
- Introducing a third-party React component (Radix, a popper/portal lib, a markdown/HTML renderer) and seeing it throw a TrustedHTML error at runtime even though your own code never writes innerHTML — check whether a `default` policy is registered.
- Editing `shared/config/csp.ts` `trusted-types` / `require-trusted-types-for` directives, or `electron/setup/protocols.ts` `onHeadersReceived` CSP header.
- A jsdom unit test fails because importing a chip widget or `FileViewerModal` throws "Trusted Types is not available" — needs a `globalThis.trustedTypes` stub.
- Vite HMR throws `Policy with name "daintree-svg" already exists` — missing `'allow-duplicates'`.
- Writing renderer bootstrap/error-fallback code that touches the DOM before app modules load — use `textContent`, not `innerHTML`.
