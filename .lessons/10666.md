## Context

`ActivityMonitor` drives the idle/working/waiting agent-state FSM (`shared/utils/agentFsm.ts` is the state machine; this file is the heuristic signal layer) from passive terminal output — no cooperation from the agent CLI itself — and agent terminals run in `simpleOutputState` mode (`ActivityMonitor.onData`, gated on `options?.agentId !== undefined`), a lighter path than the general-purpose non-agent monitor; issue #10664 was an agent asked to run a long investigation that printed 30-40s of results while the terminal stayed stuck in `waiting` the whole time.

## Problem

A terminal producing constant output looked, to the state machine, like it had gone quiet, and the symptom actively misdirected debugging: heavy output was clearly "happening" on screen, so the instinct is to look for a broken listener or a stuck timer, not to suspect the diff heuristic itself is blind to this exact shape of output.

## Root cause

Two independent gaps had to both be fixed, and fixing only the first was a documented dead end.

1. **Detection gap**: `simpleOutputState`'s `onData` returns early, before it ever reaches the byte-volume detectors (`OutputVolumeDetector`/`HighOutputDetector`) or the first-output-byte recovery branch that the non-simple path uses. So for agent terminals specifically, raw output volume never drove `waiting`→`working` recovery — only the visible-content diff (`AgentActivityTemperature`, fed by `measureVisibleContentDelta` in `SustainedChangeTracker.ts`) did.
2. **Signal-model gap**: `measureVisibleContentDelta` explicitly reports `{ changed: false, changedChars: 0 }` when one snapshot is a prefix/suffix of the other (`isSuffixOf`, `SustainedChangeTracker.ts:198`). Append-only streaming — the common case for an agent printing results — _is_ a suffix relationship, so the diff reads as "no change" the entire time output pours in.

Adding `simpleOutputVolumeDetector` (a leaky-bucket `OutputVolumeDetector`, 512-byte threshold / 0.1 B/ms drain / 256B/frame cap, wired only for agent terminals) closed gap 1: it promotes `idle`→`busy` on sustained byte volume.

That alone still failed under sustained streaming, because three separate `waiting`-demotion gates all key off the _same_ flat diff — the temperature `stateHint: idle` gate and two polling/debounce idle gates (`transitionSimpleToIdle` call sites), all released once `workingHoldUntil` (`WORKING_HOLD_MS` = 1500ms) elapses — and each read `changedChars: 0` and bounced the freshly-recovered agent straight back to `waiting` mid-stream; the fix needed a second clock, `lastSimpleOutputVolumeAt` / `hasRecentSimpleOutputVolume(now)`, true whenever the volume detector fires and for `IDLE_DEBOUNCE_MS` (8000ms) after — all three demotion sites gained a `!this.hasRecentSimpleOutputVolume(now)` guard, so none fire while streaming, and the agent still settles to `waiting` 8s after output actually stops (preserving the `AGENT_WAITING_QUIET_MS` floor from #3606).

## Lesson

- **A whole class of output can be invisible to a diff-based liveness signal, not just under-weighted.** `measureVisibleContentDelta`'s suffix check makes pure-append output — the normal shape of an agent dumping results — report `changedChars: 0` by design (it exists to ignore scroll noise). Any heuristic gated on that diff needs an independent liveness floor (byte volume, in this case) for append-heavy output, not just a lower threshold.
- **Adding a recovery detector without auditing every consumer of the signal it's fixing is a half-fix that self-defeats.** The volume detector alone recovered `idle`→`busy`, then got immediately demoted back by gates reading the still-flat diff. Before shipping a new promotion path, grep every site that reads the OLD signal (`stateHint`, `lastActivityTimestamp`, etc.) for demotion logic and confirm each one can be deferred, not just the promotion path.
- **Keep new detectors on their own clock/config, not shared with the polling signal they're patching around.** `simpleOutputVolumeRecovery` is a separate `OutputVolumeDetector` instance from `outputActivityDetection`, deliberately tuned more conservatively (needs sustained flow, not one burst — `maxBytesPerFrame: 256` prevents a single status payload from firing it alone) so it can't perturb the existing polling cycle's `hasRecentOutputActivity` signal.
- **Reuse existing suppression guards verbatim when adding a new recovery path**, don't invent new ones: the volume-recovery branch gates on the same `isResizeSuppressed`, `isFocusSuppressed`, `isRecentUserInput`, and `bootDetector.hasExitedBootState` checks the non-simple first-output-byte path already used — skip these and the new route fires during resize/focus-repaint/boot as false `working` promotions.
- **A clock defaulting to 0 needs an explicit `> 0` guard, not just a timeout comparison, to stay inert when unconfigured.** `hasRecentSimpleOutputVolume` checks `lastSimpleOutputVolumeAt > 0` first so monitors without a volume detector (never fires, stays 0) don't satisfy `now - 0 < IDLE_DEBOUNCE_MS` at small synthetic/test timestamps.

## Applies when

- Touching `ActivityMonitor.onData`'s `simpleOutputState` branch, `terminalActivityPatterns.ts`'s `buildActivityMonitorOptions`, or any `AgentActivityTemperature`/`SustainedChangeTracker` consumer.
- Diagnosing an agent terminal stuck in `waiting`/`idle` despite visibly active output — check whether the output is append-only (streaming results, long tool output) versus in-place redraw (spinner, status line), since the two take completely different recovery paths in this file.
- Adding any new idle→busy recovery signal to `ActivityMonitor` — before merging, trace every existing busy→idle demotion gate and confirm the new signal's "recent" window is consulted there too.
- Reviewing a "detector added but bug still reproduces intermittently" report in this FSM — the recurring shape is a promotion fix that a demotion gate elsewhere immediately undoes.
- Changing `measureVisibleContentDelta`'s `isSuffixOf` branch — PR explicitly left it untouched because loosening it reintroduces false `waiting`→`working` recovery on window resize (#8753).
