## Context

Panel _location_ (grid / dock / trash / background, plus worktree) is mutated by the registry slice (`createPanelRegistrySlice`, `src/store/slices/panelRegistry/`), but the pointer fields live one layer up in `usePanelStore`: `focusedId`, `previousFocusedId`, the maximize trio (`maximizedId` + `maximizeTarget` + `preMaximizeLayout`), `activeDockTerminalId`, `pingedId`. Each pointer is only valid while the panel it names is visible in that pointer's scope, so the store wraps registry mutations (`trashPanel`, `moveTerminalToDock`, …) with pointer-repair code. Three same-day PRs (#10102, #10099, #10093; issues #9937/#9936/#9938) fixed three movement paths that each violated the same invariant a different way.

## Problem

Three unrelated-looking symptoms: (1) after "Send to Background" on the focused panel, Cmd+W silently trashed the now-invisible panel — `terminal.close`, `terminal.kill`, and `terminal.moveToWorktree` all default to `focusedId`, so destructive shortcuts fired with zero feedback; (2) moving a maximized panel out of grid scope (background, move-to-worktree, drag-to-dock) left `maximizedId` set, so `ContentGrid` returned `null` and the ENTIRE grid went blank for every worktree not containing the panel; (3) restoring a trashed dock terminal brought it back as a closed chip while `focusedId` claimed the invisible panel — the restore wrapper hardcoded `activeDockTerminalId: null`.

## Root cause

The invariant is distributed: pointers live in one store but are invalidated by MANY independent movement paths, and nothing central enforces it. #9937 happened because `terminal.background` called `registrySlice.backgroundTerminal` directly — no wrapper existed, so no pointer was touched. Crucially, the reactive safety net could not catch it: the `rendererStoreOrchestrator` subscriber that un-backgrounds panels subscribes to `focusedId` _changes_, and when the panel under a stable pointer changes location the selector value never changes, so nothing fires. #9936 happened because `validateMaximizeTarget` (`terminalFocusSlice`) only clears maximize on missing/trashed panels — a panel that merely left grid scope passes validation; seven exit paths needed the clear (`backgroundTerminal`, `backgroundPanelGroup`, `moveTerminalToWorktree`, `moveTabGroupToWorktree`, `moveTerminalToDock`, `moveTerminalToPosition`, `moveTabGroupToLocation`) and only one had it.

#9938 was the subtlest: `restoreTerminal`/`restoreTrashedGroup` hardcoded `activeDockTerminalId: null` instead of deriving it from the restored panel's location — and even after fixing the wrapper the fix didn't hold, because the async `onRestored` lifecycle listener (`src/store/listeners/panel/lifecycle.ts`) fired later and unconditionally cleared `activeDockTerminalId === id`, undoing the wrapper's work. The listener now only clears when the panel did NOT land back in the dock (`panelsById[id]?.location !== "dock"`). A second-order hole from #9937: with focus correctly nulled, `terminal.close`'s fallback `find()` skipped only `location !== "trash"` and could still land on a background panel — the location enum had grown and every negative filter written against the old enum was silently wrong.

## Lesson

- **Any path that moves a panel out of visible scope needs a `panelStore` wrapper sweeping the FULL pointer family** — `focusedId` (via `pickFallbackFocusId`), `previousFocusedId`, the maximize trio (via `buildMaximizeClearPatch`), `activeDockTerminalId`, `pingedId`. Never call `registrySlice.<move>` directly from an action. Templates: `trashPanel` and `backgroundTerminal` in `src/store/panelStore.ts`.
- **Snapshot group membership and kind policy BEFORE the registry mutation.** Backgrounding and dock moves dissolve the tab group; resolve `getPanelGroup(id)`, `resolvePanelKindPolicy`, and `preferAgent` first, mutate second, so the fallback pick reads pre-mutation grid contents.
- **Guard the slice-declined no-op.** Registry slices decline missing/trash/overlay panels; verify post-mutation that the move happened (`get().panelsById[id]?.location !== "background" → return`) before repairing pointers, or a no-op steals focus from a visible panel.
- **Reactive subscribers cannot catch stale pointers.** A Zustand selector on `focusedId` never fires when the _panel_ under an unchanged id changes location. Pointer repair must be synchronous inside the mutation path — a watcher won't fix it.
- **Async lifecycle listeners must DERIVE pointer values from the panel's actual location, never hardcode.** The `onRestored` listener re-nulled `activeDockTerminalId` after the wrapper had correctly set it — any listener touching a pointer a wrapper also sets is a race until it re-derives from `panelsById[id].location`.
- **When the location enum grows, every negative filter is a hole.** `location !== "trash"` was correct until "background" existed — grep all location filters when adding a value, or filter positively on visible locations.
- Group-maximize splits across two fields — `maximizedId` holds the _triggering panel_, `maximizeTarget.id` the group — so clears must check membership, not id equality (`buildMaximizeClearPatch` does both). Current-code evolution: #11060 added `exitMaximize()` to the restore wrappers; `isPtyPanel` became `isDockPanel` in `landsInDock`.

## Applies when

- Adding or modifying any panel movement path — new drag target, location value, or relocating action — in `src/store/panelStore.ts` or `src/store/slices/panelRegistry/`.
- Diagnosing "Cmd+W closed nothing / the wrong panel", a fully blank `ContentGrid` while panels exist, or a dock chip that has focus but no open popover — first find which pointer field names an invisible panel.
- Writing or reviewing listeners on `terminalRegistryController` lifecycle events (`onRestored`, `onTerminalRemoved`) that touch `focusedId` / `activeDockTerminalId` — they run after the store wrapper and can undo it.
- Tempted to call `registrySlice.*` directly from an action definition, or to fix a stale-pointer bug with a store subscriber instead of in the mutation path.
- Filtering panels by `location` anywhere (focus fallbacks, close targets, counts) — verify the filter matches the current location union, not the one it was written against.
