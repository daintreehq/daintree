## Context

Canopy submits a prompt to an agent terminal by writing the body bytes and then the carriage return (`\r`). `submitEnterDelayMs` (in each agent's `capabilities`, default 200ms via `normalizeSubmitEnterDelay` in `electron/services/pty/terminalInput.ts`) controls the gap between those two writes. A separate `quitSubmitMode` (`"single-write" | "split-write"`, consumed in `TerminalGracefulShutdown.ts`) controls how the `/exit` (or other quit) command is submitted on shutdown. Copilot's CLI is an Ink (React-for-TUI) app, same renderer family as Claude Code.

## Problem

Copilot had `submitEnterDelayMs: 0` in `shared/config/agents/copilot.ts`. Its input field would silently stop accepting commands "after a while" (#5830) — an intermittent, time-delayed symptom that reads like a memory/buffer leak, not an ordering bug.

## Root cause

With `submitEnterDelayMs: 0`, the `\r` is delivered in the SAME event-loop turn as the body bytes. Ink processes stdin asynchronously through React's reconciler; when the CR lands before Ink's input handler has registered the body, the keypress is dropped. It's a same-tick ordering race against the agent's React reconciler, not a buffer issue — it only manifests intermittently because it depends on reconciler scheduling. Zero delay is the intuitive "fast" default but is exactly wrong for an Ink TUI. The non-obvious twist: the quit path needs the OPPOSITE timing. On `/exit`, Ink interprets any GAP between command body and CR as deliberate slow typing and never submits the slash command (#6981), so quit must be `single-write` (`quitCommand + "\r"` in one `ptyProcess.write`). Ratatui-based TUIs (Codex) are the mirror image — they read the PTY buffer atomically and conflate a combined write as a paste, so they keep the default `split-write`.

## Lesson

- For any Ink-based agent CLI (Copilot, Claude — anything built on Ink/React-for-TUI), set `submitEnterDelayMs` to the 200ms default; never `0`. A zero gap races the CR ahead of Ink's reconciler and drops input intermittently.
- The interactive-submit and quit-submit paths require opposite timing for the same Ink renderer: interactive submit needs a GAP (`submitEnterDelayMs >= 200`, body and CR as spaced separate writes); quit needs NO gap (`quitSubmitMode: "single-write"`, body+CR in one write). Set both together when onboarding an Ink agent.
- Match the TUI framework, not the vibe: Ink wants split-write-with-delay on submit and single-write on quit; Ratatui (Codex) wants the inverse on quit (`split-write`, the default). Identify the framework before picking timing.
- Intermittent "input stops accepting after prolonged use" on an agent terminal is a same-tick CR-vs-reconciler race far more often than a leak — check `submitEnterDelayMs` first.

## Applies when

Onboarding a new agent whose CLI is built on Ink (React-for-TUI) or any framework with async stdin handling; setting or reviewing `submitEnterDelayMs` / `quitSubmitMode` in `shared/config/agents/*.ts`; debugging reports that an agent's input field "stops accepting commands after a while" or that `/exit`/quit "doesn't submit on shutdown"; touching the submit/Enter timing in `electron/services/pty/terminalInput.ts` or the graceful-shutdown quit write in `electron/services/pty/TerminalGracefulShutdown.ts`.
