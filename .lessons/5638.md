## Context

`PluginService` (`electron/services/PluginService.ts`) exposes worktree state to plugins through four host methods — `getActiveWorktree`, `getWorktrees`, `onDidChangeActiveWorktree`, `onDidChangeWorktrees` — backed by the `WorkspaceClient` EventEmitter (`worktree-update` / `worktree-activated` / `worktree-removed`). The backing `WorkspaceClient` is created lazily, per-view, only when a project view initialises (`electron/window/windowServices.ts:273` calls `pluginService.setWorkspaceClient(...)` inside the view-init path), so it does not exist at PluginService construction time.

## Problem

Three independent footguns hide in "just expose read-only state to plugins":

1. A plugin's `activate()` can run before any view initialises, so `setWorkspaceClient()` hasn't fired yet — a naive `client.on(event, handler)` at subscription time silently drops the subscription against a `null` client and the plugin never gets events.
2. The change-event callbacks `await fetchAllWorktreeSnapshots()` before invoking the plugin callback. A concurrent `unloadPlugin()` can complete during that await, leaving the callback to fire into a disposed plugin closure.
3. Returning the internal `WorktreeSnapshot` directly (or via spread) both leaks future internal fields to third-party plugins and lets a plugin mutate live host state.

## Root cause

The host capability's lifecycle is decoupled from its backing service's lifecycle — activation order is not guaranteed, and every read crosses an async boundary that the unload path can interleave with.

## Lesson

For a host capability backed by a service injected after activation, build three things together:

- A pending-subscription replay queue. `subscribeWorktreeEvent` queues into `pendingWorktreeSubs` when `workspaceClient` is `null`; `setWorkspaceClient()` drains the queue and binds each `.on(event, handler)` to the real client. The returned disposer handles both the queued (`splice` out of `pendingWorktreeSubs`) and the bound (`client.off`) state, so dispose-before-replay is safe.
- A re-check-after-await guard. Every async callback re-checks `this.plugins.has(pluginId)` both before the fetch and again after the await before invoking the plugin callback; rejections are caught and `console.error`'d (Tier 0 — plugin can't act on a missed snapshot) rather than surfaced as unhandled rejections.
- An explicit no-spread freeze projection. `toPluginWorktreeSnapshot` (`shared/utils/pluginWorktreeSnapshot.ts`, shared by main and the `useActiveWorktree` renderer hook) assigns each allowlisted field by name and `Object.freeze`s the result; nested `linked` is deep-cloned before freezing so freezing never makes the host's own live `_linked` reference immutable and break later `setLinked()` merges.

Per-plugin disposers live in `pluginEventCleanups` (now shared by other host subscriptions like forge providers) and are flushed in `flushPluginEventCleanups()` on unload — snapshot-and-clear the list first, since each `dispose()` splices itself out mid-iteration.

## Applies when

Adding any plugin host capability that subscribes to or reads from a backend service created later than plugins activate (WorkspaceClient, PtyClient, forge providers), or exposing internal host state objects across the plugin trust boundary.
