## Context

IPC handlers in the main process throw typed errors (`AppError`, `BrokerError`, `GitOperationError`) carrying discriminant fields beyond `message`/`stack` — e.g. `GitOperationError` carries `gitReason`, `leaseSha`, `branchName`. The IPC envelope pattern (PR #3769, `IpcEnvelope` + `deserializeError`) gets these fields across the `ipcRenderer.invoke` structured-clone boundary, and the preload's `_unwrappingInvoke` reconstructs a typed `Error` via `_reconstructGitError` / `_reconstructAppError`. The Review Hub's force-push-with-lease recovery and `CloneRepoDialog` branch on these fields.

## Problem

The force-push-with-lease recovery in the Review Hub degraded to a plain force push (and sometimes didn't render its recovery banner) because `leaseSha` was silently missing on the renderer side. The error _looked_ like it crossed intact — `message` and `stack` were present — so the dropped discriminant fields failed silently with no exception. Doc comments at the time falsely claimed `_unwrappingInvoke` had already reattached the fields.

## Root cause

There are TWO property-stripping boundaries, not one. PR #3769's envelope solves only the first (main→preload structured clone over `ipcRenderer.invoke`). But the preload runs in a **separate V8 realm** from the renderer, and Electron's `contextBridge` strips ALL own-properties (including own `name`) off `Error` instances **again** when the preload's freshly-reconstructed error crosses preload→renderer. So setting `error.gitReason = ...` inside `_reconstructGitError` is correct only for same-realm callers; those assignments are gone by the time the renderer catches the error. The only field that survives both boundaries is the standard `message` string.

## Lesson

For any typed Error thrown by an IPC handler whose discriminant fields the renderer must read:

- Encode the fields into a structured `message` prefix in the preload's reconstruct function, e.g. `[GitError|<reason>|<urlencoded leaseSha>|<urlencoded branchName>] <original message>` (`_reconstructGitError` in `electron/preload.cts`). URL-encode any field that can contain the delimiter chars `|`/`]` or `/` (branch names, paths); use fixed positional slots (empty between pipes when absent) so the renderer regex always matches.
- Decode on the renderer with a realm-safe guard that side-effects the fields back onto the error and strips the prefix from `message` — `isClientGitError` in `src/utils/clientGitError.ts` (mirrors `clientAppError.ts` / `clientBrokerError.ts`). The guard must be idempotent (second call falls through to the duck-typed same-realm path).
- NEVER rely on `instanceof` or own-property reads across the bridge, and never trust that `_unwrappingInvoke`'s property assignments reached the renderer — they didn't. Setting standard props in the reconstruct fn is fine for same-realm tests, but the message prefix is the source of truth.
- A regex constrained to the current union shape (`[a-z-]+` for `GitOperationReason`) means adding a reason with digits/underscores is a coordinated cross-file change; consumers must keep a `?? "unknown"` fallback.

## Applies when

- Adding a new typed Error class (with custom discriminant fields) that an IPC handler throws and the renderer must branch on.
- Touching `electron/preload.cts` `_reconstruct*Error` functions or `_unwrappingInvoke`, or `src/utils/client*Error.ts` guards.
- A renderer reads `e.gitReason` / `e.code` / `e.leaseSha` (or similar custom Error field) and gets `undefined` despite the field being set in the main process.
- A recovery/branching path keyed on an error discriminant silently degrades or fails to render with no thrown exception (force-push-with-lease, clone error classification, broker-disconnect handling).
- Reviewing IPC error handling — verify both boundaries are covered, not just the #3769 envelope.
