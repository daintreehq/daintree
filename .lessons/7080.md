## Context

Renderer-supplied branch names, worktree paths, and diff ranges flow into `git.raw([...])` / `git.diff([...])` argv arrays in `GitService` (`createWorktree`, `removeWorktree`, `compareWorktrees`, `getFileDiff`), in `WorkspaceService`, and in the staged-blob conflict-marker scan (`scanStagedFilesForConflictMarkers`). The repo being operated on may be untrusted (a cloned hostile repo), so its `.gitattributes` and config are adversary-controlled. This builds on the existing `createHardenedGit` `-c` overrides (#3742) and the `--no-ext-diff` defense (#4221).

## Problem

Three separate flag/argv gaps, each with a remote-code-execution or flag-injection consequence:

1. A branch/ref/worktree-path value beginning with `-` (e.g. `--exec=evil`, `--upload-pack=...`) is parsed by git as a CLI flag, not a positional.
2. `--no-ext-diff` (the #4221 fix) blocks `diff.external` but does NOT block `textconv`/smudge filters — a hostile `[diff "x"] textconv = <binary>` mapping in `.gitattributes` still executes arbitrary binaries during read-side diff/show.
3. The conflict scanner read staged blobs via `git show :<path>`, which can run smudge filters depending on git version.

## Root cause

- `--end-of-options` only protects _positional_ tokens. Git's revision parser receives a range like `branch1..branch2` as a single argument and **re-parses dashes inside it as flags**, so `--end-of-options` in front of the range is insufficient — a leading-dash branch name still injects. The fix expands to fully-qualified `refs/heads/<branch>` so no dash can lead the range token (safe because worktree branches surface as short names — `refs/heads/` is stripped in `listWorktrees`).
- `--no-ext-diff` and `--no-textconv` are _different_ surfaces. `diff.external` is the whole-diff driver; `textconv` is a per-attribute content-to-text filter. Both execute configured binaries; you need both flags on every read-side diff.
- `git show` / `git diff` route blob bytes through smudge/textconv machinery. **`git cat-file blob` is the only diff-family command that reads the raw object bytes with that machinery fully bypassed** — the correct primitive for "give me the exact stored bytes, run nothing."
- Validation placed _after_ the `branch1 === branch2` equality fast-path meant an invalid argv-shaped name (`--exec=evil` for both args) returned a silent OK instead of being rejected.

## Lesson

When building git argv from any renderer/IPC-reachable input against a possibly-hostile repo:

- Put `--end-of-options` between subcommand flags and positionals (`worktree add -b <branch> --track --end-of-options <path> <base>`). But know it does NOT defend a composite range token — for `a..b` / `a...b`, expand each side to `refs/heads/<branch>` (or otherwise guarantee no leading dash inside the token).
- Add **both** `--no-ext-diff` and `--no-textconv` to _every_ read-side `git diff` call. `--no-ext-diff` alone (the #4221 takeaway) leaves textconv as an open RCE surface.
- To read raw staged/object bytes, use `git cat-file blob --end-of-options :<path>` — never `git show` or `git diff`, which can invoke smudge/textconv filters.
- Run the branch-name validator (`validateBranchName` in `shared/utils/pathPattern.ts`) _before_ any short-circuit/fast-path, so identical-but-invalid inputs are still rejected. It rejects leading `-`, control chars, the git-check-ref-format forbidden set (`space ~ ^ : ? * [ \`), `..`, `@{`, `//`, leading/trailing `/`, trailing `.`.

## Applies when

- Adding or modifying any `git.raw([...])` / `git.diff([...])` / `git.show(...)` call in `electron/services/GitService.ts`, `electron/workspace-host/WorkspaceService.ts`, `electron/ipc/handlers/git-write.ts`, `electron/ipc/handlers/worktree/`, or `electron/services/git/`.
- Constructing a git diff _range_ (`a..b`, `a...b`) from user/IPC-supplied branch names.
- Reviewing read-side diff/blame/show paths against untrusted repos for textconv/smudge execution (`.gitattributes` `textconv =` or smudge filters).
- Reading staged or object bytes for scanning (conflict markers, content probes) — reach for `git cat-file blob`, not `git show`.
- Any new code accepting branch names or worktree paths from the renderer — validate before fast-paths, and add `--end-of-options`.
- Extending the existing hardening from #3742 (`createHardenedGit`) and #4221 (`--no-ext-diff`); this PR is the textconv + argv-injection follow-on.
