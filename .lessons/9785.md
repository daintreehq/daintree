## Context

macOS packaging signs two spawned helper executables via `mac.binaries[]` in `electron-builder.config.cjs`: node-pty's `spawn-helper` (the forkpty trampoline every terminal spawn goes through) and posix-pty-reaper's `daintree_pty_supervisor` (help-session process reaping). Both `entitlements` and `entitlementsInherit` point at the full app plist `build/entitlements.mac.plist`, which carries `allow-jit`, `disable-library-validation`, and `com.apple.security.device.audio-input` — so the helpers were signed with the app's complete entitlement set. #9258 had settled the app plist without ever splitting the helpers off it.

## Problem

On macOS 26 (Tahoe), the `amfid` daemon SIGKILLs any spawned executable that claims a restricted entitlement without an embedded provisioning profile. `audio-input` is exactly that shape, so both helpers die at exec: terminals open blank, no shell ever spawns, and PTY reaping is dead — the app's core feature breaks entirely on the new OS (issue #9775; VS Code hit the identical node-pty failure, microsoft/vscode#313690). The misleading part: nothing in our code or config changed — a signing configuration that had shipped fine for every prior macOS became fatal purely by OS policy change, and unsigned dev builds never reproduce it.

## Root cause

Three facts stack. (1) electron-builder's `mac.binaries[]` has **no per-binary entitlements option** — every listed binary is signed with the app-level `entitlements`/`entitlementsInherit` plists, period. A forkpty helper therefore claims microphone access it never uses, and there is no config-only way to prevent it. (2) macOS 26 moved enforcement: amfid now validates restricted entitlements on _spawned_ executables against a provisioning profile at exec time and kills on mismatch, where earlier releases tolerated it for Developer ID builds. (3) The only fix point is a packaging hook that re-signs the helpers _after_ electron-builder's signing pass — but re-signing a nested Mach-O changes its cdhash, which **invalidates the outer `.app` bundle seal**; a naive re-sign produces an app that fails notarization/Gatekeeper.

The shipped fix (`scripts/resign-helpers-macos.cjs`, called from the `afterSign` hook `scripts/notarize-macos.cjs`): detect the signing identity by parsing the `Authority=Developer ID Application: ...` line from `codesign -dvv` on the already-signed .app (matches whatever cert electron-builder just used, CI or local keychain); re-sign each helper with `--force --sign <identity> --options runtime --timestamp --entitlements build/entitlements.helpers.plist` where the plist is an empty `<dict/>` (hardened runtime is conveyed by `--options runtime`, NOT by the plist); then repair the seal with `codesign --force --sign <identity> --timestamp --preserve-metadata=identifier,entitlements,flags <app>` — `preserve-metadata=entitlements` is load-bearing, since the app itself genuinely needs `audio-input` and a plain reseal would strip it. The call sits BEFORE the `DAINTREE_SKIP_NOTARIZATION` early-return (entitlements are a signing property, not a notarization property) and self-guards on `CSC_LINK`, the same signal the config uses for signed-build-only behavior.

## Lesson

- **`mac.binaries[]` cannot scope entitlements per binary** — anything listed inherits the full app plist. A helper needing fewer entitlements than the app requires a post-sign re-sign hook; `scripts/resign-helpers-macos.cjs` is the pattern to copy, not electron-builder config.
- **Re-signing any nested binary inside a signed .app breaks the outer seal.** Always follow with a bundle reseal using `--preserve-metadata=identifier,entitlements,flags`; omitting `entitlements` from that list silently strips the app's own entitlement set on the reseal.
- **Signing fixes must run before notarization skip-gates.** `DAINTREE_SKIP_NOTARIZATION=true` builds are still signed builds — `resignHelpers(context)` executes before that early-return in `notarize-macos.cjs`, or skip-notarization releases would ship the broken helpers.
- **Helper paths are duplicated in four places** — `mac.binaries[]` (electron-builder.config.cjs), `HELPER_RELATIVE_PATHS` (resign-helpers-macos.cjs), `HELPERS` (verify-helper-entitlements.sh), and the afterPack.cjs presence checks. A new spawned native helper must be added to all four; the hook throws on a missing path precisely to catch layout drift.
- **Verify fail-closed, and know codesign's stream quirks** (hardening follow-up `6e4df45eb`, same arc): a non-zero `codesign -d --entitlements -` exit must not read as "no entitlements" — capture the exit code separately from output. And `codesign -dvv` prints to stderr, so identity detection needs `spawnSync` (which exposes stderr), not `execFileSync` (stdout only).
- **CI is the canary:** `scripts/ci/verify-helper-entitlements.sh` in the `release-macos.yml` signing-audit step asserts both helpers show zero `<key>` elements via `codesign -d --entitlements - --xml` — any future packaging change that re-leaks entitlements fails the release, not the user's terminal.

## Applies when

- Adding any new native helper binary that Daintree spawns on macOS (new `asarUnpack`/`mac.binaries[]` entry) — decide its entitlement set explicitly and wire it into the re-sign hook and verify script, or Tahoe kills it.
- Editing `build/entitlements.mac.plist` or the mac signing block of `electron-builder.config.cjs` — every entitlement added there leaks onto the spawned helpers via `entitlementsInherit`.
- Diagnosing macOS-only "terminal opens blank / no shell ever spawns" on a signed or packaged build (dev builds unaffected) — check Console.app for amfid kills and run `codesign -d --entitlements -` on `spawn-helper` inside the bundle.
- Touching `scripts/notarize-macos.cjs` or the afterSign chain — the resignHelpers-before-skip-gate ordering and the `CSC_LINK` gate are invariants.
- Bumping `node-pty` or `posix-pty-reaper` (the hardcoded `build/Release` paths can drift), or when upstream node-pty ships its own microsoft/vscode#313690 fix — the hook may then be simplifiable but the verify gate should stay.
