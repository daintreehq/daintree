## Context

Terminal management moved out of the main process into the forked `pty-host` UtilityProcess (commit `5d802218b`). After that, the real terminal registry lives in the host and is queried across the IPC boundary via `PtyClient.getAllTerminalsAsync()`. But the old `getPtyManager()` singleton in `electron/services/PtyManager.ts` stayed importable and its lazy constructor still ran — the registry is only populated by `registry.add` inside that manager's own `spawn()`, which no main-process code calls anymore (real spawns route through `ptyClient.spawn` into the host's separate `PtyManager`). So `getPtyManager().getAll()` returns `[]` forever.

## Problem

Four main-process consumers read `getPtyManager().getAll()` and each silently no-op'd for months: support-bundle `terminals` always `[]` (a "terminal froze" report read as if no terminals existed), idle-terminal notifications never fired (#5064, on by default), hibernation never hibernated a single project (#8534, both the inactivity sweep and the memory-pressure path), and active-agent project views were wrongly LRU-evicted because `hasActiveAgent()` always returned false (killing #5234's protection). Nothing threw; each feature quietly did nothing. Fixed in #10190 (issue #10054).

## Root cause

Two mechanisms compound. First, an **architecture migration that leaves the old seam importable but unpopulated is invisible at the call site** — `getPtyManager().getAll()` is still valid TypeScript returning a well-typed empty array; no null, no throw, no type error. The registry moved processes; the reader didn't, and an empty result is indistinguishable from "no terminals." Second, and why it survived CI: **the unit tests mocked `getPtyManager()` itself** — the exact boundary that had gone stale. Every test did `vi.mock("../PtyManager.js", () => ({ getPtyManager: () => ...populated mock }))`, so the dead path always "worked" in CI while returning `[]` in production. Mocking the seam that went dead makes the test tautological: it asserts against a fixture that no longer corresponds to any real data source.

The fix routes all four sites to `ptyClient.getAllTerminalsAsync()` and rewrites the tests as `PtyClient`-shaped mocks. Two non-obvious wiring patterns fell out, detailed in the Lesson: a synchronous eviction guard backed by an event-fed cache (because it can't await the host), and inject-on-start client re-acquisition (because `stop()` clears the ref).

## Lesson

- **When a subsystem migrates processes, grep every reader of the old accessor — an importable-but-unpopulated singleton reads as an empty result, not an error.** `getPtyManager().getAll()` kept type-checking and kept returning `[]`; four features read a corpse. The migration commit should have deleted or hard-failed the main-process accessor. Today `getPtyManager()` still exists at `PtyManager.ts:1075` with zero production callers (only comment references) — treat it as a landmine; route new reads through `PtyClient.getAllTerminalsAsync()`.
- **A mock of the exact boundary that changed is a tautology, not coverage.** These features passed CI because the tests mocked `getPtyManager()` — the dead seam. When you migrate a data source, delete the tests that mock the _old_ accessor and rewrite against the _new_ interface; a test that still green-lights the abandoned path is worse than no test.
- **A synchronous hot path that needs cross-process data uses an event-fed cache, not an await.** `hasActiveAgent()` runs inside LRU eviction scoring and cannot go async, so it reads instance maps seeded once from the host and refreshed via `agent:state-changed` / spawn-result / host-crash events (now in `electron/window/ProjectViewAgentStateCache.ts`, extracted #11004). Seed conservatively — empty maps → `false`, so a not-yet-seeded view is never falsely protected.
- **Inject-on-start, not inject-once: `setPtyClient()` must be re-acquired at the top of `start()`.** `stop()` clears the client (so a stale host ref isn't pinned across restart, lesson #8637), so any service that clears on stop must re-fetch via `getPtyClient()` on the next start — otherwise a Settings toggle off→on disables it forever.
- **Order host-dependent seeding after the client exists.** `getPtyClient()` is null until `setupWindowServices` runs; seed any host-backed cache after that call or it silently stays empty on first launch (`0c4d86b7c`).

## Applies when

- Migrating any main-process subsystem into (or out of) a UtilityProcess/pty-host that exposes a legacy singleton accessor (`getPtyManager`, similar `get*()` getters) — audit every reader; an empty return is not a signal that there's nothing there.
- Diagnosing a feature that "never fires" with no error: empty support bundles, idle notifications that never trigger, hibernation that never hibernates, active-agent views getting LRU-evicted — check whether the reader pulls from a stale main-process registry vs. `ptyClient.getAllTerminalsAsync()`.
- Writing or reviewing tests that `vi.mock()` a module boundary — confirm the mocked seam is still the live data path; a mock of an abandoned accessor asserts against fiction.
- Adding a synchronous guard (eviction, freeze, scoring) that needs terminal/agent state — use the `ProjectViewAgentStateCache` event-fed pattern, never an await in the hot path.
- Injecting a `PtyClient` (or any host client) into a service via `setPtyClient()` — re-acquire on `start()`, clear on `stop()`, seed only after `setupWindowServices` has constructed it.
