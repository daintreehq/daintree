## Context

Panels are a discriminated union (`PanelInstance` in `shared/types/panel.ts`) keyed on `kind` ("terminal" | "browser" | "dev-preview" | "review" | plugin strings). Originally "agent" was a fifth built-in `kind`: a terminal running Claude/Gemini/Codex persisted as `kind: "agent"`, while a plain shell persisted as `kind: "terminal"`. #5801 collapsed "agent" into "terminal" — agent identity now lives only on `agentId`/`launchAgentId`, and the panel kind is always "terminal" for any PTY-backed pane.

## Problem

Encoding agent-ness as a persisted `kind` discriminator created a split-brain. A terminal that launched Claude, had the agent exit, then ran a plain shell was still frozen as `kind: "agent"`; a plain shell where the user typed `claude` could never be promoted. Every consumer had to special-case both axes with brittle `kind !== "agent" && !agentId` guards (see the old `electron/ipc/handlers/projectCrud/stats.ts` and `ProjectStatsService.ts`), and promotion/demotion between shell and agent forced a kind change — which would unmount the React subtree, kill the PTY, and recreate the xterm instance.

## Root cause

Two orthogonal facts were conflated into one field. "What surface is this" (terminal vs browser vs dev-preview — durable, decides the component tree and whether a PTY exists) is a different axis from "what process is live inside the PTY right now" (shell vs claude vs codex — transient, flips as the user launches/exits agents). The persisted `kind` is the wrong home for the second axis because it is runtime state, not structure. The correct model: kind stays "terminal", `agentId`/`launchAgentId` carries durable launch affinity (for restart/resume/preset lookup), and live detection (`detectedAgentId`, `everDetectedAgent`, `runtimeIdentity`) carries the transient signal. The component tree, PTY, and xterm instance stay stable across promotion/demotion because nothing structural changed.

## Lesson

When a "type" can change during the lifetime of an object without changing its structure, it is state, not a kind — do not put it in the discriminated-union tag. Migrate by keeping the secondary identity field and ignoring the stale tag at the boundary: `inferKind` (`shared/utils/inferPanelKind.ts`) maps legacy `kind: "agent"` → "terminal" and `normalizePtyKind` (`src/utils/stateHydration/statePatcher.ts`) does the same on hydration, so persisted `agentId` survives but the obsolete tag never re-enters the live store. Two non-obvious traps survive this refactor: (1) `TerminalRuntimeIdentity.kind === "agent"` (`shared/types/panel.ts:113`) is a _different_ `kind` field — transient runtime identity, never persisted — so a grep for `kind === "agent"` will match legitimate runtime-identity checks (`terminalChrome.ts`, `terminalType.ts`) alongside genuine bugs; disambiguate by which object you hold. (2) `inferAgentIdFromTitle` (`statePatcher.ts:158`) gates title-based agent recovery on the legacy `kind === "agent"` marker precisely so a user-renamed plain shell with "claude" in its title is NOT silently re-promoted into an agent and handed a regenerated launch command.

## Applies when

Adding a new built-in panel kind, or adding any new "type"/"mode" field to a persisted entity — ask whether the value can flip during the object's life; if yes, store it as state and derive display from it, do not extend the union tag. Also when writing guards that test panel kind against "agent" (there is no such persisted kind anymore — test `agentId`/`detectedAgentId` instead), or when grepping `kind === "agent"` and needing to tell the persisted-tag axis from the runtime-identity axis.
