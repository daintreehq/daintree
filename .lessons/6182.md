## Context

Daintree suppresses motion two ways: the OS `@media (prefers-reduced-motion: reduce)` block and the in-app "Reduce UI animations" toggle (`body[data-reduce-animations="true"]`), both in `src/index.css`. Both blanket-applied `transform: none !important; transition: none !important` to broad selectors (`button`, `[role="button"]`, `[type="button"|"submit"|"reset"]`). All overlay primitives (popover, dropdown-menu, context-menu, select, tooltip) are Radix, which use the Presence component to defer exit unmounting.

## Problem

With reduced motion enabled (OS setting or the in-app toggle), opening and closing a popover/dropdown left the closed Radix content "ghosted" — still mounted in the React tree, still holding focus/aria slots, and still able to block pointer events on the elements behind it.

## Root cause

Radix Presence does not unmount closed content immediately. It sets `data-state="closed"` and waits for the exit `animationend` (or `transitionend`) event before removing the node from the DOM. The broad reduced-motion selectors matched the Radix-rendered trigger/content elements and forced `transition: none !important` / `animation: none`, so the exit animation never started and **the `animationend` event never fired** — Presence's teardown callback was never invoked, so the node lingered indefinitely. Disabling animation for accessibility silently broke component teardown: a non-obvious coupling between a11y CSS and the unmount lifecycle of a library that gates unmount on an animation event.

## Lesson

- When you blanket-kill `transition`/`animation` for reduced motion, **exclude any element whose unmount is gated on an animation/transition event.** For Radix, that means elements carrying a Presence state attribute. The fix scopes the broad button selectors with `:not([data-state="open"]):not([data-state="closed"])` so `transition: none` never touches an element in an active Radix Presence state.
- Two valid strategies for an animation that must not visibly play but must still emit its end event: (a) exclude the element from the `none` rule (the chosen fix here — Radix exit then runs at full duration but with translate/scale zeroed via the `[data-state][data-side]` overrides, opacity fade preserved per WCAG 2.3.3), or (b) set `animation-duration`/`transition-duration: 1ms` instead of `none` (the issue's original suggestion) so the event fires immediately. Never `animation/transition: none` on a node a library unmounts on `animationend`.
- Keep the hard `none` pattern only for selectors targeting our own `.animate-*` keyframes — those don't carry `data-state` and nothing waits on their end event.
- This applies symmetrically to BOTH motion-suppression surfaces (`prefers-reduced-motion` media query AND the `data-reduce-animations` toggle); fixing one without the other leaves the bug half-live.

## Applies when

- Editing the reduced-motion blocks in `src/index.css` (`@media (prefers-reduced-motion: reduce)` or `body[data-reduce-animations="true"]`), or adding any global `transition: none` / `animation: none` rule.
- A Radix popover/dropdown/context-menu/select/tooltip stays in the DOM after closing, keeps focus, or blocks clicks on elements behind it — especially only when reduced motion / "Reduce UI animations" is on.
- Adding new overlay components (or any component) whose unmount/teardown is deferred until an `animationend`/`transitionend` listener fires (Radix Presence, Framer Motion exit, `AnimatePresence`-style patterns).
- Any accessibility motion work that touches selectors broad enough to match library-rendered DOM (`button`, `[role="button"]`, `[data-state]`).
