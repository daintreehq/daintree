## Context

`AgentStateService` classifies why a waiting agent is blocked (`prompt` / `question` / `approval` / `error`) and stamps it onto the in-memory terminal as `terminal.waitingReason`; `PtyClient`'s `TerminalInfoResponse` has carried a `waitingReason` field since `fb917ed10` (2026-03-20). PR #10949 ("Surface agent waiting reasons across the attention handoff") built the actual UI surface — header-chip tooltip, waiting-popover priority sort, fleet badges, OS notifications, screen-reader announcements, all backed by a new shared vocabulary module `shared/utils/waitingReasonDisplay.ts` — and, while doing so, discovered the value never survived a project-view rebuild.

## Problem

The classification existed and was correct for months, but no surface ever showed it, and the gap looked like a missing feature rather than a data-loss bug: after any project-view eviction (`ProjectViewManager` LRU), reconnect, or app-restart rehydration, a terminal that should carry an approval/question/error reason silently fell back to the generic "waiting for input" presentation. Nothing threw, logged, or type-errored — the rebuilt terminal object simply didn't have the field.

## Root cause

The path from backend classification to rendered UI runs through a chain of independently hand-built object literals, and none of them spread the source object — each hop re-lists only the fields its author remembered to list. `electron/ipc/handlers/terminal/snapshots.ts` alone builds **five** separate snapshot payloads (the plain `getInfo`, the batch list, and the reconnect variants, at roughly lines 166, 221, 276, 320, 402), each needing its own added `waitingReason: terminal.waitingReason` line — there is no shared serializer backing them. The declared return types (`BackendTerminalInfo`, `TerminalReconnectResult` in `shared/types/ipc/terminal.ts`) also didn't declare `waitingReason` before this PR, so TypeScript never flagged the omission: leaving an optional field out of a hand-built literal is always valid, so a field can be typed away invisibly at any non-spreading hop. On the renderer side the same field then had to be threaded through three independent restore functions in `src/utils/stateHydration/statePatcher.ts` (`buildArgsForBackendTerminal`, `buildArgsForReconnectedFallback`, `buildArgsForOrphanedTerminal`) and two near-duplicate reconnect-merge branches in `src/store/slices/panelRegistry/addPanel.ts` — each needing the _same_ gating rule, not a plain passthrough: `waitingReason` is only meaningful while the resolved `agentState === "waiting"`, so every hop needed `agentState === "waiting" ? reason : undefined` (formalized as the shared `restoredWaitingReason` helper plus `coerceWaitingReason`, which also rejects off-wire junk against a `WAITING_REASONS` set). Threading one already-computed field end-to-end took edits in 10+ spots across 4 files, each independently gated — miss one and the reason vanishes at exactly that hop, with zero build signal.

## Lesson

- **When a backend classifier clearly computes a value but the UI never shows it, suspect a dropped hop in the hydration chain before doubting the classifier.** Grep the field name across `snapshots.ts`, `shared/types/ipc/terminal.ts`, `statePatcher.ts`, and `addPanel.ts` — `waitingReason` had been sitting correctly computed on `PtyClient`'s `TerminalInfoResponse` since March, three and a half months before anyone noticed it wasn't reaching the renderer.
- **`electron/ipc/handlers/terminal/snapshots.ts` has five independently hand-built snapshot object literals and no shared serializer** — treat it as the highest-risk single file for this exact failure mode; a field added here must be copy-pasted into all five spots or it silently drops for whichever path was missed.
- **Adding a field to `BackendTerminalInfo` or `TerminalReconnectResult` does not make TypeScript enforce that every producer populates it** — omitting an optional field from a hand-built literal always type-checks. The type declaring the field is necessary but not sufficient; you must separately verify every literal that returns that type actually sets it.
- **Gate transient/contextual fields at every hop with the same rule, not a plain passthrough.** `waitingReason` is meaningless once `agentState` isn't `"waiting"`; PR #10949 centralized the gate as `restoredWaitingReason()` and reused it across all three `statePatcher.ts` restore functions specifically so the rule couldn't drift between hops.
- **A silently-dropped field at a serialization boundary produces no error, only a UI gap that looks like "never implemented" rather than "already implemented, lost in transit"** — when investigating why a computed value never surfaces, check `git log -S"<fieldName>"` on the suspected source type before assuming the whole feature needs building from scratch.

## Applies when

- Adding a new per-terminal or per-agent live-state field (a classification, timestamp, or flag) that must survive project-view LRU eviction, reconnect, or app-restart rehydration.
- Diagnosing "the backend/AgentStateService clearly computes X but the UI never reflects it" for any terminal or panel state — check the snapshot/reconnect/hydration chain for a dropped field before doubting the classifier itself.
- Touching `electron/ipc/handlers/terminal/snapshots.ts`, `shared/types/ipc/terminal.ts` (`BackendTerminalInfo` / `TerminalReconnectResult`), `src/utils/stateHydration/statePatcher.ts`, or the reconnect-merge branches in `src/store/slices/panelRegistry/addPanel.ts`.
- Reviewing any IPC handler that returns a hand-listed object literal instead of spreading its source — confirm every field the declared type promises is actually copied at every call site that returns that type.
