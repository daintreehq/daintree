# Daintree energy investigation — 20 September 2026

This change reduces work done by hidden terminal parsers and decorative status animations while retaining live terminal state, host activity detection, and immediate reveal. Measurements compare `b3a4e4f5150c5a79180a841005087606708f5c31` with this branch on the same Mac. Hardware: Apple M4 Max, 16 logical CPUs, 64 GB RAM, macOS 26.3.1, Electron 42.7.1 / Chromium 148.0.7778.280, on AC power. Other applications remained running, so small timing changes are not treated as wins. These are local CPU-work measurements, not watts, battery-life estimates, or hardware GPU utilization.

## Changes

- Frequent output in hidden terminals coalesces for at most 100 ms or 32 KiB. First and sparse chunks drain normally; focused terminals and interaction participants bypass batching. Reveal and resize flush pending output. The existing byte ordering, original chunk acknowledgements, backpressure, and lifecycle safeguards remain intact.
- Cached project views no longer treat their retained local focus ID as an interactive terminal. This applies to background projects in additional windows as well as the current window.
- Working-state spinners use 24 synchronized steps per 1.4-second revolution (about 17 updates/second). A shared epoch aligns newly mounted indicators and separate project documents. There is no recurring JavaScript animation timer. Existing reduced-motion, blur, battery, and cached-view policies still apply.
- The native idle fixture now marks seeded projects open before hydration, so its 19 terminals actually materialize. The rapid-switch benchmark explicitly checks the final destination rather than accepting a false-positive result from a stale predicted MRU order. Its final selection excludes both the still-attached outgoing view and the pending destination, avoiding an unintended UI no-op during cold-switch overlap.

## Correctness and limits

Host activity detection is unchanged. A replay experiment covered 20 fixtures with four fragmentation seeds at six polling cadences. Reducing polling could add latency and, at aggressive cadences, change final states; no cadence reduction ships. Fixed batching for sparse streams also added unnecessary overhead, so batching is adaptive. Marker removal was only a diagnostic ablation and does not ship.

Hidden worktree rendering and WebGL release already existed. The measured waste was therefore not repeated hidden painting: frequent parsing/addon callbacks and visible decorative motion still consumed CPU. Production builds do not expose the React profiling probe used by the general store-fanout harness; zero React counters in these logs are not evidence of zero React renders.

The multi-window tests found a separate pre-existing issue when the _same project_ is duplicated in two windows and one copy is cached: the cached copy can miss output routed only to the active MessagePort. Baseline reproduction and exact-output guard are retained under `BACKGROUND_ENERGY_SECOND_WINDOW=mirror`. This is tracked in [#12557](https://github.com/daintreehq/daintree/issues/12557), remains unresolved, and must not be counted as an improvement here. Distinct background projects in multiple windows passed the exact-output checks.

## Reproduction

Run serially against a matching built app with no concurrent builds or unit suites. Do not rebuild while the app is open. Use the same harness on both source revisions; the baseline renderer excludes the four product changes while retaining measurement instrumentation. The native fixture fix is shared by both arms.

```sh
RUN_PERF_STORE_FANOUT=1 PERF_STORE_FANOUT_SCALES=20 \
RUN_BACKGROUND_ENERGY=1 BACKGROUND_ENERGY_ONLY=1 BACKGROUND_ENERGY_WARM=1 \
BACKGROUND_ENERGY_PRODUCTION=1 BACKGROUND_ENERGY_STREAM_MS=20 \
BACKGROUND_ENERGY_WINDOW_MS=20000 BACKGROUND_ENERGY_MODES=hidden-stream,normal,normal \
npx playwright test --project=full-panels e2e/full/panels/store-fanout-perf.spec.ts --workers=1 --reporter=line
```

Add `BACKGROUND_ENERGY_SECOND_WINDOW=1` for distinct projects across two windows. Sparse ingestion uses `BACKGROUND_ENERGY_STREAM_MS=150` and `BACKGROUND_ENERGY_MODES=hidden-stream,normal-no-motion,normal-no-motion,normal-no-motion`; compare the three animation-paused windows to isolate ingestion overhead. Motion-paused and other ablation modes are diagnostic only, not product configurations.

```sh
RUN_ACTIVITY_ENERGY_REPLAY=1 npm test -- electron/services/__tests__/ActivityMonitor.energy-experiment.test.ts
```

The input and project-switch guards used the following bounded configurations:

```sh
RUN_PERF_INTERACTIVITY=1 PERF_INTERACTIVITY_CELLS=sim-fleet,sim-saturation \
PERF_INTERACTIVITY_ROUNDS=40 PERF_INTERACTIVITY_WARMUP=8 \
npx playwright test --project=full-terminal --project=full-resilience \
e2e/full/terminal/interactivity-perf.spec.ts e2e/full/resilience/background-terminal-bulk-output.spec.ts --workers=1

RUN_PERF_SWITCH_ROTATION=1 PERF_SWITCH_SAMPLES_PER_DEPTH=3 \
PERF_SWITCH_EXTRA_STRATA=1 PERF_SWITCH_RAPID_BURSTS=1 \
npx playwright test --project=full-resilience e2e/full/resilience/project-switch-rotation-perf.spec.ts --workers=1

npm run build:main
npm run test:idle-harness -- --projects=3 --terminals=19 --stream --blurred --window-seconds=300 --settle-seconds=30
```

The spinner epoch conversion follows the document timeline's relation to `performance.timeOrigin` in [Web Animations](https://www.w3.org/TR/web-animations-1/).

## Validation

- Full `npm test`: 2,804 files passed; 63,129 tests passed, 9 skipped, 1 todo. The opt-in cadence experiment is excluded from ordinary CI runs.
- Focused ingest, resize, WebGL visibility, full-wake, and motion checks: 281 tests passed.
- Dense single-window, distinct-project multi-window, and matched sparse E2E: passed on baseline and candidate. Every measured hidden worktree was revealed and checked for consecutive retained output, painting, and activity state; the cached second-window project was checked against the host's exact final output after stopping its stream.
- Candidate typing and background bulk-output E2E: 4 tests passed. Rotation: baseline and candidate passed with 14 isolated switches plus a rapid burst; no missing/duplicated nonce, renderer crash, hard timeout, or observed cross-PTY leak. Two evicted views were unavailable for the post-purge cross-PTY scan in each arm.
- Minified renderer and production main builds passed. Full `npm run check` passed after the sample-plugin code generator refreshed two path comments introduced by the worktree's shared `node_modules` symlink; those generated-only comments were restored and are not part of this change. A normal independent checkout should not have that path artifact.

Raw machine-local evidence is retained under `.tmp/background-energy/` and `/tmp/daintree-energy-*.log`; these logs are not committed. The comparison report contains only synthetic-fixture results. No running user installation was replaced.
